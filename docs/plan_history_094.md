## 재현 (2026-10-19 · 착수 탐침)

```
<p><a>가</a><a>나<a>다</a> 에서 김치찌개를 본다</p>  → [('p','가'), ('p','나다 에서 김치찌개를 본다')]   ← 끊긴다
<p><a>가</a><a>나</a> 에서 김치찌개를 본다</p>       → [('p','가나 에서 김치찌개를 본다')]              ← 계획 118 이 닫은 모양
<p><a>가</a><a>나 에서 김치찌개를 본다</p>           → [('p','가'), ('p','나 에서 김치찌개를 본다')]     ← 미닫힘
```

원인은 `_flush` 가 아니라 `_els` 다. `handle_endtag` 가 **안쪽부터** 자르므로
(`extract.py:382-385`) 중첩 `<a>` 의 안쪽 `</a>` 가 바깥 `a` 를 남기고, `_els[-1][2]`
(「지금 `<a>` 안인가」)가 계속 참이라 뒤따르는 글자가 **산문으로 안 잡힌다**. 브라우저는
중첩 `<a>` 를 금지해 새 `<a>` 를 만나면 앞엣것을 닫는다 — `html.parser` 는 안 닫는다.

**미닫힘(셋째 줄)은 다르다.** 브라우저에서도 그 글자는 링크 텍스트이므로 끊는 쪽이
계약과 어긋나지 않는다. **이 계획의 범위는 중첩뿐이다.**
