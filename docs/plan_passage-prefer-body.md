# 계획 74 — 근거 문단 선택을 실물로 다시 고른다 (`passage-prefer-body`)

**출처**: `discover.md` 5순위(digest 후보) — `[8]`·`[6]`. 계획 73 이 여는 조건을 열었다.

## 1. 왜 지금인가

계획 73 이 실물 361문서로 쟀다: 근거 문단 73건 중 **본문 `p` 는 41.1%**, 비-본문 58.9%.
그리고 비-`p` 43건 중 **38건(88.4%)** 은 같은 문서에 질의어를 담은 `<p>` 가 있었다.
**회수 가능한 실패가 88.4% 다.** `[8]`(무엇이 뽑히나)과 `[6]`(이름표를 쓰나)은
설계서 갈림길 6 의 같은 질문이라 **한 계획에서 판단한다** — `[6]` 이 「같은 계획에서
함께 판단할 일」이라고 스스로 적어 뒀다.

## 2. 먼저 의심할 것 — 코드가 반대를 적어 뒀다

`indexer.py:339-350` 주석은 **이름표로 갈랐더니 더 나빴다**고 적어 뒀다:
`(점수, p인가, 길이)` **13/19** < `(점수, 길이)` **15/19**. 명명된 실패 모양도 있다 —
`<footer><p>ⓒ…</p></footer>` 는 **이름표가 컨테이너를 못 본다.**

**그 19행은 합성이다.** 계획 73 에서 합성 코퍼스는 세 번 틀렸고(후보 셋 중 둘이 뒤집혔다)
방향도 제각각이었다. 그렇다고 실물 88.4% 가 자동으로 이기는 것도 아니다 —
그 숫자는 **이득만** 잰 것이다. `[6]` 이 등재한 교훈이 바로 이것이다:
**「거래를 재려면 양쪽을 같은 자로 재라」.**

**손실 축은 실재한다.** docs.python.org 은 `li` 가 본문이다(실물 태그 분포 `li` 119708 :
`p` 25087). 지금 옳게 뽑히는 `<li>` 를 보일러플레이트 `<p>` 가 덮으면 **순손실**이다.

## 3. 그래서 스텝 1 은 코드가 아니라 측정이다

규칙을 고르기 전에 **실물에서 이득과 손실을 같은 자로 잰다.**

편향을 막는 배선 — **블록을 판정하지, 규칙을 판정하지 않는다**:

1. 질의 N개 × 문서로 **후보 규칙들이 뽑을 블록의 합집합**을 모은다
2. 중복을 제거해 `(질의, url, 블록)` 풀을 만든다
3. **어느 규칙이 골랐는지 모르는 채로** 각 항목을 좋음/나쁨으로 라벨한다
4. 규칙마다 «자기가 고른 것 중 좋음의 비율» 로 점수를 낸다

같은 라벨을 모든 규칙이 나눠 쓰므로 규칙을 더 재는 값이 싸고, 판정자가 규칙 이름을
못 보므로 «내가 만든 규칙이 이기길 바라는 마음» 이 점수에 못 들어간다.

## 4. 스텝

| # | 산출물 | 완료 기준 |
|---|---|---|
| 1 | 후보 풀 + 블라인드 라벨 | 규칙 3~4개의 합집합 · 라벨 파일 |
| 2 | 규칙별 점수표 | **이득과 손실을 둘 다** 적은 표 |
| 3 | (2 가 이길 때만) 구현 + TDD | 실패 테스트 먼저 · 전수 초록 |
| 4 | 실물 재측정 | 41.1% → ? · 계획 73 과 **같은 질의·같은 자** |

**스텝 2 에서 지면 안 고친다.** 그때 산출물은 「실물로도 졌다」는 기록이고,
그것도 값이다 — 후보 둘이 닫힌다.
