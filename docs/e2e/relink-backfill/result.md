# 결과 — 계획 92 `relink-backfill` — 받아 둔 HTML 에서 링크를 되살린다

## 1. 막힌 자리 — 코퍼스 14,105장인데 크롤이 0장을 받았다

```
수집 0 페이지 · 24 도메인 · 0.8초 = 0.00 문서/초
```

상태를 재니 이렇다:

```
429 행 0 (야간이 전부 회수) · 30일 넘은 행 0 · discovered 0
→ 시드 12개가 전부 신선 → 팝에서 스킵 → 링크 추출 0 → 큐가 빔 → 0장
```

**닭-달걀이다.** 계획 91 의 `discovered` 가 이것을 막게 돼 있는데, **그 표가 비어
있다** — 영속화가 들어오기 **전에** 마지막 크롤이 끝났기 때문이다. 채우려면 크롤이
돌아야 하고, 크롤은 전부 신선해서 못 돈다. **30일을 기다리는 것 말고 길이 없었다.**

## 2. 링크는 이미 우리 손에 있다

`pages.html` 에 원문이 그대로 있다. `links.extract` 를 다시 돌리면 된다 —
**요청이 한 건도 안 나간다.**

```
표본 200장 → 링크 38,794개 · 20.8ms/장
14,105장 환산 약 293초
```

## 3. 언제 도는가 — 막힌 조건을 정확히 쓴다

```python
if not store.unfinished() and all(store.is_fresh(u) for u in ascii_seeds):
```

처음에는 `frontier.empty()` 로 물었는데 **영영 안 돌았다** — 시드가 아직 큐에 있어
거짓이기 때문이다. 시드는 그 뒤 팝에서 하나씩 스킵되고, 그때는 이미 이 갈래를 지났다.

「되찾을 것이 없고 시드가 전부 신선하다」가 **한 건도 안 나가는 상태**의 정확한 표현이다.
**평소 비용은 0** 이고 막혔을 때만 한 번 돈다 — 「할 일이 없으면 이미 가진 것을 본다.」

## 4. 계약 셋을 테스트로 못박았다

- 전부 신선한 코퍼스에서도 **일감을 찾는다** (없으면 코퍼스가 클수록 크롤이 멈춘다)
- 되살리기가 **신선도를 뒤집지 않는다** — 이미 받은 시드를 또 받지 않는다
- 범위를 **안 넓힌다** — `frontier.add` 를 지나므로 `--same-site` 가 그대로 걸린다
  (계획 88·91 이 못박은 자리가 여기서도 공짜로 지켜진다)
