### 반복 625 — 계획 phase · **어제의 「탐색 막힘」이 한 칸 성급했다** (계획 106 `verdict-last`)

여덟 출처 재측: 1~4·8 은 그대로 0건(전수 **812 OK** · 코드 마커 0 · 4순위 큐는 **파일 자체가
없다** · 이슈 0). 그런데 **7순위가 비어 있지 않았다** — `digest ## 반복 실패` 최다 항목
「러너의 판정 줄을 가린다」(**35회**)가 처방 한 줄을 **「저장소 안이라 계획으로 열 수 있다」**고
명시해 두고 있다. 어제는 이것을 ⓒ(사람 판단 대기)로 셌다. **뒤집은 것은 다시 읽은 것이
아니라 탐침 셋을 실제로 돌린 것이다**: `-b` 없이 파이프 → 판정 **0줄**(크롤 로그만) ·
`2>/dev/null` → **아무것도 없음** · `-b`+파이프 → 운으로 살아남음. **원인이 둘로 갈린다** —
둘째는 stderr 재지향이고, 첫째는 stdout 이 파이프 아래 **블록 버퍼**가 되어 끝에 밀려 나오는
**순서 역전**이다(`-b` 는 실패한 테스트의 출력을 안 삼키므로 **빨간 판에서 정확히 안 보인다**).
셋째 손실 `rc` 는 출력 길이와 무관한 파이프 자체의 성질이다. **이 반복 자신이 서른여섯 번째
표본이다** — 처음 친 명령이 `2>&1 | tail -5` 였고 항목을 읽기 전이었다. 스텝 3 · 설계 트리거
걸림(새 파일 · 대안 3갈래).

### 반복 626 — 설계 phase · **A. 얇은 zsh 래퍼** (`design_verdict-last.md`)

대안 셋을 표로 갈랐고 **가른 칸은 「러너 밖도 덮나」**였다. 이 저장소가 밤마다 치는 것은
`unittest` 만이 아니다 — 품질 기준 표 일곱 줄 중 **여섯이 `e2e/*.py`** 이고 실제 위반
표본 ⑮⑯⑳ 의 자리가 거기였다. **B(`unittest` 러너 서브클래스)는 표본의 절반을 구조적으로
못 덮고 `rc` 는 프로세스 밖 문제라 아예 못 만진다.** C(조항 조이기)의 실측값이 35회다.
**손실이 셋이고 원인이 다르다**는 것을 표로 못박았다 — ① 순서 역전(stdout 블록 버퍼)
② stderr 재지향 ③ 파이프가 먹는 `rc`. **`-b` 는 ①의 초록 절반만 덮는다**(실패한 테스트의
출력은 안 삼킨다) — 후보 `[9]` 가 ⑳에서 기각된 자리를 설계가 다시 확인했다. 형태는
/tmp 탐침 **두 판**으로 정했다(가짜 러너: stdout 200줄 + stderr 판정 + `exit 1`): `tee`판과
`>log` 후 `cat` 판이 **판정 축에서 동률**이고 갈린 것은 실행 중 화면뿐이라 **흐르는 쪽**을
골랐다. `pipestatus` 가 틀렸을 때의 증상(`rc` 가 `tee` 의 0)이 **정확히 이 계획이 막는
사고**라 변이 ②로 못박는다. 탐침은 저장소 밖에서 돌았다 — 작업 트리 무변.

### 반복 627 — 개발 스텝 1 · **재는 자가 섰고 빨갛다** (`tests/test_verdict_wrapper.py`)

6건 중 **5건 실패**(전수 818건 `FAILED (failures=5)` `rc=1`). 실패 메시지가 「없는 파일」이
아니라 **「마지막 줄이 판정을 안 실었다」**를 가리킨다 — 완료 기준 그대로다. 소스를 읽는
가드가 아니라 **실제로 돌리는** 자다: 계약 ③(`rc`)은 낱말을 세서는 영영 못 잰다. 여섯째는
**대조군**이라 지금 초록이어야 맞다 — 래퍼 없이 같은 파이프를 태우면 판정이 실제로 사라지는지
먼저 확인한다(안 사라지면 나머지 다섯은 「고쳐서 통과」가 아니라 **깨진 적 없는 것을 잰 것**).
**그리고 이 반복이 서른일곱 번째 표본을 냈다** — 전수를 친다면서 `discover -b`(시작 디렉터리
**누락**)를 쳐 **`Ran 0 tests / OK / rc=0`** 을 받았다. **파이프를 안 붙였는데도 0 을 세며
초록**이었다 — 조항이 못 덮는 **새 얼굴**이고, 잡아낸 것은 눈이 아니라 `project.md` 에 적힌
명령과 대 본 것이다(후보 등재). README 단위 수 가드가 812→818 로 물어 함께 맞췄다.

**같은 반복 끝에 하나 더 — 조항을 어겼는데 손실이 0 이다.** 기록을 갱신하고 전수를 다시
칠 때 `2>/tmp/vl_run.txt` 뒤에 `echo "rc=$?"` 와 `grep -E '^(Ran |OK|FAILED|FAIL: )'` 를
붙였다. **가려진 것은 없다** — 리다이렉션은 파이프와 달리 `$?` 를 안 먹고, 판정도 `rc` 도
화면에 있었다. **계수에 넣지 않는다**(항목이 세는 것은 «가려진 횟수»다). 값은 다른 데 있다:
손이 저절로 간 모양이 **계획 106 의 래퍼와 같은 모양**이었다 — 전량을 파일로 남기고 판정만
다시 찍기. **조항이 막으려던 충동은 「판정만 보고 싶다」이고, 그 충동은 옳다.** 막아야 할
것은 충동이 아니라 충동이 손으로 갈 때 생기는 손실이고, 그래서 처방이 문장이 아니라 기제다.

### 반복 628 — 개발 스텝 2 · **`scripts/verdict.sh`** (변이 3판 전부 죽음)

설계한 형태 그대로 ~15줄. 스텝 1 초록(6/6) · 맨몸 전수 **818 OK** · 진짜 러너를 감아
`| tail -1` 과 `2>/dev/null | tail -1` 둘 다 **`── Ran 818 tests in 25.1s OK rc=0`**.
변이 ①마지막 줄 삭제 **3건** ②`pipestatus[1]`→`[2]` **4건** ③판정을 stderr 로 **2건**.

**이 반복의 값은 변이가 아니라 원복 검사가 첫 판에 공허했던 것이다.** `git checkout --
scripts/verdict.sh` 로 되돌리려 했는데 파일이 **아직 미추적**이라 복원할 것이 없었고
(`error: pathspec … did not match any file`), 뒤따른 `git diff --quiet` 는 미추적 파일을
안 보므로 **「원복 확인: 트리 무변」이 그대로 통과했다.** 변이 셋이 쌓인 채 2·3 판을 쟀고
그 수치는 버렸다. **VCS 를 원복 검사로 쓰면 「아직 커밋 안 된 새 파일」에서 정확히 눈이
먼다** — 새 파일은 변이 검사를 가장 많이 받는 파일이다. 원본 사본과의 `cmp` + 매 판 뒤
자가 초록으로 돌아오는지까지로 바꿨다. 같은 가족이다: **재는 자를 재는 자도 재야 한다.**

**환경 변수는 래퍼 «앞»에 둔다** — `"$@"` 로 넘어온 `VAR=val` 은 배정이 아니라 명령
이름이라 `rc=127` 이다. 실측하고 주석에 적었다. 조용히 안 틀리므로(마지막 줄에
`command not found` 와 `rc=127` 이 찍힌다) 낱말을 파싱해 주는 코드는 안 넣었다.

### 반복 629 — 개발 스텝 3 · `project.md` 가 래퍼를 부른다 (개발 phase 끝)

**적기 전에 그 문자열 그대로 돌렸다** — `PYTHONPATH=src scripts/verdict.sh python3 -m
unittest discover -b tests` → `── Ran 818 tests in 25.5s OK rc=0`. **조항은 안 지웠다.**
기제가 덮는 것은 「래퍼를 통해 부른 것」뿐이고, 맨손으로 러너를 치는 길은 그대로 열려
있으며 그 자리는 여전히 조항이 지킨다 — 계획서 5절 그대로다.

**래퍼가 못 덮는 자리를 명령 바로 옆에 적었다**: 시작 디렉터리를 빼면
`Ran 0 tests / OK / rc=0` 이 **정직하게** 실려 나간다(㉓). 기제가 지키는 것은 「판정이
보이는가」지 **「모집단이 맞는가」가 아니다** — 후자는 README 단위 수 가드가 재고,
그 가드는 전수 «안»에 있어서 전수가 0건이면 자신도 안 돈다. 사람이 읽는 몫으로 남았다.

README 는 안 건드렸다 — 바깥 독자가 읽는 문서에 zsh 전용 자를 끼우지 않는다.

### 반복 634 — 설계 phase · **둘 중 하나로는 안 된다** (`design_zero-population.md`)

**C(둘 다)** 를 골랐고 고른 이유가 비교표의 마지막 두 줄이다. **A(래퍼만)는 오늘 난
사고를 못 막는다** — 그날 친 명령엔 파이프도 래퍼도 없었다. **B(`tests/__init__.py` 만)는
덫 하나를 치울 뿐** 「0건인데 초록」이라는 판정은 그대로다(오타 난 `-k`, 빈 `-s` 대상).
둘은 겹치지 않고 **서로의 구멍이 상대의 값**이다. **digest 의 처방을 탐침이 뒤집었다** —
그 항목은 「밖에서 세는 자리는 래퍼뿐」이라 적었는데 더 싼 자리가 있었다: 세는 대신
**덫을 치운다**. 래퍼 쪽 값은 `rc=2` 로 잡았다 — 이 저장소에서 **2 는 판정이 아니라
「재지 못했다」** 이고 0건이 정확히 그것이다. 3-2절 가정 셋을 실측으로 깼다: 빈
`__init__.py` 로 문서화된 **세 꼴 전부 826 OK** · `-m unittest tests.test_deps` **9건 OK**
