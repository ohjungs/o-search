# 설계: URL 에 실린 자격증명 (계획 83 `userinfo-leak`)

## 결정 — `urls.normalize` 가 netloc 에 `@` 를 든 URL 에 `None` 을 준다. 요청도 저장도 렌더도 없다

## 대안 비교

출발점을 셋으로 갈랐다(`design.md` 3-1). A·B 는 후보 `[high]` 가 적어 둔 둘이고,
C 는 컨셉 갈림길 1순위(크롤 윤리)에서 다시 낸 것이다.

| | A. 최소 — 렌더에서 가린다 | B. 정공법 — 저장 열쇠에서만 뗀다 | C. 입구에서 거절한다 |
|---|---|---|---|
| 자격증명이 남의 서버로 나가나 | **나간다** | **나간다** | 안 나간다 |
| DB 에 남나 | **남는다** | 안 남는다 | 안 남는다 |
| 화면에 나오나 | 안 나온다 | 안 나온다 | 안 나온다 |
| 되돌리기 | 쉬움 | **어려움** — 요청 URL 과 저장 URL 이 갈려 되돌리면 열쇠가 또 바뀐다 | 쉬움 (조건 한 줄) |
| 코드량 | 적음 | **많음** — `crawl`·`store`·`indexer` 가 「한 URL」 전제 위에 서 있다 | 적음 |
| 기존과 일치 | ○ | △ 새 개념(요청 URL ≠ 저장 URL) | ○ `normalize` 는 이미 `None` 을 낸다 |
| 다음이 편한가 | **나쁨** — 옛 행은 그대로라 원인이 안 닫힌다 | 보통 | 좋음 |

**선택: C.** `concept.md` 갈림길 1순위가 **크롤 윤리**다. 남의 자격증명으로 남의
서버에 인증 요청을 보내는 것은 robots·간격과 같은 칸의 문제고, 그 축은 저장·렌더보다
앞선다. A·B 는 **요청이 나가는 것을 둘 다 그대로 둔다** — 셋 중 그것을 막는 안은 C 뿐이다.
사다리로도 가장 높다: `links.extract:35` 가 `None` 을 이미 버리므로 링크 경로 배선 **0줄**.

**버린 이유: A** — 원인이 아니라 증상을 가린다. 자격증명은 여전히 나가고 DB 에 쌓이며,
DB 는 백업·복사로 화면 밖으로 나간다. **B** — 「요청 URL ≠ 저장 URL」은 되돌리기가
가장 어려운 축(설계 비교 1순위)을 건드리면서, 정작 요청은 그대로 나간다.

## 가정 — 3-2절에서 깬 결과

**깬 것**: 「거절해도 실물에서 잃는 것이 없다」.

- **제품 쪽은 참이다.** 실물 `data/crawl.db` **400행 중 거절될 URL 0건**.
- **테스트 쪽은 거짓이었다.** `tests`·`e2e`·`src` 의 URL 리터럴 352개 중 netloc 에
  `@` 를 든 것이 **10개**고, 그중 셋이 이 변경에 실제로 걸린다:
  `tests/test_urls.py:289` (`test_userinfo_survives` — **계약 자체**) ·
  `:321` (멱등성 목록) · `e2e/domain_key_e2e.py:150` (시드가 거는 링크).
  나머지 일곱은 `to_ascii`·`domain_key`·`_split`·`robots._base` 것이라 안 건드린다.

**설계를 다시 하지 않고 범위를 넓혔다** — 무너진 것은 제품 가정이 아니라 픽스처였다.
다만 `domain_key_e2e.py` 는 대가가 있어 아래에 따로 적는다.

### 대가 — `domain_key_e2e.py` 시나리오 1 의 축이 사라진다

그 파일은 **userinfo 가 「`normalize` 가 접지 않고 `domain_key` 가 접는」 살아 있는
유일한 축**이라고 스스로 적어 뒀다(파일 독스트링). C 를 넣으면 표기 셋이 프런티어에
닿기 전에 하나가 되어 **재려던 상황이 다시 안 만들어진다** — 018 때와 같은 모양이다.
그 파일의 종료 2 가드(「잴 대상이 사라지면 측정 불능」)가 **조용한 통과 대신 크게
실패**하므로 놓칠 수는 없다.

**처방: 그 시나리오를 새 계약으로 갈아 끼운다** — 같은 서버·같은 Host 헤더 로그를 그대로
쓰고, 재는 것을 「세 표기가 한 도메인으로 묶인다」에서 **「자격증명 표기는 아예 안
나간다(수신 0건) · 남은 표기는 여전히 한 도메인」**으로 바꾼다. 하네스를 재사용하므로
새 파일은 없다. **017 의 e2e 급 회귀 탐지기는 여기서 끝난다** — 남는 것은 단위
`tests/test_urls.py:162`(`domain_key` 가 userinfo 를 뗀다)이고, 그 사실을 파일
독스트링에 적는다. 이것을 감출 자리가 없다.

## 계약 — 개발이 지킬 것

- `urls.normalize(url)` → **netloc 에 `@` 가 있으면 `None`.** 다른 반환값은 무변경.
  판정은 `_split` 이 준 netloc 위에서만 한다 — **경로·질의의 `@` 는 통과**한다
  (`http://a.test/x@y?m=n@o`).
- `urls.has_credentials(url)` (새 공개 술어) → `bool`. 시드 루프가 **사유를 가르는 데만**
  쓴다. 못 읽는 URL 에도 **안 던진다** — 거기서 던지면 크롤이 끝난다(`normalize` 와 같은
  관용구). **정정 (반복 490 리뷰)**: 초안은 그 경우 「`False`」라고 적었는데 실물은
  `_split` 의 폴백이 준 netloc 후보 위에서 답한다 — `http://u:pw@[oops/p` 는 `True` 다.
  거는 쪽이 안전한 방향이고 단위로 고정했다(`TestHasCredentials`).
- `to_ascii`·`domain_key`·`_split`·`robots._base` **무변경.** `domain_key` 는 계속 userinfo 를 뗀다.
- `crawl.crawl` 의 시드 루프는 자격증명 시드에 **자기 사유**를 stderr 로 내고 건너뛴다.
  크롤은 나가지 않는다.
- `links.extract`·`crawl.py:345` **배선 0줄.** 앞은 `None` 을 이미 버리고, 뒤는
  `or url` 로 떨어지는데 그 `url` 은 프런티어를 지난 것이라 이미 안전하다.
- `serve.py`·`store.py`·`indexer.py` **0줄.**

## 되돌리기

`normalize` 안의 조건 한 줄을 지우면 옛 동작이다 (`design.md` 3절 ③ — 커밋 하나 revert).
**야간 처분이 패치라 애초에 적용되지 않는다** — `main` 은 무변경이다.

## 범위 밖

- **`serve.py` 렌더 가리기** — 오늘 가릴 대상 0건. 여는 조건: 옛 DB 에서 자격증명 행이
  1건이라도 세어지는 날.
- **기존 행 정리·재색인** — 데이터 형태 변경이라 야간 금지. `[high]` 「정규화는 새 DB
  에서만 목적을 달성한다」가 이미 잡아 둔 자리다.
- **`domain_key` 의 userinfo 접기를 지우는 것** — C 를 넣으면 크롤 경로에서 도달
  불가가 되지만, `domain_key` 는 크롤 밖에서도 불린다. 죽은 코드 판정은 따로 세어야
  한다 → **digest 후보로 올린다.**
- **`design.md` 4절 「보안 경계 변경」과의 관계** — 이 계획은 신뢰 경계의 **구조**를
  바꾸지 않는다(크롤한 웹 = 불신은 그대로). 그 경계를 **무엇이 넘는지**만 좁힌다.
  그래도 보안이라 `SKILL.md` 대로 **적용은 사람이 한다** — 판단을 뺏지 않는다.
