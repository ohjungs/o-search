# 설계: 의존성 0 을 재는 자 (계획 103 `dep-zero`)

## 결정 — `ast` 로 이름만 모으고, 「빌트인 ∪ stdlib 경로 ∪ 저장소 안의 파일」 밖은 전부 위반이다. 허용 목록 0줄

모집단은 `src/` · `tests/` · `e2e/` 셋 다(**54파일**). 판정은 `find_spec` 의 `origin` 이
`sysconfig` 의 stdlib 경로 밑인지이고, 빌트인은 `sys.builtin_module_names` 가 받는다.
**`find_spec` 이 `None` 인 것(= 안 깔린 패키지)도 위반이다** — 이 한 줄이 계획의 요점이다.

## 대안 비교

출발점을 셋으로 갈랐다(`design.md` 3-1). 계획서가 적어 둔 세 갈래와 대체로 겹치지만,
**갈리는 진짜 축은 「3.9 에서 stdlib 를 어떻게 아나」가 아니라 「안 깔린 패키지를 어떻게
판정하나」였다** — 아래 넷째 행이다.

| | A. 최소 — 손으로 쓴 허용 목록 | B. 정공법 — import 기계에 묻는다 | C. 되돌리기 우선 — 경로에 파일이 있나만 본다 |
|---|---|---|---|
| 목록 유지비 | **26개 이름을 손으로 민다** | 0줄 | 0줄 |
| 3.10 으로 올리는 날 | **두 벌이 된다** (`stdlib_module_names` 와 내 목록) | 그대로 맞다 | 그대로 맞다 |
| 새 stdlib 모듈을 쓰면 | **옳은 변경이 빨개진다** | 초록 | 초록 |
| `import requests` · **안 깔린 기계** | 빨감 | 빨감 (`origin=None` → 위반) | 빨감 |
| `import requests` · **깔린 기계** | 빨감 | 빨감 (site-packages 경로) | 빨감 |
| `sys.path` 오염에 흔들리나 | 안 흔들림 | 흔들릴 수 있음 (아래 가정에서 깼다) | 안 흔들림 |
| 빌트인(`sys`·`time`·`itertools`) | 목록에 있음 | `builtin_module_names` | **파일이 없어 따로 받아야 함** |
| 코드량 | 가장 적음 | 적음 | B + 경로 조립 |

**선택: B.** A 를 버린 이유가 이 저장소에 **이미 적혀 있다** — `tests/test_e2e_fd.py` 가
「개수를 요구하면 옳게 고친 파일이 빨개진다」로 배운 자리와 같은 모양이다. 허용 목록은
**정상 작업을 막는 자**가 되고, 그런 자는 결국 꺼진다. C 는 B 가 실제로 흔들릴 때만 값이
있는데, 아래 탐침에서 **안 흔들리는 것을 확인했다** — 사지 않은 보험이다.

**셋 다 같은 답을 내는 행이 둘 있다**(넷째·다섯째 행). `design.md` 3-1 의 「수렴하면 좋은
신호」다 — 고르는 축이 성능이나 정확도가 아니라 **유지비**뿐이라는 뜻이다.

## 가정 — 3-2절에서 깬 것 (커밋 안 함)

**① 「`find_spec` 이 남의 코드를 실행한다」 → 거짓.** 최상위 이름만 넘기면 안 돈다.
`turtle`(임포트하면 `tkinter` 를 끌어온다)로 대봤다 — `origin` 은 나오는데
`sys.modules` 에는 **안 들어간다**. 그래서 점 있는 이름은 반드시 **첫 마디로 잘라** 묻는다
(`concurrent.futures` → `concurrent`). 안 자르면 `find_spec` 이 부모 패키지를 **임포트한다**.

**② 「stdlib 경로 검사면 충분하다」 → 거짓.** `sys` · `time` · `itertools` 는 `origin` 이
경로가 아니라 **`'built-in'`** 이다(실측). 셋 다 `sys.builtin_module_names` 에 있고,
반대로 `zlib` 은 빌트인이 **아닌데** `lib-dynload/zlib.cpython-39-darwin.so` 로 stdlib
경로 **밑**이다. **두 판정이 서로를 덮지 않는다 — 합집합이어야 한다.**

**③ 「`websearch` 는 자동으로 표준 아님이라 위반으로 잡힌다」 → 잡힌다. 그게 문제다.**
전수는 `PYTHONPATH=src` 로 도는데, 그러면 `websearch` 의 `origin` 이 `src/websearch/__init__.py`
= **stdlib 밖**이다. 자기 패키지를 위반으로 신고하는 자가 된다. 그래서 1순위 판정을
**「저장소 안에 그 이름의 `.py` 나 디렉터리가 있나」**(순수 파일 시스템)로 둔다 —
`find_spec` 을 아예 안 타므로 `PYTHONPATH` 가 있든 없든 답이 같다. 실측으로 이 그물이
받아야 할 이름은 다섯이다: `websearch` · `design_check` · `passage_eval` · `quality_eval` ·
`perf_search`(뒤 넷은 `e2e/*.py` 를 형제끼리 임포트하는 것).

**④ 오늘의 위반은 셋 다 0 이다**(실측): `src` 12파일·16이름 · `tests` 19파일·28이름 ·
`e2e` 23파일·25이름. **고칠 것이 없다는 계획서의 전제가 실물에서 확인됐다.**

## 모집단 — 셋 다 넣는다

계획서가 설계로 미룬 자리다. `src/` 만이 아니라 `tests/` · `e2e/` 까지 넣는다.

- **오늘 값이 공짜다** — 셋 다 위반 0 이라(가정 ④) 넓혀도 빨개지는 것이 없다.
- 「누구나 clone 해서 돌린다」가 이 저장소의 전제인데, `tests/` 의 `import pytest` 한 줄도
  그것을 깬다. 컨셉 경량 3 의 「신규 의존성」은 제품 코드에만 걸리는 말이 아니다.
- `scripts/` 는 `.py` 가 **0개**라(`merge-to-main.sh` 뿐) 넣을 것이 없다. `rglob` 이라
  나중에 생기면 저절로 들어온다.
- **`tests/` 가 자기를 훑는 재귀는 문제가 아니다** — `ast` 로 읽을 뿐 실행하지 않는다.
  이 파일 자신의 임포트(`ast`·`sysconfig`·`importlib.util`·`pathlib`·`unittest`)는 전부 stdlib 다.

## 판정 규칙 — 네 갈래, 순서가 중요하다

이름 하나를 놓고 위에서부터 본다. **`import`·`from` 의 첫 마디만 본다.**

1. **상대 임포트**(`from . import x`, `level > 0`) → 자기 패키지다. 통과.
2. **저장소 안에 그 이름이 있다** (`src/<n>/`, `src/<n>.py`, `<pop>/<n>.py`, `<pop>/<n>/`) → 통과.
3. **`sys.builtin_module_names` 에 있다** → 통과.
4. **`find_spec(<n>).origin` 이 stdlib 경로 밑이다** → 통과.
5. **그 밖 전부 위반** — `origin` 이 site-packages 든, `find_spec` 이 `None` 이든, 예외가
   나든 **똑같이 위반이다.**

**5번의 「`None` 도 위반」이 이 계획이 존재하는 이유다.** 이것을 「못 찾았으니 건너뛴다」로
쓰면, `import requests` 는 **그 패키지가 안 깔린 기계에서 초록**이 된다 — 계획서가 적은
「전자는 영영 안 보인다」가 그대로 재현된다. **모르면 통과가 아니라 모르면 실패다.**

**`try: import X except ImportError:` 도 위반이다.** 선택적 의존성도 의존성이고, 그 갈래는
「깔린 기계에서만 다르게 도는 코드」라 컨셉이 막는 바로 그것이다. `ast.walk` 를 쓰므로
함수 안·`try` 안의 임포트도 전부 걸린다 — **최상위만 보면 한 칸 들여쓰는 것으로 빠져나간다.**

## 거짓 초록 방지 — 0 을 세면서 통과하지 않는다

계획 101 이 `\bHTTPServer\(` 로 배운 자리다. 훑은 **파일 수**와 판정한 **이름 수**에 하한을
박는다. 오늘 실측(54파일)보다 낮되 여유를 크게 두지 않는다 — 경로 오타·`rglob` 실패로
0파일을 훑고 「위반 0」을 외치는 것을 막는 것이 목적이다.

**변이**: 임시 파일에 `import requests` 를 심어 위반으로 잡히는지 본다. 파일을 진짜로
만들었다 지우는 쪽이 아니라 **판정 함수에 이름을 직접 넣는** 쪽이면 모집단 그물을 안 탄다 —
둘 다 한다(함수 단위 + 실제 `.py` 를 모집단 안에 만들고 지우는 판).

## 하지 않을 것 (계획서 + 설계에서 는 것)

- **`requirements.txt` 를 만들지 않는다** — 없는 것을 관리하는 일이다(계획서).
- **버전·해시 고정 없음.** 의존성이 0 이라 고정할 대상이 없다.
- **`ast` 가 못 보는 동적 임포트(`__import__`·`importlib.import_module`)를 안 쫓는다.**
  `ponytail:` 천장이다 — 잡는 것은 「어느 날 `import requests` 한 줄」이라는 실제 재발
  경로 하나고, 문자열로 감춘 임포트를 쫓으려면 이 자가 린터가 된다. 감춰서 넣는 사람은
  이 자가 아니라 리뷰가 막는다.
- **이름 shadowing 을 안 판정한다** — 누가 `src/websearch/requests.py` 를 만들면 규칙 2 가
  `import requests` 를 통과시킨다. 그건 의존성이 아니라 로컬 모듈이므로 옳은 통과다.

## 스텝 (계획서 그대로 · 설계로 안 갈렸다)

1. `tests/test_deps.py` — 위 규칙 + 하한 + 변이. 완료 기준: 전수 초록 · 가짜 임포트로 빨감.
2. `docs/project.md` 품질 기준 표 일곱째 줄. 합격선 **「위반 0」이고 이 자는 문다**.
