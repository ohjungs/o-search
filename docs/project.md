## 품질 기준 <!-- docs/specs/concept.md 4축의 실행 명령판 -->

- **경량 상한**: 없음 — search-ui 계획에서 JS 50KB(gzip) 측정 명령 추가 예정
- **성능 측정**: `e2e/perf_search.py` — `GET /search` 왕복 p50·p95. 순차·로컬,
  네트워크를 타지 않는다. p95 가 300ms(컨셉 성능 1)를 넘으면 실패한다
- **디자인 검사**: 없음 — search-ui 계획에서 추가 예정
- **검색 품질**: 없음 — quality-eval 계획에서 질의 40개 셋 + 포함률 측정 추가 예정
- **기준선 파일**: 없음 — 숫자를 여기 적는다. **2026-08-25 / 3000문서 색인 /
  질의 5종 × 200회 = 1000 요청: p50 1.27ms · p95 6.71ms · 최대 6.89ms.**
  p95 를 끌어올리는 것은 `page=100`(OFFSET 990, p50 6.5ms) 하나다 — 나머지 질의는
  모두 1.3ms 이하다. 설계 탐침(990에서 7.2ms)과 같은 값이다.
  **이 숫자는 합격 판정이 아니다** — 컨셉의 300ms 는 100만 문서 기준이고 여기는 3000문서다.
  색인이 커지거나 질의 경로가 바뀌었을 때 이것과 비교해 회귀를 잡으라고 적어 둔다
