# 계획 123 `signal-vocab-nail` — 병합 게이트가 읽기 시작한 값을 저장소는 아직 안 읽는다

**슬러그**: `signal-vocab-nail`
**브랜치**: `loop/signal-vocab-nail` (기점 `2b090c8` = `loop/pin-rot-nail` 끝 — 아래 「기점」 절)
**근거**: 탐색 **5순위**(`digest.md` 보류 항목의 승인) — 후보 **`[8]`**(점수 8, 열린 것 중 최고)
의 여는 조건 **「사람이 ⑲ 의 축을 고르는 날」**이 **2026-10-26 에 실측으로 섰다.**
**시작**: 2026-10-26

## 근거 — 무엇이 어젯밤과 달라졌나

**접었다 (2026-10-26 반복 760 · `ReadBudgetTest` 가 604 > 600 으로 물었다).** 원본 넷 다 실재 확인:
`status.md` **게이트 ⑲**(해소 본문) · `history_current.md` 반복 **756** ·
`docs/reports/night_2026-10-26.md` `## 🟢 완료` · `digest.md` 후보 `[8]`.

**한 줄로**: 사람이 `o-search-autoloop.sh` 에 ㉠ 을 넣어 게이트 ⑲ 를 닫았고(승인 조건 `:95-96` 에
`signal:` · 병합은 분리 워크트리 · 푸시 복구 `origin/main..main` **0** · `main` 전수 **939 OK**),
그 수리가 `signal:` 을 **장식에서 하중 받는 값**으로 바꿨다 — 그런데 **저장소에 읽는 자가 0개다.**

## 목표

`status.md` frontmatter 의 `signal:` 값이 **하네스가 정의한 넷**(`GREEN` · `YELLOW` ·
`RED` · `DONE`) 중 하나인지 전수가 센다. 완료되면 **오타·새 낱말·한글 표기가 들어간 밤에
전수가 빨개진다** — 지금은 그런 밤이 와도 전수가 초록이고, 병합 게이트는 그 값을 몰라서
**조용히 영구히 병합을 안 한다.** 그 침묵의 유일한 기록은 다시 저장소 밖 로그다(⑲ⓑ).

**이것이 재발인 것이 근거의 핵이다.** 게이트 ⑲ 가 터진 모양은 「절차를 문서에만 적고
재는 자를 안 만든다」였고, ㉠ 의 수리는 **게이트 쪽에만** 자를 세웠다. 저장소 쪽은 여전히
자를 안 들고 있어, 같은 계열의 **방향만 뒤집힌 사고**(잘못 병합 → 조용히 안 병합)가 열려 있다.

## 않을 것

- **게이트의 조건을 저장소에 복사하지 않는다** — 「DONE 이거나 GREEN+`plan: null` 이면
  병합」을 테스트에 적으면 저장소 밖 로직의 사본이 되고, 사람이 스크립트를 고치는 날
  **거짓말하는 가드**가 된다(후보 `[6]` 이 적어 둔 「측정기가 규칙을 복사하는 사고」).
  이 계획이 무는 것은 **어휘뿐**이다 — 넷 중 하나인가. 게이트가 무엇을 하는지는 안 본다.
- **보고서 이모지 축(`report_signal`)을 건드리지 않는다** — 계획 122 의 자리고 보류 중이다.
- **게이트 ⑱ 의 ㉠·㉡·㉢ 을 고르지 않는다** — 사람 몫이고 이 계획과 독립이다.
- **`signal:` 값을 고치지 않는다** — 오늘 값(`YELLOW`)은 참이다. 자를 세우는 것만 한다.
- 산문을 안 읽는다 — `live_gap` docstring 이 두 번 일부러 피한 방향이다(거짓 RED 원천).

## 설계

**생략** — `design.md` 1절 트리거에 안 걸린다. 새 파일 0개(`tests/test_docs.py` 에 더한다) ·
제품 **0줄** · 스키마·저장 형태 무변경 · 되돌리기는 함수 하나 삭제 · 공개 인터페이스는
테스트 계층의 순수 함수 하나로 **`read_budget_gap`·`live_gap`·`pin_rot_gap` 선례 그대로**다.
**대안이 갈리지 않는다**: 어휘를 리터럴로 동결하는 꼴은 `report_signal` 이 같은 파일에서
**이미 넷을 리터럴로 동결**해 저장소가 받아들인 모양이다. 게이트 조건을 복사하는 쪽은
위 「않을 것」에서 **근거를 들어 버렸다**(설계가 아니라 범위 결정이다).

## 기점 — 왜 `main` 이 아닌가

**`loop/pin-rot-nail` 끝(`2b090c8`)에서 딴다.** `main`(`8e56457`)에서 따면 **장부가 세 밤
퇴행한다** — 반복 748~755 의 기록이 보류 브랜치에만 산다(실측 `git diff --stat
main..loop/pin-rot-nail -- docs README.md` = **11파일 `+649/-242`**, 코드는
`tests/test_docs.py` **+285** 뿐). 되돌릴 길 둘이 다 막혀 있다: 손으로 조립하는 것은
`project.md` 가 금지하고(「병합은 손으로 조립하지 않는다」), 버리는 것은 **데이터 유실**이다.

**대가를 명시한다**: 이 계획은 계획 122 의 병합 차단을 **물려받는다** — 게이트 ⑱ 이
풀릴 때까지 둘 다 `main` 에 못 간다. **이것이 어젯밤 반복 755 가 세기 시작한
「보류의 대가」의 둘째 항이다**(첫째는 푸시 차단 — 그쪽은 오늘 해소됐다). 적어 두는 이유는
㉠·㉡·㉢ 중 하나를 고르는 값이 **한 계획이 아니라 쌓이는 계획 수만큼**이라는 것이
결정하는 사람에게 보여야 하기 때문이다.

## 천장 — 미리 적는다

- **하네스가 다섯째 신호를 만드는 날 거짓 RED 다.** 어휘가 저장소 밖(SKILL.md)에 정의되고
  사본이 여기 사는 구조라 피할 수 없다 — `report_signal` 의 이모지 넷이 이미 같은 천장
  위에 산다. **완화는 메시지로만 한다**: 빨강이 넷을 전부 인쇄하고 고칠 자리를 댄다.
- **게이트가 `signal:` 말고 다른 것을 보기 시작하면 이 자는 그것을 모른다.** 어휘만 무는
  결정의 대가고, 「않을 것」 첫 항과 같은 거래다.
- **하루 해상도도 아니고 값의 «참» 도 안 본다** — `signal: GREEN` 인데 실제로 빨간 밤은
  이 자가 못 잡는다. 그쪽은 게이트가 전수를 직접 돌려서 막는다(`o-search-autoloop.sh:83`).
