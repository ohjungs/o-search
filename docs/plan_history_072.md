# 계획 — `project.md` 를 읽기 예산 안으로 (`project-md-diet`)

## 1. 문제

**필수 읽기가 600/600 으로 꽉 찼다.** `docs.md` 1절 상한이 「문서 5개 / 총 600줄」인데
오늘 실측이 `project.md` 249 + `status.md` 112 + `history_current.md` 239 = **600** 이다.
여유가 0이라 **다음에 무엇을 적든 상한을 넘는다** — 반복 563 이 `status.md` 를 26줄
줄였는데 그 자리를 그 반복의 기록과 게이트 ⑨ 등재가 그대로 먹었다(압축이 두 번 다 제자리).

`history_current.md` 는 239/300 이라 두세 밤 뒤 회전하며 스스로 줄고, `status.md` 는
112 로 제 예산 50 의 2.2배지만 두 번 깎아 봤고 두 번 다 되밀렸다. **남은 레버는
`project.md` 하나고 제 예산 60 의 4.2배다.** 562·563 이 둘 다 「거의 안 바뀌는 사실」
이라며 재지 않고 넘겼다 — **안 바뀌는 것과 매 반복 읽어야 하는 것은 다른 질문이다.**

## 2. 무엇이 예산을 먹고 있나 (실측)

| 절 | 줄 | 성격 |
|---|---|---|
| `## 명령` | 94 | 명령 줄 자체는 20줄 남짓. 나머지는 **e2e 13종의 시나리오·변이 확인 서술** |
| `## 품질 기준` | 135 | 합격선은 20줄 남짓. 나머지는 **기준선 숫자·변이 7종·캡 설계 논증** |
| 나머지 4절 | 15 | 헤더 · 브랜치 · 한도 · 건드리지 않을 곳 |

**`project.md` 를 매 반복 읽는 이유는 `docs.md` 1절이 적어 두었다 — 「매 반복 명령을
다시 찾지 않기 위해」.** 그 목적에 필요한 것은 **칠 명령과 판정 기준**이고, 기준선
숫자·변이 확인 기록·캡 설계 논증은 **그 도구를 실제로 쓰는 반복에만** 필요하다.
229줄 중 약 170줄이 매 반복 읽히면서 그 반복에 쓰이지 않는다.

## 3. 목표

`project.md` **249 → 60줄 이하**. 옮기는 것은 `docs/baselines.md`(신설, 예산 밖 —
필요할 때만 읽는다)로 가고 **한 글자도 버리지 않는다.** 각 절은 포인터 한 줄을 남긴다.

**하지 않을 것:** 숫자 갱신·재측정(옮기기만 한다) · `status.md` 압축(두 번 되밀렸다) ·
`history_current.md` 조기 회전(⑥ digest 211줄을 악화시키고 빈손 대조 핀을 깬다).

## 4. 지켜야 할 계약 (테스트를 읽고 뽑았다)

1. **`tests/test_readme.py:103`** — 러너 명령 줄(`python3 -m unittest discover`, `-b` 포함)이
   `README.md` 와 `docs/project.md` **양쪽에** 있어야 한다. → 「명령」 절에 남긴다
2. **`tests/test_docs.py` `ProjectConstTest`** — ① 인용한 `mod.CONST` **= 숫자** 가 코드와
   같을 것 ② 그런 인용이 **최소 1건**(`CONST_CITATION_FLOOR = 1`). 인용 0건이면 검사가
   아무것도 안 재면서 초록이다. → `indexer.MAX_PASSAGE_TAGS` **= 3,000** 을 남긴다
3. **맨몸 규율**(파이프·`head`·리다이렉션 금지)은 **명령을 읽는 자리**에 있어야 한다 —
   그 자리로 «옮겨 온» 문장이다(digest 반복 실패 최다 항목). `baselines.md` 로 보내지 않는다

## 5. 스텝

**둘뿐인 이유**: 절이 둘이고 각각이 되돌릴 수 있는 단위다. 개수를 채우려 쪼개지 않는다.

### 스텝 1 — `## 품질 기준` 135 → 20줄 이하 · 의존: 없음

`docs/baselines.md` 를 만들고 기준선 블록(검색 품질·근거 문단·`perf_search`·캡 설계
논증·디자인 검사 변이 7종·눈먼 자리 4건)을 **그대로** 옮긴다. `project.md` 에는 축별로
「무엇을 재나 · 합격선 · 명령」 한두 줄 + `→ baselines.md` 포인터만 남긴다.

- **완료 기준**: `PYTHONPATH=src python3 -m unittest discover -b tests` **763 OK** ·
  `## 품질 기준` 절이 **22줄 이하** · `grep -c "MAX_PASSAGE_TAGS" docs/project.md` ≥ 1 ·
  6절 `comm -23` 이 **빈다**

  > **처음 적은 기준이 틀려서 고쳤다** — 「`wc -l` 이 135 이상 줄어 있다」고 썼는데
  > 그건 **22줄짜리 대체본을 안 센 산술**이다. 135줄 몸통을 빼고 22줄을 넣으면 순감은
  > **113**(249→136)이고, 파일 축 ≤60 은 스텝 2까지 가야 나온다. 재는 축을 파일에서
  > **절**로 옮겼다 — 이 스텝이 실제로 책임지는 것이 그 절이다.

### 스텝 2 — `## 명령` 94 → 30줄 이하 · 의존: 1

e2e 13종을 **명령 + 한 줄 요약**으로 줄이고 시나리오 상세·변이 확인 기록을
`baselines.md` 로 옮긴다. 테스트·변이 검사·맨몸 규율 문단은 **자리에 둔다**(계약 3).

- **완료 기준**: 전수 **763 OK** · `wc -l docs/project.md` **≤ 60** ·
  `grep -c "unittest discover" docs/project.md` ≥ 1 ·
  13종 e2e 명령 문자열이 `project.md` 에 **전부 그대로** 남아 있다(수로 대조)

## 6. 검증 — 옮긴 것이 안 없어졌는지 기계로 본다

눈으로 대조하면 놓친다. 두 파일을 합쳐 옛 본문과 **줄 단위 집합**으로 비교한다:

```bash
git show HEAD:docs/project.md | sort -u > /tmp/before.txt
cat docs/project.md docs/baselines.md | sort -u > /tmp/after.txt
comm -23 /tmp/before.txt /tmp/after.txt    # 사라진 줄 — 의도한 것만 있어야 한다
```

`docs.md` 1절의 예산 60 을 이 저장소가 처음으로 지키게 된다 — 그때 실측을
`status.md ## 규모 축` 에 다시 적는다.
