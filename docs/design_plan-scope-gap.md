# 설계: 계획서 「건드릴 파일」 칸을 읽는 자

## 결정 — **안 A(정공법)**

활성 계획서의 「건드릴 파일」 칸을 **텍스트 그대로** 두고, **그 브랜치가 실제로 건드린
기록 밖 파일**이 그 텍스트 안에 **이름으로 들어 있는지**만 본다 (`diff ⊆ 칸`, 포함 검사).
git 을 못 읽는 사본에서는 **건너뛴다** — 게이트 ⑱ ㉢ 과 같은 선례, 같은 대가.

## 대안 비교 — 출발점을 셋으로 갈라 냈다 (`design.md` 3-1절)

| | A. 정공법 (git diff ⊆ 칸) | B. 최소 (정적 · `tests/` → `README.md`) | C. 되돌리기 우선 (칸의 실재만) |
|---|---|---|---|
| 되돌리기 | 커밋 하나 revert | 커밋 하나 revert | 커밋 하나 revert |
| 코드량 | 보통 (subprocess 3줄 + 포함 검사) | 적음 | 적음 |
| 기존과 일치 | △ 문서 가드 중 git 을 읽는 **첫 자** · 건너뛰기는 선례 둘 | ○ 순수 텍스트 함수 | ○ |
| 다음이 편한가 | ○ 다섯 재발 **전부**와 장래의 다른 파일까지 | △ `README.md` 한 부류만 | ✕ 재발을 **안 막는다** |

**실측이 B 를 떨어뜨렸다.** 장부(`UNIT_COUNT`, 2026-08-29 도입) 이후 계획서 중 칸에
`tests/` 가 있고 `README.md` 가 없는 것 **6건**을 슬러그로 추적하니 **4건은 그 계획이
`README.md` 를 아예 안 건드렸다**(`crawl-gap-ab`·`merge-verdict`·`bare-citation`·
`nested-anchor-cut` — 건수가 안 변하는 작업이다). 즉 B 는 **정당한 계획 넷에 거짓
RED** 를 내고, 그러면 다음 계획은 안 건드릴 파일을 칸에 **미리 적는 습관**을 들인다 —
칸이 「예상」에서 의식(儀式)으로 바뀌는 것이고 그것은 죽은 조항을 하나 더 만드는 것이다.
**C 는 재발을 안 막는다** — 다섯 번 난 것은 「칸에 없는 파일을 고쳤다」지 「칸이 없다」가 아니다.

**A 의 유일한 대가를 실측했다** — `git archive HEAD` 를 `/var/folders` 에 풀면 `.git` 이
**없고**(`ls -a | grep -c '^.git$'` = 0) 그 안에서 `git diff` 는 *Not a git repository* 다.
그래서 리뷰 phase 의 깨끗한 사본 실행에서 **건너뛴 수가 2 → 3** 이 된다. 이 저장소는 그
대가를 **사람이 2026-10-26 에 이미 한 번 골랐고**(게이트 ⑱ ㉢ · `NightReportSignalTest`·
`ReportNameTest` 둘이 그 짝이다) 건너뛴 것은 출력에 **보인다.** 조용한 초록이 아니다.
**못 쟀다**: 사본이 저장소 «안» 에 풀리면 git 이 부모 저장소를 찾는다 — git 의 저장소
탐색 규칙상 그렇지만 이 반복에서 **재지 않았다**(측정은 개발 phase 로 넘긴다).

## 가정 — 깨 봤다 (`design.md` 3-2절 · 탐침 1회)

**「칸에 적힌 파일 이름을 기계가 알아볼 수 있다」.** 틀리면 이 설계가 무너진다 — 칸은
자유 서술이고 백틱 안에 상수·테스트 이름·`--resample` 같은 것이 섞인다.

`docs/plan_*.md` 103개에 칸 추출기를 대니 **24개가 걸리고**(나머지는 옛 꼴 `## 범위`)
걸린 24개 전부에서 경로꼴 토큰이 나왔다. 섞인 것도 실제로 나왔다 —
`ReadmeCommandsTest.test_…`·`/tmp`·`--resample`·`UNIT_COUNT`·`E2eRosterTest`.
**그런데 탐침이 가정을 깨는 대신 설계를 더 게으르게 만들었다**: 판정 방향이 `diff ⊆ 칸`
이므로 **칸을 파싱할 필요가 없다.** 건드린 경로 문자열이 칸 텍스트 안에 있는지만 보면
되고, 섞인 토큰은 **거짓 RED 를 못 만든다**(칸에 더 적힌 것은 벌하지 않는다).
→ 토큰 추출기·경로꼴 필터를 **만들지 않는다** (ponytail 1번).

## 계약 — 개발이 지킬 것

1. **`scope_gap(field_text, touched)` 순수 함수** — 칸 텍스트와 경로 순서열을 받아 한 줄
   또는 `None`. 재는 일(git·파일)과 판정을 가른다 (`verdict_gap`·`step_gap`·`read_budget_gap` 관용구).
2. **칸이 0개면 「재지 못했다」** 를 돌려준다 — 조용히 통과하지 않는다. `signal_gap`·
   `index_status_gap` 과 같은 관례고, 다음 계획이 칸 꼴을 바꾸면 **빨강으로** 알려야 한다.
3. **입력은 세 줄로 모은다** — `base = git merge-base main HEAD` ·
   `git diff --name-only <base>`(커밋된 것 **과** 미커밋 작업 트리를 함께 준다) ·
   `git ls-files --others --exclude-standard`(새 파일). **커밋 전에도 물어야** 쓸모가 있다.
4. **기록 화이트리스트는 리터럴로 못박는다** — `docs/status.md`·`history_current.md`·
   `index.md`·`metrics.md`·`digest.md` · `docs/plan_*`·`design_*`·`history_NNN.md` ·
   `docs/e2e/**`·`docs/reports/**`·`docs/patches/**`. **`docs/project.md`·`baselines.md`·
   `docs/specs/**` 는 넣지 않는다** — 그쪽은 진짜 범위 이탈이라 칸에 적혀야 한다.
   목록을 상수로 두고 **값을 손으로 세는 테스트**를 함께 둔다(계획 126 의 `SOURCE_DIRS`
   자기참조 교훈 — 기대값을 상수로 조립하면 양변이 같이 줄어 초록이 된다).
5. **git 을 못 읽으면 `skipTest`** 하고 사유에 「게이트 ⑱ ㉢ 과 같은 선례」를 적는다.
   `rc != 0` 과 `FileNotFoundError` 둘 다 같은 길로 간다.
6. **활성 계획서가 없으면 조용하다** — `PLAN_SLUG` + 파일 존재. `read_budget_gap` 과 같은 꼴.

## 되돌리기 — 커밋 하나 revert. 자가 하나와 테스트뿐이고 제품 `src/` 0줄이다.

## 범위 밖

- 칸에 적혔는데 **안 건드린** 파일(반대 방향) — 칸은 「예상」이라 벌할 것이 아니다.
- 짧은 경로(계획서 없음)의 `status.md` 세 줄 — 자유 서술이라 이 자가 안 본다. 천장.
- 아카이브 계획서 103개 소급 판정 — 칸을 든 것이 24개뿐이라 모집단이 안 맞는다.
