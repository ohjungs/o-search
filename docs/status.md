## 이번 반복이 한 것 (개발 6)

**RED 를 먼저 눈으로 봤다.** 새 단언 3건을 쓰고 돌려 실패 2건을 확인한 뒤 고쳤다:
`Lists differ: [] != ['http://a.test/']`(문서가 통째로 사라진다) ·
`'<' unexpectedly found in '김치찌개 <a href="xxx…'`(캡 아래 형제 경로의 마크업 누출).

```python
html = row[0][:MAX_PASSAGE_HTML]
if html.rfind("<") > html.rfind(">"):
    html = html[:html.rfind("<")]
```

**두 결함은 한 질문의 두 얼굴이었다.** ① 문서 전체가 문단 하나면 캡 안 마지막 `<` 가
인덱스 0 이라 옛 조건(`"<" in html`)이 참이 되어 `html[:0]` 이다 ② 되감기의 원인은
«캡» 이 아니라 «미완성 마크업» 이므로 캡보다 짧은 깨진 원문도 같은 자리를 지나야 한다.
정상 문서(`</html>` 로 끝남) · 태그 0개 · 텍스트의 날 `<` 는 안 건드린다.
**뿌리 하나에 가드 하나**라 형제 호출부가 안 남는다 — `extract_blocks` 호출부는
`passages()` 이 하나뿐임을 다시 확인했다. 딸린 지적(모순된 주석)도 함께 고쳤다:
엔티티는 «안 닫힌 `<` 뒤에 있을 때만» 사라진다고 좁혀 적었다.

**변이 3건 실측**(`.mutation-lock` 아래 · 전부 원복 · `git diff -- src/` 로 확인):
X1 되감기 삭제 → **RED 2** · X2 옛 조건 복귀 → **RED 2**(리뷰 3 이 지목한 그 둘) ·
X3 `>` → `>=` → **RED 1**(태그 0개 문서에서 `html[:-1]`, 마지막 글자가 조용히 사라진다).
**입력의 «모양» 축으로 갈랐다** — `<` 의 위치(맨앞·중간·없음) × 깨진 형태(속성값 도중)
× 캡 초과 여부. 태그명 도중·엔티티 도중은 **같은 변이에서 죽어** 단언을 새로 안 세웠다.
