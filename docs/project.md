## 품질 기준 <!-- docs/specs/concept.md 4축의 실행 명령판 -->

- **경량 상한**: `PYTHONPATH=src python3 e2e/design_check.py` 의 [2]번 축 —
  화면이 싣는 JS 를 gzip 해 50KB(컨셉 디자인 2)와 비교한다. 외부 `<script src>` 가
  하나라도 있으면 크기를 못 재므로 그 자체가 실패다.
  (2026-08-27 실측 **0 B** — 서버 렌더라 JS 가 없다. 변이 확인: 70KB 스크립트를
  끼우니 `80267 B > 51200 B` 로 종료 1)
- **크롤 간격 검사**: `e2e/crawl_delay_e2e.py` — robots `Crawl-delay` 와 1초 하한을
  서버 수신 시각으로 잰다. 간격을 어기면 실패한다 (컨셉 크롤 윤리 1순위)
- **성능 측정**: `e2e/perf_search.py` — `GET /search` 왕복 p50·p95. 순차·로컬,
  네트워크를 타지 않는다. p95 가 300ms(컨셉 성능 1)를 넘으면 실패한다
- **디자인 검사**: `PYTHONPATH=src python3 e2e/design_check.py` — 컨셉 디자인 4축을
  로컬 서버(포트 0)의 **실제 응답 바이트**로 판정한다. 네트워크를 타지 않는다.
  종료 **0** 통과 · **1** 기준 위반 · **2** 측정 불능(`quality_eval.py` 와 같은 관용구).

  | 축 | 재는 것 | 2026-08-27 실측 |
  |---|---|---|
  | 1 LCP 1.5s | **대리 지표** — 외부 서브리소스 수 · 문서 gzip · 서버 생성 시간 | 0건 · 홈 1,253 B / 결과 1,490 B · 0.7~2.4ms |
  | 2 JS 50KB(gzip) | 인라인+외부 JS 를 gzip. **홈·결과 둘 다** 잰다 | **0 B** |
  | 3 대비 4.5:1 | CSS 토큰 쌍 14개(라이트 7 + 다크 7)의 WCAG 비 | 최저 **4.87:1** (`--fg-url`) |
  | 4 360px 가로 스크롤 | **대리 지표** — viewport meta · 360px 초과 고정폭(px·rem·em·vw·%) · `overflow-wrap` | 있음 · 0건 · 3곳 |

  **1번과 4번이 대리 지표인 이유**: LCP 와 레이아웃은 브라우저 없이 못 잰다.
  헤드리스 브라우저는 의존성 추가라 루프가 야간에 붙일 수 없다. 그래서 LCP 를
  *나쁘게 만드는 원인*과 360px 을 *넘치게 만드는 원인*을 대신 잰다.
  **못 잡는 것**: 브라우저 레이아웃·페인트 시간, 웹폰트(지금 0개), 실제 RTT.
  **올리는 법**: 사람이 헤드리스를 붙이기로 하면 1번을 Lighthouse LCP 로 교체한다.

  **대비는 검사기가 색값을 들지 않는다** — `--fg-*`/`--bg-*` 토큰을 응답 CSS 에서
  매번 읽어 계산한다. 색을 고치면 검사기가 새 값으로 다시 잰다(드리프트 불가).
  `--fg-` 토큰을 새로 만들고 `design_check.PAIRS` 에 짝을 안 적으면 **종료 2** 다.
  (변이 확인 7종 전부 잡힘: JS 70KB→1 · 대비 2.78:1→1 · `width:800px`→1 ·
  `overflow-wrap` 제거→1 · viewport 제거→1 · 짝 없는 `--fg-` 토큰→2 · 토큰 전무→2)

  **검사기가 눈이 멀어 있던 네 자리를 리뷰가 찾아 닫았다**(2026-08-27, 반복 75).
  전부 "없어진 것을 못 보는" 같은 실패 유형이다 — 초록불이 근거 없이 켜져 있었다.
  1. 다크 블록이 없으면 라이트 맵이 다크 행세를 하며 **7쌍 OK 를 찍고 종료 0**
     이었다. 다크 CSS 를 통째로 지워도 통과했다 → 이제 **종료 2**
  2. 다크 미디어쿼리가 2개면 `"".join()` 결과가 원문에 없어 `replace` 가 무동작이
     되고 **라이트 맵이 다크 값으로 오염**됐다(`--bg-page` 가 `#000000` 으로 측정됨)
     → 인덱스 슬라이싱 + 중괄호 세기. `and (min-width:…)` 가 붙은 형태도 이제 찾는다
  3. `PAIRS` 커버리지 강제가 라이트 맵만 봐서 **다크에만 있는 `--fg-` 토큰이
     그냥 빠져나갔다** → 두 맵의 합집합
  4. 고정폭 검사가 `px` 만 봤는데 **이 제품 CSS 는 전부 `rem`** 이다. 눈이 먼 자리가
     정확히 제품이 사는 곳이었다 → rem/em/vw/% 환산, 모르는 단위는 **종료 2**
  (넷 다 변이로 재확인: 다크 제거→2 · 다크 블록 2개에서 라이트 맵 무오염 실측 ·
  다크 전용 `--fg-visited`→2 · `width:40rem`→1. 두 번째 다크 블록의 값이
  캐스케이드대로 이기는 것까지 확인했다)
- **검색 품질**: `PYTHONPATH=src python3 e2e/quality_eval.py` — 고정 코퍼스 64문서 위에서
  질의 40개(ko 20 / en 20)의 **정답 포함률(recall@10)**. 두 언어 다 80% 이상이면 종료 코드 0,
  미달이면 1, **코퍼스 결함이면 2**(정답 URL 부재 · 매치 ≤10 인 질의 = 측정 불능 · 언어별 질의 ≠ 20).
  (2026-08-26 실행 확인, 0.1s 미만. **네 갈림길을 전부 변이로 확인했다** — 정답 URL 오타→2 ·
  질의 19개→2 · 방해 문서 제거→2(측정 불능) · 정답 2건의 질의어 삭제→ko 75% 로 1)
- **검색 품질 기준선**: **2026-08-26 / 64문서 / 40질의: 한국어 17/20 (85%) · 영어 18/20 (90%)
  → `concept.md:22-23` 기능 2 합격**(합격선 80%). 매치 수 11~28건(평균 13.8)으로 가드 G2 여유.
  **순위 분포가 이 숫자의 성격을 말한다 — 35건이 1위, 5건은 매치 자체가 0.** 2~10위가 하나도
  없어서 `recall@1` 과 `recall@10` 이 같다. 즉 **상위 10 이라는 창은 이 fixture 에서 아무 일도
  하지 않는다**(후한 창 덕에 나온 숫자가 아니다). 미포함 5건은 전부 `unicode61` 토크나이저의
  한계다 — 복합어 뒷부분(`김치찌개보관법`←`보관법`) 2건 · 띄어쓰기 변형(`올레 길`←`올레길`) 1건 ·
  영어 굴절(`loaves`←`loaf`, `tuple`←`tuples`) 2건. **랭킹 문제가 아니라 매치 문제다**
  (`docs/design_history_006.md` `## 가정` 을 실측으로 닫았다)
  코퍼스·질의 셋은 **동결**이다 — 바꾸면 이 숫자와 비교가 끊긴다
- **기준선 파일**: 없음 — 숫자를 여기 적는다. **2026-08-25 / 3000문서 색인 /
  질의 5종 × 200회 = 1000 요청: p50 1.27ms · p95 6.71ms · 최대 6.89ms.**
  p95 를 끌어올리는 것은 `page=100`(OFFSET 990, p50 6.5ms) 하나다 — 나머지 질의는
  모두 1.3ms 이하다. 설계 탐침(990에서 7.2ms)과 같은 값이다.
  **이 숫자는 합격 판정이 아니다** — 컨셉의 300ms 는 100만 문서 기준이고 여기는 3000문서다.
  색인이 커지거나 질의 경로가 바뀌었을 때 이것과 비교해 회귀를 잡으라고 적어 둔다
