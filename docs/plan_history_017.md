# 계획 019: normalize-gaps — 018 이 못 접은 두 표기

**브랜치** `loop/normalize-gaps` · **기점 `33e531d`** (`loop/url-normalize` 끝, 018 DONE).
기점을 기본 브랜치로 안 잡은 이유: 이 계획이 고치는 `urls.normalize` 는 018 이 만든
함수다. 018 없이는 고칠 대상이 없다. (저장소에 `main` 브랜치가 실재하지 않는다 —
`project.md` 의 "기본 브랜치: main" 과 어긋난다. 아래 6절)

## 1. 문제 · 목표 · 기대 결과

**문제.** 계획 018 의 백지 리뷰가 실측으로 남긴 정규화 구멍 둘이 열려 있다
(`docs/digest.md ## 판단 필요` 의 `[4]` 와 `[2]`). 둘 다 **같은 문서인데 열쇠가 갈리는**
같은 병이고, 고치는 자리도 `src/websearch/urls.py` 한 파일이라 한 계획으로 묶는다.

1. **점 세그먼트를 안 접는다** (RFC 3986 6.2.2.3 / 5.2.4).
   `http://b.com/a/../p` 와 `http://b.com/p` 가 **두 문서**로 남는다.
   상대 링크는 `urljoin` 이 접어 주지만 **절대 href 는 안 접는다** —
   `urljoin('http://a.com/', 'http://b.com/a/../p')` 는 그대로다.
   실측(2026-08-27, 착수 전 `33e531d`):

   | 입력 | `urls.normalize` 현재 결과 |
   |---|---|
   | `http://b.com/a/../p` | `http://b.com/a/../p` |
   | `http://b.com/p` | `http://b.com/p` |

2. **앞자리 0 이 붙은 기본 포트(`:080`)를 안 접는다** (RFC 3986 3.2.3 `port = *DIGIT`).
   `urls.domain_key` 가 `port == _DEFAULT_PORT.get(scheme)` 으로 **문자열 비교**를 해서
   `'080' != '80'` 이다. 실측: `domain_key('http://b.com:080/p')` → **`b.com:080`**,
   `normalize('http://b.com:080/p')` → **`http://b.com:080/p`**.
   `domain_key` 는 예의(간격·in-flight·`Crawl-delay`)를 세는 칸이기도 하므로
   **같은 서버를 두 칸으로 세어 간격 계약을 새게 한다** — 017 이 `:80` 에서 닫은 것과
   같은 병이 `:080` 표기에 남아 있다.

**목표.** 위 두 표기가 각각 `http://b.com/p` · `b.com` 으로 접힌다. 그 외 표기의
결과는 **한 글자도 안 바뀐다**.

**기대 결과.**
- `normalize('http://b.com/a/../p') == 'http://b.com/p'`
- `domain_key('http://b.com:080/p') == 'b.com'` · `normalize(...) == 'http://b.com/p'`
- **대조군**: `normalize('http://b.com/a//b') == 'http://b.com/a//b'` (빈 세그먼트는 안 접는다),
  `normalize('http://b.com/a/b/') == 'http://b.com/a/b/'` (끝 슬래시는 안 뗀다),
  `domain_key('http://b.com:8080/p') == 'b.com:8080'` (기본 포트가 아니다)

## 2. 왜 이 방향인가 — 접는 방법 셋 중 하나

**설계 문서는 안 쓴다.** `design.md` 1절 트리거를 하나도 안 건드린다: 새 모듈 없음
(기존 파일에 비공개 헬퍼 하나) · 공개 시그니처 불변 · 저장 형태 불변 · 파일 2개 ·
되돌리기는 커밋 하나. **"대안이 갈린다" 도 아니다** — 아래 셋 중 둘은 *동작하지만
결과가 다른* 대안이 아니라 **RFC 가 동치로 인정하지 않는 것까지 접는 틀린 답**이다.
근거는 아래 실측이다.

착수 전 실측(2026-08-27, 후보 구현과 `posixpath.normpath` 를 같은 입력에 돌렸다):

| 경로 | RFC 5.2.4 가 요구 | 손으로 쓴 접기 | `posixpath.normpath` |
|---|---|---|---|
| `/a/../p` | `/p` | `/p` | `/p` |
| `/a/b/` | `/a/b/` (그대로) | `/a/b/` | **`/a/b`** ✗ |
| `/a//b` | `/a//b` (그대로) | `/a//b` | **`/a/b`** ✗ |
| `/a/.` | `/a/` | `/a/` | **`/a`** ✗ |
| `/../p` | `/p` | `/p` | `/p` |
| `/a/..` | `/` | `/` | `/` |

- **버린 것 A — `posixpath.normpath`.** 빈 세그먼트를 접고 끝 슬래시를 뗀다.
  둘 다 RFC 가 동치로 인정하지 않는 것이고, 018 이 끝 슬래시 일반화를 명시적으로
  거부한 이유("동치가 아니라 휴리스틱이고 서버가 다른 문서를 낼 수 있다")를
  뒷문으로 들여온다. **다른 두 문서를 하나로 합치는 쪽의 실수**라 더 나쁘다.
- **버린 것 B — `urljoin` 왕복.** `urljoin('/', 경로)` 는 접기는 맞게 하지만
  `urlunsplit` 으로 재조립해서 돌려준다 — 빈 질의(`http://b.com/p?`)의 `?` 를 삼킨다.
  `to_ascii` 독스트링이 재조립을 피하는 이유로 적어 둔 바로 그것이다.
- **고른 것 — 비공개 헬퍼 `_fold_dots(path)`.** RFC 3986 5.2.4 를 그대로 세그먼트
  단위로 돈다. 접는 것은 `.` 과 `..` 뿐이고 빈 세그먼트·끝 슬래시는 안 건드린다.
  되돌리기는 호출 한 줄 제거다.

**퍼센트 인코딩된 점(`%2E%2E`)은 안 접는다.** unreserved 디코딩(6.2.2.2)은 별개
규칙이고 이 저장소는 그것을 안 한다(`_TRIPLET` 은 hex 를 대문자로만 만든다).
`normalize('http://b.com/a/%2E%2E/p')` 는 그대로 남는 것이 지금 계약과 일관된다.

## 3. 스텝

### 스텝 1/4 — 개발 (`src/websearch/urls.py`)

**먼저 실패하는 테스트를 쓴다** (`rules/dev.md` 0절). `tests/test_urls.py` 의
`TestUrlNormalization` 과 `TestDomainKey` 에 1절 "기대 결과" 6건을 그대로 넣고
**빨간 것을 눈으로 확인한 뒤** 구현한다.

- `_fold_dots(path)` 신설 — 위 2절 표의 동작. `path.split("/")` 를 돌며 `..` 은 앞
  세그먼트를 지우고(루트 밑으로는 안 내려간다) `.` 은 버린다. 마지막 세그먼트가
  `.`/`..` 였으면 끝에 빈 세그먼트를 붙인다(디렉터리라 `/` 로 끝난다).
- `normalize` — `tail` 을 `partition("?")` 로 갈라 **경로에만** `_fold_dots` 를 건다.
  질의 문자열의 `..` 는 경로가 아니다.
- `domain_key` — `_DEFAULT_PORT` 비교 **앞에** `if port.isdigit(): port = port.lstrip("0")`.
  숫자가 아닌 포트(`:abc`)는 안 건드린다 — "읽을 수 없는 포트는 자기 칸에 그대로 둔다"
  는 017 의 계약이 그대로 산다.
- `normalize` 독스트링의 "**점 세그먼트(6.2.2.3)는 안 접는다**" 문장을 고친다.
  낡은 주장을 남기면 018 이 겪은 것(`domain_key` 독스트링이 이미 틀린 말을 하고 있던 것)을
  반복한다.

**완료 기준:** `PYTHONPATH=src python3 -m unittest discover tests` 379건 + 새 6건 OK.

### 스텝 2/4 — 테스트 (`tests/test_urls.py`)

갭 탐색과 변이. **무변이 기준선을 먼저 잡고 센다.**

- 변이 M1: `_fold_dots` 호출 제거 → 점 세그먼트 단언만 죽는다
- 변이 M2: `_fold_dots` 의 끝 세그먼트 보정(`out.append("")`) 제거 → `/a/..` 단언만 죽는다
- 변이 M3: `port.lstrip("0")` 제거 → `:080` 단언만 죽는다
- 변이 M4: `_fold_dots` 를 `posixpath.normpath` 로 교체 → **대조군 단언**(`/a//b`·`/a/b/`)만 죽는다
- **넷이 서로를 안 대신하는지 확인한다** — 죽는 테스트 집합의 교집합을 실제로 적는다.
  M4 가 아무것도 안 죽이면 대조군이 없는 것이다(측정 불능이지 통과가 아니다).

**완료 기준:** 변이 4종이 각각 죽고, 죽는 집합이 갈린다는 것을 기록에 실측으로 적는다.

## 4. e2e 시나리오 (계획 시점에 확정 — `rules/plan.md` 7절)

로컬 실서버가 **받은 것**으로 잰다. 나중에 구현에 맞춰 낮추지 않는다.

1. 한 페이지가 `http://a.test/a/../p` 와 `http://a.test/p` 를 둘 다 링크한다 →
   서버는 `/p` 를 **한 번만** 받고 `pages` 에 **한 행**이 남는다
2. `http://a.test:080/p` 와 `http://a.test/p` 를 둘 다 링크한다 → 문서 한 행이고,
   `a.test` 는 **한 칸**으로 세어져 요청 간격이 1초 이상이다
3. **대조군** — `http://a.test/a//b` 와 `http://a.test/a/b` 는 **두 문서로 남는다**
   (서버가 둘 다 받는다). 접기가 너무 넓어지면 여기가 먼저 빨개진다
4. **대조군** — `a.test:8080` 은 여전히 다른 서버다(기본 포트가 아니다)

**측정 불능은 조용한 통과가 아니다** — 표기가 서버에 도착조차 못 하면 **종료 코드 2**
(017 이 심고 018 이 덕을 본 가드와 같은 관용구). 갈린 표기는 전부 `PORTS` 에 등록한다.

## 5. 하지 않을 것

- **끝 슬래시 일반화**(`/p/` ↔ `/p`) — 018 이 동치가 아니라고 못 박았다
- **퍼센트 디코딩**(`%2E` → `.`, unreserved 디코딩 6.2.2.2) — `to_ascii` 계약과 얽힌다
- **`to_ascii` 수정** — 회귀 위험이 전부 거기 있다(018 판단 유지)
- **기존 `data/crawl.db` 의 옛 열쇠 행 통합** — 마이그레이션이라 야간 금지
  (`digest.md ## 판단 필요 [high]`). 이 계획도 **새 DB 에서만 목적을 달성한다**
- **URL 자격증명(`userinfo@`) 처리** — 보안 경계라 줄 수 무관 야간 금지(`digest [high]`)
- **경로·질의의 대소문자** — 서버가 구분한다
- **`loop/*` 브랜치 병합** — 사람 몫
- 무관한 리팩터링·이름 변경
