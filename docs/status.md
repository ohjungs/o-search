## 방금 것 (2026-09-01 · 설계 1/1)

**결정: `check_contrast` 는 색을 재기 전에 링을 그리는 규칙을 응답 CSS 에서 읽는다.**
`outline` 을 정하는 규칙이 정확히 1개 · 셀렉터에 `:focus` · 그 `outline` 의 색이
`NONTEXT_PAIRS` 가 재는 토큰 · 같은 규칙의 `outline-offset` > 0 — 넷 중 하나라도
깨지면 **측정 불능(2)** 이고 무효가 된 3.56:1 은 안 찍는다.

**변이를 11종으로 늘려 세 후보를 갈랐다** (전부 실측, 제품 코드 무변경·탐침은 되돌렸다):

| 후보 | 잡는 변이 |
|---|---|
| A `"var(--focus)" in css` (digest 처방) | **3/11** — V1·V2·V3 |
| B **규칙을 읽는다** ← 선택 | **9/11** — V1·V2·V3·V5·V6·**V7·V8·V10** |
| C 짝을 CSS 에서 파생 | 판정은 맞고 **메시지가 틀린다** |

- **A 를 버린 이유**: 문자열이 *어디에* 있는지 안 본다 — `body{color:var(--focus)}` 만
  남아도 통과한다. 못 잡는 V5·V6 이 하필 `NONTEXT_PAIRS` 주석의 전제를 깨는 변이다.
- **C 를 버린 이유는 실측이다**: V3(`var(--focus)`→`var(--line)`)에서 rc 2 는 나오는데
  메시지가 `짝도 제외도 없는 색 토큰: --focus` 다 — *"링이 `--line` 으로 그려지고 있다"*
  를 한마디도 못 한다. 판정만 맞고 진단이 틀린 검사기는 야간에 아무도 못 고친다.

**갈림길 A(종료 코드)는 2 로 정했다 — 형제와 갈리는 이유를 적었다.** `check_mobile` 의
`overflow-wrap` 부재는 **1** 이 맞다(실측 `fail=1 unm=0`) — 거기서는 *"긴 URL 이 360px 을
넘친다"* 는 결론이 바로 나오고 [4]번 축의 다른 숫자는 그대로 참이다. 여기서는 **[3]번 축이
찍은 3.56:1 자체가 무효**가 된다. **1 과 2 를 가르는 것은 고장의 크기가 아니라 "찍은 숫자가
아직 참인가" 다.** `--focus` 의 비율이 3.0 아래로 내려간 경우만 계속 1 이다.

**가정을 깼고 참이었다 — 그리고 가정으로 두지 않고 검사 조건으로 올렸다.** 자국이
캐스케이드를 대리하려면 **`outline` 을 정하는 규칙이 CSS 에 하나뿐**이어야 한다(실측 1개).
깨는 변이 3종을 새로 심으니 —뒤 규칙 `outline:none`(V7) · 뒤 규칙 `outline-width:0`(V8) ·
**다크 블록 안**의 `outline:none`(V10)— 셋 다 규칙 수 세기 하나에 걸린다.

**일부러 안 잡는 둘은 설계서에 사유가 있다.** V4(`:focus-visible`→`:focus`)는 키보드에
링이 그대로 보이므로 이 축이 재는 것이 안 깨진다 — 리터럴을 요구하면 유효한 구현을
금지하는 상수가 된다. V9(같은 규칙 안 `outline-width:0`)는 지금 CSS 에 0곳이고 잡으려면
한 규칙 안의 선언 순서를 해석해야 한다.
