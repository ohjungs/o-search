## 2. 시나리오 1 — 캡 값을 3,000 → 4,000 으로 변이 (계획 74 가 실제로 밟은 길)

```
sed -i '' 's/^MAX_PASSAGE_TAGS = 3_000$/MAX_PASSAGE_TAGS = 4_000/' src/websearch/indexer.py
PYTHONPATH=src python3 -m unittest discover -b -s tests   → FAILED (failures=4)
```

**메시지가 자리를 가리킨다:**

```
project.md 가 `indexer.MAX_PASSAGE_TAGS` 를 3,000 라고 적었는데 코드는 4000 다 —
그 값에서 유도한 숫자도 함께 낡았는지 문단을 다시 읽는다
```

되돌리니 **664 OK**. 계획 74 가 잊었던 바로 그 자리가, 이제 **잊는 순간 빨개진다.**

**빨개지는 것은 1건이 아니라 4건이다(실측).** `ProjectConstTest` 하나 + `ConstGapTest`
셋(`test_agreeing_citation_is_quiet` · `test_citation_reads_across_a_line_break` ·
`test_stale_value_is_reported`)이다 — 갈래 단언들이 **살아 있는 상수를 일부러 쓰기**
때문이고(가짜 이름으로만 재면 «코드에서 값을 읽어 오는 배선» 을 안 재게 된다), 그 값을
`3,000` 으로 적어 뒀다. **천장으로 받아들인다**: 캡을 정당하게 올리는 날 한 파일 안에서
넷이 함께 빨개지고, 고칠 곳은 «문단 + 갈래 단언의 예시값» 으로 둘 다 같은 커밋에 산다.
동적으로 읽게 만들면 검사 대상 함수로 검사 대상을 재는 자기순환이라 **더 나쁘다.**

`test_indexer` 의 값 가드는 안 울었다 — 동결이 `8,000 × 10 이하`라 4,000 은 정당한 값이다.
**두 자가 서로 다른 것을 붙들고 있다**: 하나는 «예산을 넘겼나», 하나는 «문서가 따라왔나».

## 3. 시나리오 2 — 상수 이름을 `PASSAGE_TAG_CAP` 으로 변이

사용처 5곳을 함께 바꿨다(`re.sub(r"\bMAX_PASSAGE_TAGS\b", ...)` · BSD `sed` 는 `\b` 를
모른다 — 첫 시도가 **0곳을 바꾸고 조용히 초록**이었다. 변이를 심었다고 믿고 결과를
읽을 뻔한 자리라 여기 적는다).

```
project.md 가 `indexer.MAX_PASSAGE_TAGS` 를 인용하는데 `indexer.py` 에
`MAX_PASSAGE_TAGS = <정수>` 가 없다
```

**조용히 넘기지 않는다** — 계획서 완료 기준 ④ 가 재려던 것이 이것이다. 되돌려 초록.

**덤으로 갈래 하나가 함께 빨개진다:** `test_absent_constant_is_reported_not_skipped` 는
「없는 이름」의 예시로 하필 `PASSAGE_TAG_CAP` 을 쓴다 — 그 이름이 코드에 생기면 예시가
가짜가 아니게 된다. 변이 상황에서만 나는 일이라 그대로 둔다(오늘 실물에는 없는 이름이다).

## 4. 시나리오 3 — 캡 문단이 `indexer.py` 와 한 글자도 안 어긋나는가

**어긋나는 자리를 하나 찾았다. 다만 낡은 쪽은 문서가 아니라 코드 주석이다.**

| 숫자 | `docs/project.md` | `src/websearch/indexer.py` | 계획 74 실측 |
|---|---|---|---|
| 캡 3,000 의 `/passages` p95 | **138ms** | **137ms** (:80) | **138.10ms** (`docs/e2e/passage-prefer-body/result.md:56`) |

그리고 `tests/test_indexer.py:845` 주석은 오늘 캡(3,000)의 품질을 **근거 73→98건 ·
본문 41.1→80.6%** 로 적는데, 그것은 무릎 표의 **8,000 행**이다 — 3,000 행은 **96건 ·
81.2%** 이고 `project.md` 와 `indexer.py:80` 은 그렇게 적혀 있다.

**둘 다 고치지 않았다.** `rules/e2e.md` 3절 — e2e 는 소스를 **계획 범위 안에서만** 고치고
이 계획의 「건드릴 파일」은 `tests/test_docs.py` 와 `docs/project.md` 둘이다. 야간에
범위 밖 소스를 만지지 않는다. `digest.md` 에 등재했다.

**이것이 오늘 세운 검사의 천장을 정확히 보여 준다:** `const_gap` 은 **`project.md` 의
`mod.CONST` = 숫자** 만 읽는다. 같은 숫자가 **코드 주석에서** 낡는 것은 못 본다 —
그리고 방금 실물에서 그 일이 일어나 있었다. 문서가 코드를 인용하는 축은 닫혔고,
**코드가 자기 실측을 인용하는 축은 열려 있다.**
