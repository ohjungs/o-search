**사용자가 하는 그대로** 확인했다 — 로컬 사이트 6쪽을 `crawl` 로 수집하고,
`python3 -m websearch.indexer` 로 색인하고, `python3 -m websearch.serve <db> --port 0`
으로 띄운 뒤 **화면(HTML)** 을 HTTP 로 열었다. 정답 판정은 화면에 그 문서의 링크가
있는지로만 한다 — 유닛이 보는 `search()` 반환값이 아니라 사람이 보는 것과 같은 것이다.

**2+ 는 계획에 없던 것을 더한 것이다.** 이번 밤 리뷰가 잡은 가장 큰 구멍이 어순이었고
(`냉장 보관법` 이 0건이었다), 유닛만으로 닫아 두면 다음에 같은 자리에서 다시 뚫린다.
시나리오를 **낮춘 것이 아니라 더한 것**이라 계획을 고치지 않고 여기에 적는다.

## 부정 단언에는 긍정 짝 (4번)

- 부정: `치찌 찌개` 가 화면에 없다 · 스니펫 구분자 `\x02` 가 화면에 없다
- 긍정: `완전히 식힌 뒤` 라는 **원문**이 화면에 있다
  → 긍정 짝이 없으면 "결과 0건인 빈 화면" 도 부정 단언을 통과한다

## 이 e2e 가 실제로 무게를 지는가 (변이 4종)

| 변이 | 결과 |
|---|---|
| 2-gram 분기 제거 (`parts.append(plain)`) | `① 복합어 뒷부분이 안 잡힌다` |
| `porter` 제거 | `③ 영어 굴절이 안 잡힌다` |
| 드리프트 감지 끄기 (`if False`) | `no column named title_ng` 로 죽는다 |
| 어절별 → 통째로 (리뷰 전 코드로 되돌림) | `② [냉장 보관법] 가 안 잡힌다` |

넷 다 **제 시나리오에서** 실패한다. 마지막 것이 요점이다 — 이 e2e 는 리뷰 전 코드를
빨간불로 만든다.

## 8단계 체크리스트

1. 정상 경로 — 위 1~5 통과
2. 경계 — 숫자 어절(`7코스`)·1자 아닌 2자 질의·한글+영어 혼합 어절 포함
3. 오류 경로 — 옛 색인에서 화면 500 / CLI rc=2, **어느 응답에도 트레이스백 없음**
4. 빈 상태 — 매치 0건 화면은 `search_api_e2e.py` 가 이미 본다(중복 안 만듦)
5. 되돌아오기 — 재색인 후 1~3 이 다시 된다(6번)
6. JS 없이 — 이 프로젝트는 JS 0 B 다. `design_check.py` 가 매번 잰다
7. 콘솔/서버 로그 — `StaleIndexError` 한 줄이 서버 stderr 에 남는다. **의도한 것**이다
   (`serve.py` 가 트레이스백을 응답에 안 싣는 대신 로그로 낸다). 그 외 예외 없음
8. 접근성 — 이번 스텝은 화면 마크업을 안 건드렸다. `design_check.py` 대비 4.87:1 유지
