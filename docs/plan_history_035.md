# 계획 49 — `focus-rule-scope`

**접근성 축의 검사기가 «링이 어느 화면에 그려지나» 를 아직 안 본다.** 계획 44 는
`focus_rule` 을 세워 «링을 그리는 규칙이 살아 있나» 를 닫았다. 그런데 그 규칙을
**다크 블록 안으로 옮기거나 `@media print` 안에 넣거나 셀렉터를 `:not(:focus-visible)`·
`:focus-within` 으로 뒤집으면** 검사기는 여전히 «포커스 링 규칙 1개 · offset 2px» 를
찍고 라이트 3.56:1 을 초록으로 낸다. 라이트 화면에는 링이 없는데도 그렇다.

## 1. 문제 · 목표 · 기대 결과

### 문제

`e2e/design_check.py` 의 `focus_rule(css)` 은 링을 그리는 규칙을 **CSS 전체에서 하나**
찾고, 그 규칙의 셀렉터에 `":focus"` 라는 **부분 문자열**이 있는지만 본다. 그래서 둘을
못 본다:

1. **그 규칙이 어느 at-rule 안에 있는지** — `RULE_RE` 는 `([^{}]*)\{([^{}]*)\}` 라
   중첩 깊이를 세지 않는다. 링 규칙을 `@media(prefers-color-scheme:dark)` 안이나
   `@media print` 안으로 옮겨도 규칙 수는 그대로 1개다.
2. **셀렉터의 극성** — `":focus" in selector` 는 `:not(:focus-visible)` 과
   `:focus-within` 을 통과시킨다. 둘 다 키보드 포커스에 링을 그리지 않는다.

계획 44 가 천장으로 적어 둔 것(`:focus` 리터럴도 허용한다)의 **사유는 지금도 참**이다
— `:focus` 는 키보드 포커스에 링을 그린다. 틀린 것은 사유가 아니라 **가드가 그 사유보다
넓다**는 것이다.

### 목표

`focus_rule` 이 **라이트 화면에 실제로 그려지는 키보드 포커스 링**만 측정 대상으로
인정한다. 아니면 색을 재지 않고 **측정 불능(종료 2)** 로 멈춘다 — 계획 44 가 세운
«잴 것이 살아 있는지 먼저 본다» 의 자리를 그대로 쓴다.

### 기대 결과

지금 종료 0 으로 통과하는 변이 넷이 전부 종료 2 가 되고, 정상 CSS 와 계획 44 가 이미
죽인 변이들은 **한 건도 움직이지 않는다**.

### 무엇이 이미 참인가 (이 저장소를 처음 여는 사람을 위한 전제)

- `e2e/design_check.py` 의 `focus_rule(css)` 은 `(색 토큰, outline-offset 문자열)` 을
  돌려주거나 `ValueError` 를 던진다. 부르는 곳은 같은 파일의 `check_contrast` **한
  곳뿐**이고, 거기서 `ValueError` 는 `unmeasurable` 목록에 담겨 종료 2 가 된다.
- 같은 파일의 `token_maps(css)` 가 이미 **라이트 맵과 다크 맵을 갈라서** 돌려준다 —
  다크 블록의 시작을 `DARK_START_RE` 로 찾고 중괄호를 세어 끝을 잡는다. 즉 «어느
  블록이 다크인가» 를 아는 코드가 이 파일에 **이미 있다**.
- 제품 CSS 의 링 규칙은 `src/websearch/serve.py` 안에 있고 지금은 **최상위**에 있다
  (`.sb input:focus-visible,.sb button:focus-visible,a:focus-visible{outline:3px solid
  var(--focus);outline-offset:2px}`). 이 계획은 제품 CSS 를 **안 바꾼다**.
- `tests/test_design_check.py` 는 161줄이고 계획 43·44 가 만든 단언들이 `focus_rule`
  과 비텍스트 대비를 붙들고 있다. 새 단언은 그 옆에 들어간다.
- 단위 **576건 OK**(맨몸 13.552초 실측) · e2e **20종** · `docs/status.md` 는
  `signal: GREEN` · 활성 계획 0개.

### 착수 탐침 — 변이 넷이 지금 전부 살아 있다 (2026-09-02 실측)

제품 응답 CSS 를 `serve._render` 에서 그대로 뽑아 `check_contrast` 에 먹였다. 변이를
심기 전에 `mutated != css` 로 **변이가 실제로 심어졌는지 먼저 단언**했다(digest
`## 다음 계획 후보` 의 «변이가 실제로 심어졌는지를 먼저 단언한다» 항목).

| 대조군 (원본) | 0 | 0 | 종료 0 — 옳다 |

와 «물려받은 처방을 실행 전에 다시 잰 두 번째 사례»(계획 44 자신)가 같은 것을

살아 있다. 다만 처방 중 ⓐⓑ 쪽은 이 저장소에 **이미 있는 코드**로 더 싸게 닫힐 수
있어 6절에서 설계로 넘긴다.

## 5. 하지 않을 것

- **제품 CSS 를 안 바꾼다.** 지금 링 규칙은 최상위에 있고 셀렉터도 옳다 — 고칠 것이
  검사기지 CSS 가 아니다.
- **`RULE_RE` 를 CSS 파서로 키우지 않는다.** 중첩 셀렉터(CSS Nesting)·주석 안의
  `outline:` 은 지금도 천장이고 파일이 그 천장을 이미 적어 뒀다. 이 계획은 그 천장을
  안 올린다.
- **한 규칙 *안에서* 자기를 뒤엎는 형태**(`outline:...;outline-width:0`)는 계획 44 가
  천장으로 남긴 것이고 지금 0곳이다 — 안 연다.
- **`:focus` 리터럴 허용을 안 뒤집는다.** `:focus-visible` 을 강제하면 제품 CSS 가
  아니라 사양에 없는 취향을 강제하게 된다.
- **`NONTEXT_PAIRS`·`MIN_CONTRAST_NONTEXT`·색값을 안 건드린다.** 계획 43 이 정한 값이다.
- **후보 B(`unittest -b`)를 이 계획에서 안 연다.** 축이 다르고(러너 규율) 파일도
  다르다 — 직교 편집이다. 2절 표에 근거와 실측을 남겨 뒀으니 **다음 짧은 경로**로
  바로 집어갈 수 있다: 살아 있는 명령 문자열은 `README.md` 와 `docs/project.md`
  **두 곳뿐**이고, `tests/test_readme.py` 의 정규식은 `-m\s+(websearch...)` 와
  `python3 -m` 이라 `-b` 를 붙여도 안 깨진다. `tests/` 의 서브프로세스 세 곳
  (`test_passage_eval`·`test_quality_eval`·`test_indexer`)은 전부
  `capture_output=True`/`stdout=PIPE` 라 `-b` 밖으로 새는 로그도 없다.

## 6. 설계가 필요하다 — 트리거 하나가 걸린다

**걸린 트리거: 「대안이 갈린다」.** 스텝 2(ⓐⓑ)를 닫는 방법이 셋이고 **셋이 닫는
범위가 다르다**:

- **A. at-rule 깊이를 센다** — digest 항목이 적어 둔 처방. `RULE_RE` 를 대체하거나
  감싸서 각 규칙 앞의 중괄호 균형을 센다. ⓐⓑ 둘 다 닫는다. 새 코드가 가장 많다.
- **B. `token_maps` 의 라이트/다크 분리를 재사용한다** — 이 파일에 **이미 있는** 코드다
  (ponytail 사다리 2칸). 그런데 `@media print` 는 라이트도 다크도 아니라 **ⓑ 를 못
  닫는다**. 범위가 다르다.
- **C. 링 규칙이 최상위(at-rule 밖)에 있을 것을 요구한다** — ⓐⓑ 둘 다 닫고 제품 CSS 는
  지금 그대로 통과한다. 가장 짧다. 대신 «다크에만 링을 그리는 CSS» 를 영구히 거절한다
  (그것이 접근성 결함이라 옳은 거절인지가 설계가 답할 물음이다).

세 대안이 **서로 다른 것을 닫으므로** 계획서에서 하나를 고르면 그것은 측정이 아니라
취향이다. 스텝 1(ⓒⓓ)에는 갈림이 없다.

**나머지 트리거는 안 걸린다**: 새 모듈 없음 · 공개 인터페이스 변경 없음
(`focus_rule` 의 반환 모양과 `check_contrast` 의 계약이 그대로다) · 데이터 구조 변경
없음 · 건드릴 파일 **2개** · 되돌리기는 `git revert` 한 번이다.

  at-rule 깊이를 세기 시작하면 «그럼 주석도, 중첩 셀렉터도» 로 번지기 쉽다 — 5절이
  그 선을 그어 뒀다.
- **살아남는 변이가 또 형제 구멍일 수 있다.** digest 의 «살아남은 변이가 등가 변이가
  아니라 형제 구멍일 때가 있다» 가 이 검사기에서만 세 번 나왔다. 스텝을 닫을 때
  살아남은 변이를 등가로 판정하기 전에 **그 경로가 정말 도달 불가인지 실측**한다.
