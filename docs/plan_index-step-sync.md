# 계획 60 — `index-step-sync`

`docs/index.md` 의 **진행** 행 스텝 칸과 `docs/status.md` 의 `step` 이 어긋난 채로 커밋된다.
`IterationSyncTest` 가 닫은 것은 `반복`↔`iteration` 축뿐이고, **스텝 칸은 아무도 안 붙든다.**

- **근거**: `docs/digest.md` `## 반복 실패` 의 「스텝을 커밋하면서 `docs/index.md`·
  `docs/metrics.md` 의 숫자를 안 올린다」 — **4회 등재**(① 2026-08-30 계획 34 리뷰 ·
  ② 2026-08-30 계획 35 리뷰 · ③ 2026-08-31 계획 37 리뷰 · ④ 2026-09-01 계획 40 개발).
  그 항목이 스스로 *"남은 후보는 검사 한 줄"* 로 닫혀 있고, **③ 이 「세 번째라 처방이
  틀렸다는 뜻이다」(`severity.md` 5절)로 이미 한 번 처방을 갈아 끼웠다.**
  탐색 1~5순위 **0건** · 6순위는 열린 항목이 **전부 「여는 조건 미도래」**라 7순위다.
- **기점**: `loop/passage-cost-band` 의 계획 59 마감 커밋. 고칠 파일
  `tests/test_docs.py` 는 `origin/main`(`d1fe3e9`)과 바이트 동일이라 병합 뒤 `main` 에서
  다시 딸 수 있다. 이 계획서가 그쪽 브랜치에 없으면 하네스가 매 반복 읽을 파일을
  잃으므로 **쌓아 둔 채로 간다**(57 → 58 → 59 와 같은 모양).

## 1. 문제 · 목표 · 기대 결과

**문제.** 스텝을 커밋할 때 만져야 하는 기록이 셋(`status.md`·`index.md`·`metrics.md`)인데
스텝 커밋은 `status.md` 만 본다. 셋 중 둘(`metrics.md` `반복` ↔ `status.md` `iteration`)은
계획 42 가 `IterationSyncTest` 로 묶었고, **남은 축인 `index.md` 의 스텝 칸은 오늘도 열려
있다.** 어긋나면 다음 반복이 자기 스텝을 잘못 읽고, 리뷰가 없는 phase 에서는 조용히 간다.

**목표.** `index.md` 의 **진행** 행 스텝 칸과 `status.md` 의 `step` 이 어긋나면 단위
스위트가 죽는다. 규율이 아니라 검사가 붙든다.

**기대 결과.** 제품 `src/` **0줄** · 고치는 파일 **`tests/test_docs.py` 하나** ·
새 테스트 메서드가 늘어 단위 건수가 **605 → 606 이상**(→ `README.md` 의 건수 줄을 함께 본다).

## 2. 착수 탐침 — 오늘 다시 쟀다 (2026-09-06 · 반복 350)

`digest [7]`「기록된 답을 실행 전에 다시 재라」의 **열한 번째 적용**.
최근 30커밋에서 두 값을 나란히 뽑았다(`git show <sha>:docs/status.md` · `:docs/index.md`).

| 상태 | 커밋 수 | 비고 |
|---|---|---|
| `status.step` == `index` 진행 행 | 16 | 정상 |
| **어긋남 (`status` 1/1 · `index` 0/1)** | **11** | 계획 56 ×4 · 57 ×3 · 58 ×3 · **59 ×1(HEAD)** |
| **진행 행이 0개** | 3 | `9c6f763`·`e66968c`·`724d8c8` — 계획 커밋과 index 등재 커밋이 갈린 자리 |

**둘을 다 찾았다.** ① 결함은 5회째로 **HEAD 에 살아 있었다**(계획 59 를 오늘 닫기 전까지
`index` 가 `0/1` · `status` 가 `1/1`). 어긋나는 방향은 **11/11 전부** `index` 가 뒤처지는
쪽이라 digest 의 *"어긋나는 것은 늘 `index.md` 의 스텝 칸이다"* 가 그대로 참이다.
② **기록된 처방은 갈아 끼운다** — ③ 이 적은 「`git log` 의 개발 커밋 수와 대조」는 커밋
메시지 문자열에 기대고 브랜치 모양에 따라 답이 달라진다. 같은 값을 **문서 둘**로 재면
`IterationSyncTest` 와 **같은 모양의 다섯 줄**이고 새 의존성도 서브프로세스도 없다.

## 3. 스텝 1개

**스텝 1/1.** `tests/test_docs.py` 에 `IterationSyncTest` 옆자리로 스텝 축 검사를 세운다.
`status.md` 의 `step: N/M` 과 `index.md` 의 **상태 칸이 `진행` 인 행**의 스텝 칸을 뽑아
대조한다. 정규식은 `ITER_ROW`·`ITER_LINE` 과 같은 자리에 상수로 둔다.

TDD 순서(`rules/dev.md` 0절): ① 검사를 먼저 쓰고 `index.md` 의 스텝 칸을 **손으로 비틀어**
빨개지는 것을 본다 ② 되돌리고 초록을 본다 ③ 정규식 자신을 리터럴 표로 붙드는 단언을
`IterationPatternTest` 와 같은 이유로 함께 세운다(실물 문서가 초록이면 **넓어지는 변이가
조용히 산다** — 계획 42 가 같은 자리에서 배운 것이다).

## 4. 완료 기준 — 전부 검증 가능

1. 전수 `PYTHONPATH=src python3 -m unittest discover -b tests` 가 `OK` · rc 0 · 건수 606 이상
2. `index.md` 진행 행의 스텝 칸을 `0/1` 로 비트는 변이에서 **새 검사가 죽는다**(오늘 `status` 는 `0/1` 이므로 반대로 `1/1` 로 비튼다) · 되돌리면 초록
3. `status.md` 의 `step` 을 비트는 변이에서도 죽는다 — **한쪽만 재는 검사가 아니다**
4. 정규식을 넓히는 변이(예: 상태 칸을 안 보고 아무 행이나 잡는다)에서 패턴 단언이 죽는다
5. `README.md` 의 단위 건수 줄이 새 건수와 맞는다(`tests/test_readme.py` 초록)
6. 제품 `src/` **0줄** · 스키마·재색인·새 의존성 0 · `docs/specs/`·`data/crawl.db` 무접촉

## 5. 하지 않을 것

- **`metrics.md` 의 `계획 (완료/폐기/보류)` 칸은 안 잰다** — 스텝 축과 다른 축이고,
  digest 항목이 지목한 것은 스텝 칸이다. 넓히면 별건이다
- **`git log` 를 읽지 않는다** — 2절 ②. 서브프로세스·커밋 메시지 파싱은 이 값의 몸값이 아니다
- **훅·스크립트를 만들지 않는다** — 저장소 밖(`~/.claude/skills/loop-harness/`)은 무접촉이다
- 새 e2e 파일 0개 예정(`rules/e2e.md` 3절 — 제품 0줄이면 프로세스 밖에서 달라지는 것이 0)

## 6. 설계 트리거 — 걸린다 (`rules/design.md` 1절 「대안이 갈림」)

진행 행이 **0개**인 커밋이 실재해서(2절 표 셋째 줄) 대안이 산출물째 갈린다.

- **A. 진행 행이 정확히 1개임을 요구한다** — 0행·2행을 둘 다 잡지만, 계획 커밋과 index
  등재 커밋이 갈린 자리(`9c6f763` 꼴)에서 **오탐 RED** 가 난다
- **B. 진행 행이 있을 때만 대조한다** — 오탐 0 이지만 0행에서 **조용히 통과**한다.
  digest 가 두 번 경고한 「닿을 수 없는 가드」가 하나 더 느는 모양이다
- **C. `git log` 의 개발 커밋 수와 대조한다**(항목이 기록해 둔 원래 처방) — 2절 ② 로 이미 약해졌다

세 안이 **잡는 것과 오탐이 서로 다르므로** 설계 phase 가 실측으로 고른다. 눈금은
「최근 30커밋에 먹였을 때 진짜 11건을 잡고 오탐이 몇 건인가」다.

## 7. 위험

  변이가 산다 → 완료 기준 4 의 패턴 단언이 그 자리다

  새 검사가 그 커밋에서 죽는다. 그것이 이 계획이 원하는 동작이다
