# 설계 55 `db-state-invariant`

**결정: 자는 눈금을 우리가 안 적고 sqlite 에게 묻는다(①'), 처방은 한 낱말이다(A).**
자는 `tests/test_indexer.py` 에 새 클래스 하나 — 정상 DB 를 만들어
`PRAGMA table_info(pages)` 로 열 목록을 받고, 열을 하나씩 뺀 DB 마다 세 질의의
**판정**이 같은지 본다. 처방은 `src/websearch/indexer.py` 의 계획 54 가 심은 줄을
`SELECT url, html FROM pages LIMIT 0` 로 넓히는 것이다. **제품 diff 한 파일 ·
`serve.py` 0줄 · `README.md` 0줄 · 새 예외 0 · 스키마·마이그레이션·재색인 0.**

## 1. 갈림길 1 — 눈금을 어디서 얻나

계획서가 연 셋에 **①'** 를 더해 넷을 세웠다(사다리 3·4번: 스키마를 읽는 파서는
이미 sqlite 안에 있다).

| 안 | 눈금의 출처 | 다섯째 열이 생기는 날 | 값 |
|---|---|---|---|
| **①' `PRAGMA table_info(pages)`** | **정상 DB 자신** | **자동으로 자에 오른다** | **파서 0줄. 소스 문자열이 아니라 실제로 만들어진 표를 잰다** |
| ① `store.SCHEMA` 문자열 파싱 | 소스 문자열 | 자동 | 우리가 파서를 짊어진다. `DEFAULT (datetime('now'))` 처럼 괄호가 든 줄이 이미 있어 「첫 낱말」 규칙이 언제 깨질지가 우리 책임이 된다 |
| ② 손으로 적은 열 표 | 사람 | **안 오른다** — 사람이 표를 고쳐야 안다 | 읽기 쉽다 |
| ③ 상태마다 클래스 | 사람 | 안 오른다 | **오늘 셋(계획 53·54)이 이 방식이고, 그것이 네 번 재발한 이유다** |

①' 는 자를 세우는 김에 **재현 절차까지 일반화한다**: 열을 뺀 `pages` 를 다시 만들
때 열 이름과 **선언 타입**을 둘 다 `PRAGMA` 가 준다(`r[1]`, `r[2]`). 손으로 적는
타입 표가 0개다. `ALTER TABLE … DROP COLUMN` 은 sqlite 버전을 타므로 계획 54 가
쓴 「새로 만들어 다시 넣기」를 그대로 승계한다.

**①' 를 실제로 돌려 확인했다** (2026-09-05 반복 322, 임시 DB · `data/crawl.db` 무접촉):
눈금 `['url', 'html', 'status', 'fetched_at']` 4칸, 오늘 코드에서 **RED 정확히 1행**
(`url`), 처방 A 를 붙인 사본에서 **4행 전부 PASS**. ① 파싱도 같은 넷을 냈다 —
**오늘은 두 안의 눈금이 같고, 갈리는 것은 앞으로의 유지비뿐이다.**

## 2. 눈금의 단위는 결과가 아니라 **판정**이다

첫 초안이 세 질의의 **반환값**을 비교했더니 정상 DB 가 `n=2 / n=0 / n=0` 으로
**거짓 RED** 였다. 질의마다 결과가 다른 것은 검색이 일하는 것이지 고장이 아니다.
자가 재는 것은 «같은 DB 상태에서 **같은 이름의 답**이 나오는가» 다 —
예외면 예외 **클래스 이름**, 정상 반환이면 `ok`. 이 한 줄이 자의 전부다.

**자의 자기검사(위험 1 의 완화).** 눈금이 0칸이면 루프가 0회 돌고 조용히 초록이
된다. 그래서 자는 먼저 **열이 4칸 이상이고 `url`·`html` 을 담는지** 단언한다.
4는 하한이라 열이 늘어도 안 낡고, `url`·`html` 은 제품이 실제로 읽는 두 열이다.

## 3. 갈림길 2 — 처방

계획 55 반복 321 이 적어 둔 실측을 **다시 쟀다**(같은 결론 + 새 사유 하나).

| 안 | `url` 없음 | `status` 없음 | `fetched_at` 없음 | 정상 |
|---|---|---|---|---|
| 오늘 | 예외 / ok / ok **갈림** | ok 셋 | ok 셋 | ok 셋 |
| **A `SELECT url, html … LIMIT 0`** | **예외 셋** | ok 셋 | ok 셋 | **ok 셋(오탐 0)** |
| B `PRAGMA` + `SCHEMA` 전 열 요구 | 예외 셋 | **예외 셋** | **예외 셋** | ok 셋 |
| C 제품 0줄 | 오늘과 같다 | — | — | — |

**A 를 고른다.** 제품이 읽는 열은 `url`·`html` 둘뿐이고, A 는 **읽는 것만**
요구한다. 비용은 잡음이다 — 1,000행·행당 6,826바이트 DB 에서 200회 × 7반복 최소:
`SELECT html … LIMIT 0` **0.0014ms** vs `SELECT url, html … LIMIT 0` **0.0015ms**
(`LIMIT 1` 은 0.0087ms — 계획 54 가 `LIMIT 0` 을 고른 근거는 그대로 유효하다).

**B 를 버렸다.** 두 사유인데 **둘째가 결정적이다.** ① `passages()` 가 안 읽는
`status`·`fetched_at` 이 없다고 500 을 내는 오탐이다. ② **앞으로 `store.SCHEMA` 에
열이 하나 늘면 기존 DB 전부가 그날로 500 이 된다** — 4절.

**C 를 버렸다.** 계획 54 설계가 C 를 버린 사유가 네 번째로 그대로 참이다:
고장을 안 고치고 「판정이 질의 내용에 달렸다」를 함수에 한 번 더 못박는다.
자만 세우고 처방을 미루면 자가 세워지는 날 곧바로 RED 한 행을 안고 커밋된다.

## 4. 가장 위험한 가정을 깼다 — B 의 expand 함정

**가정: 「스키마 전 열을 요구한다」는 앞으로 열이 늘어도 안전하다.** 추측하지 않고
깼다 — 사본에서 `store.SCHEMA` 에 `lang TEXT` 를 더하고 **기존 정상 DB** 를 새
코드로 다시 열었다. `Store()` 의 `CREATE TABLE IF NOT EXISTS` 는 열을 안 더하므로
표는 `['url','html','status','fetched_at']` 그대로였고, B 에서 세 질의가 전부
`OperationalError: no such column: lang` 이 됐다. **판정은 일관되지만 일관되게
틀렸다** — 읽을 수 있는 DB 를 500 으로 만든다. B 는 열 추가를 사실상 `contract`
단계로 바꿔 놓는 안이고, `project.md` 의 마이그레이션 규율상 **항상 보류** 대상이다.
A 는 이 함정이 없다: 새 열은 A 의 질의에 안 들어가 기존 DB 가 계속 200 이다.

## 5. 계약 (개발이 지킬 것)

**제품** — `src/websearch/indexer.py` `passages()`, 계획 54 가 심은 그 줄:

    db.execute("SELECT url, html FROM pages LIMIT 0")

시그니처·docstring·자리(‌`sqlite_master` 가드 **직후** · `hits` 루프 **앞**) 무변.
**그 줄 위의 `ponytail:` 주석 두 문장은 이제 거짓이 되므로 같은 커밋에서 고친다** —
「`html` **한 열만** 본다」와 「`url` 축은 남아 있다 … 넓히는 날은 한 낱말」이
그것이다. 계획 54 리뷰가 잡은 두 건이 전부 **새로 쓴 주석의 거짓**이었다.

**자** — `tests/test_indexer.py`, `TestPassages` 옆에 클래스 하나
(`passages()` 를 직접 부른다 · HTTP 안 띄운다). 절차: 정상 DB 생성 → `PRAGMA` 로
(이름, 타입) 목록 → 자기검사 단언 → 열마다 `subTest` 로 ①정상 DB 재생성
②그 열 뺀 `pages` 로 교체 ③세 질의(`김치찌개`·`zzzznope`·`\x01`)의 판정 이름 수집
④`len(set(...)) == 1` 단언. **RED 는 정확히 `url` 한 행**이고, 처방을 붙이면 4행
초록이다. 자가 0행을 재거나 RED 가 0행이면 그 자체가 결함이다(2절).

**안 만드는 것** — `tests/test_serve.py` 에 새 클래스 **0개**. `url` 축이 더하는
것은 새 *상태*지 새 *매핑*이 아니고, `OperationalError → 500` 은 이미
`TestPassagesWithoutHtmlColumn` 이 HTTP 표면에서 붙들고 있다. 한 벌 더 두면 같은
매핑의 사본이 늘 뿐이다. **바뀌면 다시 본다**: `serve.py` 의 예외 튜플을 손대는
계획이 생기는 날.

**안 건드리는 것** — `serve.py` · `README.md` · `store.py` · 스키마 · `index_pages()`
· 화면(HTML) 사다리 · `sqlite_master` 질의 두 벌의 공통화(셋째 호출자 없음) ·
`docs/specs/` · `data/crawl.db` · 새 의존성 · PR.

## 6. 천장 (`ponytail:` 주석으로 코드에 남긴다)

- **A 는 `passages()` 가 읽는 두 열만 본다.** 타입이 바뀐 열, 권한이 막힌 DB,
  `docs` 쪽이 깨진 DB 는 여전히 다른 경로가 판정한다. 자는 **열 유무 축만** 잰다.
- **자는 열을 하나씩만 뺀다.** 두 열이 동시에 빠진 조합(2^4)은 안 잰다 — 조합이
  늘면 재현 비용만 늘고, 한 열 축이 닫히면 조합도 같은 줄이 잡는다.
- **`serve.py` 매핑은 자의 밖이다**(5절). HTTP 코드는 기존 클래스가 지킨다.

## 7. 역할 검토

- **스태프** — 제품 diff 가 한 낱말이고 revert 가 커밋 하나다. 새 추상화 0.
- **QA** — 변이: 처방을 되돌리면 `url` 행이 RED. 자의 판정 비교를 결과 비교로
  바꾸면 정상 DB 가 RED(2절 실측). 자기검사 단언을 지우고 `PRAGMA` 를 빈 표에
  걸면 조용한 초록이 되는데, 그 단언이 그것을 막는다.
- **보안** — 응답 본문에 DB 경로·트레이스백이 안 실린다(기존 단언 유지). 새 SQL 에
  사용자 문자열이 안 닿는다. 자는 임시 디렉터리에서만 DB 를 만든다.
- **SRE** — 안 낫는 상태에 503 을 안 준다는 계획 53·54 의 판단을 승계한다.
  **B 를 안 골라 「열 추가 = 전면 500」 배포 사고를 미리 막았다**(4절).
- **제품** — 소비자가 같은 고장을 질의에 따라 다르게 보는 일이 `pages` 열 축에서
  끝난다. 사양 5(상태를 정직하게 말한다)를 지킨다.

## 8. 되돌리기·마이그레이션

**커밋 하나로 revert**(설계 룰 3절 ③). 피처 플래그 없음 — 되돌릴 것이 한 낱말과
테스트 한 클래스다. **마이그레이션 3단계 어디에도 안 걸린다** — 스키마 DDL 0,
데이터 무변, `data/crawl.db` 무접촉(sha256 `85c96744…5bda18` 대조).
