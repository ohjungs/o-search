## 목표 · 기대 결과

활성 계획서의 「건드릴 파일」 칸과 **그 계획이 실제로 건드리는 것**이 어긋나면 전수가
파일·칸을 대면서 빨개진다 — 오늘 트리(이 계획서 자신)에서는 조용하다.

## 설계 — **필요하다** (`design.md` 1절 「대안이 2개 이상 갈림」)

산출물은 `design_plan-scope-gap` — 아직 없고 다음 반복이 쓴다. 갈림이 실재한다:

- **A 정공법** — `git diff --name-only <기점>..HEAD` 가 낸 파일이 칸에 전부 있나.
  일반형이고 다섯 재발 전부를 덮는다. **위험**: 리뷰 phase 가 전수를 돌리는
  `git archive HEAD` 사본에는 `.git` 이 없다 → 건너뛰거나 거짓 RED 다.
  그 모양이 **게이트 ⑱**(계획 122 가 죽은 자리)이고 사람이 2026-10-26 에 ㉢ 으로 닫은 자리다.
- **B 최소·정적** — 칸에 `tests/` 가 있으면 `README.md` 도 요구한다. 근거는 단위 수
  장부(`tests/test_readme.py` 의 `UNIT_COUNT`)가 README 수정을 **기계적으로 강제**하는 것.
  git 을 안 읽어 어느 체크아웃에서나 돈다. **위험**: 위 재측정 4 가 커밋 축에서 거짓이다.
설계가 `3-2절` 대로 가장 위험한 가정 하나를 깨 본다 — **「활성 계획서는 칸을 글머리표
한 꼴로 든다」**(재측정 3 이 꼴이 넷임을 보였다. 활성 1개는 참이지만 **다음 계획이 그 꼴을
안 쓰면 자가 조용히 0행을 판정한다** — 이 저장소 최다 재발이 들어오는 문).

  픽스처로 경계를 고정한다)이고 **모양은 설계 문서의 「계약」 절이 정한다.**

- **완료 기준**: ① 설계가 고른 안의 위반을 심은 합성 입력에서 `scope_gap` 이 **파일명과

  함께 고친다. **이 계획이 닫는 바로 그 누락이라 여기 먼저 적는다.**
