# 계획 71 `index-e2e-verdict` — 계획 행의 e2e 칸이 판정인지 잰다

## 1. 무엇이 오늘 거짓인가

`docs/index.md` 의 계획 행 표는 여섯 칸이다(표 머리 행):

```
| 계획 | 상태 | 브랜치 | 스텝 | e2e | 비고 |
```

**다섯째 칸(e2e)에는 판정이 들어간다** — 실물 47행 중 46행이 `통과 …` · `없음(…)` ·
`**새 e2e 0개**(…)` 처럼 **e2e phase 가 무엇을 보고 무엇으로 끝냈는지**를 적는다.

`plan_noindex-entity-prefilter` 행 하나만 다르다:

```
| plan_noindex-entity-prefilter | 완료 | loop/noindex-entity-prefilter | 1/1 | 2026-09-07 | 설계 없음. …
```

**e2e 칸에 판정이 아니라 날짜가 들어 있다.** 그 계획의 e2e 는 실제로 통과했고 판정은
`docs/e2e/noindex-entity-prefilter/result.md:3` 에 그대로 있다 — *"판정: 통과 — 전수
`Ran 632 tests in 15.889s` · `OK` · rc 0"*. 즉 **일이 잘못된 것이 아니라 기록이 잘못됐다.**

**그리고 이 칸을 재는 자가 0개다.** 같은 표의 다른 칸에는 있다:

| 칸 | 재는 자 | 세운 계획 |
|---|---|---|
| 둘째 (상태) | `strike_gap` (`tests/test_docs.py:181`) | 70 `digest-strike-sync` |
| 넷째 (스텝) | `step_gap` (`tests/test_docs.py:129`) | 60 `index-step-sync` |
| **다섯째 (e2e)** | **없음** | — |

부기 드리프트를 두 번 잡아 놓고 **세 번째 칸에서 같은 종류가 실재한 채로 남아 있다.**
소비자는 루프 자신이다 — 탐색(`discover.md` 5절)이 `index.md` 를 「이미 한 것」의 명부로
읽는데, 판정이 없는 행은 「e2e 를 통과해서 완료인지」를 그 행만으로는 알 수 없다.

## 2. 착수 탐침 실측 (2026-09-07 · 읽기 전용 · 워킹트리 무변경)

`docs/index.md` 의 계획 행 47개를 전부 파싱해 쟀다. **이 절의 숫자가 3절의 설계를 고른 근거다.**

| 잰 것 | 값 |
|---|---|
| 계획 행 수 | **47** (`^\| plan_` 로 시작하는 줄) |
| 상태 칸 분포 | **`완료` 47 / 진행 0 / 보류 0** — 오늘 열린 계획은 없다 |
| e2e 칸이 **날짜뿐**인 행 | **1** — `plan_noindex-entity-prefilter` = `2026-09-07` |
| e2e 칸에 `통과` 라는 낱말이 **없는** 행 | **7** |

**마지막 줄이 갈림길을 죽였다.** 「e2e 칸은 `통과` 로 시작해야 한다」로 자를 세우면
**멀쩡한 6행이 거짓 RED** 다 — `plan_digest-rotate`·`plan_indexer-lock` 은
`없음(…)` 이고, `plan_exit-code-contract`·`plan_crawl-db-guard`·
`plan_docs-citation-guard`·`plan_focus-contrast` 는 `**새 e2e 0개**(…)` 다. 넷 다 `rules/e2e.md` 가 허용하는 정당한 판정이다.

그래서 자는 **어휘를 요구하지 않고 날짜를 거절한다.** 오늘 실물에서 오탐 **0** · 진탐 **1**.

## 3. 스텝 1개

스텝이 3개 미만인 이유(`rules/plan.md` 3절): 고칠 것이 **판정 함수 하나와 표의 한 칸**
이고, 검사를 먼저 빨갛게 만든 뒤 그 칸을 고치는 것이 TDD 한 바퀴 그 자체다. 쪼개면
「검사만 있고 실물은 빨간 커밋」이 남는다.

### 스텝 1/1 — e2e 칸이 날짜뿐인 완료 행을 무는 자를 세우고, 오늘의 위반 1건을 고친다
- **의존**: 없음
- **건드릴 파일 (예상 2개)**: `tests/test_docs.py` · `docs/index.md`
- **먼저 빨갛게 만든다** (`rules/dev.md` 0절): 새 검사가 오늘 실물 `docs/index.md` 에서
  **그 행을 슬러그 이름으로 대고 실패**하는 것을 본 뒤에 칸을 고친다.
- **어디에 붙이나** — 이 파일의 관용구를 그대로 따른다(`step_gap`·`iter_gap`·`strike_gap`
  셋이 이미 같은 모양이다. `tests/test_docs.py:129`·`:108`·`:181`):
  1. 상수: 다섯째 칸을 무는 행 템플릿을 `STEP_ROW`(`tests/test_docs.py:59`) 옆에 둔다.
     `STEP_ROW` 는 넷째 칸, `PLAN_ROW`(`:66`) 는 둘째 칸을 보고 이것은 **다섯째**를 본다.
  2. 순수 함수 `verdict_gap(index_text)` — 어긋난 자리를 한 줄로 돌려주고 없으면 `None`.
     **몸통을 함수로 빼는 이유는 앞 셋과 같다**: 실물 문서는 고치고 나면 늘 맞아서,
     검사가 문서에만 붙어 있으면 판정을 무력화하는 변이가 조용히 산다.
  3. `VerdictSyncTest` — 실물 `docs/index.md` 위에서 `verdict_gap` 이 `None` 인가.
  4. `VerdictGapTest` — 합성 표로 갈래를 밟는다(진탐·오탐·하한).
- **하한 못**: 행 추출기가 0행을 내면 판정이 **조용한 초록**이 된다(계획 70 이 실제로
  밟은 자리 — `STRIKE_POINTER_FLOOR`, `tests/test_docs.py:74`). 오늘 실물 **47행**이고
  행은 늘기만 하므로 하한을 **45** 로 박는다. **값 축에 딱 붙이지 않는다** — 붙이면
  표를 정리하는 날 거짓 RED 다(계획 70 리뷰가 등재한 그 갈림).
- **고칠 칸**: `index.md` 의 `plan_noindex-entity-prefilter` 행 다섯째 칸을 `docs/e2e/noindex-entity-prefilter/result.md`
  의 실제 판정으로 바꾼다. **날짜를 지우는 것이 아니라 판정을 적는 것이다** — 판정 문구는
  그 파일에서 옮겨 오고 지어내지 않는다.

## 4. 완료 기준 — 무엇이 죽어야 통과인가

전부 **저장소 밖 사본**(`mktemp -d`)에서 맨몸으로 돌린다(`docs/project.md ## 명령`).
변이 실행마다 `PYTHONPYCACHEPREFIX=$(mktemp -d)` 를 함께 준다.

| 판 | 입력 | 기대 결과 |
|---|---|---|
| **M0 대조군** | 스텝 완료 후 성한 트리 | 전수 `OK` rc 0 · 오탐 0 |
| **M1 구멍** | 검사만 심고 `index.md` 의 그 행은 날짜 그대로 | **`failures=1`** · 메시지가 `plan_noindex-entity-prefilter` 를 이름으로 댄다 · **나머지 검사는 안 흔들린다** |
| **M2 처방** | M1 입력에서 그 칸을 판정으로 고친 것 | 위반 **0** — 조용해진다 |
| **M3 재발** | M2 입력에서 **다른** 완료 행의 e2e 칸을 `2026-09-01` 로 바꾼 것 | **`failures=1`** — 재발을 심으면 다시 운다 |
| **M4 오탐 축** | 성한 트리 (위 여섯 행이 `없음(…)`·`새 e2e 0개(…)` 인 채) | 위반 **0** — 어휘를 요구하지 않는다는 것이 실물로 증명된다 |
| **M5 판정 무력화** | `verdict_gap` 몸통을 `return None` 으로 | `VerdictGapTest` 가 **죽는다** |
| **M6 추출기 무력화** | 행 정규식을 아무 행도 안 무는 것으로 | **하한 못이 죽인다**(조용한 초록 금지) |

**M5·M6 가 이 계획의 값이다** — M1~M4 만으로는 「오늘 맞다」만 사고, 무력화 변이는
실물이 맞춰진 뒤 전부 조용히 산다(계획 60 실측 6/6 생존 · 계획 61 실측 4/4 생존).

전수 러너가 **맨몸으로** `OK` rc 0 이고 건수가 **639 + 새 검사 수** 여야 한다.

## 5. 하지 않을 것

- **`통과` 같은 어휘 요구** — 2절 실측 오탐 6건. 자는 날짜만 거절한다
- **다른 칸(브랜치·비고) 가드** — 근거가 0건이다. 없는 일을 만들지 않는다
- **`docs/index.md` 의 다른 46행 서술 손대기** — 고칠 칸은
  `plan_noindex-entity-prefilter` 행의 다섯째 하나다
- **`docs/digest.md` 가 213줄로 상한 200 을 넘은 것** — 별건이고 `rules/docs.md` 3절대로
  **회전이 밟을 자리**다. 이 계획에서 안 연다
- **계획 69 리뷰가 등재한 `is_noindex()` 의 `</head>` 컷** — 여는 조건(recrawl 증분 뒤에도
  예산을 밟는 날)이 오늘 안 찼다
- **`src/`·`e2e/` 제품 코드** — 0줄. 이 계획은 기록 축이다
- **`docs/specs/`** — 읽기 전용

## 6. 설계 트리거 판정

**설계 생략.** `rules/design.md` 1절 트리거 여섯을 하나씩 댔다:

- 새 모듈·파일 생성 — **아니다**. `tests/test_docs.py` 에 붙인다
- 공개 인터페이스 — **아니다**. 테스트 안의 순수 함수다
- 데이터 구조·저장 형태 — **아니다**. 표 모양을 안 바꾸고 읽기만 한다
- 3개 이상 파일 — **아니다**. 2개
- 되돌리기 어려운 선택 — **아니다**. 검사 삭제로 무른다
- **대안 2개 이상 갈림 — 2절 실측이 죽였다.** 「어휘 요구」 안은 오탐 6건으로 탈락이고

## 7. e2e 시나리오

**이 산출물의 소비자는 루프 자신이다** — 제품 `src/` 가 0줄이라 크롤→색인→서버로 관통시킬
것이 없다(`rules/e2e.md` 3절 면제, 계획 70 과 같은 자리). 대신 **루프가 매 반복 돌리는
전수 러너**를 파이프라인으로 삼아 실제 편집 순서를 재연한다:

1. 루프가 계획을 마치고 `index.md` 행을 `진행`→`완료` 로 넘기면서 **e2e 칸에 판정 대신
   날짜를 적는다**(오늘 그 행이 실제로 그렇게 생겼다) → 전수 러너가 `FAILED` rc 1 을 내고
   그 계획 슬러그를 이름으로 댄다
2. 그 칸에 `docs/e2e/<슬러그>/result.md` 의 판정을 옮겨 적는다 → `OK` rc 0
3. e2e 를 새로 안 만든 계획(`없음(…)`·`새 e2e 0개(…)`)은 두 경우 모두 **안 물린다**

## 8. 위험 · 천장

- **천장: 날짜가 아닌 아무 말은 안 문다.** `-` · 빈 칸 · `미정` 은 판정이 아닌데 이 자는
  통과시킨다. **처방**은 「완료 행의 e2e 칸에 최소 길이·판정 어휘를 요구한다」인데 2절이
  잰 오탐 6건이 그 처방의 값이다 — **여는 조건은 날짜 아닌 비판정이 실물에 한 번이라도
  나타나는 날**이고, 그날 답은 어휘 목록이 아니라 그 모양 하나를 더 거절하는 것이다.
- **위험: 표의 열 모양이 바뀌면 다섯째 칸 가정이 깨진다.** `step_gap` 이 이미 같은 위험을
  지고 있고(`tests/test_docs.py:153` 이 그 메시지를 적어 둔다) 답도 같다 — 못 읽으면
  조용히 넘어가지 말고 **그 사실을 실패로 신고한다.**
- **오탐 방향**: 이 자가 우는 방향은 「기록을 안 고쳤다」뿐이고 제품·데이터는 안 건드린다.
  깨져도 아침에 되돌릴 것은 검사 하나다.
