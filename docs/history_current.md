### 반복 602 — 설계 phase · 갈린 축이 계획서가 적은 것과 **달랐다**

- **`docs/design_dep-zero.md`.** 계획서는 갈래를 「3.9 에서 stdlib 를 어떻게 아나」로 적었는데
  **셋 다 같은 답을 낸다** — 넷째·다섯째 행(`import requests` 가 깔린 기계·안 깔린 기계에서
  어떻게 되나)이 A·B·C 전부 빨감이다. 남는 축은 **유지비**뿐이라 허용 목록(A)을 버렸다:
  새 stdlib 모듈을 쓰면 **옳은 변경이 빨개지고**, 3.10 으로 올리면 두 벌이 된다.
  그 실패 모양은 `tests/test_e2e_fd.py` 가 「개수를 요구하면 옳게 고친 파일이 빨개진다」로
  이미 겪었다. C(경로에 파일이 있나)는 B 가 `sys.path` 에 흔들릴 때만 값이 있는데, 탐침에서
  **안 흔들리는 것을 확인**했다 — 사지 않은 보험이다.
- **진짜 결정은 한 줄이다 — 「`find_spec` 이 `None` 인 것도 위반」.** 「못 찾았으니 건너뛴다」로
  두면 `import requests` 가 **그 패키지가 안 깔린 기계에서 초록**이 된다. 계획서가 적은
  「전자는 영영 안 보인다」의 정확한 재현이다. **모르면 통과가 아니라 모르면 실패다.**
- **탐침 넷**(커밋 안 함): ① `find_spec` 은 최상위 이름이면 **모듈을 실행하지 않는다**
  (`turtle` 로 대봤다 — `origin` 은 나오는데 `sys.modules` 에 안 들어간다). 그래서 점 있는
  이름은 **첫 마디로 잘라야** 한다 — 안 자르면 부모 패키지를 진짜로 임포트한다.
  ② **경로 검사만으로는 모자란다** — `sys`·`time`·`itertools` 는 `origin` 이 `'built-in'`
  이고, 거꾸로 `zlib` 은 빌트인이 **아닌데** `lib-dynload/*.so` 로 stdlib 밑이다.
  두 판정이 서로를 안 덮어 **합집합**이어야 한다. ③ 전수가 `PYTHONPATH=src` 로 도는 탓에
  `websearch` 의 `origin` 이 **stdlib 밖**이라 자기 패키지를 신고하게 된다 → 1순위 판정을
  **「저장소 안에 그 이름의 파일이 있나」**(순수 파일 시스템 · `find_spec` 을 안 탐)로 뒀다.
  이 그물이 받을 이름은 다섯이다(`websearch` + `e2e` 형제 넷). ④ 오늘 위반은 실측 **0**.
- **모집단은 `src`·`tests`·`e2e` 셋 다**(54파일). 셋 다 위반 0 이라 넓히는 값이 공짜고,
  `tests/` 의 `import pytest` 한 줄도 「누구나 clone 해서 돌린다」를 깬다. `scripts/` 는
  `.py` 가 0개다. **자기를 훑는 재귀는 문제가 아니다** — `ast` 로 읽을 뿐 실행하지 않는다.
- **설계대로 실물에 대 봤다**: **54파일 · 387 임포트 · 위반 0** · `requests`·`numpy`·`pytest`
