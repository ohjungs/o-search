# e2e 결과 — retry-interval (016)

2026-08-27 · 브랜치 `loop/retry-interval` (기점 `5e7b525`) · 자동(야간) · 반복 106

## 무엇을 사용자 관점으로 봤나

여기서 "사용자" 는 **크롤당하는 사이트**다. 컨셉 1순위가 크롤 윤리라 이 계획의
관객은 검색하는 사람이 아니라 우리가 때리는 서버다. 그래서 재는 자리도 우리 로그가
아니라 **서버가 요청을 받은 시각**이다 (`crawl_politeness_e2e.py` 와 같은 자세 —
우리가 의도한 간격이 아니라 사이트에 실제로 닿은 간격).

계획이 연 문제는 한 문장이다 — **한 서버인데 두 경로가 다른 값을 쓴다.**
`robots.txt` 는 스킴별 문서라 `https` 쪽엔 선언이 없고, `_fetch_one` 이 그것만 보면
`http` 가 선언한 5초를 모른 채 **1초로 재시도**한다. 프런티어는 netloc 단위로 모아
5초를 알고 있는데도 그랬다. 그리고 재시도가 나가는 상황은 **서버가 이미 아플 때**다
(연결 거부·RST). 덜 조심할 자리로 최악이다.

수단은 새 `e2e/retry_interval_e2e.py`. 진짜 소켓·진짜 HTTP·진짜 robots 파서·진짜
프런티어·진짜 `fetcher` 재시도가 돈다. 바깥 네트워크는 안 탄다.

**한 가지만 주입했다: 스킴이 어느 포트로 가느냐.** TLS 를 세우지 않고
`https://127.0.0.1/` 를 로컬 평문 서버로 보낸다 — hosts 파일이 하는 일과 같은 층이고,
URL·robots 캐시 열쇠(`스킴://netloc`)·프런티어 열쇠(netloc)는 전부 진짜 그대로다.
`crawl_politeness_e2e.py` 가 워커 예외 하나만 주입한 것과 같은 절제다.

**포트를 안 쓰는 것이 이 e2e 의 핵심 조건이다.** 다른 e2e 는 전부 임시 포트를 URL 에
달지만, 그러면 `http://127.0.0.1:8001` 과 `https://127.0.0.1:8002` 는 netloc 이 갈려
**재려는 상황 자체가 안 만들어진다**. 기본 포트라 netloc 에 안 실릴 때만 한 도메인이다.

## 변이 — 이 e2e 가 실제로 무엇을 잡는가

계획 이전 상태를 그대로 되살렸다: `_fetch_one` 의 `interval = max(DOMAIN_INTERVAL,
floor, requested or 0)` 에서 `floor` 를 뺀다("이 줄을 안 썼다면", digest `[7]`).

```
AssertionError: http 이 선언한 5초를 같은 서버의 https 재시도가 안 지켰다
              — 간격 ['1.004', '1.010'] (프런티어는 알고 있었다)
종료코드: 1
```

**빨강(1)이지 측정 불능(2)이 아니다.** 그리고 실측값이 digest `[5]` 가 8일 전에
적어 둔 **1.0초와 같은 숫자**다 — 탐침이 재던 것과 e2e 가 재는 것이 같다는 뜻이다.
대조군 단언(`g < 2.0`)은 반대쪽을 막는다: "전부 5초로 재우기" 로 1번을 통과시키면
2번이 빨개진다.

## 안 잰 것 · 남은 것

- **`https` 를 먼저 치는 순서는 안 잰다.** 그 순간 프런티어는 `http` 의 선언을 아직
  모른다. 닫으려면 추측성 `robots.txt` 왕복이 필요한데 그쪽이 **덜 조심하는** 쪽이라
  안 닫기로 했다(리뷰 #2). 보장되는 것(어떤 순서든 1초 바닥은 산다)은 단위에서 못박았다
- **도메인 열쇠 정규화는 이 계획 밖이다.** `http://B.test` · `http://b.test:80` 이
  `http://b.test` 와 남남이라 같은 서버를 동시에 때린다 — 016 diff 밖이고 착수 전
  코드도 같은 값을 낸다. digest `[high]` · 다음 계획 1순위
- `Ctrl-C` 최악 대기가 이 계획으로 커졌다(재시도 대기가 도메인 간격만큼) — digest `[6]`.
  진짜 답은 `--deadline` 이거나 워커가 보는 중단 플래그다
