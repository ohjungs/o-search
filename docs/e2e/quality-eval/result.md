## 시나리오 2 — 두 형태로 확인했다

정답 문서를 "뺀다"는 두 가지로 읽힌다. 둘 다 돌렸고, **둘이 다른 종료 코드로 갈리는 것**이
이 러너의 계약이다 (fixture 결함 2 · 품질 미달 1).

```
(a) 코퍼스에서 URL 째 제거   → G1 정답 URL 이 코퍼스에 없다: http://q.test/ko/kimchi/01 (질의 [ko] 레시피)   exit 2
(b) 문서는 두고 그 문서에서만 질의어 삭제(2건) → 한국어 15/20 (75%) · 영어 18/20 (90%) · 미달   exit 1
```

(b) 에서 `[ko] 맛집 → http://q.test/ko/kimchi/06 (매치 27건, 미검출)` 처럼 **어느 질의가 왜
틀렸는지**까지 나온다. 러너가 거짓말하지 않는다 — 정답을 건드리면 반드시 숫자가 움직인다.

## 시나리오 3 — 반증. 이 계획에서 가장 중요한 결과다

방해 문서를 빼고 **정답 40문서만** 색인해 돌렸다.

```
포함률 35/40 (87%) — 방해가 있을 때(35/40)와 같다.  오르지 않았다
G2(매치 ≤ 10 = 측정 불능) 가 40질의 중 38건에서 발화
그래도 못 찾은 질의: [ko] 보관법 · 올레길 · 일출봉 / [en] loaf · tuples  (전체 코퍼스일 때와 같은 5건)
```

계획은 "안 오르면 방해 문서가 방해하고 있지 않다는 뜻이고, 그 코퍼스로 잰 80% 는 의미가
없다" 라고 적었다. 앞 절반은 **맞다**. 뒤 절반은 실측이 더 정확한 말을 준다:

- 전체 코퍼스에서의 순위 분포는 `1위 35건 / 2~10위 0건 / 매치 없음 5건` 이다
  (리뷰 뒤로는 러너가 매 실행 이 줄을 스스로 찍는다 — 임시 스크립트가 필요 없다).
  **`recall@1` 과 `recall@10` 이 같다** — 상위 10 이라는 창이 아무 일도 하지 않는다
- 즉 이 fixture 는 **매치되면 1위, 아니면 미검출인 이진 상태**다. bm25 정렬은 한 번도
  시험되지 않았다. 원인은 `## 구조` 를 지키느라 **정답 문서에만 질의어를 제목에 걸었기**
  때문이다 — 제목 가중이 경쟁을 끝내버린다
- 그러므로 **이 85/90% 는 랭킹 품질이 아니라 매치 품질의 숫자**다. 무의미하지는 않다.
  실제로 이 측정이 잡아낸 5건은 전부 진짜 결함(토크나이저)이었고, 정답을 옮기면(시나리오 2)
  숫자가 정확히 따라 움직인다. 못 재고 있는 것은 **랭킹 한 축**이다

**판정**: 계획의 합격 기준(`concept.md:22-23` 기능 2, 포함률 80% 이상)은 달성했으므로 계획을
닫는다. 시나리오 3 은 **통과로 적지 않는다** — 반증으로 적고, "이 코퍼스는 랭킹을 재지
못한다" 를 `project.md` 기준선과 `digest.md` 후보[6]에 한계로 못박는다. 랭킹까지 재려면
정답과 방해 문서가 같은 질의어를 같은 강도로 갖는 fixture 가 따로 필요한데, 그것은 이
계획이 만든 기준선을 먼저 고정한 뒤에 할 일이다 (`## 하지 않을 것` — 자를 만들면서 재는
대상을 같이 고치지 않는다).
