## 승인이 필요한 것 하나 — `porter` 를 남길지 뺄지

내가 대신 정하지 않는다. **거래이고 양쪽 수치를 다 쟀다** (`severity.md` 3절 — 설계
결정·사용자 눈에 보이는 동작 변경). `loop/tokenizer` 는 병합 전이라 아직 아무것도 안 나갔다.

| | 영어 포함률 | 영어 접두 검색 |
|---|---|---|
| `porter unicode61` (현재) | **19/20 (95%)** | 어휘 448개 중 **49개(10.9%)** 가 특정 접두 길이부터 0건 |
| `unicode61` (porter 제거) | 18/20 (90%) | **0개** |

- 한국어는 어느 쪽이든 20/20 이다. 이 결정은 영어에만 걸린다
- 잃는 예: `anythi`* → `anything` 0건, `buildi`* → `building` 0건, `decora`* → `decorator` 0건
- 사는 것은 `tuples` 질의 **한 건**이다. 영어는 porter 없이도 90% 로 합격선 80% 를 넘는다
- `prefix='2 3'` 과 `"어절"*` 재작성이 있는 한 접두 검색은 **의도된 기능**이다.
  porter 는 질의어도 색인어도 어간으로 줄여서, 사용자가 친 접두가 어간보다 길면 매치가 사라진다
- **`quality_eval` 은 이 손실을 구조적으로 못 잰다** — 영어 질의 20개가 전부 완전한 낱말이다
- 되돌리는 법: `SCHEMA` 의 `'porter unicode61'` → `'unicode61'`. 드리프트 감지가 색인을
  자동 재구축하므로 코드 한 줄이면 끝이고, `tests/test_quality_eval.py` 의 `EN_BASELINE`
  을 19 → 18 로 내리고 `test_english_inflection_matches` 를 지우면 초록으로 돌아온다
