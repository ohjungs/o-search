# 설계: 근거 문단 «소비» 축 — 모양 블록이 근거로 나가 본문을 이기나

## 결정

**새 측정기 `e2e/passage_consume.py` 가 동결 URL 목록의 모양 블록마다 «그 블록 자신에서
뽑은 질의» 로 `indexer.passages()` 를 부르고, 근거로 돌아온 블록이 그 모양 블록인지 센다.**
질의가 모양 블록에 가장 유리하므로 이 수는 **상한**이다 — 0 이면 후보가 닫힌다.
**제품 `src/` 0줄**이고 고르는 규칙은 제품에게 묻는다(사본 없음).

## 대안 비교 — 갈림 1: 질의가 어디서 오나

| | A. 모양 블록에서 뽑는다 (최소·상한) | B. 실물 정답 질의 세트 (정공법) | C. DB 빈출 토큰 (분포) |
|---|---|---|---|
| 되돌리기 | 쉬움 (파일 삭제) | 어려움 — 라벨이 자산이 된다 | 쉬움 |
| 코드량 | 적음 — 블록 텍스트에서 토큰 | 많음 + **사람 라벨** | 적음 |
| 기존과 일치 | ○ 95% 상한으로 닫아 온 방식 | △ `quality_eval` 과 중복 | ○ |
| 다음이 편한가 | 보통 — 상한만 안다 | 좋음 | **나쁨 — 분모가 희박** |

**선택: A** — 0 이 나오면 **그것만으로 후보가 닫힌다**(질의를 가장 유리하게 줘도 안 이긴다).
라벨이 0 이라 야간이 사람을 안 부른다. **버린 이유: B** — 실물 정답 질의는 사람 판단이고
야간 금지 목록이다. **C** — 모양 블록은 20,000문서 블록 698만 중 53개(0.0008%)라 빈출
토큰으로는 분모가 사실상 0 이고, 그 0 은 「안 이긴다」가 아니라 「안 만났다」다.

## 대안 비교 — 갈림 2: 어디에 두나

| | A. `e2e/passage_shapes.py` 에 축 추가 | B. 새 파일 `e2e/passage_consume.py` |
|---|---|---|
| 되돌리기 | 보통 — 기존 자를 건드린다 | **쉬움 — 새 파일만 지운다** |
| 코드량 | 적음 (표본·지문·DB 열기 재사용) | 보통 |
| 기존과 일치 | ○ 계획 119 가 축을 더한 선례 | ○ `e2e/` 명부가 받는다 |
| **잴 수 있나** | **못 잰다** | 잴 수 있다 |

**선택: B** — 결정적인 수가 하나다: **동결 표본 1,000건에 중첩 `<a>` 문서가 0건**이다
(`baselines.md` 계획 119 표 — 실물 1,000 에서 0.0% · census 20,000 에서 6문서). 그 파일의
모집단으로는 후보 `[5]` 의 분모가 **구조적으로** 0 이라 축을 더해도 「죽은 측정기의 0」만
낸다. 모집단이 다르면 자도 다르다. **버린 이유: A** — 코드량은 A 가 적지만 그 적음이
못 재는 자를 낳는다. 「자가 죽었는데 초록이다」는 2026-10-18 이 두 번 꺼낸 그 교훈이다.

## 가정 — 깼다 (2026-10-20 탐침 · 커밋 없음)

1. **`indexer.passages()` 가 실물 DB 에서 돈다** — 참. `data/crawl.db`(`pages` 275,482 ·
   `docs` 222,569)에서 질의 6종이 전부 예외 없이 결과를 냈다.
2. **읽기만 한다** — 참. 호출 전후 `crawl.db` 의 mtime·size 가 동일했다
   (`1789398436` · `10980196352`). `passages()` 가 `_connect` 로 `rw` 를 열지만 순수
   `SELECT` 라 파일을 안 건드린다 — `passage_shapes.py` docstring 이 적어 둔 그 성질이다.
3. **모양 문서가 자기 블록에서 뽑은 질의로 hit 된다** — **조건부로 참이고, 이것이 분모다.**
   `gnustatus-2011-10` 은 `Health`·`Coreutils` 로는 상위 10 에 **안 들었고**
   `GNU Status Reports October 2011`·`Fontutils Gama Gawk`(TOC 블록 9·10·11 의 글자)로는
   **들었다**. 그래서 **분모(hit 수)를 분자와 함께 낸다** — 계획서가 미리 못박은 줄이다.
4. **탐침이 측정의 심장을 한 번 돌렸다** — 위 두 질의에서 근거로 돌아온 것은
   position **30**·**122**(둘 다 본문)이고 TOC 블록(position 2~11)이 **아니다**. 이유는
   고르는 규칙 `key = (score, len(block))` 이다 — TOC `li` 는 40자 score 1 이고 본문은
   길며 같은 글자를 여러 번 담는다. **즉 수는 0 쪽으로 기울어 있지만 판정은 스텝 1 이 한다.**

## 계약 — 개발이 지킬 것

1. **`src/` 0줄.** 고르는 규칙을 함수로 빼내지 않고, 복사하지 않는다.
   `indexer.passages(DB, q, limit)` 를 **그대로** 부른다.
2. **모집단은 동결한다** — `e2e/shapes/consume.jsonl` 에 `{url, sha}` 만 적는다
   (`e2e/shapes/sample.jsonl` 과 같은 모양 · 본문 0바이트 · 남의 저작물을 이력에 안 싣는다).
   중첩 `<a>` 모집단은 `baselines.md` 의 census SQL
   (`LIMIT 20000 OFFSET 40000`)을 한 번 돌려 얻은 **그 6문서**다.
3. **분자와 분모를 함께 찍는다** — 분모 = 모양 문서가 `passages()` 결과에 든 (문서, 질의)
   쌍 수 · 분자 = 그중 근거 position 이 모양 블록 position 인 수. **합치지 않는다.**
4. **종료 코드**: `0` 쟀다 · `1` 분자가 0 이 아니다(= 후보가 열린다) · **`2` 재지 못했다**
   (DB 부재 · 픽스처 부재 · **분모 0**). 2 는 판정이 아니다 — `passage_shapes.py` 와 같은 관용구.
5. **전수 안에서 실물 DB 를 안 읽는다** — 격리. 단위는 순수 함수(질의 뽑기·모양 판정)와
   **합성 예문**만 본다. `e2e/` 명부(`project.md`·`test_docs.py`)에 이름을 등재한다.

## 되돌리기

**커밋 하나 revert** — 새 파일 둘(`e2e/passage_consume.py` · `e2e/shapes/consume.jsonl`)과
테스트·명부 한 줄뿐이고 제품 경로에 진입점이 없다. 플래그가 필요 없는 모양이다.

## 범위 밖

- **ⓑ(구분자가 낀 연접)** — census 가 없어 모집단을 못 동결한다. 후보 `[6]` 의 ⓑ 는
  이 계획이 **판정하지 않는다**(스텝 3 이 「재지 않았다」로 적는다 — 「닫혔다」로 적지 않는다).
- **`pre`(후보 `[4]`)** — 동결 표본에 2,671블록 있어 같은 루프로 닿는다. 스텝 1 이
  중첩 `<a>` 를 닫은 뒤 **여유가 있으면** 같은 자에 모양 하나를 더한다. 못 하면 스텝 3 이
  「재지 않았다」로 적는다. **모양별 술어를 일반화하는 플러그인 틀은 안 만든다**(ponytail).
- **모양을 고치는 것** — 수가 1 이상일 때의 별도 계획이다. 이 계획은 재기만 한다.
