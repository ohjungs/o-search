| 시나리오 (plan_crawl-delay.md) | 결과 |
|---|---|
| `Crawl-delay: 2` 사이트를 크롤 → 요청 간격 2초 이상 | 통과 — 서버 수신 시각 기준 최소 **2.01s** |
| 페이지를 빠뜨리지 않는다 (느려질 뿐) | 통과 — 두 사이트 6/6 수집 |
| 지시가 없는 사이트는 지금까지대로 1초 | 통과 (`e2e/crawl_e2e.py` 최소 1.004s, 회귀 없음) |
| `Crawl-delay: 0` → **1초 아래로 내려가지 않는다** | 통과 — 최소 1.00s |
| 남의 사이트 간격이 새지 않는다 | 통과 — 하한 도메인의 간격이 2초 미만(전역으로 느려진 것이 아니다) |

- **두 도메인을 한 서버로 만든다**: `127.0.0.1` 과 `localhost` 는 netloc 이 다르다.
  Host 헤더를 보고 robots.txt 를 갈라 낸다(2초 / 0초). 도메인별 간격이라는 계약은
  **도메인이 둘일 때만** 검증된다 — 하나면 전역 지연과 구분할 수 없다.
- **잡는지 확인했다**: `Frontier._interval` 이 항상 `DOMAIN_INTERVAL` 을 돌려주게 변이시키면
  `Crawl-delay: 2 인데 2초 미만 간격 ['1.009', '1.005']` 로 실패한다. 돌아가는 것과 잡는 것은 다르다.
- 시나리오에 없던 것을 하나 더 봤다: **수집 누락 0**. 간격을 지키느라 페이지를 빠뜨리면
  윤리는 지키고 기능을 잃는다 — 둘 다여야 통과다.
