# 계획 131 — `mutant-anchor-unique`

## 1. 문제

**변이 검사의 「생존」 판정이 앵커가 어디에 심겼는지를 안 본다.**

이 저장소는 테스트 phase 마다 **손으로 쓴 변이 하네스**로 「테스트가 이 코드를 무는가」를
잰다 — 파일에서 한 줄(앵커)을 찾아 바꾸고 전수를 돌려, 빨개지면 「죽음」 초록이면 「생존」
이다. 그 치환이 `str.replace(old, new, 1)` · `sed` 류 **첫 적중 하나**라서, 앵커가 파일에
둘 이상 있으면 **의도한 자리가 아닌 남의 코드**가 바뀐다. 남의 코드는 그 변경에 무던할
수 있고, 그러면 전수가 초록이라 **「생존」으로 읽힌다** — 재지 못한 것이 판정으로 둔갑한다.

- **근거(실물 재현)**: 2026-11-01 반복 792 · 계획 130 테스트 phase. 변이 M8 의 앵커
  `if not missing:` 가 `tests/test_docs.py` 에 **둘**이라(지금 실측 `:1097` 다른 가드 ·
  `:4403` 계획 130 의 자 — 등재문의 `:4385` 는 파일이 자라 드리프트했다)
  `replace(old, new, 1)` 이 **남의 함수**를 고쳤고 전수가 초록이라 「생존」이 됐다.
  앵커를 유일하게 바꿔 다시 돌리니 **죽는다.**
- **근거(사전 확률 — 착수 전 재측정으로 새로 나온 수)**: 변이가 가장 자주 꽂히는
  `tests/test_docs.py` 의 **비어 있지 않은 비주석 줄 3,321 중 608줄(18.3%)이 중복 종류
  158개에 속한다.** 손으로 집은 한 줄 앵커가 모호할 확률이 **약 1/5.5** 다 —
  후보 등재문의 「오늘 피해는 0」보다 이쪽이 날카롭다. 피해가 0 이었던 것은 운이고,
  **이 저장소의 변이 실측 전부가 같은 함정 위에 서 있다.**
- **값**: 「생존」은 「테스트가 약하다」로 읽히고 그 판정이 다음 테스트를 더 짜게 만든다.
  계획 126·127 이 생존을 근거로 테스트를 고쳤고 **그 판들의 앵커가 유일했는지는 어디에도
  안 적혀 있다.** 즉 틀린 입력으로 테스트를 고친 적이 있는지를 **오늘 알 수 없다.**
- **출처**: 탐색 6순위 — `docs/digest.md` `## 다음 계획 후보` 의 `[7]`
  「변이 하네스의 「심긴 것을 먼저 단언한다」가 «어디에» 심겼는지는 안 본다」.
  **여는 조건 없음**(등재문이 「지금 열려 있다」고 적었다) · 열린 것 중 최고점.

## 2. 목표

손으로 쓰는 하네스를 **기제로 바꾼다** — 변이를 적용하기 **전에** 앵커가 파일에 정확히
하나인지 재고, 아니면 적용하지 않고 「재지 못했다」로 끝낸다. 이 저장소가 다섯 번
반증한 처방(「다음 밤이 잘 기억한다」)을 쓰지 않는다 → 계획 130 과 같은 계열.

**기대 결과**: 반복 792 의 M8 을 실물에서 다시 부르면 **적용 전에 거부**되고, 그 결과가
「생존」과 **다른 종료 코드**로 나온다.

## 4. 스텝

**둘뿐인 이유**: 산출물이 「앵커를 재는 자」와 「적용하고 반드시 되돌리는 자」 둘이고,
각각 독립으로 검증·되돌리기가 된다. 개수를 채우려 쪼개지 않았다(`rules/plan.md` 3절).

### 스텝 1 — 앵커를 세어 0 · 1 · 다수를 가르는 판정자 (의존: 없음)

- **어디서 시작하나**: `scripts/` 에 새 파일. 선례는 `scripts/verdict.sh`(90줄)와
  그 테스트 `tests/test_verdict_wrapper.py` · `scripts/merge-to-main.sh`(49줄)와
  `tests/test_merge_script.py`(115줄) — **둘 다 스크립트를 `subprocess` 로 부르는 꼴**이다.
- **무엇이 이미 참인가**: 이 저장소에 변이 하네스 파일은 **0개**다(`ls scripts/` 가 둘).
  하네스는 반복마다 인라인으로 쓰였고, 그래서 전수가 그것을 못 본다.
- **완료 기준**(실행해서 확인한다):
  - 실물 `tests/test_docs.py` + 앵커 `if not missing:` → **적용하지 않고** 거부하며
    적중이 **2건**임과 **두 줄 번호를 모두** 인쇄한다.
  - 같은 파일 + 실물에 없는 문자열 → 「0건」으로 거부한다. **다수와 0 은 사람이 할 일이
    다르므로 메시지로 갈라 말한다**(다수는 앵커를 좁혀라 · 0 은 앵커가 썩었다).
  - 같은 파일 + 유일 앵커(예: `def scope_touched(root=ROOT):`) → 통과로 판정한다.
  - `tests/test_mutate_script.py` 신규 테스트 전부 통과 · 전수 1068 → 증가분 `OK rc=0`.
- **건드릴 파일**: `scripts/mutate.py` · `tests/test_mutate_script.py` · `README.md`
  (`tests/test_readme.py` 의 `UNIT_COUNT` 가 「단위 N건」 장부 줄을 기계적으로 강제한다 —
  단위 수가 바뀌는 스텝은 이 파일을 **반드시** 고친다. 다섯 번 재발해 계획 130 이 못을
  박은 자리라 **처음부터 칸에 적는다**)

### 스텝 2 — 적용 → 감싼 명령 실행 → **반드시 복원** (의존: 1)

스텝 1 의 판정자를 **읽어서** 쓴다(통과한 앵커만 적용된다). 그래서 진짜 의존이다.

- **어디서 시작나**: 스텝 1 이 만든 `scripts/mutate.py` 의 판정 함수.
- **완료 기준**(실행해서 확인한다):
  - 유일 앵커로 부르면 적용 후 감싼 명령이 돌고, **끝나고 `git status --short` 가 비어
    있다**(원본 복원). 명령이 실패해도 · 중간에 예외가 나도 복원된다.
  - **복원이 실패하면 조용히 끝내지 않는다** — 작업 트리가 더러운 채 0 으로 끝나는 길이
    없다. 데이터 안전은 사다리로 타협하지 않는 영역이다(ponytail · 카파시 4번).
  - 거부된 앵커(0건·다수)에서는 파일이 **한 바이트도** 안 바뀐다.
  - 전수 `OK rc=0` · e2e 18종 `rc=0`.
