## 2. 이 phase 가 실제로 잰 것 — **실서버 둘을 띄워 상태 코드를 받았다**

단위는 `ServeTestCase` 안에서 핸들러를 부른다. e2e 가 더할 수 있는 것은 하나뿐이다 —
**`python3 -m websearch.serve --port 0` 로 진짜 프로세스를 띄우고, 소비자가 실제로 받는
상태 코드와 본문을 소켓에서 읽는 것.** 계획 53 이 고친 것이 «본문» 이 아니라 «상태 코드»
라서 그 값은 이 자리에서 재야 참이다.

DB 는 임시 디렉터리에서 `store.upsert` → `indexer.index_pages` 로 1문서를 만들고
사본 쪽에만 `DROP TABLE pages` 를 했다 — **저장소의 `data/crawl.db` 는 읽지도 않았다**
(계획서 7절: 원본 무변경 · 재색인 0).

### 2-3. 변이 둘을 **HTTP 표면에서** 다시 죽였다 (완료 기준 10)

개발·리뷰는 단위 실패 건수로 쟀다. 여기서는 같은 변이를 심고 **상태 코드가 어떻게
갈리는지**를 봤다 — 소비자가 보는 값이 그것이다. `src/` 사본을 스크래치패드로
복사해 심었다(`.git` 없는 트리 · `git checkout` **0회** · 저장소 무변).

| 변이 | `q=김치찌개` | `q=zzzznope` | `q=%01` | 탐침 rc |
|---|---|---|---|---|
| 없음(제품 그대로) | **503** | **503** | **503** | 0 |
| ① 503 튜플에서 `NoCrawlDataError` 제거 | 500 | 500 | 500 | **1** (실패 6건) |
| ② `passages()` 가드 삭제 | 500 | **200 `[]`** | **200 `[]`** | **1** (실패 6건) |

**②가 이 phase 의 값이다** — 가드를 지우면 착수 때의 그 갈림(500 / 200 / 200)이
**HTTP 표면에 글자 그대로 돌아온다**. 계획서 1절이 «판정이 질의 내용에 달렸다» 고 적은
고장을 프로세스 밖에서 다시 본 것이고, 단위가 세는 `failures=N` 이 아니라 **소비자가

**①과 ②는 서로 다른 것을 잡는다.** ①은 셋을 500 **하나로 모으지만** 이름이 틀렸고
(재시도하면 낫는 상태에 «재시도 마라» 를 준다), ②는 이름 이전에 **갈림 자체**를 되살린다.
