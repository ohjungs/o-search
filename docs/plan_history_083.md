# 계획 108 — 병합 게이트가 「모집단 0」을 초록으로 통과시키지 않는다

- **슬러그**: `merge-verdict` · **브랜치**: `loop/merge-verdict` (기점 `main` = `b39abdc`)
- **근거**: `discover.md` **6순위** — `digest ## 다음 계획 후보` 의 `[7]` 「`merge-to-main.sh` 의
  전수는 래퍼를 안 통과해 0건이어도 병합을 민다」(2026-09-19 반복 639 리뷰 실측). 계획 107 이
  **명시적으로 범위 밖**에 둔 자리다(`design_history_080.md`).
- **시작**: 2026-09-28 (반복 643)

## 1. 문제

계획 107 이 「0건 전수는 판정이 아니라 사고」를 `scripts/verdict.sh:78-87` 에 넣었다.
**그런데 `main` 을 지키는 문 자신은 그 자를 안 탄다.**

```
merge-to-main.sh:23   TEST_CMD="${MERGE_TEST_CMD:-… python3 -m unittest discover -b -s tests}"
merge-to-main.sh:36   OUT=$(eval "$TEST_CMD" 2>&1); trc=$?
merge-to-main.sh:39   [ $trc -eq 0 ] || { echo "전수 RED — 푸시 안 함" >&2; exit 1; }
```

39행은 `trc` 만 보고 `unittest` 는 0건에도 `rc=0` 을 준다 → **빈 전수가 병합을 통과한다.**
오늘은 23행이 `-s tests` 를 박아 무해하다(831건). 위험은 그 문자열이 바뀔 때(`-p`/`-k`,
시작 디렉터리) 열린다. **즉 「지금 빨간 것」이 아니라 「지금 무는 자가 없는 것」**이고,
이 저장소 최다 재발 계열(「절차를 문서에만 적고 재는 자를 안 만든다」)의 자리다.

## 2. 목표

기본 전수가 `scripts/verdict.sh` 를 타게 해서 모집단 0 이면 `rc=2` 가 나고 39행이 병합을
막는다. 끝나면 **0건 전수로는 `main` 을 밀 수 없다.**

## 3. 하지 않을 것

- **`MERGE_TEST_CMD` 주입까지 강제로 감싸기** — 취향이 아니라 **측정으로 닫혔다**: 36행이
  `eval` 이고 `TEST_CMD` 가 `PYTHONPATH=src …` 처럼 **환경 변수 배정으로 시작**하므로 앞에
  덧대면 배정이 명령 이름으로 읽혀 **`rc=127`** 이다(`verdict.sh:7-11` 의 실측). 일반 감싸기는
  그 낱말 파싱을 요구하는데 래퍼가 **일부러 안 넣기로** 한 코드다. 14행이 이 변수를 **테스트
  주입 구멍**으로 선언해 두었다.
- **`verdict.sh` 수정** — 계획 107 의 산출물. 이 계획은 부르는 쪽만 고친다.
- **다른 스크립트**(`reschedule.js`·`metrics-record.js` 등) — 범위 밖.
