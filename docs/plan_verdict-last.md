# 계획 106 — `verdict-last` · 판정 줄을 가리는 손을 기제로 막는다

## 1. 문제

`digest.md ## 반복 실패` **최다 재발 항목**이다 — 「러너의 판정 줄을 가린다」 **35회,
뒤의 서른네 번이 연속**이다. 러너를 `| tail -N` · `2>/dev/null` · `2>&1 | tail -N` 에
얹으면 `Ran N tests / OK|FAILED` 와 종료 코드가 함께 사라지고, **실패가 통과로 보인다.**

**막으려는 시도가 이미 셋 있었고 셋 다 문장이었다:**

1. `docs/project.md:7` 「아래 명령은 전부 맨몸으로 돈다」 — 조항.
2. 조항을 「판정 실행」에서 「러너를 부르는 모든 호출」로 조이기 — ⑬⑭ 가 뚫었다.
3. 「러너를 파이프의 왼쪽에 두지 않는다」 — ㉒ 가 뚫었다.

항목 자신이 열아홉 번째 표본에서 결론을 적었다: **「문장은 소진됐다」.** 그리고 처방
후보 한 줄이 **저장소 안이라 계획으로 열 수 있다**고 명시돼 있다 —
「막을 자리는 사람의 손이 아니라 러너의 출력이다」.

### 1-1. 오늘 재현했다 (반복 625 탐색 · 맨몸)

| 탐침 | 명령 | 화면에 남은 것 |
|---|---|---|
| A | `python3 -m unittest discover tests 2>&1 \| tail -3` | `  김치` / `1 문서 색인` / `1 문서 색인` — **판정 0줄** |
| B | `python3 -m unittest discover -b tests 2>/dev/null \| tail -3` | **아무것도 없음** |
| 대조 | `python3 -m unittest discover -b tests 2>&1 \| tail -3` | `Ran 812 tests in 24.877s` / `OK` — **운으로 살아남았다** |

**원인이 둘로 갈린다.** B 는 판정이 stderr 라 재지향이 통째로 버린 것이고, A 는 다르다 —
`unittest` 의 판정은 stderr(**무버퍼**)인데 테스트의 stdout 은 파이프 아래에서
**블록 버퍼**가 되어 **프로세스가 끝날 때 한꺼번에 밀려 나온다.** 그래서 순서가 뒤집혀
판정이 위로 밀려난다. 대조군이 초록인 것은 `-b` 가 stdout 을 삼켜 밀 것이 없어서일 뿐이고,
**실패한 테스트의 출력은 `-b` 가 안 삼킨다** — 즉 빨간 판에서 정확히 안 보인다.

**세 번째 손실은 `rc` 다.** 파이프 오른쪽 명령의 종료 코드가 쉘의 `$?` 가 되므로
`rc` 는 출력 길이와 무관하게 **파이프 그 자체의 성질**로 사라진다(㉑ 이 도달한 지점).

### 1-2. 이 계획 자신이 서른여섯 번째 표본이다

이 반복이 **처음 친 명령**이 `... -b tests 2>&1 | tail -5` 였다 — 항목을 읽기 전이다.
운으로 `Ran/OK` 는 살았고 `rc` 는 죽었다. **읽은 뒤에도 나는 것이 이 항목의 논지인데,
읽기 전에도 난다는 것이 같은 논지의 더 싼 증거다.**

## 2. 목표

러너 호출에 출력 조작을 붙일 **이유**를 없앤다. 붙여도 판정이 살아남게 만든다.

기대 결과 — 판정과 `rc` 가 **stdout 의 마지막 줄**에 있어서, 위 세 형태
(`| tail -1` · `2>/dev/null` · `2>&1 | tail -3`) **어느 것을 붙여도 살아남는다.**
`tail` 은 마지막을 남기므로 **가장 자주 붙는 손이 오히려 판정만 남긴다.**

### 스텝 1 — 재는 자를 먼저 세운다 · 의존: 없음

`tests/test_verdict_wrapper.py`. 가짜 러너(긴 stdout + stderr 판정 + 종료 코드)를
