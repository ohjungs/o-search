# 설계: 변이 앵커 유일성 (계획 131 `mutant-anchor-unique`)

## 결정

**`scripts/mutate.py` 를 세운다** — 변이를 적용하기 전에 앵커가 파일에 정확히 하나인지
**적용기와 같은 술어**(부분문자열 셈)로 재고, 0 이나 다수면 **한 바이트도 안 바꾸고**
`rc=2`(재지 못했다)로 끝낸다. 유일하면 적용 → 감싼 명령 실행 → **원본 바이트 되쓰기**로
복원하고, 변이가 죽으면 `rc=0` 살면 `rc=1` 이다.

## 대안 비교 — 출발점 셋에서 하나씩 (`design.md` 3-1절)

| | **A. 최소**<br>`grep -c` 한 줄 + 조항 | **B. 정공법**<br>`scripts/mutate.py` 전 주기 | **C. 되돌리기 우선**<br>판정만 하는 얇은 자 |
|---|---|---|---|
| 되돌리기 | 만든 것이 없다 | 커밋 하나 revert · 파일 삭제 | 파일 삭제 |
| 코드량 | 0 | 보통 (선례 `verdict.sh` 90줄) | 적음 |
| 기존과 일치 | △ 조항은 다섯 번 반증됐다 | ○ `verdict.sh`+`test_verdict_wrapper.py` · `merge-to-main.sh`+`test_merge_script.py` | ○ |
| 다음이 편한가 | 나쁨 — 매 밤 기억해야 한다 | 좋음 | **나쁨** — 손 하네스 «위에» 얹는 추가 노동 |
| **같은 것을 재나** | **✗ 아니다 (탐침이 깼다)** | ○ | ○ |

**선택: B.**

**버린 이유 A** — 두 가지가 겹쳐 떨어졌다. ① **적용기와 다른 것을 센다**: 하네스의 적용은
`str.replace(anchor, …, 1)` 로 **부분문자열**을 세는데 `grep -c` 는 **줄**을 센다. 탐침이
실물에서 `grep -c = 1` 인데 적용기는 둘을 보는 자리 **7개**를 찾았고, 그중 하나가
하필 `dup_def_gap` 의 픽스처(`"class A:\n    def go(self):\n …"` — `go(self):\n` 가 **한
물리 줄 안에 두 번**)다. 즉 A 는 **이 계획이 닫으려는 거짓 초록을 제 판정으로 다시
만든다**. ② 조항은 이 저장소에서 다섯 번 반증됐다(`[R76-2]`~`[R129-5]` 계열 ·
계획 130 이 그 처방을 기제로 바꾼 자리).

**버린 이유 C** — 판정만 하면 **쓰는 쪽이 더 힘들어진다.** 손으로 하네스를 쓰고 그 위에
판정 호출을 **더** 얹어야 하므로, 잊으면 그만인 A 와 채택률이 같아진다. 조항을 기제로
바꾸는 **유일한 레버**는 「이 자를 쓰는 것이 손으로 쓰는 것보다 쉽다」이고 C 는 그것을
포기한다. 적용·실행·복원이 추측성 확장이 아닌 이유가 여기다 (ponytail 1번 통과).

## 갈림 셋을 여기서 못박는다 (계획서 5절이 넘긴 것)

1. **종료 코드 ㉠** — `0 변이가 죽었다 / 1 변이가 살았다 / 2 재지 못했다`.
   `docs/project.md` 관용구(`0 통과 / 1 기준 위반 / 2 재지 못했다`)와 같은 꼴이고,
   **2 가 「재지 못했다」인 것이 이 계획의 주제 그 자체**다 — 거짓 생존은 재지 못한 것을
   판정으로 읽은 사고였다. 생존이 1 인 것도 관용구와 맞는다(「테스트가 약하다」= 기준 위반).
   **㉡·㉢(판정과 실행을 가르기)은 위 C 와 같은 이유로 버렸다.**
2. **자리** — `scripts/` 한 파일. 두 선례가 이미 「스크립트 + `subprocess` 테스트」 꼴이다.
3. **되돌리기 수단** — **원본 바이트를 메모리에 들고 `try/finally` 로 되쓴다.**
   `git restore` 를 부르지 않는다: `rules/plan.md` 3-1절이 「`restore .` 를 쓰면 남의
   미커밋 변경까지 날아간다」고 적은 자리이고, 변이는 **작업 중인 트리**에서 돈다.
   **데이터 안전이라 사다리로 타협하지 않는다** — 복원 실패는 조용히 끝내지 않는다.

## 가정 — 탐침으로 깼다 (`design.md` 3-2절)

**「판정 술어가 적용기와 같아야 한다」.** 틀리면 이 설계가 무너진다 — 다른 것을 세는 판정은
거짓 초록의 새 통로다. **확인했다**: 실물 `tests/test_docs.py` 에서 `grep -c`(줄)와
`text.count`(부분문자열)가 갈리는 자리가 7개이고 전부 `grep` 쪽이 **작게** 센다
(`None` 316 vs 321 · `gap` 598 vs 781 · ` · ` 71 vs 95). 커밋하지 않고 되돌렸다.

## 계약 — 개발이 지킬 것

1. **판정 술어는 `text.count(anchor)`** — 줄 단위로 세지 않는다. 적용이 쓰는 것과 **같은
   함수**로 센다(둘이 갈리면 그것이 결함이다).
2. **0 과 다수는 메시지가 다르다.** 0 = 앵커가 썩었다(파일이 움직였다) · 다수 = 적중 수와
   **걸린 모든 자리의 줄 번호**를 댄다. 사람이 할 일이 다르다.
3. **거부(0·다수)면 파일을 한 바이트도 안 바꾼다** — 판정이 적용보다 **먼저** 돈다.
4. **복원은 원본 바이트 되쓰기**이고 `try/finally` 로 **명령이 실패해도·예외가 나도** 돈다.
   복원 자체가 실패하면 **stderr 로 크게 말하고 `rc=2`** — 더러운 트리를 0 으로 끝내는
   길이 없다.
5. **종료 코드**: `0` 죽음 · `1` 생존 · `2` 재지 못했다. **생존과 거부가 같은 코드로 나오는
   길이 없다** — 이 계획이 닫는 병이 종료 코드 쪽에서 되살아나는 것을 막는다.
6. **판정을 stdout 의 마지막 한 줄로 다시 찍는다** — `scripts/verdict.sh` 관례. `| tail -1`
   을 붙여도 판정이 산다.
7. **명령줄 두 꼴**(스텝 경계와 같다):
   - `scripts/mutate.py --check <파일> <앵커>` → 판정만. **절대 안 쓴다.** `rc` 0/2.
   - `scripts/mutate.py <파일> <앵커> <치환> -- <명령…>` → 판정 → 적용 → 실행 → 복원.

## 되돌리기

**이 두 커밋만 revert 하면 끝난다** — 새 파일 둘(`scripts/mutate.py`·
`tests/test_mutate_script.py`)과 `README.md` 장부 줄뿐이고, 기존 코드가 이 자를 **부르는
자리는 0개**다(하네스는 사람·루프가 손으로 부른다). 제품 `src/` 는 안 건드린다.

## 범위 밖 → `digest.md` 후보로

- **`rules/test.md` 변이 절이 이 자를 쓰라고 적는 일** — 룰 저장소(`~/.claude`)라 못 건드린다.
  **천장 ①**: 자를 만들어도 다음 밤이 손으로 쓰면 그만이다. 줄어드는 것은 확률이고 0 이 아니다.
- **과거 변이 실측의 소급 재검** — 계획 126·127 이 「생존」을 근거로 테스트를 고쳤고 그
  판들의 앵커가 유일했는지는 안 적혀 있다. 근거는 있지만 범위가 다르다.
- **`tests/test_docs.py` 의 중복 줄 158종** — 직교 편집(카파시 3번). 신고만 하고 안 없앤다.
- **여러 변이를 한 번에 돌리는 일(배치)** — 추측성이다. 지금 하네스는 한 판씩 돈다.
