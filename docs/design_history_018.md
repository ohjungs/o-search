# 설계 020: deadline — 총 크롤 시간 예산

계획서 `docs/plan_deadline.md` · 브랜치 `loop/deadline` · 2026-08-28 00:00

**트리거** (`design.md` 1절): ① 공개 인터페이스 변경(`crawl()` 시그니처 + CLI 플래그)
② 대안이 2개 이상 갈린다.

## 1. 정하려는 것 하나

크롤을 **시간으로** 끊는 수단이 없다. 착수 전 실측은 계획서 1절에 있다 —
`Crawl-delay: 2` · 5페이지에 8.05초, 시간 인자 0개, SIGINT 대기 5.56초.

## 2. 대안 셋 — 출발점을 갈라 냈다 (`design.md` 3-1절)

### ① 최소 — 코드 0줄. `timeout(1)` 로 감싼다

```
timeout 3600 python3 -m websearch.crawl http://a.test/ --max 100000
```

**실측했다** (같은 탐침, SIGINT 를 SIGTERM 으로만 바꿔서):

```
SIGTERM 0.51s 에 보냄 → 종료 0.51s (대기 0.00s) · rc=-15
```

**상한의 정확도는 이쪽이 이긴다.** SIGTERM 은 기본 동작이 즉시 종료라
재시도 잠을 자든 말든 0.00초에 죽는다. 유실도 없다(`store.upsert` 마다 커밋).

**그런데 버렸다. 세 가지가 걸린다.**

1. **함수에는 상한이 안 걸린다.** `timeout` 이 묶는 것은 프로세스다.
   `crawl()` 을 직접 부르는 곳이 이미 여럿이다 — e2e 14종 전부와 `tests/test_crawl.py`.
   digest `[4]` 가 요구한 것은 "총 크롤 시간 예산" 이고 그건 크롤 루프의 성질이지
   껍데기의 성질이 아니다.
2. **stock macOS 에 `timeout` 이 없다.** 이 기계에서도 `/opt/homebrew/bin/timeout`
   (`command -v` 실측) — coreutils 를 깐 자리에만 있다. stdlib 만 쓰는 저장소가
   핵심 운영 보장 하나를 외부 바이너리에 맡기는 셈이다.
3. **깨끗하게 못 끝난다.** `수집 N 페이지` 도 rc 0 도 안 나온다(rc 124).
   "예산대로 끝났다" 와 "죽었다" 가 구별되지 않는다.

**남긴다.** 지금 당장 하드한 상한이 필요한 사람에게는 이것이 맞는 답이다 —
`docs/project.md` 에 적지 않고 이 문서에만 둔다(플랫폼 조건이 붙어서).

### ② 정공법 — 워커까지 보는 중단 신호 (`threading.Event`)

`crawl()` 이 `stop = threading.Event()` 를 들고 `_fetch_one` 까지 넘긴다.
`before_send` 의 `time.sleep(remaining)` 이 `stop.wait(remaining)` 이 되고,
예산 소진과 `KeyboardInterrupt` 가 **같은 한 기계**로 흘러 들어간다.
예산 초과분이 ≈0 이 되고 **SIGINT 5.56초도 함께 닫힌다.**

**그런데 버렸다 — 이번엔.** 이유가 취향이 아니라 실측이다:

`tests/test_crawl.py` 가 **9곳**에서 `mock.patch("websearch.crawl.time.sleep")` 을
걸고 `ms.side_effect = lambda s: clock.__setitem__("t", clock["t"] + s)` 로
**가짜 시계를 흘려보낸다.** 이 저장소가 간격을 초 단위로 단언할 수 있는 이유가
전부 그 이음매다(`TestCooldownBurn` · `TestRetriesKeepTheInterval` ·
`TestDelaySurvivesWorkerException` …). `Event.wait` 로 바꾸면 그 시계가 멈춘다.

- **깨진 테스트를 지우는 답은 없다** — 018 이 017 e2e 를 깼을 때 축을 userinfo 로
  옮겨 회귀 탐지기로 살렸다. 여기서 옮길 축을 찾으려면 9곳의 시계 주입을
  다시 설계해야 하고, 그건 이 계획의 크기가 아니라 **자기 계획**의 크기다.
- **두 경로로 도망가지 않는다.** "`stop` 이 None 이면 `time.sleep`, 아니면 `Event.wait`"
  는 테스트를 초록으로 만들지만 **테스트가 도는 경로와 제품이 도는 경로가 갈린다** —
  digest `[6]`(`**kw` 로 인자를 삼키는 가짜는 있을 수 없는 협력자를 흉내낸다)이
  정확히 그 실패다. 검토했고 명시적으로 거부한다.

### ③ 되돌리기 우선 — 메인 스레드만 예산을 본다 ← **고른 것**

`crawl(..., deadline=None)`. 이미 주입돼 있는 `now()` 로 남은 예산을 재고,
**메인 스레드가 새 요청을 안 던지는 것**으로 크롤을 끝낸다. 워커는 그대로다.

## 3. 비교 (`design.md` 3절 기준 순서)

| | ① `timeout` | ② `Event` | **③ 메인 예산** |
|---|---|---|---|
| **되돌릴 수 있나** | 안 쓰면 그만 | 9곳 시계 재설계가 딸려 온다 | **커밋 하나 revert. 기본 `None` 이라 안 주면 새 경로가 아예 안 돈다**(3절 ② 덧붙이기만) |
| **더 적게 쓰나** | 0줄 | 워커 계약 + 테스트 9곳 | **~10줄, 새 개념 0개** |
| **기존 것과 맞나** | 외부 바이너리 | `time.sleep` 이음매를 부순다 | **`now` 주입·`_number_flag`·`--max`/`--workers` 오류 관용구를 그대로 쓴다** |
| **다음이 편한가** | 함수에는 못 건다 | ②가 나중에 필요해지면 ③ 위에 얹힌다 | **얹을 자리를 안 막는다** |
| 상한 정확도 | **0.00초** | ≈0 | 예산 + 최악 90초 (아래 5절) |
| SIGINT 5.56초 | 해당 없음 | **닫는다** | **못 닫는다 — 안 닫는다고 적는다** |

**컨셉 우선순위와 충돌하지 않는다.** `concept.md` 갈림길 1순위는 크롤 윤리이고
세 안 모두 간격을 안 건드린다. 셋 중 고르는 기준이 윤리가 아니라 되돌리기라
`design.md` 3절 기준 순서를 그대로 따랐다.

## 4. ③ 의 형태 — 무엇을 어디에 놓나

```python
def crawl(seeds, max_pages, db_path="data/crawl.db", robots_cache=None,
          now=time.monotonic, workers=WORKERS, deadline=None):
```

- **`deadline` 은 상대 초다** (절대 시각이 아니다). `now` 가 주입 가능한
  `time.monotonic` 이라 절대 시각은 테스트에서 뜻이 없고, CLI 도 초가 자연스럽다.
- 진입에서 `started = now()`. **소진 = `now() - started >= deadline`.**
- 보는 자리는 **셋뿐**이다:

| 자리 | 하는 일 | 안 하면 |
|---|---|---|
| `while saved < max_pages` 상단 | 소진이면 `break` | 안 끝난다 |
| 제출 루프 안 | 소진이면 새 URL 을 안 던진다 | 예산이 지난 뒤에도 요청이 나간다 |
| `time.sleep(frontier.seconds_until_ready())` | 남은 예산으로 **자른다** | 예산이 지난 뒤 최대 30초 더 잔다 |

- **`concurrent.futures.wait` 의 timeout 은 안 건드린다.** 그건 결과를 기다리는
  자리라 일찍 깨어나도 `with pool` 나가면서 똑같이 기다린다 — 줄 수만 는다.
- **간격을 깎지 않는다.** 예산을 지키려고 `DOMAIN_INTERVAL`·`Crawl-delay` 를
  줄이는 코드는 **RED** 다(`project.md ## 한도` · `concept.md` 갈림길 1순위).
  예산이 하는 일은 "덜 보낸다" 뿐이고 "빨리 보낸다" 는 아니다.

**CLI.** `_number_flag(args, "--deadline", None)` — 있는 헬퍼를 그대로 쓴다(정수 초).
`None` 이거나 1 미만이면 `--workers` 와 같은 문구로 **rc 2**.

**끊겼을 때.** 정상 반환·**rc 0** 이고 stderr 에 한 줄 남긴다
(`예산 N초 소진 — M페이지에서 멈춘다`). 계획서 6절 열린 질문 1 의 값싼 절반이다 —
종료 코드를 나누는 것은 사람 몫이지만 **"다 돌았다" 와 구별되게** 만드는 것은 공짜다.

## 5. 이 설계가 **안** 닫는 것 — 그대로 적는다

1. **SIGINT 최악 대기 5.56초(상한 30 이면 60초)는 열려 있다.** ③ 은 예산으로
   *시작*을 막을 뿐 이미 자고 있는 워커를 깨우지 않는다. `digest.md` 의
   `[4] Ctrl-C 가 최대 30초 안 먹는다` 는 **지우지 않는다** — 대신 이번에 실측한
   숫자(0.51→6.07초)와 "②를 왜 미뤘나"(테스트 9곳 이음매)를 함께 적어 갱신한다.
2. **예산 초과분은 최악 90초다** — 소진 시점에 떠 있던 요청이
   `fetcher` 타임아웃 10초 × 재시도 + 재시도 사이 간격(최대 `MAX_DELAY` 30초 × 2)
   만큼 남는다. 예산이 시간 단위일 때 90초는 0.4% 라 받아들인다.
   *제출 시점에 남은 예산이 `interval × RETRIES` 보다 작으면 `retries=0`* 이
   이것을 한 번의 타임아웃으로 줄이지만, **근거가 산수뿐이라 안 넣는다** —
   실물에서 초과분이 문제로 잰 날 연다(추측성 확장 감점, `design.md` 3절 4번 기준).
3. **`fetcher` 재시도 구조** — digest `[high]` 가 "옳지만 크다" 로 남긴 별도 후보.

## 6. 되돌리기

커밋 하나 `revert`. 그 전에도 **`--deadline` 을 안 주면 새 경로가 안 돈다** —
`deadline is None` 이면 세 자리 전부 오늘과 같은 분기로 흐른다. 피처 플래그를
따로 안 두는 이유가 이것이다(기본값이 곧 꺼진 플래그다).

**되돌아갔는지 확인하는 법**: 기존 e2e 14종 rc=0 + 단위 388건 OK.
`--deadline` 없이 도는 세계가 오늘과 한 글자도 다르면 안 된다.

## 7. 개발이 먼저 쓸 실패하는 테스트 (`dev.md` 0절)

1. 예산이 짧으면 `max_pages` 를 못 채우고 끝난다 — 가짜 시계로 초 단위 단언
2. `deadline=None` 이면 오늘 그대로 `max_pages` 를 채운다 (**대조군**)
3. **간격 대조군** — 예산으로 끊긴 크롤에서도 같은 도메인 요청 간격이
   `Crawl-delay` 이상이다. 예산이 예의를 깎으면 여기가 먼저 죽는다
4. `--deadline` 이 값 없음·비숫자·0 에 **rc 2** (`--workers` 와 같은 관용구)
5. 소진으로 끊기면 stderr 에 그 사실이 남는다 — 조용히 적게 수집한 것과 구별된다

**변이는 "이 줄을 안 썼다면 무엇이 되는가" 로 고른다** (digest `[7]`).
`deadline` 은 **기본값이 있는 인자**라 특히 위험하다 — 인자를 지운 변이가
2번(대조군) 때문에 통과하면 그 변이는 아무것도 고정하지 못한 것이다.
