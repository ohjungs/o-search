## 1. 문제 · 목표 · 기대 결과

### 무엇이 이미 참인가 (이 저장소를 처음 여는 사람을 위한 전제)

- `src/websearch/indexer.py` 에 DB 를 여는 자리가 **셋**이고 셋 다 같은 모양이다:
  `os.path.exists(db_path)` 로 먼저 보고, 그 다음 줄에서 `sqlite3.connect(db_path, timeout=30)`.
  `index_pages()`(76~78행) · `_doc_count()`(134~136행) · `search()`(176~181행).
- `sqlite3.connect(path)` 는 **파일이 없으면 만든다.** 그래서 두 줄 사이에 파일이 사라지면
  존재 검사는 통과했는데 여는 것은 **새 빈 DB** 다.
- `search()` 는 `os.path.exists` 뒤·`connect` 앞에서 `match = _fts_query(query)` 를 만들고
  `if not match: return []` 로 **DB 를 열지 않고** 빠져나간다(178~180행).
  `_fts_query` 는 제어문자를 지우므로(154~156행) 제어문자만으로 된 질의는 빈 문자열이 된다.
- `serve.py` 의 두 경로(JSON `/search` · 화면 `/`)는 `_page_hits` 한 벌을 나눠 쓰고,
  `(FileNotFoundError, StaleIndexError)` 를 **503**, 나머지 `Exception` 을 **500** 으로
  번역한다(263~268 · 292~297행). 즉 **`indexer.search` 가 무엇을 던지느냐가 곧 HTTP 계약**이다.
- 단위 스위트는 오늘 **495건 OK** · `e2e/*.py` **19종 rc 0** · p95 **8.71ms**.

### 착수 탐침 — 두 갈래를 실제로 다시 쟀다 (2026-09-02, 임시 디렉터리)

`digest.md` 의 `[7] 기록된 답을 실행 전에 다시 재라` 가 요구하는 것이다.
`digest.md ## 판단 필요` 의 `[4]` 항목이 적어 둔 것은 **전부 참이었고, 한 줄이 모자랐다.**

| 상황 | 질의 | `indexer.search` | 서버 응답 |
|---|---|---|---|
| 정상 색인 | `q=김치` | 1건 | 200 |
| 정상 색인 | `q=%01` · `q=(빈)` | `[]` | 200 |
| **손상 DB** | `q=김치` | `DatabaseError: file is not a database` | **500** (계약대로) |
| **손상 DB** | `q=%01` | **`[]`** | **200** — 계약에 없는 갈래 |
| 없는 DB | `q=김치` · `q=%01` | `FileNotFoundError` | 503 (어느 질의든 샌다) |

**문제 A — TOCTOU.** `exists` 와 `connect` 사이에서 파일을 지우는 훅을 걸어 창을 실제로
벌렸다. `search()` 는 예외 대신 **`[]`(→200)** 을 냈고, 그것만이 아니다:

> **크기 0 의 빈 DB 파일이 그 자리에 새로 생겼다.**

**이것이 digest 에 없던 줄이고, 이 계획의 값을 바꾼다.** digest 는 이 건을 *"실물 창은
마이크로초 · 값은 낮다"* 로 적었는데, **한 번 지나가면 흔적이 영구적**이다 — 빈 파일이
남으므로 그 뒤로는 `os.path.exists` 가 계속 참이고, 503(`FileNotFoundError`)은 **다시는
안 난다.** 마이크로초짜리 창이 한 번 열리면 계약이 영구히 200 으로 고정된다.
`index_pages()` 도 같은 파일을 보고 `NoCrawlDataError` 로 갈아탄다.

**문제 A' — 같은 뿌리가 `_doc_count()` 의 독스트링을 거짓으로 만든다.** 그 함수는
*"DB 가 없거나 색인 전이면 0 **(DB 파일을 만들지 않는다)**"* 라고 자기 계약을 적어 뒀는데,
같은 창에서 재니 **0 을 돌려주면서 빈 DB 파일을 만들었다.** 세 자리가 한 뿌리라
한 곳에서 고친다 (ponytail — *"한 가드를 공유 함수에 넣는 것이 호출부마다 넣는 것보다
작은 diff 다"*).

**문제 B — DB 고장 판정이 질의 내용에 달려 있다.** 손상 DB 에 `q=%01` 을 보내면 200 이다.
`if not match: return []` 가 `connect` **앞**이라 DB 를 아예 안 본다.
`tests/test_serve.py:530` 의 `test_corrupt_db_is_500_not_503` 이 *"손상은 기다린다고 낫지
않는다"* 며 500 을 못박아 뒀는데, **그 단언이 `q=김치` 한 갈래에만 걸려 있다.**
옛 색인(`StaleIndexError` → 503)도 같은 방식으로 빠져나간다.

### 목표

`indexer` 가 DB 상태를 보는 것이 **① 열기와 원자적이고 ② 질의 내용과 무관하게** 되는 것.
바깥으로 드러나는 계약(`serve` 의 400·404·500·503·200)은 **한 칸도 안 바뀐다** —
계획 46 이 정한 표가 지금은 특정 조건에서 거짓인데, 그 표를 참으로 만드는 일이다.

### 기대 결과

| 상황 | 오늘 | 이 계획 뒤 |
|---|---|---|
| `exists` 뒤 파일 소멸 | `[]` → 200 · **빈 DB 파일 생성** | `FileNotFoundError` → **503** · 파일 생성 **0** |
| `_doc_count` 가 같은 창을 만남 | 0 · **빈 DB 파일 생성** | 0 · 파일 생성 **0** (독스트링대로) |
| 손상 DB + `q=%01` | `[]` → 200 | `DatabaseError` → **500** |
| 옛 색인 + `q=%01` | `[]` → 200 | `StaleIndexError` → **503** |
| 정상 색인 + `q=%01` | `[]` → 200 | **`[]` → 200 (무변경)** |
| 그 밖 전부 | — | **무변경** |

## 6. 설계가 필요하다 — 트리거 둘

`design.md` 1절: **「대안이 2개 이상 갈림」**과 **「공개 인터페이스 변경」**(함수 시그니처는
그대로지만 `search()` 가 **던지는 예외의 조건**이 바뀌고 그것이 곧 HTTP 계약이다).

설계가 고를 것 — 착수 탐침이 각 대안의 함정까지 이미 쟀다:

- **대안 A — `sqlite3.connect("file:…?mode=rw", uri=True)`.** 없는 파일이면 열기 자체가
  실패하므로 원자적이고 파일을 안 만든다. 실측: `OperationalError: unable to open database file`,
  파일 생성 0. **함정 둘을 실측했다.** ① 경로를 날것으로 끼우면 **조용히 다른 파일을
  연다** — `a b#c?d.db` 를 그대로 넣으니 `#` 뒤가 프래그먼트로 잘려 **`a b` 라는 새 파일이
  생겼고 `mode=rw` 는 통째로 무시됐다**(`urllib.request.pathname2url` 로 감싸면 옳게 열린다).
  ② `OperationalError` 를 전부 `FileNotFoundError` 로 번역하면 **권한 오류(EACCES)까지
  503** 이 된다 — 지금은 500 이다. 번역을 어디까지 좁힐지가 설계의 몫이다.
- **대안 B — 열고 나서 «내가 만든 파일인가» 를 사후 판정.** `connect` 뒤에
  `getsize == 0` 이면 우리가 만든 것이라고 보고 `FileNotFoundError`. URI 인용 함정이
  없지만 **빈 파일은 이미 만들어진 뒤**라 문제 A 의 영구성을 못 막는다(치우려면 삭제가
  필요한데 5절이 금지한다).
- **대안 C — `os.open(db_path, os.O_RDONLY)` 로 fd 를 먼저 잡는다.** 존재 판정은 원자적이나
  `connect` 는 여전히 **경로로** 다시 열어 창이 남는다. 반쪽이다.

**`digest.md` 의 `[8] 깨우고 접는다 — 한 줄씩은 0초를 회수한다`** 가 이 계획의 짝 검사다:
문제 A(원자화)와 문제 B(판정 순서) 중 **하나만 고치면 회수가 0 인 갈래가 있나** 를
설계에서 센다. 예비 판단으로는 독립이다(A 는 없는 DB, B 는 있는 DB 의 고장) — 설계가 확인한다.

## 8. 접은 후보 — `Makefile` 은 이 실패를 안 막는다

*"러너의 판정 줄을 가린다"* 는 **15회 재발**이고 직전 반복에서 **두 번 더** 났다(⑭ 파이프 ·
⑮ `2>/dev/null`). `digest` 의 처방 후보는 *"러너 호출을 한 줄로 굳혀 두고(별칭·`make test`)
손으로 조립하지 않기"* 다. 저장소 안에 `Makefile` 을 만드는 것은 루프가 할 수 있는 일이지만,
**만들어도 이 실패는 안 막힌다** — 15건의 방아쇠를 보면 알 수 있다:

- ⑭ 는 **`wc -l` 명령에 러너를 `&&` 로 이어 붙이면서** 그 명령의 `tail` 이 러너까지 덮은 것이다.
  `make test` 라도 `wc -l docs/*.md && make test 2>&1 | tail -4` 는 **똑같이 조립된다.**
- ⑮ 는 파이프가 아니라 `2>/dev/null` 이다. `make test 2>/dev/null` 도 `Ran/OK` 를 똑같이 삼킨다.
- ⑥⑨⑪⑫ 의 최다 방아쇠는 **재확인 실행**이다 — 짧은 명령을 원한 것이 아니라 **짧은 출력**을
  원한 것이라, 명령이 짧아지는 것으로는 안 줄어든다.

**즉 `Makefile` 은 «명령을 조립하는 수고» 를 줄이지 «출력을 자르려는 손» 을 안 막는다.**
막는 것은 *"러너 호출에 출력 조작을 아무것도 붙이지 않는다 — 재지향 포함"* 이라는 문장이고,
그 문장이 살 곳은 `~/.claude/skills/loop-harness/rules/` 와 `docs/project.md` 다.
**후자는 이미 있다**(`project.md ## 명령` 첫 문단이 정확히 그것을 적어 뒀고, 그러고도 났다).
전자는 **저장소 밖이라 루프가 못 고친다 — 사람이 연다**(`status.md ## 사람이 정할 것` 3번과
같은 종류다). 근거 없는 도구를 하나 만드는 것은 ponytail 1번 위반이라 **접는다.**

**접으면서 남기는 것**: 다음에 이 항목이 또 오르면 물을 것은 *"도구가 없어서인가"* 가 아니라
*"짧은 출력을 원한 순간이 언제였나"* 다. 15건 전부 그 순간에 났다.
