## 형식

```
## YYYY-MM-DD HH:MM | <plan-slug> | <phase> <step> | 시도N
- 한 일: <무엇을 했나. 파일 경로 포함>
- 결과: <검증 결과. 테스트 12/12 통과 / 린트 0건 / 실패 출력 요약>

```

실패한 반복도 반드시 남긴다. 실패 기록이 없으면 같은 실수를 반복한다.

**회전 명부는 `digest.md` 의 `## 완료` 절 «아카이브 명부» 줄이 정본이다.**
여기 있던 스물한 회전의 서술(233줄)은 그 줄과 내용이 겹쳤고, 검사가 강제하는 명부도
그쪽 하나뿐이라(`tests/test_docs.py` 의 `ArchiveIndexTest`) **개발 9(반복 269)가 이
자리에서 지웠다** — 회전으로는 300줄 상한을 못 맞추던 세 반복(309 → 372 → 418줄)의
원인이 이 명부였다. **지운 것은 머리말이지 반복 기록이 아니다** — 항목은 여전히
append 전용이고 수정·삭제 금지다. 각 회전의 사유는 `digest.md` 의 같은 줄에, 원문은
`history_<NNN>.md` 에 그대로 있다.

  그 못이 막으라고 세워진 조용한 초록 자체다. B 는 후보 절이 append-only 라는 전제
  위에 있었고 그 전제가 오늘 틀렸다. **C(역방향 — `index.md` 완료 슬러그가 후보 절에

  모듈 이름과 계획 슬러그가 같은 글자다.
- **시뮬레이션이 사이 반복의 빨간 저장소를 미리 보여줬다**: 취소선 18줄을 지운 사본에서

### 반복 416 — 계획 72 설계 (GREEN · `design_digest-rotate-guard.md`)

- **갈림길은 하나였다** — 회전은 안 갈린다(지울 줄이 실측으로 확정). 갈리는 것은
  하한 못의 **모집단과 값**이다.
- **탐침 둘이 갈랐다**(커밋 안 함 · 원복함). ① 코드 상수 `CANDIDATE_HEAD` 변이 →
  **4건 RED**(합성 `StrikeGapTest` 셋 + 실물 하나) ② **실물 문서**의 첫 후보 절 머리만
  드리프트 → **1건 RED**, `test_pointer_extractor_still_bites` **하나뿐**.
  **②가 D3(못을 지운다)을 반증한다** — 합성 넷은 문서 드리프트에 전부 조용했다.
  상수와 실물 문서를 잇는 자가 이 못 하나다. 「축을 옮겨야지 지우면 안 된다」의 자리.
- **결정 D5 — 못을 후보 절 «머리 개수» 위에 세우고 하한 2.** 가정 탐침도 참이다:
  머리 수가 현재 2 · **회전 후에도 2**(거짓 RED 없음) · 머리 하나만 드리프트하면 **1**(RED).
- **버린 이유**: A 오탐 21 · B 회전 뒤 실측치 0 · C 오탐 4 · **D1(목록 줄, 값 58)은
  오늘 사고의 반복**(목록 줄은 회전이 지우는 쪽이다 76→58) · **D2(값 1)는 머리 하나
  드리프트를 못 문다**(탐침 2 상태에서 목록 줄은 여전히 1 이상이라 조용) · D3 위 참조.
- **천장을 적고 나간다**: 이 못은 「후보 절이 살아 있다」를 재지 「그 안의 줄이 규약대로
  적혔나」는 안 잰다. 문구 드리프트는 문구가 아니라 **규약**을 바꿔야 닫힌다 — 범위 밖.
- **다음**: 개발 1/2 — `candidate_lines` 분리 + `CANDIDATE_HEAD_FLOOR = 2`. TDD 로 RED 먼저.
