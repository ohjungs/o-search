## 판정 — 새 e2e 를 왜 0개로 두는가

계획 7절의 논거는 *"산출물이 검사이고 제품 diff 가 0줄이라, 사용자가 보는 동작
(크롤·색인·검색·CLI 종료 코드·화면)이 한 바이트도 안 바뀐다"* 였다. 위 실측이 그 전제를
그대로 확인한다 — `src/` 빈 diff.

`rules/e2e.md` 3절이 e2e 를 요구하는 이유는 **단위가 구조적으로 못 보는 자리**(프로세스
배선·진짜 시계·진짜 신호·실제 응답 바이트)를 재기 위해서다. `DocCitationTest` 와
`CitationPatternTest` 에는 그런 자리가 없다:

| e2e 가 사는 이유 | 계획 42 에 있나 |
|---|---|
| 프로세스 경계(rc·stderr·CLI 배선) | **없다** — 검사는 러너 안에서만 산다. 진입점이 `unittest` 하나다 |
| 진짜 시계·신호·네트워크 | **없다** — `Path.read_text` 와 `re.search` 뿐이다 |
| 실제 응답 바이트(화면·API) | **없다** — 출력이 없다 |
| 여러 모듈의 배선 | **없다** — `src/` 를 임포트조차 안 한다 |

e2e 로 옮기면 같은 계약을 두 번 재고 19종이 20종이 될 뿐이다(ponytail 1번).
**e2e 를 늘리는 것 자체는 목표가 아니다** — 계획 41 이 같은 판정을 내린 선례를 따른다.

## 반증 신호 둘을 실측했다 — 둘 다 발동 안 함

계획 7절이 "이것이 나오면 판정을 뒤집는다" 로 적어 둔 둘을 이 스텝에서 직접 쟀다.

### ① 검사가 `docs/` 를 도는 방식이 루프 운영 계약이 되는가 — **아니다**

우려는 *"활성 계획서가 없거나 예상 못 한 이름의 `.md` 가 생겼을 때 검사가 죽는다면
그것은 단위가 아니라 루프 운영 계약"* 이었다. 코드를 읽어 판정한다:

- 순회는 `DOCS.glob("*.md")` 라 **파일이 없으면 그냥 안 돈다.** 활성 계획서가 0개여도
  예외가 없다. `assertIn` 이 존재를 요구하는 것은 `APPEND_TARGETS` 세 이름뿐이고,
  그 셋은 append 전용이라 사라지지 않는다(사라지면 그때는 진짜 사고다).
- 예상 못 한 이름의 `.md` 는 **그냥 훑는 대상이 하나 늘 뿐**이다. 이름꼴을 요구하는
  곳은 아카이브 **제외** 쪽 하나이고, 안 맞으면 제외가 안 될 뿐 죽지 않는다.

→ 파일이 있으면 읽고 없으면 안 읽는 것이 전부다. 운영 계약이 아니다. 판정 유지.

### ② 회전이 만드는 새 아카이브 이름이 제외 규칙과 맞는가 — **맞다 (실물로 쟀다)**

우려는 *"아카이브 제외가 이름꼴에 걸려 있으니, 회전이 만드는 파일 이름이
`history_018.md` 형태가 아니면 검사가 아카이브를 잡는다. 변이 M2 가 이 자리를 재지만
실제 회전은 DONE 이후에나 일어난다"* 였다.

**그 회전이 이 반복에서 실제로 일어났다.** `history_current.md` 가 300줄 상한을 64줄
넘긴 상태(364줄)라, 계획 41 전체 다섯 반복(204~208)을 `docs/history_018.md` 로 밀고
221줄로 줄였다. 즉 반증 신호 ②가 예고한 상황이 **가정이 아니라 실물로 생겼다.**

- 회전 **직후** 맨몸 재실행: **469건 OK 11.760초.** `DocCitationTest` 초록.
- 새 파일 `history_018.md` 는 제외 정규식 `^(?:history|plan_history|design_history)_[0-9]+\.md$`
  에 걸려 훑는 대상에서 빠졌다. 밀려난 본문에 줄번호 인용이 있어도 검사는 안 본다 —
  **수정·삭제 금지 문서를 검사가 붙들지 않는다**는 설계가 실물에서 성립했다.

→ 반증 신호 없음. 판정 유지. 변이 M2 가 가상으로 재던 자리를 **실제 회전이 한 번
확인해 줬다** — 이 계획이 DONE 되는 반복에 마침 그 사건이 붙은 것은 운이 좋았다.
