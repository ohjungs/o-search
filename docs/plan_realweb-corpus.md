# 계획: realweb-corpus — 실물 웹 코퍼스를 만든다

**출처: 사용자 지시** (`discover.md` 0절). 2026-09-07 「실물 크롤 진행해」.
탐색하지 않는다 — 무엇을 할지는 이미 정해졌다.

## 1. 왜

`digest.md` 의 높은 점수 후보 **셋이 전부 같은 문 하나**를 여는 조건으로 지목한다.

| 후보 | 여는 조건으로 적힌 것 |
|---|---|
| `[9]` `/passages` 총 p95 의 대부분은 `/search` 몫이다 | 「실물 분포가 먼저다」 |
| `[8]` 숨은 텍스트·`<nav>` 인라인 연접이 근거 문단을 이긴다 (뒷부분) | 「갈림길 6 을 닫는 실물 코퍼스」 |
| `[6]` `extract_blocks` 의 이름표를 읽는 소비자가 0곳 | 「실물 코퍼스로 갈림길 6 을 닫는 계획」 |

오늘 저장소에 실물은 **없다** — `e2e/quality/corpus.json` 64건은 전부 `q.test` 합성이고
`data/crawl.db` 는 localhost 테스트 잔재 2건(12KB)이었다. 문을 여는 유일한 열쇠가
**실제 웹 크롤**이고, 그것은 바깥을 향하는 행동이라 사람의 허가가 필요했다. 받았다.

## 2. 무엇을 만드나

`data/crawl.db` 에 **실물 HTML 코퍼스**. `.gitignore` 대상이라 저장소에 들어가지 않는다 —
남는 것은 코퍼스가 아니라 **코퍼스의 프로필과 그것으로 잰 숫자**다.

## 3. 시드 — 고른 근거

**기준 셋**: ① robots 가 우리를 허용한다 ② 라이선스가 열려 있다 ③ **구조가 풍부하다**
(내비·보일러플레이트·숨은 텍스트가 실제로 있어야 갈림길 6 을 잰다 — 그게 목적이다).

| 시드 | 라이선스 | 우리 robots 판정 (2026-09-07 실측) | 왜 이것인가 |
|---|---|---|---|
| `docs.python.org/3/` | PSF | 허용 · 적용 간격 없음 | 사이드바 내비가 크고 본문이 길다 |
| `developer.mozilla.org/en-US/docs/Web/` | CC BY-SA | 허용 · 적용 간격 없음 | 인라인 링크 밀도가 높다 (`[8]` 뒷부분의 축) |
| `en.wikipedia.org/wiki/` | CC BY-SA | 허용 · 적용 간격 없음 | 내비·각주·숨은 텍스트가 한 페이지에 다 있다 |
| `ko.wikipedia.org/wiki/` | CC BY-SA | 허용 · 적용 간격 없음 | **한국어** — `quality_eval` 의 ko 축이 합성만 보고 있었다 |

**위키백과의 `Crawl-delay: 5` 는 우리 것이 아니다** — semrushbot 그룹에 달린 줄이고
우리 `_applicable_delay` 가 옳게 배제했다(`delay()` → `None`). 그래서 바닥은
`frontier.DOMAIN_INTERVAL` 1.0초다. **그래도 그 파일이 「너무 빠른 크롤러는 차단한다」고
적어 뒀으므로 규모로 갚는다** — 아래 4절.

## 4. 규모 — 작게 잡은 것이 결정이다

`--max 400` · 4 도메인 라운드로빈 → **도메인당 약 100장, 초당 1건**.
concept 의 1단계 목표는 10만 문서지만 **이 계획이 답할 질문은 규모가 아니라 구조**다
(갈림길 6 은 「어떤 블록이 근거로 뽑히나」이지 「몇 건까지 되나」가 아니다).
합성 64건 대비 6배이고, 성능 축(`[9]`)의 실물 분포를 재기에도 충분하다.
**모자라면 다음 계획이 늘린다 — 지나치게 받아 온 것은 되돌릴 수 없다.**

## 5. 스텝

| # | 산출물 | 완료 기준 |
|---|---|---|
| 1 | 시드 robots 실측 근거 | 4 시드 전부 `allowed=True` · 적용 간격 기록 ✅ 완료 |
| 1-a | **`--same-site` 범위 손잡이** | 새 테스트 5건 · 기본 동작 무변 ✅ 완료 |
| 2 | `data/crawl.db` 실물 코퍼스 | `--max 400` 완주 · rc 0 · 수집 건수 기록 |
| 3 | 색인 + 코퍼스 프로필 | 도메인·언어·길이 분포를 잰 문서 |
| 4 | 세 후보의 여는 조건 판정 | 각 후보가 **실제로 열렸는지** 한 줄씩 |

## 5-a. 스텝 1-a 는 계획을 세운 뒤에 생겼다 — 왜 늘었나

착수 전에 6절에 「`src/` 를 건드리지 않는다. 크롤러는 이미 있다」고 적었다. **틀렸다.**
`links.extract` 는 모든 `http(s)` 링크를 뽑고 `frontier.add` 가 그대로 받는다 —
**범위 개념이 없다.** 위키백과 한 장의 외부 링크가 수백 개라 `--max 400` 은 4 사이트가
아니라 임의의 웹 200여 도메인을 받아 온다. 3·4절(라이선스·구조·규모)의 근거가 통째로
무너지고, 내가 확인하지 않은 사이트로 요청이 나간다.

**기본값은 안 바꿨다.** concept 의 「열린 웹 검색엔진」은 밖으로 나가는 것이 곧 제품이라,
가두는 것을 기본으로 만들면 제품을 바꾸는 것이다(`severity.md` 「사용자 눈에 보이는 동작
변경」). 그래서 **옵트인 `--same-site`** 다. 거르는 자리는 `Frontier.add` **하나** —
시드와 발견된 링크가 둘 다 거기로 모인다.

계약을 양쪽으로 못박았다: 켜면 안 나간다(2건) · **끄면 오늘과 같다**(2건, 기존
`test_crawls_seed_and_follows_links` 포함) · CLI 가 플래그를 시드로 안 읽는다(2건).

## 6. 하지 않을 것

- **후보 `[9]`·`[8]`·`[6]` 을 이 계획에서 고치지 않는다.** 여는 것과 푸는 것은 다른 계획이다.
- **`src/` 는 범위 손잡이 하나로 끝낸다** (5-a절). 크롤러 본체는 이미 있다.
- 코퍼스를 커밋하지 않는다 (`data/` 는 `.gitignore`).
- 규모를 400 이상으로 올리지 않는다. 올릴 근거는 3~4 스텝의 측정에서 나온다.
