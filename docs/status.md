## e2e phase 가 할 일

`plan_recrawl.md` 6절의 시나리오 넷이다. **1·2 가 급하다** — 단위 706건이 전부 초록인
채로 F1·F2 가 살아 있던 직접 원인이 「두 실행을 실제로 잇는 자가 없다」는 것이다.
`e2e/noindex_e2e.py` 는 재크롤을 `Store.upsert` 직접 호출로 흉내 내 **`is_fresh` 게이트를
한 번도 안 지난다**.

1. 크롤 → 본문 갈고 `fetched_at` 31일 전 → 재크롤. **서버 수신 기록으로** 요청을 세고,
   재색인 뒤 새 본문이 검색되고 옛 본문은 안 나오는 것까지 본다.
2. 29일 된 문서는 **서버에 요청 0건** (TTL 이 자를 갖는다는 음성 대조).
3. 404 로 바뀐 URL 은 검색에서 빠지고 `pages` 묘비는 `status=404` 로 남는다.
4. 재크롤이 새 링크를 주울 때 도메인 간격 1초를 **서버 수신 시각으로** 잰다.

**`RETRY_DAYS` 를 e2e 로 재려면 시드에 실패를 심어야 한다** — 자식 URL 로는 안 닿는다
(`store.py` 의 `ponytail:` 천장 · 프런티어가 메모리다).
