# 계획 51 — `hidden-passage`

**화면에 안 보이는 텍스트가 «근거 문단» 으로 나간다.** `/passages` 는 문서마다
`pages.html` 을 다시 파싱해 «질의어를 가장 많이 담은 블록» 을 하나 고르는데, 그 후보
목록에 `<template>`·`aria-hidden`·`display:none`·`hidden`·0px 폰트로 **사람에게는 안
보이는 블록**이 그대로 들어 있다. 고르는 규칙이 밀도를 적극적으로 선호하므로, 키워드를
채운 숨은 블록은 본문 문단을 **확정적으로** 이긴다.

- **슬러그**: `hidden-passage`
- **브랜치**: `loop/hidden-passage`
- **기점**: `d5367fa` (`loop/merge-48-50` 의 HEAD · 계획 48·49·50 을 담은 커밋)
- **기점을 `main` 으로 안 잡은 이유**: 원격을 이 반복이 직접 다시 읽었다 —
  `git ls-remote origin main` 은 `687a1598…`(계획 47)이고 `gh pr view 7` 은
  `state: OPEN · mergedAt: null` 이다. 계획 48·49·50 은 **아직 원격 `main` 에 없다.**
  `README.md` 의 `단위 579건`·`e2e 시나리오 20종` 과 `tests/test_readme.py` 의 건수
  단언이 이 기점에 맞춰져 있어 `main` 에서 따면 첫 커밋부터 RED 다.

## 1. 문제 · 목표 · 기대 결과

### 문제

`indexer.passages()` 는 `search()` 가 고른 문서마다 `pages.html` 앞부분을 다시 파싱해
`extract.extract_blocks()` 가 낸 블록 중 **질의어와 그 2-gram 을 가장 많이 담은 것**을
하나 고른다. 그 블록 목록은 «HTML 에 텍스트가 있나» 만 보고 만들어지므로, 브라우저가
사람에게 **안 보여 주는** 텍스트도 후보다.

부르는 쪽은 남의 시스템(RAG)이고, 근거 문단의 계약은 «출처 URL · 문서 제목 · 문서 내
위치» 다. 사람이 그 URL 을 열어서 **찾을 수 없는 문단**은 그 계약이 뜻하는 것을 못
지킨다. 스니펫은 FTS5 가 매치 주변을 뜨는 것이라 숨은 텍스트의 노출이 우연이었는데,
문단 선택은 밀도를 **선호**하므로 우연이 아니라 규칙이 된다.

### 목표

**근거 후보에서 «화면에 안 보이는 블록» 을 뺀다.** 색인 본문(`docs.body`)은 한 글자도
안 바꾼다 — 재색인 0 · 스키마 변경 0 · `data/crawl.db` 무변경.

### 기대 결과

같은 탐침에서 `/passages` 가 내는 숨은 텍스트가 **0/5**(오늘 5/5)이고, 본문이 질의어를
담으면 본문 문단이 나온다. 숨은 블록만 질의어를 담은 문서는 **문단을 아예 안 낸다** —
첫 블록으로 대신하면 사양 기능 8(근거 정확도)이 첫 줄에서 무너진다.

### 무엇이 이미 참인가 (이 저장소를 처음 여는 사람을 위한 전제)

1. `/passages` 는 계획 48 `passage-api` 가 만들었다. 흐름은
   `serve.do_GET` → `indexer.passages(db_path, query, limit=PASSAGE_LIMIT)` →
   `indexer.search()` 로 문서 선정 → 문서마다 `SELECT html FROM pages` →
   `extract.extract_blocks(html[:MAX_PASSAGE_HTML])` → 점수 최고 블록 하나.
2. 블록을 만드는 것은 `src/websearch/extract.py` 의 `_BlockParser` 이고, 색인 본문을
   만드는 것은 같은 파일의 `extract_text()`(부모 `_TextParser`)다. **둘은 부모를
   공유하지만 다른 함수다.**
3. **이 파일에는 «블록 파서만 읽는 집합» 이라는 선례가 이미 있다** — `_NON_BLOCK_TAGS`
   (계획 48 리뷰 5). 그 집합은 `_TextParser._separate(block=...)` 의 인자로만 쓰여
   색인 경로를 한 글자도 안 바꾼다. 반대로 `_SKIP_TAGS`·`_INLINE_TAGS` 는 **색인
   경로가 직접 읽는다** — 건드리면 `docs.body` 가 바뀌고 그것은 재색인이다.
4. `extract_blocks()` 는 docstring 에 불변식
   (`" ".join(t for _tag, t in extract_blocks(h)) == extract_text(h)[1]`)과 **알려진
   예외 둘**(EOF 에 남은 안 닫힌 마크업 · 블록 전체가 제어문자)을 적어 뒀고,
   `tests/test_extract.py` 의 `TestExtractBlocks` 가 그것을 고정한다.
5. 오늘 이 기점에서 단위 **579건 OK**(13.400초, 맨몸·단독) · e2e **20종**.
6. 승인 게이트에서 **닫혀 있는 것**: 스키마 변경 · 마이그레이션 · 의존성 추가 ·
   `data/crawl.db` 변경. 이 계획은 넷 다 안 건드린다(7절).

## 6. 설계가 필요하다 — 트리거 둘이 걸린다

**① 대안이 갈린다.** 어디서 거르나가 셋이고 **닫는 범위와 비용이 다르다**:

- **A. `_BlockParser` 전용 술어** — `_NON_BLOCK_TAGS` 선례를 따라 블록 경로만 읽는
  판정을 세운다. 색인 경로 무변. 새 코드가 붙는 자리는 `handle_starttag`/`handle_data`.
- **B. `_SKIP_TAGS` 확장** — 후보가 적어 둔 처방. 가장 짧지만 색인 본문이 바뀌어
  **재색인**이고 승인 게이트 밖이다. 재논의 조건까지 적어 두고 버릴 대안이다.
- **C. `passages()` 쪽에서 감점** — `extract.py` 를 안 건드린다. 그런데 블록 튜플이
  `(태그, 텍스트)` 뿐이라 숨김 여부를 알려면 **반환 모양을 바꿔야** 한다(계약 변경).

**② 어디까지 닫나** — 태그·속성(`template`·`hidden`·`aria-hidden`)은 `attrs` 로 바로
읽히지만, `display:none`·`font-size:0` 은 **인라인 스타일 문자열**이라 문자열 규칙이
필요하다. 「CSS 파서를 안 만든다」는 이 저장소가 검사기 쪽에서 이미 두 번 그은 선이고,
여기서도 어디가 천장인지를 설계가 정해 `ponytail:` 주석으로 남겨야 한다.

**③ 공개 인터페이스의 *뜻*이 바뀐다** — 스키마(`{url,title,position,text}`)는 그대로지만
같은 DB·같은 질의에 **다른 문단**이 나간다. 사양 기능 9(계약 안정성)가 「필드를 지우거나
**뜻을 바꾸는** 변경은 새 버전에서만」이라고 적었으므로, 이것이 `VERSION` 을 올릴 일인지
아닌지를 설계가 판정한다(판정 자체가 설계의 산출물이다 — 계획서가 정할 것이 아니다).

**나머지 트리거는 안 걸린다**: 새 모듈·파일 0 · 데이터 구조·저장 형태 변경 0 ·
건드릴 파일 2~3개 · 되돌리기는 `git revert` 한 번이다.

**짧은 경로가 아닌 이유**: 다섯 조건 중 셋이 거짓이다 — 파일 1~2개(경계) · 설계 트리거
걸림 · **신뢰 경계**(크롤한 남의 HTML 이 근거 자리를 고르는 축이라 보안과 무관하지
않다. XSS 는 아니다 — `/passages` 는 JSON 전용이고 `json.dumps`·`nosniff` 다).

## 7. 하지 않을 것 (범위 고정)

- **색인 경로를 안 바꾼다** — `_SKIP_TAGS`·`_INLINE_TAGS`·`_normalize`·`extract_text`
  무변경. 재색인·마이그레이션·`data/crawl.db` 변경은 승인 게이트 밖이다.
- **CSS 파서를 안 만든다** — 외부 스타일시트·클래스로 숨긴 것은 못 본다(HTML 한 장만
  본다). 문자열 규칙의 천장은 `ponytail:` 주석으로 적고 거기서 멈춘다.
- **고르는 규칙(계획 48 갈림길 6)을 안 건드린다** — 점수·동점 키·이름표 삭제는 닫는
  조건이 **실물 크롤 코퍼스**다. 이 계획은 «후보에서 뺀다» 이지 «후보 중 무엇을
  고른다» 가 아니다. 두 축을 섞으면 실물이 왔을 때 무엇이 무엇을 바꿨는지 못 가른다.
- **`<nav>` 인라인 연접 축을 안 연다** — 같은 후보의 뒷부분이지만 `_INLINE_TAGS` 가
  색인 경로 공유라 재색인이다.
- **화면(`/search`)·스니펫·랭킹을 안 건드린다.** 숨은 텍스트는 색인에 그대로 남고,
  그 문서는 검색 결과에는 계속 나온다.
- **다른 축의 후보를 안 연다** — 속도 제한(사양 `## 사람이 정할 것` 1번) ·
  `/search` 의 p95 · `pages` 테이블이 없을 때의 500/503 · 검사기 후보 넷.
- **PR 을 안 연다.** PR #7 이 아직 OPEN 이라 원격 `main` 은 계획 47 이다. 병합은
  사용자가 처리한다.

## 8. 위험

- **오탐이 제일 큰 위험이다.** 정상 문단을 숨김으로 잘못 판정하면 근거가 조용히
  사라진다 — 5절 3·4·6·8번이 그 자리다. 특히 `hidden` 은 흔한 속성 이름이라 속성
  이름만 보고 자르면 넓게 문다.
- **천장을 올리려는 유혹.** 인라인 스타일을 문자열로 보기 시작하면 「그럼 클래스도,
  외부 CSS 도, 화면 밖으로 밀어낸 좌표도」로 번진다. 7절이 선을 그었다.
- **되돌리기는 싸다** — 제품 코드가 한 파일이고 스키마·데이터가 안 움직인다.
