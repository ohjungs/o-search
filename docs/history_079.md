## 형식

```
## YYYY-MM-DD HH:MM | <plan-slug> | <phase> <step> | 시도N
- 한 일: <무엇을 했나. 파일 경로 포함>
- 결과: <검증 결과. 테스트 12/12 통과 / 린트 0건 / 실패 출력 요약>
- 다음: <다음 스텝 또는 정지 사유>
```

실패한 반복도 반드시 남긴다. 실패 기록이 없으면 같은 실수를 반복한다.

**회전 명부는 `digest.md` 의 `## 완료` 절 «아카이브 명부» 줄이 정본이다.**
여기 있던 스물한 회전의 서술(233줄)은 그 줄과 내용이 겹쳤고, 검사가 강제하는 명부도
그쪽 하나뿐이라(`tests/test_docs.py` 의 `ArchiveIndexTest`) **개발 9(반복 269)가 이
자리에서 지웠다** — 회전으로는 300줄 상한을 못 맞추던 세 반복(309 → 372 → 418줄)의
원인이 이 명부였다. **지운 것은 머리말이지 반복 기록이 아니다** — 항목은 여전히
append 전용이고 수정·삭제 금지다. 각 회전의 사유는 `digest.md` 의 같은 줄에, 원문은
`history_<NNN>.md` 에 그대로 있다.

### 반복 487 — 계획 83 개발 1/2 · 018 이 되붙이던 것을 거절로 뒤집었다

- `urls.normalize` 가 netloc 에 `@` 를 든 URL 에 `None` 을 준다. 되붙이던
  `userinfo + at` 을 지웠고, **판정은 `_split` 이 준 netloc 위에서만** 한다 —
  경로·질의의 `@` 를 자격증명으로 읽으면 멀쩡한 문서를 통째로 못 줍는다.
- **RED 를 먼저 봤다**: 세 모양(`u:pw@` · `user@` · `google.com@evil.test`)이
  전부 「is not None」으로 떨어지고 대조군은 그대로 초록이었다.
- **뒤집은 것은 테스트 이름이지 근거가 아니다.** 018 이 적은 「떼면 요청 내용이
  바뀐다」는 **요청에 대해서는 지금도 옳다** — 그래서 떼는 대신 **안 받는다**.
  그 사실을 `normalize` 독스트링과 새 테스트 독스트링 양쪽에 적었다.
- **가드 둘이 울려서 곁가지를 닫았다.** ① `HistoryCapTest` 321 > 300 →
  반복 461~474 를 `history_077.md` 로 회전(계획 76 가드의 **두 번째 발화**이고,
  첫 발화 때와 달리 이번엔 **같은 반복 안에서** 잡혔다) ② README 단위 수 709 → 710.
- 전수 **710 OK**. `e2e/domain_key_e2e.py` 는 아직 안 고쳤다 — 설계가 예고한 대로
  지금 돌리면 종료 2 로 크게 실패한다.

### 반복 488 — 계획 83 개발 2/2 · 사유를 알리려다 같은 것을 흘릴 뻔했다

- `urls.has_credentials(url)` 를 내고 `normalize` 가 **그것을 부른다.** 스텝 1 은
  netloc 을 직접 봤는데, 시드 루프가 같은 판정을 해야 하는 순간 규칙이 두 곳에
  생기므로 한 자리로 모았다. `_split` 을 한 번 더 부르지만 `domain_key` 도 이미
  그렇게 하고 크롤은 네트워크에 묶여 있다.
- **가지 순서가 계약이다.** 자격증명 가지는 `normalize is None` **앞**이다 —
  뒤에 달면 `normalize` 가 이미 `None` 을 줘서 영영 안 닿는다.
- **정작 위험했던 것은 메시지였다.** 위·아래 가지는 시드를 통째로 찍는다(거긴 숨길
  것이 없다). 그대로 따라 했으면 **비밀번호가 stderr 로 나가** 이 계획이 막으려던
  것을 로그로 다시 흘렸을 것이다. `urls.domain_key(seed)` 가 userinfo 를 떼므로
  호스트만 적는다 — 새로 만들 것이 없었다.
- 단언은 넷이다: 사유에 「자격증명」이 있고 **「읽을 수 없는」이 없다**(거짓 사유를
  금지하는 쪽이 핵심이다) · 요청이 0건 · 경로의 `@` 는 시드로 통과.
- 전수 **712 OK**. `e2e/domain_key_e2e.py` 는 여전히 안 고쳤다 — e2e phase 몫.

### 반복 489 — 계획 83 테스트 · 가드가 둘이라 변이도 둘이었다

- 계획 기준 6 은 「가드를 지우면 2·4·5 가 빨개진다」였는데 **변이 A**(`normalize`
  거절 삭제)는 2·4 만 죽이고 **5 는 초록으로 살았다** — 시드 가지가 `normalize` 가
  아니라 `has_credentials` 를 직접 부르기 때문이다. **변이 B**(시드 가지 삭제)로
  5 를 따로 죽였다: 사유가 「자격증명」에서 「읽을 수 없는」으로 바뀐다(= 거짓 사유).
- **변이 A 가 조용히 통과한 것이 갭을 드러냈다.** 기준 4(링크 경로)에 테스트가
  **아예 없었다.** 시드는 운영자가 주지만 href 는 **남이 심는다** — 실제 유입구는
  이쪽이다. 자격증명 href 둘은 버리고 같은 페이지의 정상 링크는 남는 단언을 넣었다.
- 새 public 술어 `has_credentials` 에 직접 테스트가 0 이었다(`test.md` 6절 ⑥).
  특히 **「못 읽는 URL 에 `False`」 가지**는 아무도 안 밟았다 — 거기서 던지면
  못 읽는 시드 하나가 크롤 전체를 끝낸다.
- 전수 **717 OK** (+5) · README 712 → 717.

### 반복 490 — 계획 83 리뷰 · 백지 패스가 **내가 낸 RED** 를 주웠다

- 패스 A 를 별도 세션에 넘겼다(diff 와 수정된 파일만). 가장 무거운 발견은 코드가
  아니라 **직전 반복의 기록**이었다: 반복 489 가 `status.md` 에 `step: —` 를 적어
  `test_docs.StepSyncTest` 가 빨개졌다. 전수를 **status 수정 전에** 돌린 탓에
  커밋 시점에 못 봤다 — 순서가 만든 구멍이다. `step: 2/2` 로 되돌려 **717 OK**.
- `has_credentials` 독스트링의 「못 읽는 URL 에는 `False`」가 **자기 테스트와
  모순**이었다(폴백의 `u:pw@[oops` 는 `True`). 실제 계약은 「안 던진다」다 —
  독스트링과 설계 계약 절을 함께 고쳤다(코드만 고치고 문서를 두면 반려다).
- 설계가 예고한 digest 후보를 등재했다: `domain_key` 의 userinfo 접기는 죽은 코드가
  아니라 **호출자 둘 중 하나에서만 산다** — 시드 스킵 메시지가 `normalize` 앞이다.
- e2e 종료 2 는 설계가 예고한 것이라 e2e phase 로 넘긴다. 커플링 지적은 실제로
  갈리는 입력을 못 만들어 80점 미만으로 버렸다.

### 반복 491 — 계획 83 e2e · 내가 만든 단언이 **누출 위에서 초록**이었다

- `domain_key_e2e.py` 시나리오 1 을 갈아 끼웠다. 017 의 **e2e 급** 회귀 탐지기는
  여기서 끝난다(표기가 갈린 채 프런티어에 오는 경로가 없다) — 남는 것은 단위
  `TestDomainKey` 이고, 그 사실을 파일 독스트링과 `project.md` 에 적었다.
- **첫 단언은 Host 헤더의 `@` 를 봤다.** 변이 사본(거절 삭제)에서 도착이 3→4회로
  늘었는데 **통과했다** — `urllib` 이 Host 에 userinfo 를 안 싣기 때문이다.
  이 파일이 겨냥한 실패 모양(「잴 대상이 사라졌는데 참이 되는 단언」)을 **내가 새로
  만든 자에서** 반복한 것이다.
- 증거를 **경로**로 바꿨다: `/p1` 은 자격증명 href 로만 존재하므로 도착 = 그 URL 로
  요청을 보냈다는 뜻이다. 변이에서 종료 1 로 죽는다. `Authorization` 검사도 더했다.
- 실측 `OK 5.2s` · `--control` 측정 불능(2) · 전수 717 OK.
