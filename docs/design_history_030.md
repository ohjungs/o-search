# 설계: 포커스 링의 존재 (계획 44 `focus-ring-presence`)

## 결정 — `check_contrast` 는 색을 재기 전에 **링을 그리는 규칙을 응답 CSS 에서 읽는다.**

`outline` 을 정하는 규칙이 정확히 1개이고 · 셀렉터에 `:focus` 가 있고 · 그 `outline` 의
색이 `NONTEXT_PAIRS` 가 재는 토큰이고 · 같은 규칙의 `outline-offset` 이 0 보다 클 때만
비텍스트 짝을 잰다. 넷 중 하나라도 깨지면 **측정 불능(2)** 이고 3.56:1 은 안 찍는다.

## 대안 비교

|  | A. 최소 (digest 처방) | **B. 규칙을 읽는다** | C. 짝을 CSS 에서 파생 |
|---|---|---|---|
| 무엇 | `"var(--focus)" in css` | 규칙 하나를 파싱해 색·offset 을 읽는다 | `NONTEXT_PAIRS` 를 상수에서 없애고 그려지는 토큰으로 짝을 만든다 |
| 변이 11종 중 잡음 | **3** (V1·V2·V3) | **9** (V4·V9 제외) | 6~9, 단 메시지가 틀린다 |
| 되돌리기 | 커밋 하나 | 커밋 하나 | 커밋 하나 |
| 코드량 | 1줄 | 약 15줄 | 약 15줄 |
| 기존과 일치 | △ 문자열 존재 검사 | ○ `stylesheet`·`token_maps` 와 같은 ValueError 관용구 | ✕ *"이름만 여기 있고 값은 CSS 에서 읽는다"* 규약을 뒤집는다 |
| 다음이 편한가 | ✕ 다음 구멍마다 문자열이 하나씩 는다 | ○ | △ |

**선택: B.**

**버린 이유 — A**: 문자열이 **어디에** 있는지 안 본다. `body{color:var(--focus)}` 만 남아도
통과한다. 잡는 것이 9종 중 3종이고(실측), 못 잡는 V5·V6 이 하필 `NONTEXT_PAIRS` 주석의
전제를 깨는 변이다. 이 저장소가 두 번 닫은 실패 유형(계획 13 *어느 맵을 보나* · 43 *어느
이름을 보나*)의 세 번째가 *"그 토큰을 쓰는 규칙이 살아 있나"* 인데, A 는 그 질문에 문자열로
답한다 — `digest` 가 경계하는 *"검사기가 검사처럼 생긴 상수가 되는 것"* 이다.

**버린 이유 — C**: 짝을 파생하면 커버리지 강제(`paired`)와 얽힌다. V3(`var(--focus)`→
`var(--line)`)를 **실측**하니 rc 2 는 나오는데 메시지가 `짝도 제외도 없는 색 토큰: --focus`
다 — 사람에게 *"링이 --line 으로 그려지고 있다"* 를 한마디도 못 한다. 판정만 맞고 진단이
틀린 검사기는 야간에 아무도 못 고친다.

## 갈림길 A — 종료 코드는 **2**(측정 불능)이다

형제 관용구는 갈린다: `check_mobile` 의 `overflow-wrap:anywhere` 부재는 **1**(실측
`fail=1 unm=0`). 그래도 여기는 2 다. 거기서는 *"긴 URL 이 360px 을 넘친다"* 라는 결론이
바로 나오고 [4]번 축이 찍는 다른 숫자는 그대로 참이다. 여기서는 **[3]번 축이 찍은
3.56:1 자체가 무효**가 된다 — 아무 데도 안 그려지는 색의 대비다. *"잴 것이 없어진 검사는
조용히 통과하면 안 된다"* 는 이 파일 첫머리의 규칙이 그 경우에 2 를 준다(`token_maps` 의
다크 블록 가드가 같은 자리다: 규칙이 통째로 없어지면 ValueError → 측정 불능).
`--focus` 의 비율이 3.0 아래로 내려간 경우만 계속 1 이다. **1 과 2 를 가르는 것은 고장의
크기가 아니라 "찍은 숫자가 아직 참인가" 다.**

## 갈림길 B — 자국은 **문자열이 아니라 규칙**이다

응답 CSS 실측 출현 수: `var(--focus)` 1 · `:focus-visible` 3 · `outline` 2 ·
`outline-offset` 1 · **`outline` 을 정하는 규칙 1개**. 마지막 것에 건다. 규칙 수를 세면
`:focus` 셀렉터 아래에서만 세지 않고 CSS 전체에서 세므로, 뒤에 오는 규칙이 링을 덮는
갈래(아래 가정)가 같은 조건 하나로 닫힌다.

## 가정 — **깨봤고 참이다. 그리고 가정으로 두지 않고 검사 조건으로 올렸다**

*"응답 바이트의 자국으로 '링이 보인다' 를 대리할 수 있다"* 가 성립하는 조건은
**`outline` 을 정하는 규칙이 CSS 에 하나뿐**이라는 것이다(둘이면 캐스케이드를 바이트로
흉내내야 하고 그건 브라우저 일이다). 실측 **1개**. 깨는 변이 3종을 심어 보니
—뒤 규칙이 `outline:none`(V7) · 뒤 규칙이 `outline-width:0`(V8) · **다크 블록 안**에서
`outline:none`(V10)— 셋 다 규칙 수 세기 하나에 걸린다. 그래서 이 가정은 주석이 아니라
조건이 된다.

**천장 (`ponytail:` 주석으로 남긴다)**
- **V4 `:focus-visible`→`:focus` 는 일부러 안 잡는다.** `:focus` 도 키보드 포커스에 링을
  그린다 — 이 축이 재는 것(키보드 사용자에게 링이 보이나)은 안 깨지고, 마우스 클릭에도
  링이 뜨는 스타일 회귀다. `:focus-visible` 리터럴을 요구하면 유효한 구현을 금지하는
  상수가 된다.
- **V9 같은 규칙 안에서 `outline-width:0` 으로 자기를 뒤엎기는 못 잡는다.** 지금 CSS 에
  그런 형태가 0곳이고, 잡으려면 한 규칙 안의 선언 순서까지 해석해야 한다.

## 계약 — 개발이 지킬 것

1. `e2e/design_check.py` 에 `focus_rule(css)` 하나. `(색 토큰, offset 문자열)` 을 돌려주거나
   **`ValueError`**(이 파일의 `stylesheet`·`token_maps` 와 같은 관용구 — 부르는 쪽이
   `unmeasurable` 에 담는다).
2. `check_contrast` 는 그것을 부른 뒤 **성공하면** 요약 한 줄을 찍고 `NONTEXT_PAIRS` 를
   재고, **`ValueError` 면** 사유만 담고 비텍스트 짝은 **안 잰다**. 텍스트 7짝 × 2맵은
   어느 쪽이든 그대로 잰다.
3. 상수 `PAIRS` · `NONTEXT_PAIRS` · `NO_PAIR` · `MIN_CONTRAST_NONTEXT` 의 **값과
   커버리지 강제(`paired`)는 안 바뀐다.** `--focus` 는 계속 짝이 있다.
4. 새 출력 한 줄은 `check_mobile` 의 요약 줄과 같은 꼴 —
   `포커스 링 규칙 1개 · outline var(--focus) · offset 2px`.
5. **메시지는 깨진 것과 못 재게 된 것을 함께 말한다.** 네 갈래:
   `outline 을 정하는 규칙이 N개 — 캐스케이드를 바이트로 못 정한다` /
   `outline 이 색 토큰을 안 쓴다 (none)` /
   `그려지는 색 --line ≠ 재는 색 --focus` /
   `outline-offset 이 0 이다 — 링의 이웃이 페이지 배경이 아니다`.
6. `NONTEXT_PAIRS` 위 주석에서 *"outline-offset:2px 라 링의 이웃은 언제나 페이지
   배경이다"* 는 **단언에서 포인터로 바꾼다** — 그 전제는 이제 `focus_rule` 이 매 실행
   확인한다. 무효화된 전제를 사유 없이 남겨 두지 않는다.
7. **`NO_PAIR["--line"]` 의 `다크도 1.08:1` 을 실측값으로 고친다** — 여섯 짝을 다 재니
   라이트 page/input **1.34** · button 3.86, 다크 page **1.37** · input **1.27** ·
   button 4.88 이고 **1.08 은 어느 짝도 아니다.** 이 파일은 사유를 계약으로 쓰므로
   (*"틀린 사유를 적으면 문이 거짓으로 열린다"*) 숫자 하나만 고친다. **판단 보류
   문장은 안 건드린다** (`--line` 이 SC 1.4.11 대상인가는 사람 몫으로 열려 있다).
8. 단위는 `tests/test_design_check.py` 의 `twist` 자리에 6건(V1·V2·V3·V5·V6·V7) +
   제품 CSS 가 요약 줄을 찍는다는 단언 1건. **색값을 기대값으로 들지 않는다.**
9. `src/websearch/serve.py` **0줄.** 제품 CSS 는 멀쩡하므로 `design_check.py` 는 계속 rc 0.

## 되돌리기 — 커밋 하나 revert

제품 코드가 0줄이라 배포 영향이 없다. 검사기만 되돌아간다.

## 범위 밖

- **`--focus` / `--bg-button` 1.45:1 짝을 안 늘린다.** 그 배경은 `outline-offset` 이
  0 일 때만 링의 이웃이 되고, 지금 2px 이며 **이제 검사기가 매 실행 그것을 확인한다.**
  늘리면 그 자리에서 rc 1 이 되고 색을 바꿔야 하므로 계획이 커진다. offset 이 0 이 되는
  날 검사기가 rc 2 로 멈추고, 짝을 정하는 것은 그때 열릴 계획의 일이다 —
  `status.md ## 사람이 정할 것 ②` 2번은 **열려 있되 "가정" 에서 "검사기가 붙들고 있는
  조건" 으로 성격이 바뀐다.**
- V4(`:focus` 허용)와 V9(같은 규칙 자기 뒤엎기)는 위 천장대로 안 잡는다 — `digest` 후보.

## 개발 스텝 — 1개

`e2e/design_check.py` + `tests/test_design_check.py` 두 파일. 설계 트리거의 "3개 이상
파일" 에 안 걸리고 계약이 한 함수라 가르지 않는다.
