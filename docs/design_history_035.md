# 설계 49 — `focus-rule-scope`

**걸린 트리거**: 「대안이 갈린다」 하나. 스텝 2(ⓐⓑ)를 닫는 방법 셋이 **닫는 범위가
서로 달랐다**(계획서 6절). 셋을 실제로 만들어 같은 변이 12종에 먹였더니 갈림이 계획서가
쓴 자리가 아니라 **다른 자리**에 있었다.

**결론: C(최상위 요구)를 고른다.** 계획서는 C 를 「가장 짧지만 다크 전용 CSS 를 영구히
거절한다」로 적어 두고 그 거절이 옳은지를 설계에 넘겼다. 실측이 답한 것은 그 물음이
아니다 — **A 계열은 거짓 초록을 다시 만든다.** 이 계획이 죽이러 온 바로 그 고장이다.

## 1. 실측 — 후보 넷을 CSS 변이 12종에 먹였다 (2026-09-02)

제품 응답 바이트(`serve._render` → `design_check.stylesheet`)에서 CSS 를 뽑고, 변이마다
`mutated != css` 를 먼저 단언한 뒤 `check_contrast` 에 먹여 종료코드를 받았다.
후보 구현은 전부 탐침 스크립트 안에 있다 — **저장소는 한 줄도 안 고쳤다**(`git status`
clean, `.mutation-lock` 이 필요 없었다). 표는 종료코드다: **0 통과 · 1 기준 위반 · 2 측정 불능**.

## 2. 갈림길 — 계획서가 물은 것과 실측이 답한 것

**계획서의 물음**: 「C 는 다크 전용 CSS 를 영구히 거절하는데, 그것이 접근성 결함이라
옳은 거절인가?」 → 옳다. 라이트 화면에 링이 없는 것은 결함이고, 판정은 기준 위반(1)이
아니라 **측정 불능(2)** 이라 검사기는 거짓말을 하는 대신 멈춘다.

**실측이 뒤집은 것**: F3·F4 를 넣기 전까지 A·A′ 는 「C 보다 오탐이 적은 정교한 쪽」으로
보였다. 아니었다. A 계열이 F1~F4 를 통과시키는 이유는 **prelude 블랙리스트**
(`prefers-color-scheme|print`)를 쓰기 때문이고, 블랙리스트는 **모르는 조건을 안전으로
분류한다**. `@media (forced-colors:active)` 안의 링은 강제색 모드에서만 그려지는데
A 는 라이트 3.56:1 을 초록으로 낸다 — 계획 44 가 죽인 고장과 **같은 형태**다.
화이트리스트로 뒤집으면 통과하는 at-rule 이 0개가 되어 그것이 곧 C 다.

**at-rule 은 전부 조건이다.** 링 규칙을 감싼 at-rule 이 하나라도 있으면 링은 조건부이고,
조건부 링의 대비 한 숫자는 참이 아니다. F1(구형 브라우저에 링 없음)·F2(360px 에 링
없음 — 디자인 4축이 재는 바로 그 화면)·F3 는 **오탐이 아니라 정탐**이다. F4 `@layer` 만
조건이 아니지만 캐스케이드를 바꾸고, `focus_rule` 은 캐스케이드를 바이트로 판정하지
않기로 이미 정해 두었다(규칙이 2개면 측정 불능). 거절이 그 방침과 같은 줄에 선다.

**B 를 버린 이유는 실측 한 칸**이다 — ⓑ 에서 종료 0. 계획서가 예상한 대로 `@media print`
는 다크가 아니라 라이트 소스에 남는다. 코드가 짧아도 **닫으라는 것을 안 닫는다**.

## 3. 계약

`focus_rule(css)` 의 **반환 모양과 예외 종류는 안 바뀐다** — `(색 토큰, offset 문자열)`
또는 `ValueError`. 부르는 곳은 `check_contrast` 한 곳뿐이고 거기서 `ValueError` 는
`unmeasurable` 로 가 종료 2 가 된다. 공개 인터페이스 변경 0.

조건 **둘을 더한다**. 기존 넷(규칙 1개 · 포커스 셀렉터 · 색 토큰 · offset>0)은 그대로다.

| # | 스텝 | 조건 | 실패 메시지 갈래 |
|---|---|---|---|
| 5 | 1 | 셀렉터에서 `:not(…)` 안을 지운 뒤 `:focus` 또는 `:focus-visible` 이 **낱말로** 남아야 한다 (`:focus-within` 은 `-` 가 붙어 안 남는다) | `키보드 포커스용이 아니다: <셀렉터>` |
| 6 | 2 | 링 규칙 앞의 `{`·`}` 개수가 같아야 한다 (= at-rule 밖) | `at-rule 안에 있다 — 라이트 화면에 늘 그려지지 않는다` |

조건 5 는 기존 `":focus" not in selector` 를 **대체**한다(넓어서 틀린 가드였다).
V11(`:hover`)은 메시지 문구만 바뀌고 판정은 종료 2 그대로다 — `tests/test_design_check.py`
의 V11 단언이 무는 문자열이 `포커스용이 아니다` 라 **부분 문자열로 그대로 산다**.

## 4. 스텝 — 계획서의 둘을 그대로 둔다

쪼개지도 합치지도 않는다. 실측에서 조건 5 와 6 은 **서로의 산출물을 안 읽는다**(A′ 에서
둘을 따로 켜고 껐다). 스텝 1 = 조건 5(6줄), 스텝 2 = 조건 6(3줄). 순차로 도는 이유는
의존이 아니라 같은 파일을 건드리기 때문이다.

**두 축이라 검사도 둘이다.** 셀렉터 극성과 at-rule 위치는 다른 것을 재므로 단언을
한 손잡이로 합치지 않는다 — 스텝 1 은 ⓒⓓ, 스텝 2 는 ⓐⓑ 를 각각 죽인다.

## 5. 되돌리기

**커밋 하나로 revert**(`rules/design.md` 3절 ③). 피처 플래그를 안 쓴다 — 검사기 안의
조건 두 줄이고, 스텝마다 커밋이 하나다. 제품 `src/` 0줄이라 배포가 없고 롤백도 없다.

## 6. 천장 — 안 하는 것과 그 사유

- **CSS 파서를 안 만든다.** 주석 안의 `{`, 문자열 안의 중괄호, CSS Nesting 은 조건 6 의
  중괄호 세기를 속인다. 지금 그런 CSS 는 0곳이고, 생기면 규칙 수가 틀려 **종료 2 로
  멈춘다**(조용히 통과하지 않는다) — `RULE_RE` 가 이미 서 있는 천장과 같은 자리다.
- **`:focus-within` 을 영구히 거절하는 것이 옳은가는 안 닫는다.** 컨테이너에 그리는 링도
  키보드 사용자에게는 보인다. 다만 그때 링의 이웃은 페이지 배경이 아니라서
  `--focus on --bg-page` 라는 짝 자체가 틀린 측정이 된다. 판정이 2 라 사람이 본다.
- **at-rule 화이트리스트를 안 만든다.** 1절 F1~F4 가 넷 다 정탐이라 지금 넣을 것이 없다.
  제품 CSS 에 정당한 at-rule 중첩이 실제로 생기는 날 열린다 — 그날 검사기는 초록이
  아니라 종료 2 로 멈춰서 알린다.
- **다크만 재고 라이트는 못 잰다는 반쪽 판정을 안 만든다.** 3번 축은 라이트·다크 두 맵을
  한 루프로 돌리고, 맵별로 측정 가능 여부를 가르면 `scales` 구조를 바꿔야 한다. 조건부
  링은 통째로 측정 불능이다.
