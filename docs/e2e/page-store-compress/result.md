## 3. 스텝 1 이 잡은 함정 — `LIKE` 는 압축분을 영영 못 만난다

`indexer.py` 의 「뒤늦게 noindex 를 선언한 문서를 뺀다」 경로가
`WHERE p.html LIKE '%robots%'` 로 후보를 골랐다. **압축분은 BLOB 이라 매치가 0 이다.**
초록불인 채로 **크롤 윤리 축이 조용히 죽는** 모양이었다.

**기존 테스트가 잡았다** — `test_already_indexed_page_that_declares_noindex_is_removed`
가 `Store.upsert` 로 픽스처를 넣기 때문이다. 픽스처를 raw SQL 로 넣었다면 그 테스트는
**옛 표현만 검증하며 초록**이었을 것이다(`test.md` 갭 ⑥ — 변경된 함수의 기존 테스트가
옛 동작만 덮는 함정). **픽스처가 제품 경로를 지나간 것이 값을 냈다.**

처방은 필터를 걷어내는 것이다. **판정은 안 바뀐다** — 걷어낸 조건이 `is_noindex()` 가
자기 첫 줄에서 이미 하는 검사와 같아서(`extract.py:207`) 함수를 더 자주 부를 뿐이고,
그 값이 위의 +0.7% 다.

## 4. 마이그레이션을 안 만든 이유

`page_html()` 이 `str`(옛 TEXT)과 `bytes`(새 BLOB)를 다 받는다. `sqlite3` 가 타입으로
갈라 주므로 판별 열도 필요 없다. 그래서 **기존 100MB 코퍼스를 변환하지도 버리지도
않고 그대로 읽고**, 재크롤이 자연히 갈아 끼운다 — 되돌리기 어려운 단계가 아예 없다.
