# 설계 45 — `docs-record-guard`

계획서 `docs/plan_docs-record-guard.md` 의 갈림길 둘을 닫는다.
**결정: ① 검사 범위는 `digest.md` 의 `## 완료` 절만 · ② 색인은 그 절 머리의 "아카이브
명부" 한 줄이 산다.** 제품 코드는 0줄이고 고치는 파일은 `tests/test_docs.py` 와
`docs/digest.md` 둘이다.

**트리거** — `design.md` 1절 *"대안이 2개 이상 갈림"*. 계획서 5절이 건 그대로다.

## 1. 설계 탐침이 새로 잰 것 (2026-09-02)

계획서의 실측을 재확인하고 **두 자리를 확대했다.** 세 숫자 다 경계 매칭으로 다시 쟀다.

| 범위 | 오늘 구멍 | 무엇을 놓치나 |
|---|---|---|
| `digest.md` 전체 | **4** — 002·003·005·019 | **001 을 신고문이 초록으로 만든다** |
| `digest.md` **`## 완료` 절만** | **5** — 001·002·003·005·019 | — **채택** |
| 살아있는 문서 어디든 | **0** | 그 0 을 만든 문장이 전부 이 계획의 것이다 |

**확대 ①** — 대안 3(살아있는 문서 어디든)은 오늘 구멍 0 인데, **002·005 를 이름으로
붙들고 있는 자리가 `index.md` 의 계획 45 행 · `history_current.md` 의 이번 계획 기록 ·
`status.md` 셋뿐**이다. 셋 다 이 계획이 이번 주에 직접 쓴 문장이고, 계획서는 DONE 되면
`plan_history_031.md`(아카이브 = 검사 제외)가 되며 `history_current.md` 는 300줄에서
회전한다. **자기가 쓴 글을 자기가 읽는 검사**라 실측으로 죽었다.

**확대 ②** — 순진한 substring 이 `plan_`/`design_` 접두를 오인하는 자리가 살아 있는
문서에 **8곳** 있다(`digest.md` 3 · `history_current.md` 1 · `index.md` 4). 가장 뚜렷한
것은 **`index.md` 의 `history_022.md`**: 접두 형태로 1회 나오고 **맨 이름으로는 0회**다.
순진 매칭이면 오늘 이미 거짓으로 잡고 있다.

## 2. 갈림길 A — 범위는 `## 완료` 절만

**대안 1(전체)을 기각하는 이유가 이 계획의 존재 이유다.** `digest.md` 에서 001 이 맨
이름으로 나오는 자리는 `## 반복 실패` 의 *"회전을 돌리면서 그 아카이브의 `digest` 압축
줄을 안 남긴다"* 항목 **하나뿐**이다. 구멍을 신고하는 문장이 신고 대상을 초록으로 만든다.
저장소가 네 번째로 밟는 "거짓 초록" 계열이라(BSD `sed` · 기본값 인자를 감시하는 mock ·
링 없는 링 검사) 여기서 끊는다.

**대안 3(느슨)은 1절 확대 ①이 죽였다.**

**대안 2 의 값싼 위험은 "절 이름이 바뀌면 빈 텍스트 위에서 조용히 통과"** 다. 계획서
2-1 의 V3 함정과 같은 꼴이고, 이 파일이 이미 두 번 쓴 수법으로 막는다 — `DocHeadTest` 의
`assertTrue(path.is_file(), …)`, `DocCitationTest` 의 `assertIn(name, scanned, …)`.
**절을 못 찾으면 통과가 아니라 실패**다(4절 계약 b).

## 3. 갈림길 B — 명부 한 줄이 색인이다

**본체는 두 룰의 정면 충돌**이다. `rules/docs.md` 는 *"`digest.md` 가 200줄을 넘으면
**완료 항목부터** 지운다"* 고 하고, 새 불변량은 *"모든 아카이브 이름이 `## 완료` 절에
있어야 한다"* 고 한다. 완료 항목을 지우면 색인 구멍이 생긴다. 그리고 `digest.md` 는
지금 **정확히 200줄**이라 이 충돌이 첫 줄부터 발동한다. 실제로 003 이 그렇게 사라졌다 —
계획 44 테스트 반복이 상한을 맞추려 지운 회전 안내가 `docs/` 안의 유일한 003 포인터였다.

**해결은 역할 분리다.** 이름 색인은 **명부 한 줄**이, 판단 재료 요약은 **완료 항목들**이
맡는다. 분리되면 완료 항목 삭제가 다시 안전해진다 — 이름은 명부에 남는다.
명부는 회전 1회당 **약 18자**만 늘고 **줄 수는 영원히 1**이라 상한과 안 부딪힌다.

| 대안 | 줄 예산 | 판정 |
|---|---|---|
| 1. `## 완료` 머리에 명부 1줄 + **가장 오래된 완료 항목 1줄 삭제** | 200 유지 | **채택** |
| 2. 기존 회전 줄에 이름을 이어 붙인다 (계획 44 의 수법) | 200 유지 | 기각 — 이름이 **어느 줄에 사는지가 암묵**이라 다음 회전의 "오래된 항목부터 삭제"가 그 줄을 지운다. 003 을 잃은 경로 그대로다 |
| 3. 색인을 `index.md` 로 옮긴다 | 상한 없음 | 기각 — `digest.md` 가 스스로 *"원본은 `history_<NNN>.md` 에 그대로 있다"* 로 색인을 자처하는 계약을 깬다 |
| 4. `rules/docs.md` 를 고친다 | — | 기각 — **이 저장소 밖**이다. 대신 명부 규약을 `digest.md` 자신의 머리 주석에 적어 저장소 안에서 자족하게 한다 |

**삭제할 1줄은 공짜다** — 실측: `## 완료` 의 가장 오래된 항목 둘(`cooldown-burn`(011) ·
`normalize-gaps`(019))은 **맨 아카이브 이름을 하나도 안 갖고 있다**. 둘 중 하나를 지워도
새 구멍 0 이다. 어느 쪽을 지울지는 개발 스텝이 고른다.

**명부의 대상은 `docs/history_<NNN>.md` 만이다.** `plan_history_*`·`design_history_*` 는
`index.md` 의 계획 행이 이미 계획당 한 줄로 붙들고 있어 넣지 않는다(의도한 경계).

## 4. 계약

두 검사 모두 `tests/test_docs.py` 에 붙는다. 새 파일 0 · 새 의존성 0 · `src/` diff 0줄.

### 스텝 1 — `IterationSyncTest` (불변량 A)

| 항목 | 계약 |
|---|---|
| 값 A | `docs/metrics.md` 에서 `^\| 반복 \| ([0-9]+) \|` (`re.M`) 의 첫 매치 |
| 값 B | `docs/status.md` 에서 `^iteration: ([0-9]+)$` (`re.M`) |
| 단언 | 두 정수가 같다. 실패 메시지에 **두 값과 파일 이름**을 찍는다 |
| 눈먼 자리 | 매치가 `None` 이면 **비교 전에 실패**한다(`assertIsNotNone`) |

`| 반복 수 |`·`| 반복 상한 | 0 |`·`| 평균 반복 |` 은 `| 반복 |` 정확 형태가 아니라 안
물린다 — 오늘 `## 누적` 표의 그 한 행만 잡는 것을 실측으로 확인했다.

### 스텝 2 — `ArchiveIndexTest` (불변량 B)

| 항목 | 계약 |
|---|---|
| 대상 | `sorted(DOCS.glob("history_[0-9]*.md"))` 의 파일명 전부 (오늘 22개) |
| 텍스트 | `digest.md` 를 줄로 쪼개 `## 완료` 부터 **다음 `^## ` 직전**까지 |
| 매칭 | `(?<![A-Za-z_])` + 파일명 — 접두 `plan_`/`design_` 을 배제한다 (1절 확대 ②) |
| 단언 | 빠진 이름이 없다. 실패 메시지에 **빠진 이름을 전부** 찍는다 |
| 눈먼 자리 a | `digest.md` 가 파일이 아니면 실패 |
| 눈먼 자리 b | `## 완료` 절을 못 찾으면 **통과가 아니라 실패** |
| 눈먼 자리 c | 아카이브 목록이 비면 실패 — glob 이 빈손이어도 "구멍 0" 이 된다 |

**계획 42 검사와의 관계**: 명부는 이름만 적으므로 `DocCitationTest` 와 안 부딪힌다.
이 설계서도 `digest.md`·`index.md`·`history_current.md` 를 **항목 이름으로만** 가리킨다.

개발·테스트 스텝이 **눈으로 RED 를 본 뒤** 되돌린다. 문서 변이는 커밋하지 않는다.

|---|---|---|

| V2 | `status.md` 의 `iteration` 값을 1 올린다 | RED |
| V3 | `metrics.md` 의 행 이름을 `\| 반복수 \|` 로 바꾼다 | RED (조용한 통과 금지) |
| V4 | `status.md` 의 `iteration` 줄을 지운다 | RED |

초록일 때 린트형 검사는 자신을 못 잰다" 로 적어 둔 그 자리다.

## 6. 되돌리기 · 범위 · 보안

- **되돌리기**: 커밋 하나로 revert (`design.md` 3절 ③). 피처 플래그 불필요 — 테스트와
  문서만 바뀌고 제품 표면은 안 움직인다.
- **파일**: `tests/test_docs.py`(스텝 1·2) · `docs/digest.md`(스텝 2). 새 파일 0.
  아카이브는 글자도 안 건드린다.
- **보안 무관** — 신뢰 경계·비밀정보·권한 어디에도 안 닿는다.
- **`data/crawl.db` 무변경** — 매 스텝 sha256 으로 확인한다.
- **사양**: `docs/specs/concept.md` 4축은 제품 축이라 이 갈림길을 안 가른다(읽기만 했다).
  기준은 사양이 아니라 **오늘 실측된 거짓 초록**이었다.

## 7. 설계가 틀렸다면 어디서 드러나나

- **명부 1줄을 넣고 완료 항목 1줄을 지웠는데 200줄이 안 맞으면** — 갈림길 B 대안 1 이
  틀린 것이다. 그때 대안 2 로 간다(그 경우 명부 줄을 지우지 말라는 주석을 함께 박는다).
- **`ArchiveIndexTest` 가 처음부터 GREEN 이면** — 범위가 잘못 잘렸다. 대안 3 쪽으로 샌
  것이니 절 추출을 다시 본다. 오늘의 기준선은 **구멍 5개**다.
- **V7 이 안 죽으면** — 경계 매칭이 안 걸린 것이다(`re.escape` 를 빼먹었거나 lookbehind
  가 문자열 시작에서 안 먹는 경우).
- **다음 회전이 새 아카이브를 만들고 명부를 안 고치면** — 검사가 즉시 RED 다. 그것이
  이 계획이 사려는 물건이고, 그때 회전 절차가 명부를 함께 고치는지 확인한다.
