## 3. 변이 검사 — 단언이 진짜 잡는가 (6/6)

앞 세션이 남긴 파일이라 **통과했다는 사실만으로는 근거가 안 된다.** 일부러 깨고
잡히는지 봤다. 원본 트리를 건드리지 않으려고 `src`·`e2e` 를 scratchpad 로 복사해
거기서 변이했다 (반복 78 사고의 교훈 — 기준선 비교로 작업 트리를 되돌리지 않는다).

| 변이 | 잡혔나 | 터진 단언 |
|---|---|---|
| M1 `_fts_query` 에서 2-gram 분기 제거 | 잡힘 rc=1 | ① 복합어 뒷부분이 안 잡힌다 |
| M2 어절을 통째로 이어 붙임 (반복 80 회귀 재현) | 잡힘 rc=1 | ② `냉장 보관법` 가 안 잡힌다 |
| M3 스니펫을 `snippet(docs, -1, …)` 로 되돌림 | 잡힘 rc=1 | ④ 화면에 bigram 나열이 나온다 |
| M4 `porter` 제거 | 잡힘 rc=1 | ③ 영어 굴절이 안 잡힌다 |
| M5 `search()` 드리프트 감지 무력화 | 잡힘 rc=1 | ⑥ CLI 가 옛 색인에서 1 로 끝났다 |
| M6 `index_pages()` 드리프트 재구축 제거 | 잡힘 rc=1 | `table docs has no column named title_ng` |

**M5 에서 알아낸 약점 하나를 적어 둔다.** ⑥ 의 `status == 500` 단언은 드리프트 감지를
꺼도 통과했다 — 감지가 없으면 질의 자체가 `OperationalError` 로 터져 서버가 어차피
500 을 낸다. 실제로 가른 것은 **CLI rc=2** 단언이다. 500 한 줄만 두면 눈이 멀었을 자리다.

## 7. 보류였던 것을 닫는다 — `porter` 를 남긴다

반복 80 이 "승인이 필요한 것 하나" 로 남긴 항목이다. **닫았다. 근거는 아래 표 한 줄이
전부인데, 그 줄을 앞 세션은 재지 않았다.**

앞 세션은 `porter` 의 **손실**(접두 검색)만 448개 어휘로 쟀고, **이득**은 fixture 질의
1건(`tuples`)으로만 봤다. 그러면서 "사는 것은 한 건" 이라고 적었다. 그런데 앞 세션이
손실 쪽에서 정확히 진단한 구조적 눈멂 — **영어 질의 20개가 전부 완전한 낱말이라
quality_eval 이 접두 손실을 못 잰다** — 은 **이득 쪽에도 똑같이 걸린다**: 그 20개는
거의 전부 기본형이라 굴절 이득도 못 잰다. 한쪽만 448개로 재고 다른 쪽을 1건으로 재면
**잰 쪽이 이긴다.** 같은 어휘로 양쪽을 다시 쟀다.

| | 포함률 ko/en | 굴절형 질의가 원문을 찾는 비율 (898건) | 접두 검색이 깨지는 낱말 (448개) |
|---|---|---|---|
| **`porter unicode61` (유지)** | 20/20 · **19/20** | **865 (96.3%)** | 50 (11.2%) |
| `unicode61` (제거) | 20/20 · 18/20 | 9 (**1.0%**) | **0 (0%)** |

**선택: `porter` 유지.** 굴절 축에서 856건을 사고 접두 축에서 50개를 판다.
`concept.md` 기능 2 의 80% 는 양쪽 다 넘으므로 합격선은 이 결정을 가르지 않는다 —
가르는 것은 위 두 실측 열이다.

**이것은 루프가 스스로 정해도 되는 결정이다** (`rules/design.md` 4절). 보류하는 넷 중
어디에도 안 걸린다: 사용자 데이터 형태 아님(`docs` 는 `pages` 에서 파생된 색인이고
`pages` 는 손대지 않는다) · 공개 계약 파괴 아님(`search()` 의 `(url, title, snippet)` 과
`GET /search` JSON 이 무손상) · 의존성 없음 · 보안 경계 아님.
**되돌리기도 쉽다** — `SCHEMA` 의 한 낱말이고 드리프트 감지가 색인을 자동 재구축한다.

**대신 판 것을 천장으로 명시한다.** 어휘 448개 중 **50개(11.2%)** 가 부분 접두 검색을
잃는다. `porter` 가 질의어도 색인어도 어간으로 줄이는데 `y→i` 규칙 때문에 **짧은 접두도**
끊긴다 — `any*` 는 `anything`(3/8자)을 못 찾는다. `activa*`→`activate`(6/8자),
`buildi*`→`building`(6/8자)도 같다. **우회는 있다**: 낱말을 끝까지 치면 잡힌다.
그리고 **`quality_eval` 은 이 손실을 앞으로도 못 잰다** — fixture 는 동결이다.
실물 사용자 로그가 생기면 그때 다시 볼 값이다(digest 후보).

측정 스크립트는 저장소에 남기지 않았다(scratchpad). 재현하려면 `indexer.SCHEMA` 를
**임포트 후 메모리에서** 갈아 끼우고 `quality_eval.build_index` 로 같은 코퍼스를 두 번 쌓는다.
