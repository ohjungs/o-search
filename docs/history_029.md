  임시 디렉터리에서 여섯 조합을 재니 `[4]` 의 진단은 **전부 참**이었다: 손상 DB +
  `q=김치` → `DatabaseError`(500), 같은 DB + `q=%01` → **`[]`(200)**, 없는 DB 는
  어느 질의든 `FileNotFoundError`(503).
- **항목에 없던 한 줄이 값을 바꿨다** — `exists` 와 `connect` 사이를 훅으로 실제로
  벌리니 `search()` 가 `[]` 를 내면서 **크기 0 의 빈 DB 파일을 그 자리에 만든다.**
  `digest` 는 *"창은 마이크로초 · 값은 낮다"* 로 적었는데 **흔적이 영구적**이다:
  빈 파일이 남으므로 그 뒤로 `os.path.exists` 가 계속 참이라 **503 이 다시는 안 난다.**
  같은 창이 `_doc_count()` 의 독스트링(*"DB 파일을 만들지 않는다"*)도 거짓으로 만들었다
  (0 을 돌려주면서 파일을 만들었다). 세 자리가 한 뿌리라 **한 곳에서 고친다**.
- **대안 셋의 함정도 탐침이 냈다**(설계 몫). 대안 A(`?mode=rw` URI)는 없는 파일에
  `OperationalError` 를 내고 파일을 안 만들지만, 경로를 날것으로 끼우면 **조용히 다른
  파일을 연다** — `a b#c?d.db` 에서 `#` 뒤가 잘려 `a b` 가 새로 생겼고 `mode=rw` 는
  통째로 무시됐다(`pathname2url` 로 감싸면 옳게 열린다). 그리고 `OperationalError` 를
  전부 번역하면 **권한 오류까지 503** 이 된다(지금은 500).
- **후보 셋 중 골랐다.** ① 이 계획(7순위) ② 근거 문단 API(8순위)는 **다음** — `search()`

  ⑭ 는 `wc -l` 에 러너를 이어 붙인 것이라 `make test` 도 똑같이 조립되고, ⑮ 는
  `2>/dev/null` 이라 명령 길이와 무관하며, 최다 방아쇠(재확인 넷)가 원한 것은
  **짧은 명령이 아니라 짧은 출력**이다. 근거는 계획서 8절에 있다.

## 2026-09-02 04:30 | db-open-atomic | 설계 1/1 시도0

한 일: 설계서 `docs/design_db-open-atomic.md` **신규 111줄**. 제품 `src/` **0줄**.
- **갈림길 넷을 전부 실측으로 갈랐고 사람에게 넘긴 것 0건이다.** ① 원자화 수단 →
  **`file:…?mode=rw` URI**(대안 B «사후에 빈 파일을 지운다» 는 계획 5절 «파일을 안
  지운다» 정면 위반, 대안 C «`os.open` 으로 errno 를 먼저 본다» 는 **열기가 두 번**이
  되어 고치려던 TOCTOU 가 그 사이로 되돌아온다 — 둘 다 접었다) ② `OperationalError`
  번역 폭 → **열기가 실패한 뒤 `os.path.exists` 를 한 번 되본다**(있으면 원문 그대로
  →500, 없으면 `FileNotFoundError`→503) ③ 세 자리를 **한 뿌리 `_connect()`** 로
  ④ `_doc_count` 독스트링은 **문서가 아니라 동작을 고친다**.
- **②의 근거가 이 반복의 핵심 실측이다** — 없는 파일과 **권한 거부(EACCES)와
  디렉터리**가 메시지까지 똑같다(`unable to open database file`). 가를 수 있는
  `e.sqlite_errorcode` 는 **파이썬 3.11+ 인데 여기는 3.9.6** 이라 없다(실측).
  그래서 errno 대신 사후 `exists` 로 분류하는데, **이것은 TOCTOU 가 아니다** — 열기는
  이미 원자적으로 **실패**했고 남은 일은 실패를 어느 칸으로 부를지 분류뿐이라, 최악의
  오분류라도 응답이 503↔500 사이에서 흔들릴 뿐 **파일이 생기거나 없는 것이 있는 것으로
  보이지 않는다.** 무조건 번역하면 계획 46 이 500 에 못박은 «기다려도 안 낫는 상태» 가
  503(재시도하라)이 된다.
- **계획이 «함정» 으로 적어 둔 인용 문제를 다시 재니 «필수 조건» 이었다.**
  `a b#c?d.db` 에서 `#` 이 프래그먼트를 열어 **`?mode=rw` 가 통째로 무시되고 `rwc`
  기본값으로 떨어져 빈 DB 를 새로 만든다** — 즉 **고치려던 바로 그 버그가
  `pathname2url` 하나 빠져 부활한다**. `%` 도 같다. **한글·공백은 인용 없이도 우연히
  돌아가서 기존 495건은 이 구멍을 못 본다**(`남의.db` 테스트가 이미 비ASCII 경로를
  지나는데 M2 를 못 잡는 이유가 이것이다). 상대 경로 `data/crawl.db`(제품 기본값)도
  URI 로 정상 동작하는 것까지 확인했다.
- **갈림길이 다섯이 되려던 것을 실측이 막았다** — `search`·`_doc_count` 는 읽기 전용이라
  `mode=ro` 로 갈라야 하나 싶었는데 **444 파일도 `mode=rw` 로 열린다**(SQLite 가 알아서
  읽기 전용으로 떨어진다). 안 갈라도 되는 것이 확인돼 `_connect` 는 인자 하나로 남았다.
- **계획서의 엣지 하나를 정정했다 — 스텝 둘 사이에 의존이 없다.** 계획서와 `index.md`
  는 *"② 가 ① 의 산출물을 읽는다"* 로 적었지만 ① 은 `exists`+`connect` 짝을, ② 는
  `if not match: return []` 의 **위치**를 건드려 두 편집이 겹치지 않는다. 짝 검사
  (`digest [8]`)도 같이 답했다 — **어느 하나만 고쳐도 회수가 0 이 아니다**(① 만이면
  손상 DB + `q=%01` 이 그대로 200, ② 만이면 레이스가 그대로 빈 파일을 만든다).
  둘 다 필요하고 **순서는 임의**다. 각자 검증 가능하므로 스텝은 2 로 유지했다.
- **변이 표 8줄 · 좁히는 변이 6개**(M1 `mode=rwc` · M2 인용 제거 · M3 사후 `exists`
  삭제 · M4 `_doc_count` 의 `except` 삭제 · M5 조기 반환 원복 · M6 조기 반환을 옛 색인
  검사 **앞**에). 대조군 둘은 기존이 잡는다(M7 `timeout=30` 삭제 → `test_every_
  connection_waits_the_same_thirty_seconds` · M8 번역 안 함 → `test_missing_db_raises`
  2건). **M4 가 교훈 ①의 이번 판이다** — `_doc_count` 의 방어를 지워도 CLI 로만 보면
  rc·문구가 같아 통과하므로 **`_doc_count(없는경로) == 0` 를 직접 부르는 단언**이 필요하다.
- 스텝 2 의 새 자리를 **옛 색인 검사 뒤**로 못박았다(앞에 두면 옛 색인 + `q=%01` 이
  `[]`→200 으로 새 나가 구멍이 절반 남는다 — M6 이 그것을 잡는다). 비용 실측
  **0.066ms/회**(무토큰 질의가 이제 DB 를 연다) · p95 8.71ms · 예산 300ms 대비 무시 가능.
