# 계획 107 `zero-population` — 0건 전수는 초록이 아니다

## 1. 문제

전수를 친다면서 시작 디렉터리를 빠뜨리면 이 저장소는 **초록으로 답한다**:

```
$ PYTHONPATH=src python3 -m unittest discover -b
Ran 0 tests in 0.000s
OK                                   ← rc 0
```

`tests/` 에 `__init__.py` 가 없어 탐색이 안 내려간다. **가려진 것은 출력이 아니라
모집단**이다 — 판정 줄도 `rc` 도 멀쩡히 있고 둘 다 참을 말한다. 0건을 돌렸으니 0건이
통과다.

- **근거**: `digest ## 반복 실패` 최다 항목(「러너의 판정 줄을 가린다」 **37회**)의
  **서른일곱째**. 그 항목이 처방 후보까지 적어 두고 **계획 106 스텝 2 의 범위를 안
  넓히려고 미뤘다** — 106 이 닫혔으므로 미룬 이유가 오늘 없다(`discover.md` 6순위).
- **계획 106 의 래퍼(`scripts/verdict.sh`)는 이 자리를 못 덮는다.** 래퍼는 감싼 명령의
  `rc` 를 그대로 싣는데 그 `rc` 가 0 이다. 탐침 1 이 실물로 확인했다.
- **조항(`project.md` 「맨몸으로 돈다」)도 구조적으로 못 덮는다** — 파이프가 없다.
- 그날 잡아낸 것은 눈이 아니라 `project.md` 에 적힌 명령과 **대 본 것**이다. 사람이
  대조를 한 번 거르면 다시 뚫린다.

## 2. 착수 탐침 — 2회(무인 상한)

**탐침 1 · 실물 저장소(2026-09-19 반복 633).** 재현했다.
맨몸 `PYTHONPATH=src python3 -m unittest discover -b` → `Ran 0 tests in 0.000s` · `OK` ·
**rc 0**. 같은 명령을 `scripts/verdict.sh` 로 감싸면 마지막 줄이
`── Ran 0 tests in 0.000s OK rc=0` · **rc 0**. 둘 다 초록이다.

**탐침 2 · `git clone --local` 사본 `/tmp/zp2` 에 `tests/__init__.py` 한 개(빈 파일).**
맨몸 `discover -b`(시작 디렉터리 없이) → **`Ran 826 tests` OK**. 덫이 뿌리에서 사라진다.
문서화된 두 꼴도 그대로다 — `discover -b tests` **826 OK** · `discover -b -s tests`
(`scripts/merge-to-main.sh` 가 쓰는 꼴) **826 OK**. `tests/` 안의 상호 import **0건**이라
모듈 이름이 `tests.test_x` 로 바뀌어도 부를 자가 없다.

## 3. 대안이 갈린다 → **설계 phase 로 넘긴다**

- **A. 래퍼가 `Ran 0 tests` 를 판정이 아니라 사고로 읽는다** — 사고 «부류»를 막지만
  래퍼를 통과한 명령만 덮는다.
- **B. `tests/__init__.py` 한 개** — 오늘의 덫을 뿌리에서 없애지만 0건이 나오는 다른
  길(잘못된 `-k` · 빈 `-s` 대상 · 다른 cwd)은 그대로 초록이다.
- **C. A + B.**

**계획서 안에서 저울질하지 않는다**(`plan.md` 6-1절). 갈림길·처방·변이표는
`docs/design_zero-population.md` 가 정한다. 아래 스텝의 예상 파일은 설계가 갱신할 수 있다.

## 4. 스텝

세 스텝이고 사슬이 일렬이 아니다.

**스텝 1 — 재는 자를 세운다(먼저 빨갛게).** 의존: 없음.
0건으로 끝난 전수가 초록으로 보이는 것을 무는 단언. 오늘 트리에서 **빨개야** 한다.
- 예상 파일: `tests/test_verdict_wrapper.py`
- 완료 기준: 새 단언이 오늘 트리에서 RED 이고, 실패 메시지에 실측 `Ran 0 tests` 가 찍힌다.

**스텝 2 — 처방을 넣는다.** 의존: 1(스텝 1 의 단언을 읽고 초록으로 만든다).
- 예상 파일: 설계가 고르는 것 — `scripts/verdict.sh` 또는 `tests/__init__.py` 또는 둘 다
- 완료 기준: 스텝 1 의 단언이 초록. 변이(처방 줄 제거)를 심으면 그 단언만 다시 죽고
  원복은 `cmp -s` 로 확인한다. 전수 826 이상 OK.

**스텝 3 — 문서를 사실에 맞춘다.** 의존: 2(무엇이 참이 됐는지 읽어야 쓴다).
- 예상 파일: `docs/project.md`(「래퍼도 모집단은 못 지킨다 … 건수는 사람이 읽는다」가
  더는 참이 아니면 고친다)
- 완료 기준: `tests/test_docs.py` 전수 초록 · 읽기 예산 초과 0.

## 5. 하지 않을 것

- **건수의 «값» 을 못박지 않는다** — `README.md` 의 단위 수 가드가 이미 그 자다. 여기가
  다루는 것은 **0 대 0 아님**뿐이다. 다만 **그 가드가 `README.md:104` 동반 수정을
  강제한다**(스텝 1 에서 826→829). 계획 76·98 이 같은 자리를 안 적어 리뷰에 두 번
  걸렸으므로 여기 미리 적는다 — 이 계획이 손대는 파일에 `README.md` 가 든다.
- `tests/` 의 기존 파일을 고치지 않는다(스텝 1 이 더하는 단언 말고).
- `scripts/merge-to-main.sh` 를 건드리지 않는다 — 시작 디렉터리를 이미 명시한다.
- 의존성·스키마·`src/` 제품 코드 — 전부 범위 밖. 이 계획의 `src/` 는 **0줄**이다.

## 6. e2e 시나리오 (계획 시점에 확정)

1. 시작 디렉터리를 빠뜨린 전수를 **사람이 치던 대로** 친다 → 초록이 안 나온다.
2. 옳게 친 전수(`discover -b tests`)는 그대로 826 이상 OK · rc 0.
3. 래퍼를 통과한 0건도 마지막 줄이 초록이 아니다(`| tail -1` 로 봐도 그렇다).
4. `scripts/merge-to-main.sh` 의 전수 꼴(`-s tests`)이 처방 뒤에도 826 이상 OK.
