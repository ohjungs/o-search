# e2e 결과 — domain-key (017)

2026-08-27 · 브랜치 `loop/domain-key` (기점 `677ed3e`) · 자동(야간) · 반복 111

## 무엇을 사용자 관점으로 봤나

016 과 같다 — 여기서 "사용자" 는 **크롤당하는 사이트**다. 그래서 재는 자리도 우리
로그가 아니라 **서버가 요청을 받은 시각**이다 (`crawl_politeness_e2e.py` ·
`retry_interval_e2e.py` 와 같은 자세). 크롤러 내부 상태를 재면 "우리가 의도한 간격"
을 재는 것이지 사이트가 겪은 간격을 재는 것이 아니다.

계획이 연 문제는 한 문장이다 — **한 서버인데 표기가 다르면 다른 서버 취급.**
열쇠가 날 `netloc` 이라 `http://a.test` · `http://A.test` · `http://a.test:80` 이
큐도 `_last_fetch` 도 `_delays` 도 따로 갖는다. 호스트는 대소문자 무관이고
`:80`/`:443` 은 각 스킴의 기본 포트라, 셋은 **DNS 상으로도 소켓 상으로도 같은
서버 한 대**다. 선언한 `Crawl-delay` 가 표기 수만큼 나뉘어 빠져나갔다.

수단은 새 `e2e/domain_key_e2e.py`. 진짜 소켓·진짜 HTTP·진짜 robots 파서·진짜
프런티어가 돈다. 바깥 네트워크는 안 탄다.

**한 가지만 주입했다: 이름이 어느 포트로 가느냐.** `PORTS` 가 netloc → 로컬 임시
포트를 건네고 `HTTPConnection` 공장이 그리로 보낸다 — hosts 파일이 하는 일과 같은
층이다. URL 문자열·`Host` 헤더·robots 캐시 열쇠·프런티어 열쇠는 전부 진짜 그대로다.
**세 표기가 같은 실서버 하나로, 대조군만 다른 실서버로 간다** — 이 배치가 없으면
"같은 서버였다" 는 전제가 e2e 안에서만 참인 이야기가 된다.

### 2번을 따로 세지 않고 1번 안에서 재는 이유

`http://a.test:80/p2` 를 **다른 서버로 보내면** 그것이 같은 칸인지 아닌지를 못 잰다 —
같은 칸이라는 말의 뜻이 "한 서버에 나가는 요청들이 한 줄로 선다" 이기 때문이다.
그래서 세 표기를 한 실서버에 꽂고 **도착 순서 하나**로 잰다. 대신
`hosts == {a.test, A.test, a.test:80}` 단언을 붙였다 — **표기 하나를 안 따라가면
간격 단언이 공짜로 참이 되는** 구멍(016 이 같은 자리에서 겪은 것)을 막는 긍정 짝이다.

## 변이 — 이 e2e 가 실제로 무엇을 잡는가

세 갈래를 전부 심어 봤다 (사본 아닌 원본에 심고 `git checkout` 으로 되돌림,
`PYTHONDONTWRITEBYTECODE=1`).

| 변이 | 무엇을 되살리나 | 결과 |
|---|---|---|
| A `domain_key` → 날 `netloc` | **원래 버그 그대로** | `AssertionError: 표기가 다르다고 2초 선언이 새어 나갔다 — 서버 수신 간격 ['0.001', '0.000']` → **1** |
| B `domain_key` → 포트를 통째로 버림 | **과잉 수정** | `AssertionError: 기본이 아닌 포트가 a.test 의 2초에 묶였다 — ['8.019', '2.004']` → **1** |
| C `robots._base` 만 날 `netloc` | 열쇠는 고쳤는데 robots 캐시가 안 따라옴 | `AssertionError: 같은 서버의 robots.txt 를 3회 받았다(표기 ['a.test', 'A.test', 'a.test:80'])` → **1** |

**A 의 실측 0.001초가 계획서 1절이 탐침으로 적어 둔 0.002초와 같은 자리다** — 탐침이
재던 것과 e2e 가 재는 것이 같다는 뜻이다. 셋 다 빨강(1)이지 측정 불능(2)이 아니다.

**세 변이가 서로를 못 대신한다.** A 는 대조군 단언(3번)을 통과하고, B 는 1·2번을
통과하며, C 는 1·2·3번을 전부 통과한다. 단언 하나를 지우면 그만큼 눈이 먼다.

## 안 잰 것 · 남은 것

- **URL 정규화는 이 계획 밖이다** (계획 4절 · digest `[5]`). `http://A.test/p1` 과
  `http://a.test/p1` 은 지금도 **두 번 수집되고 두 행으로 저장된다.** 이 e2e 도 그
  전제 위에 서 있다 — 표기마다 경로를 갈라 놓은 것이 그 때문이다. 고쳐진 것은
  **예의 계약이 세는 칸** 하나뿐이다
- **읽을 수 없는 포트**(`:abc` · `:99999`)와 **IPv6 리터럴**은 여기서 안 잰다 —
  단위 테스트가 못박았고(`test_urls.py` · `test_frontier.py`), 크래시 경로는
  스텝 4 백지 리뷰가 실물로 재현해 닫았다. 로컬 서버로 재현하려면 소켓 층을 더
  주입해야 해서 e2e 로는 값이 안 나온다
- **끝점 하나**(`b.test.` ↔ `b.test`)는 계획 4절대로 안 건드렸다 — DNS 상 같은
  이름이지만 `Host` 헤더가 달라져 가상호스트가 갈릴 수 있다. 실물에서 보이면 그때 잰다
- **`Ctrl-C` 최악 대기**는 016 이 키운 그대로다 — digest `[6]`, `--deadline` 이 답
