# 계획 85 `iter-third-witness` — 반복 번호에 셋째 증인을 세운다

## 1. 왜 지금인가 — 등재한 그 실패가 같은 날 다시 났고, 지금 초록불 아래 있다

`digest ## 반복 실패` 39행이 어제 등재됐다: **「`iteration` 은 status·metrics 가
«나란히» 틀리면 아무도 못 잡는다」.** 오늘 탐색이 실물을 재니 **그 상태가 지금 그대로다.**

```
docs/status.md      iteration: 490
docs/metrics.md     | 반복 | 490 |          ← 둘이 서로 같다 → IterationSyncTest 초록
docs/history_current.md  `### 반복` 머리 최대값 = 494
전수 719건 OK · rc 0                          ← 아무도 안 문다
```

**원인은 등재된 것과 같은 모양이다.** `loop/backoff-429` 가 494 이전 지점에서 갈라져
나가 `status`·`metrics` 를 자기 쪽 숫자로 들고 있었고, 그것이 494 마감 **뒤에**
병합됐다(`ad1f674` 16:22 vs `d05ea2a` 15:06). 두 파일이 **나란히** 490 으로 돌아왔고
`iter_gap` 은 둘을 서로만 대조하므로 조용했다.

**증상이 하나 더 있다 — 번호가 겹친다.** `history_current.md` 의 `### 반복` 머리:

```
… 487 · 488 · 489 · 490 · 491 · 492 · 493   (계획 83 userinfo-leak)
   485~486                                   (계획 82 seed-tier1 — 485·486 재사용)
   494                                       (짧은 경로 archive-backlog)
   487~490                                   (계획 84 backoff-429 — 487~490 재사용)
```

마지막 항목이 **494 보다 뒤에 일어난 일인데 앞 번호를 달고 있다.**

**「마지막 항목」이 아니라 「최댓값」이어야 한다.** digest 39행은 처방을 「마지막
`반복 NNN`」이라 적었는데 오늘 실물에서 **마지막 항목은 490 이고 최댓값은 494** 다 —
적어 둔 처방을 그대로 코드로 옮겼으면 틀린 자를 세울 뻔했다. 병합 순서가 파일 순서를
뒤집을 수 있는 한, 붙들 수 있는 불변식은 **최댓값**뿐이다.

## 2. 처방 — `iter_gap` 에 셋째 증인을 준다

지금 판정: `metrics.반복 == status.iteration`. 둘이 한 병합에 함께 실려 오면 무력하다.

바꿀 판정: 위에 더해 **`status.iteration == max(history_current.md 의 ### 반복 머리)`**.

셋째 증인이 `history_current.md` 인 이유는 그것이 **다른 손이 쓰는 파일**이기 때문이다 —
status·metrics 는 덮어쓰기/숫자 갱신이고 history 는 append 다(`test_docs.APPEND_TARGETS`).
병합이 두 숫자를 함께 옮겨도 append 된 기록은 양쪽이 다 남는다. 실제로 오늘 그랬다.

**회전은 이 자를 안 깬다** — `history_current.md` 는 오래된 항목부터 밀려나므로 최댓값은
살아남고, 파일이 비는 것은 `HISTORY_ENTRY_FLOOR` 가 이미 막는다.

## 3. 스텝

| # | 산출물 | 완료 기준 | 의존 |
|---|---|---|---|
| 1 | `iter_gap` 셋째 증인 + `IterGapTest` 갈래 (TDD) | 갈래 테스트 먼저 실패 → 통과 · 전수 초록. **이빨의 증거는 `git show 9947049:docs/*.md`** — 오늘 아침 실물을 새 자에 먹여 490 ≠ 494 를 신고시킨다 | 없음 |
| 2 | 기록 정정 — `backoff-429` 항목 머리 `487~490` → `495~498` | 전수 초록(rc 0) · `### 반복` 머리가 494 → 495~498 → 499 로 이어진다 | 1 |
| 3 | 변이 3종 + digest 39행에 처방 등재 | 변이 3종이 각각 잡힌다 | 2 |

3스텝인 이유: 고칠 것이 함수 하나이고, 2번은 1번의 자가 없으면 「정정했다」를 검증할 수
없다. 3번은 이 저장소가 자를 세울 때마다 요구하는 절차(`test.md`)다.

**이 계획 phase 자신이 드리프트를 손으로 닫는다** — 반복 번호를 **499** 로 잡았다.
490 은 병합이 실어 온 틀린 값이고, 참값은 494(archive-backlog) + backoff-429 의 네
반복(495~498) 다음이다. 자를 세우기 전에 숫자를 맞춰 두는 이유는, 자가 서는 순간
실물이 빨간 것과 자가 이빨이 있는 것은 **다른 명제**이기 때문이다 — 후자는 1번의
`git show` 측정과 3번의 변이가 증명한다.

## 4. 번호를 495~498 로 정정하는 근거

`backoff-429` 의 네 반복은 494 **뒤에** 커밋됐다(`ad1f674` 16:22:07 · `d05ea2a` 15:06:45).
반복 카운터는 단조 증가라 뒤에 일어난 일이 앞 번호를 가질 수 없다. 494 다음은 495 다.

**옛 겹침(482 · 485~486 · 487~490 의 계획 83 쪽)은 건드리지 않는다.** 이미 아카이브·
digest·index 가 그 번호로 서로를 가리키고 있어 지금 바꾸면 인용이 통째로 깨진다.
새 자가 무는 것은 **최댓값 하나**라 옛 겹침이 남아도 판정은 성립한다.

## 5. 하지 않을 것

- **중복 번호를 무는 자를 만들지 않는다.** 오늘 실물에 이미 세 쌍이 있고, 켜는 순간
  영구 RED 다. 겹침은 다른 증상이고 근거(옛 병합들)도 이미 지나갔다.
- **`history_NNN.md` 아카이브는 안 읽는다.** 회전된 번호까지 세면 회전이 판정을 바꾼다 —
  자가 파일 회전에 흔들리면 안 된다.
- **`iteration` 을 자동으로 고치는 것은 안 만든다.** 자는 신고만 하고 정정은 사람/반복이
  한다. 자동 정정은 「나란히 틀린 것」을 조용히 나란히 만들어 준다.
- **`night_iterations` 축은 안 건드린다.** 밤당 리셋되는 다른 셈이다.
