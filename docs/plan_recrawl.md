# 계획 80 `recrawl` — 색인된 문서를 30일 안에 다시 방문해 갱신·삭제를 반영한다

## 1. 왜 지금인가

`docs/specs/concept.md:31` 기능 5 (*"재크롤: 색인된 문서는 30일 이내에 재방문해
갱신·삭제를 반영한다"*)가 `index.md` 사양 분할 **8번 중 유일하게 남은 미착수
항목**이다. 실물은 셋 다 안 한다:

- **재방문 0** — `crawl.py:250` 의 `store.has(url)` 이 **상태 불문·시각 불문**으로
  건너뛴다. 같은 DB 로 재실행하면 시드부터 스킵돼 0페이지로 끝난다.
- **갱신 0** — 같은 URL 의 `pages.html` 을 갈고 `index_pages()` 를 돌리면 새 본문
  **영영 0건** · 옛 본문 1건 (2026-09-08 야간 탐침 재현).
- **삭제 0** — `indexer.py` 는 `pages.status` 를 **한 번도 안 읽는다**(`indexer.py:404`
  주석이 「`url`·`html` 두 열만 본다」고 적어 둔 그 자리다). 404 를 받아도 색인은 남는다.

**막고 있던 사유 둘이 다 사라졌다.** ① 스키마 — `pages.fetched_at` 은 원래 있는 열이고
실물 400행이 400/400 갖는다(`min 2026-09-07 09:09:12` · `max 09:11:01`), 갱신 반영은
계획 78 이 만든 워터마크 루프(`indexer.py:243-260`)가 **이미 읽는 집합**이라
**마이그레이션 0줄**이다. ② 정책 — 사양이 숫자를 안 준 셋을 **2026-09-08 사용자가
위임했고 `digest.md` 에 답이 적혔다**(아래 2절).

## 2. 정해진 정책 셋 — 이 계획은 이대로 짓는다

1. **실패 상태도 다시 받는다. 다만 주기는 절반(15일)이다.** 4xx·5xx·`status 0` 은
   「없는 문서」가 아니라 「그때 못 받은 문서」다 — 안 받으면 일시 장애가 **영구 결손**이
   된다. 성공과 같은 30일로 두면 죽은 URL 을 영원히 같은 빈도로 두드리게 되므로 가른다.
   연속 실패 횟수로 늘리는 **백오프는 이 계획에서 안 한다**(5절) — 실측 근거가 없다.
2. **삭제 반영은 `docs` 행만이다. `pages` 는 묘비로 남긴다.** 지우면 「404 를 받았다」는
   사실이 사라져 다음 크롤이 그 URL 을 새 것으로 다시 줍고, 삭제가 **망각**이 되어 루프가
   돈다. `status`·`fetched_at` 을 든 행으로 남기고 검색에서만 뺀다 — 데이터 삭제가 아니라
   **야간 금지에도 안 걸린다.**
3. **재크롤은 링크를 다시 추출한다.** 안 하면 색인이 이미 아는 URL 안에서만 늙어
   프런티어가 안 자라고 기능 4(10만 문서)에 영영 못 간다. **새 링크는 기존 프런티어와
   같은 예산·같은 간격**을 쓴다 — 크롤 윤리가 갈림길 1순위라 재크롤이라고 예외는 없다.
   이것은 스텝 1 에서 **공짜로 온다**: `_store_result` 가 2xx 면 이미
   `frontier.add(links.extract(...))` 를 부른다(`crawl.py:342`).

## 3. 설계가 필요하다 — 갈림 넷

트리거 3개 해당: 파일 3개 이상(`store.py`·`crawl.py`·`indexer.py`) · 대안이 갈림 ·
저장 형태에 준하는 판정(신선도의 정본이 SQL 인가 Python 인가). `design_recrawl.md` 에서 고른다.

1. **신선도를 어디서 재나** — SQLite 의 `datetime('now','-30 days')` 인가 파이썬 시계인가.
   `store.upsert` 가 `datetime('now')`(UTC)로 박고 계획 78 이 「파이썬 시계를 쓰면
   타임존·해상도가 어긋나 비교가 조용히 틀린다」를 이미 겪었다(`indexer.py:201`).
2. **`store.has` 를 고치나, 술어를 새로 더하나** — 호출자 둘의 뜻이 다르다.
   `crawl.py:250` 은 「이 URL 을 지금 받을까」고 `crawl.py:337` 은 「리다이렉트 도착지가
   이번 실행에서 이미 저장됐나」다. 한 함수로 합치면 뒤쪽 의미가 조용히 바뀐다.
3. **삭제 반영을 워터마크 루프에 얹나, 경로를 따로 내나** — 그 루프는 지금 `p.html` 만
   집어 오고 `p.status` 를 안 든다. 얹으면 열 하나를 더 뜨는 값이고, 가르면 같은 집합을
   두 번 훑는 값이다.
4. **TTL 상수의 자리와 이름** — `store` 인가 `crawl` 인가. `project.md` 의 상수 인용
   가드(`ProjectConstTest`)가 무는 자리라 문서와 함께 움직인다.

## 4. 스텝

| # | 스텝 | 완료 기준 (검증 명령) |
|---|---|---|
| 1 | **크롤이 신선도를 본다** — `crawl.py:250` 이 「저장돼 있나」 대신 「아직 신선한가」를 묻는다. 2xx 는 30일, 그 밖은 15일. | 31일 된 200 행의 URL 은 다시 나가고 29일 된 것은 안 나간다 · 16일 된 404 는 나가고 14일은 안 나간다 · 리다이렉트 중복 검사(`crawl.py:337`)의 기존 동작 무변. `PYTHONPATH=src python3 -m unittest discover -b tests` |
| 2 | **색인이 갱신을 반영한다** — 워터마크 루프가 「noindex 면 지운다」에 더해 「본문이 갈렸으면 `docs` 행을 갈아 끼운다」를 한다. | 같은 URL 의 `pages.html` 을 갈고 `index_pages()` → 새 본문 검색 **1건** · 옛 본문 **0건**. 신규 문서 수(반환값)와 갱신 수가 섞이지 않는다. 같은 러너 |
| 3 | **색인이 삭제를 반영한다** — 404·410 을 받은 URL 을 `docs` 에서 뺀다. `pages` 행은 안 지운다. | 색인된 URL 이 404 로 재크롤되면 `search()` **0건** · `pages` 행은 `status=404` 로 **살아 있다** · 5xx 는 안 뺀다(일시 장애다). 같은 러너 |

각 스텝은 TDD 다 — 테스트를 먼저 빨갛게 만들고 스텝 **안**에서 초록으로 만든다
(계획 75 가 배운 것: 의도적으로 빨간 커밋을 밤새 브랜치에 남기지 않는다).

## 5. 하지 않을 것

- **`pages` 행 삭제** — 2절 정책 2 가 정한 묘비다. 데이터 삭제는 야간 금지이기도 하다.
- **연속 실패 백오프** — 15일 고정으로 시작한다. 실측 근거(실물 코퍼스에 실패 행 **0건**,
  status 분포 `200: 400`)가 없어 지금 정하면 숫자를 지어내는 것이다.
- **스키마 변경·마이그레이션** — `pages`·`docs`·`index_meta` 정의를 한 글자도 안 고친다.
  고쳐야 할 것이 나오면 그 자리에서 멈추고 보류한다.
- **정규화 안 된 옛 열쇠 통합** — `digest.md [high]`(반복 115). 마이그레이션이라 별건.
- **URL 자격증명(`userinfo@`) 처리** — `digest.md [high]` 보안 항목. 공개 동작 변경이라
  줄 수와 무관하게 야간 자동 적용 금지.
- **크롤 예산·간격 정책 변경** — 재크롤은 기존 `--max`·`--deadline`·도메인 간격을 그대로 쓴다.
- **`docs/specs/` 수정** — 사용자 영역이다.
- **기존 테스트 리팩터링** — 계약이 바뀌어 깨지는 것만 고치고, 깨진 쪽이 테스트인지
  제품인지 매번 판정해 기록한다(계획 78 이 실제로 겪었다).

## 6. e2e 시나리오 (초안 — `design_recrawl.md` 에서 확정)

1. 로컬 서버로 크롤 → 본문을 갈고 `fetched_at` 을 31일 전으로 돌린 뒤 재크롤 →
   **서버가 그 URL 을 다시 받고**, 재색인 후 **새 본문이 검색되고 옛 본문은 안 나온다**.
2. 29일 된 문서는 재크롤 요청이 **서버에 0건** 도착한다(TTL 이 자를 갖는다는 음성 대조).
3. 404 로 바뀐 URL 은 검색에서 사라지고 `pages` 묘비는 `status=404` 로 남는다.
4. 재크롤이 새로 생긴 링크를 주워 **프런티어가 넓어진다** — 그때 도메인 간격이
   1초 이상으로 지켜지는 것을 **서버 수신 시각으로** 잰다.
