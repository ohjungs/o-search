# 계획 48 — `passage-api`

**사양 확장이 만들라고 한 둘 중 하나가 남았다 — 근거 문단 API.** 계획 46 이 JSON 검색을
계약으로 만들었고(`version`·400·404·500·503), 계획 47 이 그 계약 밑의 DB 열기 구멍을 닫았다.
이 계획은 그 위에 **문단을 돌려주는 자리**를 세운다. 소비자가 사람의 브라우저가 아니라
**다른 시스템**이고, 그쪽이 원하는 것은 결과 목록이 아니라 **출처가 붙은 텍스트 조각**이다.

- **슬러그**: `passage-api`

- **기점**: `6e99031` (계획 47 e2e · DONE 커밋. 현재 HEAD)
- **phase**: 설계 (트리거 걸림 — 6절)
- **스텝**: 3개

## 1. 문제 · 목표 · 기대 결과

### 문제

`docs/specs/concept.md` 의 `# 확장: 다른 시스템이 쓰는 검색` 절이 만들 것을 둘로 적었다.
**1번 JSON API 는 계획 46 이 닫았고, 2번 근거 문단 API 는 오늘 없다.**
그 절의 `### 기능` 7번이 요구하는 셋(출처 URL · 문서 제목 · **문서 내 위치**) 중
**위치가 어디에도 없다.** 지금 `GET /search` 가 내주는 `snippet` 은
`snippet(docs, 0/1, …, '…', 20)` 의 산물이라 20토큰짜리 조각이고, 문서의 어디에서 왔는지
부르는 쪽이 알 방법이 없다 — 인용도 검증도 못 한다.

### 목표

`GET /passages?q=…` 가 **문단 N개**를 JSON 으로 돌려준다. 문단마다 출처 URL · 문서 제목 ·
문서 내 위치가 붙고, **위치가 없는 문단은 아예 안 돌려준다**(사양 기능 7의 마지막 문장).
그리고 그 응답이 사양의 두 숫자를 실측으로 통과한다 — **근거 정확도 90%**(기능 8) ·
**p95 500ms**(성능 5).

### 무엇이 이미 참인가 (이 저장소를 처음 여는 사람을 위한 전제)

- `src/websearch/serve.py` 의 `do_GET` 은 경로 셋으로 갈린다: `/`(화면) · `/search`(JSON) ·
  그 외 **404**. 새 경로는 `parts.path != "/search"` 줄(249행) 위에 한 갈래를 더하는 일이다.
- JSON 응답 계약은 `_send`(313행) 한 곳에 있다 — `{"version": VERSION, **payload}` 라
  200·400·404·500·503 이 전부 `version` 을 갖는다. **새 경로도 이 함수를 쓰면 계약을
  공짜로 물려받는다**(사양 기능 9 · 디자인 5).
- 파라미터 검증은 `_parse`(38행) 한 곳이고 `(query, page)` 를 돌려준다. `q` 없음·200자
  초과·`page` 범위 위반이 `ValueError` → **400** 이다.
- `src/websearch/indexer.py` 의 `search()`(202행)가 `(url, title, snippet)` 만 돌려준다 —
  **본문(`body`)을 안 돌려준다.** 문단을 자르려면 본문이 필요하다.
- `_connect()`(66행)가 DB 를 여는 유일한 자리이고 `FileNotFoundError`·`StaleIndexError` 가
  곧 **503**, 나머지 예외가 **500** 이다(계획 46·47 이 만든 계약).
- `pages` 테이블에 **원본 HTML 이 그대로 남아 있다** — `index_pages()` 가
  `SELECT url, html FROM pages` 로 읽고 지우지 않는다(126~129행).
- 오늘 실측: 단위 **506건 OK(12.431초)** · `e2e/*.py` **19종 rc 0** · p95 **8.90ms**.

### 착수 탐침 — 문단은 색인 안에 남아 있지 않다 (2026-09-02 실측)

`digest.md ## 다음 계획 후보` 의 `[7] 기록된 답을 실행 전에 다시 재라` 가 요구하는 것이다.
이 계획은 물려받은 처방이 없어서(사양이 직접 근거다) 대신 **전제를 쟀다.**

`src/websearch/extract.py` 의 `_normalize` 는 `" ".join("".join(parts).split())` 다.
블록 태그 경계에 `_separate()` 가 넣는 것도 **공백 한 칸**이라, 낱말 사이 공백과
문단 사이 공백이 색인 뒤에는 **구별되지 않는다.**

탐침(`<h2>`·`<p>`×3·`<ul>` 이 든 HTML 을 `extract_text` 에 넣었다):

```
body = '재료 배추 한 포기와 소금을 준비한다. 고춧가루는 다섯 큰술이면 넉넉하다. 배추 소금 냉장 보관법: 김치는 4도에서 익힌다.'
개행 0 · 연속 공백 0
```

**즉 `docs.body` 에서는 문단을 복원할 수 없다.** 사양 기능 7이 요구하는 «문서 내 위치» 를
어디서 얻을지가 이 계획의 본체이고, 그것이 6절의 설계 트리거다.

두 번째 탐침 — **원본 재파싱이 예산 안에 드는가**(위 갈림길 하나를 죽이지 않으려고 쟀다):

| `pages.html` 크기 | `extract_text` 1회 | 10건이면 |
|---|---|---|
| 975 B (블록 20) | 0.13 ms | 1.3 ms |
| 4,655 B (블록 100) | 0.54 ms | 5.4 ms |
| 18,455 B (블록 400) | 2.08 ms | 20.8 ms |

**셋 다 예산 500ms 의 5% 미만이다** — 성능이 갈림길을 아직 안 가른다. 그러므로 설계는
"싼 것" 이 아니라 **"위치가 무엇을 뜻하나"** 로 갈라야 한다.

## 3. 스텝 (그래프)

노드는 산출물, 엣지는 진짜 의존이다.

```
[1] indexer 가 문단을 돌려준다 ──┬──▶ [2] GET /passages 배선 ──▶ [3] 두 숫자를 잰다
                                 └──────────────────────────────▶ (정확도만은 1 에만 의존)
```

**1. `indexer` 가 문단을 낸다** — 질의에 매치된 문서에서 문단을 잘라
   `(text, url, title, 위치)` 를 돌려주는 함수 하나. 위치가 없으면 그 문단은 안 낸다.
   검증: `tests/test_indexer.py` 에 새 단언 — 문단 경계·위치 값·빈 결과·옛 색인(503 경로)·
   **위치 없는 문단이 안 나온다**. 러너는 `PYTHONPATH=src python3 -m unittest discover tests`.

**2. `GET /passages` 배선** — `serve.do_GET` 에 갈래 하나. `_send`·`_parse` 를 재사용해
   `version`·400·404·500·503 을 **물려받는다**(새로 만들지 않는다).
   검증: `tests/test_serve.py` 에 새 단언 — 200 스키마 · `q` 없음 400 · 없는 DB 503 ·
   손상 DB 500 · 모든 응답에 `version` · **화면(`/`)과 `/search` 응답 무변경**.
   의존: 1(그 함수를 부른다).

**3. 두 숫자를 잰다** — 사양 기능 8(문단의 90% 가 질의어 또는 그 2-gram 을 포함) ·
   성능 5(p95 500ms). 둘 다 **실행 가능한 판정**이어야 한다(종료 코드 0/1/2).
   검증: 그 측정 명령을 실제로 돌려 두 숫자를 `docs/project.md` 에 기준선으로 적는다.
   의존: 정확도는 1, p95 는 2.

**임계경로는 1 → 2 → 3** 이다. 3의 정확도 축만 1 에 직접 붙지만, 야간에는 worktree 를
가르지 않으므로(`rules/plan.md` 3-1절) 순차로 돈다.

## 4. 완료 기준 (검증 가능한 것만)

- `GET /passages?q=김치` 가 **200 + 문단 목록**이고 문단마다 `url`·`title`·위치가 있다.
- 위치가 없는 문단은 응답에 **0건**이다.
- 실패 응답이 전부 JSON 이고 `version` 을 갖는다 — `q` 없음 **400** · 없는 DB **503** ·
  옛 색인 **503** · 손상 DB **500** · 없는 경로 **404**.
- **근거 정확도 ≥ 90%** — 측정 명령이 실측값을 찍고 미달이면 종료 1.
- **p95 ≤ 500ms** — 측정 명령이 실측값을 찍는다.
- 단위 스위트 **506건 + 새 단언 전부 OK**, `e2e/*.py` **19종 전수 rc 0**(회귀 없음).
- `README.md` 의 단위 건수·e2e 종수가 실제와 맞는다(`tests/test_readme.py` 가 센다).
- `python3 -m websearch.serve` 명령이 **늘지 않는다**(사양 경량 4) · 의존성 **0 유지**(경량 5).

## 5. 하지 않을 것

- **생성(LLM 호출)·임베딩·벡터 DB** — 사양 `## 하지 않을 것` 이 명시적으로 닫았다.
  이 저장소는 R 만 한다.
- **속도 제한** — 사양 `## 사람이 정할 것` 1번이고 시점은 사람이 정한다. 열지 않는다.
- **`pages`·`docs` 스키마 변경 · 기존 `data/crawl.db` 마이그레이션** — `digest.md
  ## 판단 필요` 의 recrawl·정규화 항목과 **같은 수술**이고, 그 항목이 «마이그레이션이자
  데이터 형태 변경이라 야간 금지 — 사람 승인» 으로 이미 판정해 뒀다.
  설계가 재색인을 요구하는 안을 고르면 **거기서 보류하고 사람에게 올린다.**
  (2026-09-02 테스트 3: 원래 `status.md ## 한도` 를 가리켰는데 **그 절이 없다** —
  러너 명령 문장이 `project.md ## 명령` 으로 옮겨질 때 함께 사라졌고, 남은
  `project.md ## 한도` 는 크롤러·네트워크만 담아 이 금지를 안 든다. 없는 절을 새로
  만드는 대신 **실제로 판정을 든 자리**로 참조를 옮겼다.)
- **화면(HTML)에 문단을 붙이는 것** — 이 소비자는 기계다. `_send_html` 경로는 안 건드린다.
- **`/search` 응답 스키마 변경** — 계획 46 이 만든 공개 계약이다. 필드를 더하지도 않는다.
- **OFFSET 페이지네이션 드리프트** — `digest.md ## 다음 계획 후보` 의 `[7] 게이트가 열렸다`
  항목이 "사람이 정할 갈림길" 로 못박아 뒀다. `/passages` 에 페이지를 열지 않으면 안 만난다.
- **`docs/specs/` 편집** — 읽기 전용이다.

## 6. 설계가 필요하다 — 트리거 넷이 걸린다

`rules/design.md` 1절 기준으로:

| 트리거 | 이 계획에서 |
|---|---|
| 공개 인터페이스 추가 | 새 엔드포인트 `GET /passages` 와 그 응답 스키마 |
| 새 모듈·파일 생성 | 측정기와 문단 자르기를 어디에 둘지 (새 파일이 될 수 있다) |
| 3개 이상 파일에 걸침 | `indexer.py` · `serve.py` · 측정기 · README |
| **대안이 2개 이상 갈림** | 아래 |

**설계가 갈라야 할 것 — 문단을 어디서 얻나.** 셋 다 동작하고 결과가 다르다.

| 안 | 문단의 출처 | 위치의 뜻 | 대가 |
|---|---|---|---|
| A 원본 재파싱 | `pages.html` 을 질의 시점에 다시 판다 | 블록 순서(N번째 블록) | 질의 경로가 `pages` 에 의존한다 (10건 21ms — 예산 안) |
| B 표식 색인 | `extract` 가 블록 경계 표식을 `body` 에 남긴다 | 표식 사이 순서 | **재색인이 필요하다** — 5절 한도에 걸릴 수 있다 |
| C 문자 창 | `docs.body` 를 문자 창으로 자른다 | 본문 문자 오프셋 | 사양의 «문단» 을 «창» 으로 바꿔 읽는 것이다 |

부수 갈림길 셋도 함께 정한다: ① 응답 파라미터(문단 수를 받나 · `_parse` 를 재사용하나
넓히나) ② 위치의 표기(블록 인덱스 · 문자 오프셋 · 둘 다) ③ 정확도 측정기를
`e2e/quality_eval.py` 에 얹나 새 파일로 두나(코퍼스·질의 셋은 **동결**이다).

**대안이 갈리므로 다음 phase 는 설계다.**

## 7. 위험

- **가장 큰 위험은 사양의 «문단» 을 조용히 «스니펫» 으로 바꿔 읽는 것이다.** 그러면
  오늘 `/search` 가 이미 내주는 것과 같아지고 계획이 아무것도 안 만든 것이 된다.
  방어: 완료 기준에 «위치 없는 문단 0건» 을 넣었다 — 위치를 못 만드는 안은 이 줄에서 죽는다.
- **정확도 90% 는 fixture 에 달린 숫자다.** 코퍼스 64문서·질의 40개는 동결이고
  전부 완전한 낱말이다(`digest.md ## 다음 계획 후보` 의 `[6] porter 가 어휘 11.2%…`
  항목이 적은 눈멂이 여기에도 그대로 걸린다). **이득과 손실을 같은 표본으로 재라**
  (같은 절의 `[6] 거래를 재려면 양쪽을 같은 자로 재라`).
- **p95 500ms 는 3000문서에서 잰 숫자가 된다** — 사양의 예산은 100만 문서 기준이다.
  `project.md` 의 기준선 줄과 같은 주의를 함께 적는다.
