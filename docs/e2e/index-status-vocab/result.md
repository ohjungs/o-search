## e2e 가 잡은 것 — `[E129-1]`

**실패 메시지가 짧은 경로 행에 «없는 행 이름»을 댔다.** 시나리오 1' 에서 메시지가
`` `plan_digest-cap-verdict` 행 `` 이라고 인쇄했는데 그 표에 그런 행 머리는 **없다**
(실물은 `| (짧은 경로) digest-cap-verdict |` 다). `ANY_PLAN_ROW` 가 접두를
**비캡처**로 두므로 어느 꼴로 걸렸는지 모르는데 `plan_%s` 를 박아 적은 것이다.

- **왜 설계 계약 위반인가**: 계약이 「실패 메시지는 슬러그와 칸 원문을 댄다 — 어느
  행인가를 사람이 다시 찾지 않게」다. 24행에 대해 **그 계약을 못 지켰다.**
- **왜 「그냥 보기 나쁜 것」이 아닌가**: 두 등재 꼴이 이 표에 **섞여 산다**
  (`ANY_PLAN_ROW` 주석 실측: `interval-call-site` 는 `plan_` 꼴, `verdict-head` 는 뒤
  꼴). 같은 슬러그가 두 꼴로 다 있으면 **없는 행이 아니라 «다른» 행을 가리킨다.**
- **처방**: 메시지 셋에서 `plan_` 접두를 뺐다(슬러그만 댄다) + docstring 에 이유를
  적었다. 수정 뒤 두 꼴 다 제 슬러그를 그대로 인쇄한다.
- **합성 갈래가 못 잡은 이유**: 테스트들이 `assertIn("delta", gap)` 처럼 **슬러그만**
  확인한다 — `plan_delta` 든 `delta` 든 통과한다. **실물 표에서 그 이름을 실제로 찾아
  보는 것만이 이 종류를 잡는다**(`review.md` 0절의 「작성자 머리 밖」).
