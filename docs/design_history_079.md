# 설계: 판정을 **마지막 줄**로 옮긴다 (계획 106 `verdict-last`)

## 결정 — 얇은 zsh 래퍼가 러너를 감싸고, **판정과 `rc` 를 stdout 의 마지막 한 줄로 다시 찍는다**

고치는 것은 **손버릇이 아니라 출력의 순서**다. 판정이 마지막 줄에 있으면
가장 자주 붙는 손(`tail`)이 **오히려 판정만 남긴다** — 방아쇠를 없애는 대신
**방아쇠를 무해하게** 만든다. 조항은 지우지 않는다(래퍼가 안 덮는 자리가 남는다).

## 왜 문장이 아니라 기제인가 — 이미 셋을 썼다

| 시도 | 결과 |
|---|---|
| `project.md:7` 조항 「전부 맨몸으로 돈다」 | ⑩⑬ 이 뚫었다 |
| 조항을 「러너를 부르는 **모든** 호출」로 조이기 | ⑬⑭ 가 뚫었다 |
| 「러너를 파이프의 **왼쪽**에 두지 않는다」 | ㉒ 가 뚫었다 |

**35회 중 서른네 번이 연속**이고, 여러 번 **이 항목을 읽은 같은 반복 안에서** 났다.
항목 자신의 결론이 「문장은 소진됐다」다.

## 무엇이 사라지는가 — 손실이 **셋**이고 원인이 다르다

계획서 1-1 의 탐침 셋을 그대로 읽으면 이렇다.

| # | 사라지는 것 | 원인 | `-b` 가 막나 |
|---|---|---|---|
| ① | `Ran/OK` 줄 | 판정은 stderr(**무버퍼**)인데 테스트 stdout 은 파이프 아래 **블록 버퍼**라 끝에 한꺼번에 밀려 나온다 — **순서 역전** | **초록일 때만**. 실패한 테스트의 출력은 `-b` 가 안 삼킨다 |
| ② | 판정 전부 | `2>/dev/null` — 판정이 stderr 다 | 아니다 |
| ③ | `rc` | 파이프 오른쪽 명령의 종료 코드가 `$?` 가 된다 | 아니다 |

**①이 「빨간 판에서만 안 보인다」는 것이 이 설계의 핵심**이다. 대조군(`-b` + 파이프)이
초록이었던 것은 판정이 안전해서가 아니라 **밀어낼 stdout 이 없어서**다. 즉 오늘의
관용구는 **초록일 때 초록이고 빨간 날 눈이 먼다** — 막으려는 사고와 정확히 같은 모양이다.

후보 `[9]`(「`unittest -b` 로 충분하다」)가 ⑳에서 기각된 이유가 여기 있다: `-b` 가
삼키는 것은 **통과한 테스트의 stdout** 뿐이라 ①의 빨간 절반도, ②도, ③도 못 막는다.

## 대안 비교

| | **A. 얇은 쉘 래퍼** | B. `unittest` 러너 서브클래스 | C. 조항만 더 조인다 |
|---|---|---|---|
| 되돌리기 | 파일 하나 삭제 | 파일 하나 삭제 + 호출 되돌리기 | 즉시 |
| 코드량 | **~10줄** | ~40줄(러너 + 진입점) | 0줄 |
| ①②③ 을 덮나 | **셋 다** | ①② 만 — `rc` 는 프로세스 밖 문제라 못 만진다 | **하나도 못 막는다(실증 35회)** |
| 러너 밖(`e2e/*.py` 22종·`merge-to-main.sh`)도 덮나 | **덮는다** — 아무 명령이나 감는다 | **못 덮는다** — `unittest` 전용 | 해당 없음 |
| 기존과 일치 | ○ `scripts/merge-to-main.sh` 가 이미 zsh 다 | △ 새 모듈 유형 | ○ |
| 다음이 편한가 | ○ | △ e2e 를 덮으려면 두 벌이 된다 | ✕ |

**A 를 고른 결정적 칸은 「러너 밖도 덮나」다.** 이 저장소가 밤마다 치는 것은
`unittest` 만이 아니다 — 품질 기준 표 일곱 줄 중 여섯이 `e2e/*.py` 이고 ⑮·⑯·⑳ 의
실제 위반 자리가 거기였다. B 는 위반 표본의 절반을 구조적으로 못 덮는다.

**C 를 표에 남긴 이유**는 기각하기 위해서다. 35회가 C 의 실측값이다.

## 결정된 형태 — /tmp 탐침으로 실제로 돌려 보고 정했다 (커밋 안 함)

```zsh
#!/bin/zsh
log=$(mktemp)
trap 'rm -f "$log"' EXIT INT TERM
"$@" 2>&1 | tee "$log"
rc=${pipestatus[1]}
print -r -- "── $(grep -E '^(Ran |OK|FAILED)' "$log" | tr '\n' ' ')rc=$rc"
exit $rc
```

**두 판을 만들어 대 봤다**(가짜 러너: stdout 200줄 + stderr 판정 + `exit 1`).

| 판 | `\| tail -1` | `2>/dev/null \| tail -1` | 맨몸 `rc` | 실행 중 화면 |
|---|---|---|---|---|
| `tee` + `pipestatus[1]` | `── Ran 812 … FAILED (failures=3) rc=1` | **같음** | 1 | **흐른다** |
| `>log` 후 `cat` | 같음 | 같음 | 1 | **끝날 때까지 없다** |

**판정 축에서는 둘이 같고**, 갈린 것은 실행 중 화면뿐이라 **흐르는 쪽**을 골랐다 —
25초짜리 전수는 몰라도 분 단위 e2e 에서 「멈춘 건가」를 구별할 수 있어야 한다.
값은 `pipestatus` 라는 zsh 낱말 하나이고, 그것이 틀렸을 때의 증상(`rc` 가 `tee` 의 0)이
**정확히 이 계획이 막는 사고**라 **변이 ②로 못박는다.**

### 출력을 줄이지 **않는다**

래퍼는 원래 출력을 **그대로 흘린다.** ⑳ 이 도달한 지점이 이유다 —
방아쇠 「출력이 길다」의 나머지 절반은 **「빨간 쪽이 길다」**이고 그건 줄이면 안 되는
쪽이다. 이 설계가 바꾸는 것은 **길이가 아니라 순서**다.

### 판정은 stdout 으로 찍는다

`print` 의 기본이 stdout 이라는 것이 손실 ②(`2>/dev/null`)를 덮는 유일한 이유다.
stderr 로 찍으면 래퍼가 **원래 버그를 그대로 물려받는다** — 변이 ③이 그 자리다.

## 계약

1. **마지막 줄이 판정이다.** `tail -1` 로 잘라도 `Ran`·`OK|FAILED`·`rc` 셋이 다 있다.
2. **`rc` 는 감싼 명령의 것이다.** `tee` 의 것도, `grep` 의 것도 아니다.
3. **래퍼의 종료 코드도 감싼 명령의 것이다.** 파이프 없이 쓰면 `$?` 가 그대로 산다.
4. **원래 출력은 안 줄인다.** 흐르는 것과 로그에 남는 것이 같다.

## 하지 않을 것 (계획서 5절 + 설계에서 더하는 것)

- **`-q`·필터·요약** — 계약 4 를 깬다
- **`e2e/*.py` 22종을 래퍼로 감싸기** — 래퍼는 아무 명령이나 감으므로 **감을 수 있게만**
  해 두고, 실제로 갈아끼우는 것은 스텝 3 의 범위 밖이다(값이 확인되면 후보로 등재)
- **조항 삭제** — 기제가 덮는 것은 「래퍼를 통해 부른 것」뿐이다. 맨손으로 러너를
  직접 치는 길은 그대로 열려 있고, 그 자리는 여전히 조항이 지킨다
- **`bash` 호환** — `pipestatus` 는 zsh 다. 이 저장소의 유일한 쉘 스크립트가 이미 zsh 고,
  둘 다 지원하면 그 분기가 **아무 테스트에도 안 걸리는 코드**가 된다

## 천장 (ponytail:)

- 래퍼를 **안 거치고** 러너를 직접 치면 아무것도 안 바뀐다. 이 자는 **강제가 아니라
  이유 제거**다 — 강제하려면 `~/.claude` 의 훅이어야 하고 그건 저장소 밖이다(`status.md` ⑤)
- 판정 `grep`(최종 표기는 아래 「리뷰가 고친 것」)은 `unittest` 의 표기에 묶여 있다. e2e 스크립트는
  그 낱말을 안 쓰므로 판정 칸이 비고 **`rc=N` 만 남는다** — 그게 e2e 에서 재는 값이라 족하다

## 스텝 (계획서 그대로 · 설계로 안 갈렸다)

셋 그대로. 스텝 2 의 변이 셋이 위 계약 1·2·3 에 하나씩 붙는다.

## 리뷰가 고친 것 — **위 초안 세 줄이 틀렸다** (2026-09-19 · 반복 631)

리뷰 phase 백지 패스가 낸 결함 여섯 중 **셋이 구현의 실수가 아니라 이 문서의 초안**이다.
그대로 두면 다음 사람이 「설계와 다르다」며 되돌리는 순간 셋이 함께 살아난다. 셋 다
**고치기 전 코드로 되돌려 빨강을 확인**하고 테스트를 붙였다(`VerdictReviewTest`).

| 초안 | 무엇이 나나 | 실제 코드 |
|---|---|---|
| `trap 'rm -f "$log"' EXIT INT TERM` | **심각도 8.** Ctrl-C 가 트랩만 돌리고 셸이 정상 경로로 빠져나가 **`── rc=0` 을 찍고 0 으로 끝난다**(실측) | `stopped 130`/`143` 을 INT·TERM 에 따로 걸고 EXIT 는 정리만 |
| `grep -E '^(Ran \|OK\|FAILED)'` | 크롤 로그의 `OKAY …` · `FAILED to fetch …` 가 판정 칸에 섞여 **마지막 줄을 위조한다**(실측) | `'^(Ran [0-9]+ test\|OK$\|OK \(\|FAILED \()'` |
| `log=$(mktemp)` | ⑴ 인자 없는 `mktemp` 는 macOS 에서 **`TMPDIR` 을 안 본다**(`_CS_DARWIN_USER_TEMP_DIR`) ⑵ 실패하면 빈 `$log` 로 나아가 **판정 칸이 빈 채 초록**이 된다 | 자리를 명시하고 실패하면 `rc=2` |

**첫 줄이 이 계획의 논지 자체를 친다** — 막으려던 사고(초록으로 보이는 실패)를
**정리 코드가 새 경로로 재현했다.** 그래서 중단은 판정과 구별해 찍는다(`── 중단됨 rc=130`):
`Ran/OK` 를 지어내면 그 줄이 또 하나의 거짓말이 된다.

나머지 셋은 문서 쪽이었다 — `| head` 는 SIGPIPE 라 안 덮는다(천장 주석으로), 단위 수
`818`→`826`, 그리고 초록 경로 테스트의 `assertEqual(0, rc)` 가 **파이프 아래 `tail` 의
rc 라 공허**했던 것(맨몸 호출로 다시 재게 고쳤다).
