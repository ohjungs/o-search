# 계획 67 — `spec-citation-address`

저장소가 `docs/specs/concept.md` 를 **줄 번호로 18곳에서 인용하는데, 그 주소가 맞는지
아무도 안 잰다.** 오늘 실측하니 **5곳이 빈 줄을 가리키고, 4곳은 자기가 따옴표로 옮겨 적은
문구가 그 줄에 없다.** 값은 다 맞고 주소만 썩었다 — 사양에 줄 하나가 끼거나 빠질 때
열여덟 개 주소가 **조용히** 한 칸씩 밀리는 구조다.

**근거**: `digest [7]③`(2026-09-06 계획 65 e2e phase 등재 · `digest ## 다음 계획 후보 (테스트 phase 갭)` 의 `QualityBandTest` 항목 ③) —
「**세 번째 사본 `docs/specs/concept.md` 는 여전히 안 묶여 있다**」. 계획 65·66 이 묶은 것은
README ↔ `e2e/*.py` 상수 두 사본이고, 세 번째 사본인 사양은 그 밖에 남았다. 같은 항목이
「③ 사양 축은 사람이 고치는 읽기 전용 문서라 **별도 판단**」으로 잘라 뒀고, `digest [5]`
(`digest` 의 「예산 `500` 이 테스트 안에서 두 번 리터럴이고 `docs/specs/concept.md` 와 안 묶여 있다」 항목)도 「사양-테스트 인용 가드는 `DocCitationTest` 가
**문서만** 훑는 오늘 구조를 넓히는 일이라 **별건으로 판단한다**」로 같은 자리를 가리킨다.
**이 계획이 그 별건이다.** `docs/status.md` 가 반복 386 을 닫으며 「`concept.md` 세 번째
사본 `[7]③` 이 첫 자리다」로 지목한 것과 같다.

**여는 조건이 이미 왔다 — 잠복이 아니다.** digest 는 ③ 을 「오늘 셋 일치를 다시 확인했다」로
적고 넘겼는데, 그 확인은 **값**만 봤다. 2절이 **주소**를 재니 오늘 이미 거짓이다.

## 1. 문제 · 목표 · 기대 결과

**문제.** `concept.md:<N>` 인용은 이 저장소가 「이 상수는 사양의 여기서 왔다」를 적는
유일한 방법인데, **주소가 실재하는지 보는 단언이 0개**다.

- **① 다섯 곳이 빈 줄을 가리킨다.** `concept.md:49` · `concept.md:49-54` 는 사양 49행이
  **빈 줄**이다(디자인 축은 50~54행). 인용이 통째로 한 칸 밀렸다.
- **② 네 곳은 자기가 옮겨 적은 문구가 그 줄에 없다.** `JS_BUDGET`(`e2e/design_check.py:33`)과
  「JS 0KB 계약」(`tests/test_serve.py:918`)이 `concept.md:50` 을 대는데 50행은 「화면은
  둘뿐」이고 JS 50KB 는 **51행**이다. `TOP_N = 10 # concept.md:22 "상위 10건"`
  (`e2e/quality_eval.py:34`)과 「`concept.md:22` 가 "80% 이상"이다」
  (`tests/test_quality_eval.py:153`)가 대는 22행에는 그 두 문구가 없다 — **23행**이다.
- **③ 그래서 값 대조도 못 자란다.** `digest [5]` 가 미룬 「예산 `500` 을 사양에 잇는다」는
  주소가 맞아야 설 수 있다. 주소가 썩은 위에 값 가드를 세우면 거짓 초록이 하나 는다.

**이 파일이 존재하는 이유와 같은 모양의 구멍이다** — `tests/test_readme.py:3-6` 는
「README 가 없는 모듈 `websearch.cli` 를 안내한 채 419건 초록 위에서 8일을 갔다」로
자기 존재 이유를 적는다. 문서와 코드 **사이**는 소스만 보는 테스트가 구조적으로 못 본다.

**목표.** `src/`·`tests/`·`e2e/` 의 모든 `concept.md:<N>`(및 `<N>-<M>`) 인용에 대해
**① 주소가 사양의 빈 줄이 아닌 줄을 가리키고 ② 그 인용이 따옴표로 옮겨 적은 문구가
가리킨 줄 범위 안에 실제로 있는지**를 잰다. 사양은 **읽기만** 한다.

**기대 결과.** 가드를 먼저 심으면 **오늘 상태에서 ①이 5건 · ②가 4건 RED** 다. 인용 쪽
주소를 고치면 전수가 초록으로 돌아오고, 그 뒤 **사양에 줄 하나를 끼우는 편집은 다시 RED** 다.

## 2. 착수 탐침 — 주소는 오늘 이미 틀렸다 (2026-09-06 · 반복 387)

`digest [7]`(「기록된 답을 실행 전에 다시 재라」)를 적용해 digest 의 「오늘 셋 일치」를
다시 쟀다. **정적 판독이라 변이를 안 걸었다**(`digest` 의 정지 사례 2회 — 읽으면 끝나는
것에 변이 예산을 쓰지 않는다). 워킹트리 무변경, 전수는 기준선 한 판만 돌렸다.

| 판 | 무엇을 쟀나 | 결과 |
|---|---|---|
| **기준선** | 저장소 원본 · 전수 | `Ran 625 tests in 15.969s` · `OK` · rc 0 |
| **P1** | `concept.md:<N>` 인용 전수 · 대상 줄 출력 | **18건** — 그중 **5건이 빈 줄(49행)** |
| **P2** | 인용문이 대상 줄에 있나 (`:50` JS · `:22` 상위10·80%) | **4건 불일치** — 정답은 51행 · 23행 |
| **P3** | 인용을 읽는 단언이 있나 (`grep -rn concept tests/ e2e/ src/`) | **0건** — 전부 주석·docstring |

**주소가 맞는 것도 실측으로 갈랐다** — `:44`(초당 5문서) ×3 · `:53`(대비 4.5) ×2 ·
`:54`(360px) · `:59`(우선순위) ×2 · `:22-23`(범위 인용) 은 오늘 참이다. **가드는 이 아홉을
안 물어야 한다**(오탐 0). 틀린 아홉과 맞는 아홉이 같은 파일 안에 섞여 있어, 「전부 빨갛다」나
「전부 초록이다」는 둘 다 배선 오류의 신호다(`digest [6]` 탐침의 배선을 먼저 의심한다).

**digest 의 처방을 정정한다.** `[7]③` 은 「사양 축은 별도 판단」까지만 적고 무엇을 잴지는
안 적었고, `[5]` 는 처방을 「지역 상수 `BUDGET_MS = 500` 으로 **테스트 안을** 먼저 묶는
두 줄」로 적어 뒀다. **그 두 줄은 이 계획이 여는 구멍을 안 막는다** — 값을 상수로 모아도
주소는 여전히 아무도 안 본다. 값 축은 5절로 미루고 **주소 축을 먼저** 연다.

## 3. 스텝 — 2개

**스텝 1 — 주소 축.** `tests/test_docs.py` 에 인용 주소 가드 한 벌을 더한다. 인용을
정규식으로 전수 수집해 `subTest` 로 파일·줄마다 돈다. 단언: 대상 줄 번호가 사양 길이
안이고, 범위의 **첫 줄이 빈 줄이 아니다.** 그 뒤 인용 쪽 다섯 자리를 고친다
(`49` → `50` · `49-54` → `50-54`). **사양은 안 고친다.**

**스텝 2 — 인용문 축.** 같은 수집기 위에, 인용과 같은 줄에 **따옴표로 옮겨 적은 문구**나
바로 앞 상수의 값 표기가 있으면 그 문자열이 대상 줄 범위 안에 실재하는지 단언한다.
그 뒤 네 자리를 고친다(`:50` → `:51` ×2 · `:22` → `:23` ×2).

스텝 1 이 먼저인 이유는 **주소가 맞아야 문구를 찾을 자리가 정해지기 때문**이다. 스텝 2 만
먼저 넣으면 빈 줄을 가리키는 다섯이 「문구가 없다」로도 빨개져 라벨이 뭉개진다.

## 4. 완료 기준 — 무엇이 죽어야 통과인가

각 줄은 **살아 있으면 실패**인 편집을 하나씩 이름으로 든다. 대조군 편집은 저장소 밖
`mktemp -d` 사본에서만 심고, 심기 전에 앵커 줄이 정확히 1개인지 먼저 단언한다
(`digest [8]` — 변이가 실제로 심어졌는지를 먼저 단언한다).

| # | 죽어야 하는 편집 | 어느 단언이 물어야 하나 |
|---|---|---|
| C1 | 고친 주소를 되돌린다 (`concept.md:50-54` → `49-54`) | 스텝 1 · 빈 줄 단언 |
| C2 | 사양 머리에 줄 하나를 끼워 전체를 한 칸 민다 | 스텝 1 · 다수 RED (`subTest` 라벨에 파일:줄) |
| C3 | 없는 주소를 인용한다 (`concept.md:9999`) | 스텝 1 · 길이 단언 |
| C4 | 고친 인용문 주소를 되돌린다 (`:51` → `:50`) | 스텝 2 · 문구 단언 |
| C5 | 인용문만 바꾼다 (`"상위 10건"` → `"상위 20건"`) | 스텝 2 · 문구 단언 |
| C6 | 가드의 빈 줄 검사만 지운다 | C1 이 **되살아나야** 한다 |
| C7 | 가드의 수집 정규식을 못 물게 깬다 (`concept\.md:` → `concept\.mdX:`) | 수집 건수 하한 단언 (0건 수집 = 초록은 거짓) |

- **오탐 0**: 오늘 맞는 아홉 인용(`:44` ×3 · `:53` ×2 · `:54` · `:59` ×2 · `:22-23`)은
  두 스텝 어디서도 안 빨개진다.
- **전수**: 스텝마다 `PYTHONDONTWRITEBYTECODE=1 PYTHONPYCACHEPREFIX=$(mktemp -d)
  PYTHONPATH=src python3 -m unittest discover -s tests -b` 가 `OK` · rc 0.
  기준선은 625 건이고 새 단언이 붙은 만큼만 는다(`README.md` 건수 줄을 함께 고친다 —
  `tests/test_readme.py` 가 그 숫자를 문다).
- **제품 무변**: `src/` 0줄 · `docs/specs/` 무변 · `data/crawl.db` 무변 · 새 의존성 0.
- **TDD**: 각 스텝은 가드를 먼저 심어 **RED 건수를 판정 줄로 기록**한 뒤(①5건 ②4건)
  인용을 고쳐 GREEN 으로 간다. RED 를 못 본 스텝은 완료가 아니다.

## 5. 하지 않을 것

- **`docs/specs/concept.md` 를 고치지 않는다.** 읽기 전용이다(`rules/discover.md` 0절).
  주소가 어긋나면 **인용 쪽을** 고친다. 사양 자체가 틀렸다고 판단되면 사용자에게 알린다.
- **값 축(사양 숫자 ↔ 상수)은 안 연다.** `digest [5]` 의 여는 조건은 「사양 성능 4·5 의
  숫자가 처음 움직이는 날」이고 오늘 값 아홉은 전부 일치한다(2절 P2). 주소 가드가 서면
  그날 값 가드를 얹을 자리가 생긴다 — 그것이 다음 계획이다.
- **줄 번호 인용을 텍스트 인용으로 갈아치우지 않는다.** 18곳 전면 개편이고, 주소를 재는
  가드가 서면 줄 번호 인용의 유일한 약점이 사라진다 (YAGNI).
- **`docs/`·`README.md` 의 `concept.md:<N>` 인용은 범위 밖.** 2절 P1 은 `src`·`tests`·`e2e`
  만 셌다. 문서끼리의 인용은 `tests/test_docs.py` 의 기존 축이 따로 있다.
- **`digest [7]①②`(재파싱 예산 배정 · `Decimal` 대 float)는 안 연다.** 둘 다 여는 조건이
  아직이다(캡을 올리려는 판단이 생기는 날 · 이진 부정확 합격선이 생기는 날).

## 6. 설계 생략 사유

설계 트리거 여섯을 하나씩 봤다.

- **새 모듈 0 · 공개 인터페이스 0 · 데이터 구조 0** — 새 테스트 클래스 하나뿐이고,
  수집기는 `tests/test_readme.py` 의 「문서를 읽어 코드와 대조한다」 패턴을 그대로 쓴다.
- **되돌리기 쉽다** — 테스트 한 벌과 주석/문자열 아홉 줄이다. `git revert` 한 판.
- **대안이 갈리지 않는다** — 「사양을 고친다」는 5절이 규정으로 막았고, 「텍스트 인용으로
  전환」은 YAGNI 로 잘랐다. 남은 것은 한 갈래다.
- **파일 3개 이상은 걸린다** — `tests/test_docs.py` 1개 + 인용 정정 4개
  (`e2e/design_check.py` · `e2e/quality_eval.py` · `tests/test_serve.py` ·
  `tests/test_quality_eval.py`) = **5개**. 다만 넷은 **주석/문자열 한 줄씩**이라
  설계가 고를 것이 없다. 이 판정을 `status.md` 에 남긴다.

→ **설계 phase 를 건너뛰고 개발로 간다.**

## 7. 위험

- **가드가 0건을 수집하고 초록을 낸다.** 정규식이 깨지면 「인용이 없으니 다 통과」다 —
  C7 이 그것을 잡고, 수집 건수 하한(≥ 14)을 단언에 넣는다.
- **줄 번호를 고치는 순간 또 낡는다.** 사양이 바뀌면 이 계획이 고친 주소도 밀린다.
  그것이 정확히 가드가 존재하는 이유고, 그날 RED 가 사람을 데려온다.
- **인용문 축의 과탐** — 인용 줄에 우연히 숫자가 있으면 문구로 오인할 수 있다.
  스텝 2 는 **따옴표로 감싼 문구**와 **바로 앞 상수의 리터럴**만 본다. 오탐 0 을 2절의
  맞는 아홉으로 확인한다.
