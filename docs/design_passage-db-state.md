# 설계 53 `passage-db-state`

**결정: 편집 둘 + 주석 하나.** ① `indexer.passages()` 의 `_connect()` 직후·`hits` 루프
**앞**에 `index_pages()` 가 쓰는 것과 같은 `sqlite_master` 가드(네 줄)를 인라인으로 두고,
② `serve.do_GET` JSON 사다리의 503 튜플에 `indexer.NoCrawlDataError` 를 더한다.
③ 화면 사다리는 **안 넓히고** 그 자리의 `# JSON 과 같은 값` 주석을 비대칭 사유로 고친다.
헬퍼는 안 뽑는다. 제품 diff 는 `src/websearch/indexer.py`·`src/websearch/serve.py`
두 파일 · 스키마·재색인·마이그레이션 0 · 시그니처 무변.

## 1. 갈림길 셋 — 출발점을 갈라서 냈다

계획서 6절이 셋을 열었다. 각각 ① 최소(아예 안 만든다·있는 것으로) · ② 정공법 ·
③ 되돌리기 우선에서 하나씩 냈다. **갈리는 행에 ★ 를 달았다.**

### 갈림길 1 — `pages` 없는 DB 에서 `/passages` 는 무엇을 내나

| 안 | 출발점 | 무엇 |
|---|---|---|
| **A 최소** | 사다리 1번(안 만든다) | 200 `[]`. 문서 단위 «원본이 사라진 문서는 뺀다»(`passages()` 의 `continue`)의 극한으로 본다. 코드 0줄 |
| **B 정공** | 정면으로 푼다 | 503 + `NoCrawlDataError`. `README.md` 상태 코드 계약의 «낫는 상태» 목록에 넣는다 |
| **C 되돌리기 우선** | 5분에 무른다 | 200 유지 + 응답에 경고 필드(`"degraded": true`). `VERSION` 규칙상 필드 추가는 1 그대로 |

| 재는 것 | A 200 `[]` | B 503 | C 200+필드 |
|---|---|---|---|
| ★ 소비자가 «우리가 터졌다» 와 «근거가 없다» 를 구별하나 | **아니다** | 그렇다 | 본문을 파싱하면 |
| ★ 상태 코드만 읽는 인프라가 재시도하나 | **안 한다** | 한다 | **안 한다** |
| `README.md` 「낫는 상태에는 503」 계약과 일치 | 어긋난다 | 맞다 | 어긋난다 |
| 계약 표면 | 무변 | 상태 코드 한 칸 | **새 필드** — 붙은 소비자가 생기면 못 뺀다 |
| 되돌리기 | — | 튜플에서 이름 하나 뺀다 | 필드 제거 = 소비자 파손 |
| 코드량 | 0줄 | 6줄 | 10줄+ |

**선택: B.** 갈리는 첫 행이 실측으로 갈렸다 — 같은 고장난 DB 에서
`/search?q=김치찌개` 는 **200 · 결과 1건**이다(2절 표 4행). 그러니 A 가 내는
「문서는 있는데 근거는 0건」은 **오늘의 정상 응답과 글자 그대로 같다**: 제목만
매치됐거나 2-gram 이 문단 경계를 넘어 매치된 문서가 그 답을 내고
(`e2e/hidden_passage_e2e.py` 가 숨은 텍스트 5모양에서 0/5 로 재는 값이 그것이다),
소비자에게는 두 상태가 구분되지 않는다. 이것이 `NoCrawlDataError` docstring 이
*"0 으로 합치면 DB 경로를 잘못 준 것이 조용한 성공으로 보인다"* 로 금지한 그 합침이다.

**버린 이유: A** — 위 두 행. 문서 단위 `continue` 는 «이 문서 하나의 원본이 없다» 이고
지금 것은 «원본 창고가 통째로 없다» 라, 극한이 아니라 **다른 상태**다.
**C** — 상태 코드가 뜻을 갖는다는 사양(`docs/specs/concept.md` 디자인 5)을 우회해
뜻을 본문으로 옮긴다. 200 을 보고 재시도를 접는 인프라에게는 A 와 같은 답이고,
계약 표면은 셋 중 가장 넓어져 되돌리기가 가장 어렵다.

### 갈림길 2 — 가드를 어디에 두나

| 안 | 출발점 | 무엇 |
|---|---|---|
| **A 최소** | 한 곳에서 다 막는다 | `_connect()` 안. 모든 호출자가 공짜로 얻는다 |
| **B 정공** | 고장난 함수에 둔다 | `passages()` 의 `_connect()` 직후·루프 앞. `index_pages()` 와 같은 네 줄을 두 번째로 적는다 |
| **C DRY** | 두 벌을 안 만든다 | `_require_pages(db, db_path)` 헬퍼를 뽑아 `index_pages()`·`passages()` 가 부른다 |

| 재는 것 | A `_connect` | B 인라인 | C 헬퍼 |
|---|---|---|---|
| ★ `pages` 없는 DB 의 `/search` (완료 기준 5) | **200 → 503 파손** | 200 무변 | 200 무변 |
| ★ 판정이 질의 내용에 안 달리나 | 그렇다 | 그렇다 | 그렇다 |
| 같은 SQL 문자열이 두 벌인가 | 한 벌 | **두 벌** | 한 벌 |
| 직교 편집(`index_pages` 를 건드리나) | 안 건드림 | 안 건드림 | **건드림** |
| 새 줄 수 | 4 | 4 | 6 + 호출 2 − 기존 4 |
| 되돌리기 | 네 줄 삭제 | 네 줄 삭제 | 헬퍼·호출부 세 곳 되돌림 |

**선택: B.** A 는 첫 행에서 죽는다 — `search()` 도 `_connect()` 를 지나므로 색인
`docs` 만으로 되는 검색까지 503 이 된다. 계획서 7절이 *"«두 경로가 다른 답을 낸다» 를
«둘 다 죽인다» 로 읽지 않는다"* 로 못박은 자리다. C 와 B 는 관측이 같아 남는 축은
「두 벌 문자열」 대 「직교 편집」인데, 이 저장소가 두 벌을 금한 선례(`_CURRENT_SQL`
옆 주석: *"문자열을 따로 적지 않고 SCHEMA 에서 만든다 — 두 벌이면 언젠가 갈라진다"*)는
**서로 맞아야만 참인 두 문자열**에 대한 것이다. 여기 둘은 서로 맞을 필요가 없다 —
한쪽이 갈리면 그쪽 테스트가 바로 빨개진다. 호출자가 둘뿐이라 뽑을 값이 아직 얇고
(계획서 6절이 이미 그렇게 적었다), 대신 **천장을 `ponytail:` 주석으로 코드에 남긴다**.

**자리를 더 좁힌다 — `search()` 뒤·루프 앞.** 두 가지를 산다.
`search()` 가 이미 내는 `FileNotFoundError`·`StaleIndexError` 의 **우선순위가 오늘
그대로**고(옛 색인은 옛 색인이라고 부른다 — 소비자에게는 둘 다 503 이지만 CLI 문구가
다르다), `passages()` 가 어차피 여는 연결을 쓰므로 **연결 추가 0** 이다. `search()`
앞에 두면 연결을 한 벌 더 열어야 하고(계획 47 이 「DB 를 여는 자리 하나」로 모은 것을
흔든다) 우선순위도 뒤집힌다.

### 갈림길 3 — 화면 사다리(`_do_html`)의 503 튜플도 넓히나

| 안 | 출발점 | 무엇 |
|---|---|---|
| **A 최소** | 안 만든다 | 안 넓힌다. `# JSON 과 같은 값` 주석이 거짓이 되므로 주석만 고친다 |
| **B 정공** | 대칭 | 화면 튜플에도 `NoCrawlDataError` 를 넣는다 |
| **C 한 벌로** | 갈릴 수 없게 | 튜플을 모듈 상수로 뽑아 두 사다리가 같은 것을 쓴다 |

| 재는 것 | A 안 넓힌다 | B 넓힌다 | C 상수 |
|---|---|---|---|
| ★ 오늘 관측이 바뀌나 | 아니다 | **아니다 — 닿을 수 없다** | 아니다 |
| ★ 변이로 죽는 줄인가(완료 기준 10) | 해당 없음 | **못 죽는다** | 못 죽는다 |
| `serve.py` 주석이 참인가 | 고쳐야 참 | 참 | 참 |
| 직교 편집 | 없음 | 없음 | **있다**(리팩터링) |
| 줄 수 | +1(주석) | +1 | +5 |

**선택: A.** 화면은 `_page_hits()` → `search()` 만 지나고 `search()` 는
`NoCrawlDataError` 를 내지 않는다 — 2절 탐침 5행이 그것을 프로세스 밖에서 확인했다
(`pages` 없는 DB 의 `/?q=김치찌개` 는 **200 · 결과 1건**이다). B 가 넣는 줄은
**어떤 테스트로도 RED 로 만들 수 없어** 계획서 완료 기준 10(변이 둘이 죽는다)이 덮지
못하는 코드를 새로 만든다. C 는 계획서 범위(제품 diff 두 파일·직교 편집 금지) 밖이고,
두 사다리가 **일부러** 달라질 자유를 뺏는다. 값은 주석 한 줄이다 — `serve.py` 화면
사다리의 `# JSON 과 같은 값` 이 이 커밋으로 거짓이 되므로 **왜 좁은지**로 바꾼다.

## 2. 고른 뒤 가장 위험한 가정을 깼다 (2026-09-04 · 반복 310 실측)

**가정: 정상 경로 어디에도 `pages` 없는 DB 로 `passages()` 를 부르는 곳이 없다.**
거짓이면 가드가 오탐이 되어 `/passages` 가 통째로 죽는다 — 계획서 8절이 최대 위험으로
적은 것이다. 추측하지 않고 **고른 안을 실제로 넣고 전수를 돌린 뒤 되돌렸다**(커밋 없음).

- 단위: 가드만 넣었을 때 `Ran 593 tests ... OK`, 가드+튜플 둘 다 넣었을 때도
  `Ran 593 tests ... OK`. 기존 단언 중 이 상태에 기대는 것은 **0건**이다.
- e2e **21종 전수 rc 0**. `e2e/passage_eval.py` 의 정확도 **100.0%** · 채택률 **99.5%** ·
  지연 p95 **1.52ms**(예산 500ms) — 세 숫자 무변. `e2e/search_api_e2e.py` 의 503/500
  계약 단언도 그대로 통과했다.
- 프로세스 밖 HTTP 탐침(`scratchpad/probe_http2.py` — 계획 3절이 쓴 그것에 `/search` 와
  화면 두 줄을 더했다). 서버는 매 열마다 `python3 -m websearch.serve` 로 띄우고 끝에 종료했다.

| 질의 | 오늘 | 가드만 | **가드+튜플(고른 안)** | 정상 DB 대조군 |
|---|---|---|---|---|
| `/passages?q=김치찌개`(매치 있음) | 500 | 500 | **503** | 200 · 문단 1건 (세 열 무변) |
| `/passages?q=zzzznope`(매치 없는 낱말) | 200 `[]` | 500 | **503** | 200 `[]` (무변) |
| `/passages?q=%01`(무토큰) | 200 `[]` | 500 | **503** | 200 `[]` (무변) |
| `/search?q=김치찌개` | 200 | 200 | **200** | 200 (무변) |
| `/?q=김치찌개`(화면) | 200 | 200 | **200** | 200 (무변) |

**가정은 참이다** — 대조군 다섯 줄이 세 열에서 한 글자도 안 움직였다. 덤으로 둘이 굳었다.

1. **가드만으로는 여전히 500 이다**(2열). 계획서 3절의 «처방은 한 곳이 아니라 두 곳»
   이 프로세스 밖에서 확인됐다. 이 열이 그대로 완료 기준 10 의 **변이 ②**(튜플에서
   `NoCrawlDataError` 를 빼면 1행이 RED)의 기대값이다.
2. **«판정이 질의 내용에 안 달린다» 를 내는 것은 가드 하나다.** 가드만 넣어도 세 질의가
   같은 코드(500)로 모인다 — 503 은 그 위에 얹는 «맞는 이름» 이다. 계획서가 «고장이
   둘» 이라고 쓴 것이 맞다: 겹쳐 있었을 뿐 서로 다른 고장이고, 서로 다른 편집이 고친다.

## 3. 계약 (개발이 지킬 것)

**`src/websearch/indexer.py` — `passages()`.** `db = _connect(db_path)` 직후,
`for url, title, _snippet in hits:` **앞**. 시그니처·docstring 의 계약 무변.

```python
    db = _connect(db_path)
    try:
        # `pages` 판정은 **루프 앞**이다 — 안이나 뒤에 두면 hits 가 빈 질의는 판정에
        # 닿지 못해 같은 고장난 DB 가 `q=김치` 면 503, `q=%01` 이면 200 으로 갈린다.
        # `search()` 안에서 무토큰 조기 반환을 DB 상태 판정 뒤로 민 것과 같은 이유다.
        # `search()` **뒤**인 것도 값이다: 옛 색인은 옛 색인이라고 부르고(우선순위 무변),
        # 이미 연 연결을 써서 연결 추가가 0이다.
        # ponytail: index_pages 와 같은 네 줄이 두 곳이다. 셋째가 생기면 헬퍼로 뽑는다
        if not db.execute(
                "SELECT 1 FROM sqlite_master WHERE type = 'table' AND name = 'pages'"
        ).fetchone():
            raise NoCrawlDataError(db_path)
        for url, title, _snippet in hits:
```

**`src/websearch/serve.py` — JSON 사다리에 이름 하나, 화면 사다리에 주석 하나.**

```python
            except (FileNotFoundError, indexer.StaleIndexError,
                    indexer.NoCrawlDataError) as exc:
```

화면 쪽 `except (FileNotFoundError, indexer.StaleIndexError) as exc:` 의 꼬리 주석
`# JSON 과 같은 값` 을 **왜 좁은지**로 바꾼다 — 화면은 `_page_hits()` → `search()` 만
지나고 `search()` 는 `NoCrawlDataError` 를 내지 않아 넣어도 닿지 않는다는 사실을 적는다.

**`README.md`** — 상태 코드 계약 줄의 «낫는 상태(DB 파일 없음·옛 색인)» 목록에
«크롤 데이터 없음» 을 더한다. 같은 커밋에서 실행 예시 줄의 `단위 593건` 을 새 건수로
바꾸고 `tests/test_readme.py` 의 건수 단언도 맞춘다(안 맞추면 그 자리가 RED 다).

**테스트** — 2절 표의 세 질의가 단언이 된다.
`tests/test_indexer.py` 의 `test_missing_db_raises`·`test_stale_index_raises` 와
**같은 클래스**에 `pages` 를 DROP 한 DB 로 세 질의(매치 있음·매치 없는 낱말·무토큰)가
전부 `NoCrawlDataError` 를 내는 것을 단언한다 — 세 질의가 한 테스트 안의 `subTest`
셋이어야 「판정이 질의 내용에 안 달린다」가 하나의 축으로 잡힌다.
`tests/test_serve.py` 는 `test_every_passages_response_carries_version` 이 이미
`(예외, 기대 상태)` 표를 mock 으로 도는 자리라 거기에 `NoCrawlDataError → 503` 행을
더하고, 실제 DB 로 `pages` 를 DROP 해 HTTP 503 과 본문
`{"version": 1, "error": "색인이 아직 준비되지 않았다"}` 를 재는 것 하나를 더한다.
**같은 DB 의 `/search` 가 200 인 단언을 그 옆에 둔다** — 갈림길 2 의 A 를 막는 자리다.

## 4. 천장 (ponytail 주석으로 코드에 남긴다)

- 가드는 **테이블의 유무만** 본다. `pages` 는 있는데 `html` 열이 없거나 권한이 막힌
  DB 는 여전히 500 이다 — 기다린다고 안 낫는 상태라 500 이 맞는 이름이다.
- 같은 네 줄이 `index_pages()`·`passages()` 두 곳. **셋째 호출자가 생기면 헬퍼로 뽑는다.**
- `pages` 도 `docs` 도 없는 빈 DB 의 `/passages` 는 오늘 200 `[]` → **503 으로 바뀐다.**
  의도한 것이다(«남의 DB»). 같은 DB 의 `/search` 는 200 `[]` 그대로라 두 경로가 여전히
  다른 답을 내는데, 이번에는 그 다름이 **뜻이 있다**: 색인은 답할 수 있고 근거는 없다.

## 5. 역할 검토 (파일 3개+ 규모)

- **제품** — 소비자는 인프라다. 500 을 보고 재시도를 접던 것이 503 으로 재시도한다.
- **스태프 리뷰** — diff 는 네 줄 + 이름 하나 + 주석 하나. 되돌리기가 삭제뿐이다.
- **보안** — 본문은 고정 문구다. `str(exc)` 는 DB 경로라 안 싣는다(오늘 규약 그대로).
  새 경로로 새는 정보 0. 신뢰 경계 입력 검증은 `_parse()` 그대로 앞에 있다.
- **QA** — 깨지는 자리는 오탐 하나다. 2절이 단위 593 · e2e 21종으로 쟀다.
- **SRE** — 503 은 새 종류가 아니다(`FileNotFoundError`·`StaleIndexError` 가 이미 낸다).
  `Retry-After` 는 안 붙인다 — 오늘 두 503 도 안 붙이므로 여기서만 붙이면 비대칭이다.
