# 설계: 인접 링크 경계가 «산문» 도 끊는다 (계획 116 · 천장 ⓐ)

## 결정

`_BlockParser` 의 인접 링크 경계를 **「그 블록에 링크 밖 글자가 아직 안 쌓였을 때」로만**
세운다. 블록 하나짜리 불리언(`self._prose`)을 두고, 링크 안/밖은 `_els` 의 숨김 깃발과
**같은 관용구로 전파**해 O(1) 로 읽는다. 끊는 방향은 **오직 좁아진다** — 오늘 끊는 자리의
부분집합만 끊는다.

## 대안 비교 — 셋을 다른 출발점에서 냈다

| | A. 최소 — 이름표로 가른다 | **B. 정공법 — 쌓인 것이 링크뿐인가** | C. 사후 — 블록 끝에서 비율로 |
|---|---|---|---|
| 새 상태 | **0개** (`_open` 재사용) | 불리언 1개 + `_els` 깃발 1칸 | 경계 오프셋 **목록** + 임계값 상수 |
| 되돌리기 | 커밋 revert | 커밋 revert (덧붙이기만) | 커밋 revert |
| 코드량 | 1줄 | **5줄 안** | 15줄+ |
| 기존과 일치 | ○ | **◎ 숨김 깃발 전파와 같은 꼴** | △ 새 임계값은 이 저장소가 이미 앓는 것 |
| 다음이 편한가 | 보통 | 좋음 | 임계값을 누가 정하나가 남는다 |
| **실측 판정** | **죽었다 — 아래** | 산문 끊김 **2049/5521 제거 · 내비 끊김 유지** | B 와 같은 답에 상태만 더 든다 |

**선택: B.** `concept.md` 갈림길 우선순위가 **검색 품질**을 성능·규모보다 위에 두고,
B 는 산문 끊김을 **측정된 만큼** 없애면서 계획 115 가 얻은 내비 끊김을 그대로 남긴다.
새 상수를 안 만들어 「임계값을 감으로 정한다」(`metrics.md` 가 이미 들고 있는 문제)를
늘리지 않는다.

**A 를 버린 이유 — 실측이 죽였다.** 「끊는 자리가 내비 이름표 안인가」로 가르려 했는데
실물 520문서 5,521자리 중 `nav` 이름표는 **8자리(0.1%)** 다. 끊김은 `li` 2,403 ·
`section` 821 · `pre` 667 · `p` 575 · `dd` 575 에 흩어져 있다. 이름표로는 내비와 본문이
갈리지 않는다 — `tests/test_extract.py:100` 이 「이름표는 근거를 고르는 자가 안 읽는다」고
적은 것과 같은 자리다.

**C 를 버린 이유.** 판정 규칙이 B 와 같은 답을 내는데(링크 비율이 100% 인 블록 = 링크밖
글자가 0인 블록) 경계 오프셋 목록과 비율 임계값이 더 든다. 「더 적게 쓰나」에서 진다.
비율로만 할 수 있는 일(링크 90%+ 블록을 끊는다)은 **이 계획의 근거가 아니다** — 후보
`[6]` 이 적은 ⓐ 는 「산문을 끊지 말라」이지 「링크 많은 블록을 더 끊어라」가 아니다.

## 가정 — 개발 전에 깨봤다 (참이었다)

고른 안이 참이라 믿는 것: **「링크 밖 글자가 쌓인 자리는 본문이고, 거기서 안 끊어도
계획 115 가 얻은 내비 이득은 사라지지 않는다」.** 거짓이면 내비·목차가 다시 한 블록으로
붙어 본문을 점수로 이기고 설계가 무너진다.

**실물 크롤 DB(`data/crawl.db` · 200 응답 264,188문서)에서 600문서를 무작위로 떠서
520문서를 파싱해 쟀다**(seed 116 · 탐침은 저장소 트리 밖 `/tmp` 에서 돌렸고 커밋하지
않았다 — `plan.md` 3-1절):

| | 자리 수 | 비율 |
|---|---|---|
| 오늘 끊는 자리 전부 | **5,521** | 100% |
| └ 링크 밖 산문이 이미 쌓인 자리 (**B 가 안 끊는다**) | **2,049** | 37.1% |
| └ 링크 텍스트뿐인 자리 (**B 도 끊는다**) | **3,472** | 62.9% |

**이름표별로 보면 가정이 참임이 분명하다** — 내비·목차 모양은 산문이 거의 0이다:
`section` 821자리 중 산문 **0** · `li` 2,403 중 **291(12%)** · `nav` 8 중 **0**.
반대로 본문 모양은 거의 전부 산문이다: `pre` 667/667 · `dt` 192/192 · `dd` 423/575 ·
`p` 382/575 · `figcaption` 36/41.

**표본을 문서마다 한 장으로 제한해 뜬 산문 끊김은 전부 본문 문장이다** —
`ko.wikipedia.org/…자유_소프트웨어_재단` 의 「자유 소프트웨어 재단(Free Software
Foundation, FSF)은 1985년 10월 4일 리처드 스톨먼이 설립한[7] 501(c)(3)…」,
`en.wikipedia.org/wiki/Internet` 의 「…Numbers (ICANN). The technical underpinning
and standardization of the core protocols…」, `peps.python.org/pep-0538/` 의 PEP 산문.
**이것이 후보 `[6]` 이 말한 「문장 중간부터 시작하는 조각」의 모집단이다.**

## 계약 — 개발이 지킬 것

1. **공개 인터페이스 무변.** `extract_blocks(html)` 의 시그니처와 반환 형태
   (`[(이름표, 텍스트)]`)를 바꾸지 않는다. 색인 경로(`extract_text`)는 지나가지 않는다 —
   `_BlockParser` 만 고친다. **재색인 없음**(계획 115 e2e 시나리오 ② 가 그 자다).
2. **방향은 좁아지는 쪽뿐.** 고친 뒤 끊는 자리는 오늘 끊는 자리의 **부분집합**이다.
   새로 끊는 자리를 하나도 만들지 않는다.
3. **판별식은 블록 단위 불리언 하나.** 이름은 `self._prose`. `_flush()` 에서 **반드시**
   내린다 — 안 내리면 첫 문단 뒤의 모든 내비가 안 끊긴다(블록마다 새로 판정해야 한다).
4. **링크 안/밖은 `_els` 에 전파한다.** 숨김 깃발과 같은 관용구다(`(태그, 숨김, 링크안)`).
   `handle_data` 에서 O(깊이) 로 훑지 않는다 — 가장 뜨거운 경로이고 리뷰 51 [R51-2] 가
   같은 자리에서 깊이² 비용을 이미 한 번 잡았다.
5. **숨김·스킵 축은 건드리지 않는다.** `handle_endtag` 의 깃발이 숨김을 보는 것
   (리뷰 115 [R115-2])은 그대로다. 숨김 안 글자는 애초에 안 담기므로 `_prose` 도 안 선다.
6. **천장 주석을 사실로 고친다.** `_BlockParser.__init__` 의 ⓐ 문단은 「고치려면 설계가
   갈린다(사람 몫)」로 적혀 있다 — 이 계획이 ⓐ 를 닫으므로 그 문단을 고치고 ⓑ 만 남긴다.

## 되돌리기

**커밋 하나 revert.** 덧붙이기만이고(조건이 좁아지고 깃발이 하나 는다) 저장 형태·스키마·
공개 계약을 안 건드린다. 피처 플래그는 쓰지 않는다 — `project.md` 의 플래그 항목이 비어
있고, 값이 안 변하는 설정은 ponytail 이 막는 자리다.

## 범위 밖

- **천장 ⓑ(구분자가 끼면 안 끊는다)** — ⓐ 와 반대 방향이라 같이 못 간다. 후보 `[6]` 유지.
- **링크 비율로 더 끊는 쪽(대안 C 의 나머지 반)** — 근거가 없다. 열리는 조건은
  「링크 90%+ 블록이 본문을 이기는 실물 측정」이 나오는 날이다.
- **`pre` 블록(코드)이 근거 문단으로 나오는 것** — 이 측정에서 667자리가 전부 코드였다.
  끊든 안 끊든 코드가 근거로 나가는 것 자체는 다른 축이고, 후보로 등재한다.
