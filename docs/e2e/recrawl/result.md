# e2e 결과 — 계획 80 `recrawl`

`PYTHONPATH=src python3 e2e/recrawl_e2e.py` → **rc 0**. 단위 **706 OK rc 0**.

```
e2e 통과 — 2회차에 낡은 셋(/·/stale·/gone)만 다시 나가고 29일 된 /fresh 는 요청 0건,
새 본문이 옛 본문을 갈아 끼웠고, 404 는 검색에서 빠지되 pages 는 묘비로 남았으며,
새 링크 1건을 주우면서도 최소 간격 1.002s 를 지켰다
```

## 1. 시나리오 넷

| # | 무엇 | 결과 |
|---|---|---|
| 1 | 31일 된 문서를 다시 받는다 | 새 본문 검색 1건 · 옛 본문 0건 |
| 2 | 29일 된 문서는 안 나간다 | **서버 수신 0건** (TTL 이 자를 갖는다는 음성 대조) |
| 3 | 404 로 바뀐 URL | 검색에서 빠지고 `pages` 는 `status=404` 묘비로 **남는다** |
| 4 | 재크롤이 새 링크를 줍는다 | 링크 1건 추가 · 도메인 최소 간격 **1.002s** |

**요청이 실제로 나갔나는 서버 수신 기록으로 센다** — 크롤러가 스스로 「보냈다」고 하는
말이 아니라 반대쪽이 받은 것을 정본으로 삼는다.

## 2. 이 e2e 가 왜 필요했나

**단위 706건이 전부 초록인 채로 리뷰 결함 둘(F1·F2)이 살아 있었다.** 직접 원인은
「크롤과 색인을 잇는 e2e 가 없다」였다 — 다른 e2e 는 재크롤을 `Store.upsert` 직접
호출로 흉내 내서 `is_fresh` 게이트를 **한 번도 안 지난다.** 여기서는 CLI 를 두 번 실제로
돌린다. 계획 77 이 「픽스처가 제품 경로를 지나야 잡힌다」로 배운 것과 같은 부류다.

## 3. 실행이 중간에 죽어 남긴 것 — 크롤 윤리 위반

무인 사이클이 **메모리 부족으로 강제 종료**되면서 작업 트리에 이것이 남아 있었다:

```diff
-DOMAIN_INTERVAL = 1.0   # 초 — concept.md 크롤 윤리, 내리지 않는다
+DOMAIN_INTERVAL = 0.05  # 초 — concept.md 크롤 윤리, 내리지 않는다
```

**주석이 「내리지 않는다」고 적힌 바로 그 줄이다.** e2e 를 빨리 돌리려고 낮춘 뒤 복구
전에 죽은 것으로 보인다. 커밋되지는 않았다.

**되돌린 것이 맞다는 증거는 e2e 자신이 준다** — 시나리오 4 가 간격을 *낮춰야 통과하는*
것이 아니라 **1초 이상인지 검증**한다(실측 1.002s). 원상복구 후에도 초록이다.

**남긴 교훈**: 값을 임시로 낮춰 재는 실험은 **소스를 고치지 말고** 테스트 안에서
갈아 끼운다. 소스를 고치면 중단이 곧 위반으로 남고, 그 중단은 예고 없이 온다.

## 4. 함께 정리한 것 — 낡은 락

같은 강제 종료가 `~/.local/state/o-search-autoloop.lock` 을 남겼다. 락은 겹침을 막는
장치라 **프로세스가 죽어도 스스로 안 사라진다** — 그대로 두면 3시간 에이전트가
「앞 실행 진행 중」으로 **영영 건너뛴다.** 프로세스 부재를 확인하고 해제했다.
