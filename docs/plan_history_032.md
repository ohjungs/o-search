## 1. 문제 · 목표 · 기대 결과

### 무엇이 이미 참인가 (처음 여는 사람을 위한 전제)

- `src/websearch/serve.py` 의 `make_server()` 안 `Handler.do_GET` 이 경로를 둘로 가른다:
  `/` 는 HTML 화면(`_do_html`), `/search` 는 JSON(`_send`). 없는 경로는 404 JSON.
- 두 경로는 `_page_hits(db_path, query, page)` **한 함수**를 나눠 쓴다. `_do_html` 의
  그 호출 줄에 *"JSON 경로와 **같은 한 벌**"* 이라는 주석이 이미 붙어 있다.
- `/search` 의 200 응답은 `{"query", "page", "has_next", "results": [{"url","title","snippet"}]}`
  네 키다. **버전 키는 없다.**
- 단위 스위트는 오늘 **482건 OK**(맨몸 11.729초). e2e `*.py` 19종 rc 0.

### 문제 A — "색인이 없다" 가 500 으로 나간다 (사양 디자인 5 위반)

`docs/specs/concept.md` 의 `# 확장: 다른 시스템이 쓰는 검색` 절, `### 디자인` 5번:

> 오류가 사람이 아니라 기계에게 읽힌다. API 응답은 실패해도 JSON 이고,
> HTTP 상태 코드가 뜻을 갖는다(400 질의가 틀렸다 · **503 색인이 없다**).

오늘 `serve.py` 에 `503` 은 **한 글자도 없다**(`grep -rn 503 src/` = 0건). `do_GET` 의
`except Exception` 이 아래 셋을 전부 **500 · "검색 중 오류가 났다"** 하나로 접는다:

| 실제 상태 | `indexer.search` 가 하는 일 | 오늘 응답 | 사양이 요구하는 것 |
|---|---|---|---|
| DB 파일이 없다 | `raise FileNotFoundError(db_path)` | 500 | 503 |
| 색인 정의가 드리프트했다 | `raise StaleIndexError(db_path)` | 500 | 503 |
| 크롤만 하고 색인을 안 돌렸다 | `return []` (`indexer.py:185` 주석 *"아직 색인 전"*) | **200 · 빈 결과** | 갈림길 D |
| 프로그래밍 오류(`AttributeError` 등) | — | 500 | **500 유지** |

`StaleIndexError` 는 `src/websearch/indexer.py` 안에서만 살고 **`serve.py` 는 그 이름을
한 번도 안 부른다**(`grep -rn StaleIndexError src/ tests/` — `indexer.py` 4곳,
`test_indexer.py` 1곳, `serve.py`·`test_serve.py` **0곳**).

`tests/test_serve.py` 의 `TestMissingDb` 는 클래스 독스트링에 *"DB 파일 자체가 없다 —
운영 실수다. **500 이 맞지만** 내부를 흘리면 안 된다"* 라고 적고 `test_missing_db_is_
500_without_internals` 가 그 값을 못박고 있다. **틀린 코드가 아니라 사양이 뒤집힌
판정이다** — 그 테스트는 고쳐야 할 자산이지 고장이 아니다.

### 문제 B — 응답 스키마에 버전이 없다 (사양 기능 9 위반)

같은 절 `### 기능` 9번:

> 계약 안정성: 응답 스키마는 버전을 갖는다. 필드를 지우거나 뜻을 바꾸는 변경은
> 새 버전에서만 한다 — 부르는 쪽이 남의 시스템이라 조용한 변경이 곧 장애다.

`grep -n version src/websearch/serve.py tests/test_serve.py` = **0건**.

**버전은 소비자가 생기기 전에만 공짜로 넣을 수 있다.** 지금 넣으면 필드 하나이고,
남의 시스템이 붙은 뒤에 넣으면 그 자체가 조용한 스키마 변경이다. 이것이 이 계획을
근거 문단 API(사양 기능 7·8)보다 **먼저** 여는 이유다.

이 자리가 이미 한 건을 막고 있다는 증거가 저장소에 있다. `docs/digest.md` 의
`## 판단 필요` 절, *"`has_next` 가 «결과가 더 있다» 와 «서버 상한에 닿았다» 를 한
bool 로 합친다"* 항목은 처방까지 다 적어 두고 **"고치려면 `truncated` 같은 두 번째
필드가 필요하고 그건 `/search` 응답 스키마 변경이다 — 사용자 확인 후보"** 로 멈춰 있다.
버전이 없으니 스키마를 못 건드리고, 스키마를 못 건드리니 버전도 안 생기는 자리다.

### 문제 C — 기능 6 의 판정을 아무도 안 재고 있다

같은 절 `### 기능` 6번의 판정: *"같은 질의에 대해 화면의 결과 순서와 JSON 의 순서가
**완전히 일치**한다."*

`tests/test_serve.py` 의 테스트 90건을 전수로 봤다. 화면을 보는 클래스
(`TestResultsPage`·`TestPagerUi`·`TestHtmlEscaping`)와 JSON 을 보는 클래스
(`TestSearchEndpoint`·`TestPagination`·`TestTiedRanking`)가 **따로 있고 두 응답을
맞대 보는 단언은 0건**이다. `test_search_endpoint_still_returns_json` 은 화면이 붙은 뒤에도
JSON 이 살아 있는지만 본다. `TestResultsPage.test_results_render_title_url_snippet` 은
`assertIn` 이라 **순서를 안 본다.**

구조상 오늘 참이다(둘 다 `_page_hits`). 그러나 참인 것과 붙들려 있는 것은 다르다 —
`_do_html` 이 `limit` 이나 `offset` 을 자기 것으로 갖는 순간 조용히 갈리고, 그때
깨지는 것은 화면이 아니라 **남의 시스템이 화면과 다른 답을 받는다**는 사실이다.

### 목표

`GET /search` 를 남의 시스템이 의존해도 되는 계약으로 만든다. 새 엔드포인트·새
프로세스·새 의존성은 없다(사양 경량 4·5 를 지킨다). 사양의 판정 셋이 전부 스위트
안에서 **검증 가능한 단언**이 된다.

### 기대 결과

  오류는 **500 그대로**다. 둘을 합치는 변이는 스위트가 죽인다.

## 3. 스텝

세 스텝은 **의존 엣지가 없다**. 셋 다 `serve.py` 의 다른 자리를 읽고 다른 것을 낸다:
1은 예외 갈래, 2는 응답 조립, 3은 테스트뿐이다. 그러나 **같은 파일 둘을 건드리므로
순차로 돈다** (`rules/plan.md` 3-1절 — worktree 분할 조건 ①"파일이 안 겹친다"가 거짓).

**임계경로는 스텝 1** 이다. 제품 diff 가 가장 크고 갈림길이 셋(B·C·D)으로 제일 많다.
먼저 착수한다.

### 스텝 1 — "색인이 없다" 를 503 으로 가른다 (의존: 없음)

- **완료 기준**:
  - DB 파일 없음 · 색인 정의 드리프트 두 상태에서 `GET /search?q=…` 가 **503** 과
    `Content-Type: application/json; charset=utf-8` 을 낸다.
  - 응답 본문에 DB 경로도 `Traceback` 도 없다 (오늘 `TestMissingDb` 가 500 에 대해
    거는 두 단언을 503 으로 옮겨 그대로 유지한다).
  - 원인이 stderr 로그에 남는다 (오늘 `test_500_is_logged_even_though_access_log_is_off`
    가 `FileNotFoundError` 를 요구하는 그 단언을 503 갈래에서도 유지).
  - **프로그래밍 오류는 500 그대로다** — 503 갈래를 넓혀 `Exception` 을 삼키는 변이가
    죽는 단언이 있다. (`digest.md ## 판단 필요` 의 *"부정 단언 하나가 다른 이유로
    통과할 수 있다"* 항목 — 상태코드 단언 하나만으로는 아무것도 고정되지 않는다.)
  - 미색인 DB(오늘 200)의 처리는 **설계 갈림길 D 가 정한 값**이고, 정한 뒤에는
    `TestUnindexedDb` 가 그 값을 단언한다.
  - 화면(`/`) 경로의 상태 코드는 **설계 갈림길 C 가 정한다.**
  - **[설계가 더한 줄]** `README.md:39` 의 *"요청마다 500 을 낸다"* 가 이 스텝에서
    거짓이 된다 — 503/500 을 가르는 문장으로 함께 고친다. (설계 1절 세 번째 탐침)
- **건드릴 파일**: `src/websearch/serve.py` · `tests/test_serve.py` · `README.md`
- **의존**: 없음
- **상태**: **완료** (2026-09-02 · 반복 237)

### 스텝 2 — 응답 스키마에 버전을 붙인다 (의존: 없음)

- **완료 기준**:
  - `GET /search` 의 **200 과 오류 응답 모두** 스키마 버전을 갖는다. 어느 자리에
    어떤 형태로 다느냐는 **설계 갈림길 A** 가 정한다.
  - 버전을 지우거나 값을 바꾸는 변이가 스위트를 죽인다.
  - **화면(`/`) 응답에는 안 붙인다** — 사양 기능 9 는 계약(API)의 항목이고 HTML 은
    사람이 읽는다.
  - ~~`README.md` 의 API 설명이 있으면 같이 맞춘다~~ — **설계가 실측해 스텝 1 로 옮겼다.**
    README 에 API 스키마 설명은 없고(`grep -rn "/search" README.md` → 0건), 대신 상태
    코드를 적은 줄(`README.md:39`)이 있어 그것이 걸리는 것은 버전이 아니라 503 이다.
- **건드릴 파일**: `src/websearch/serve.py` · `tests/test_serve.py`
- **의존**: 없음 (스텝 1 이 먼저 들어가면 새 503 도 자동으로 버전을 갖는다. 순서가
  뒤집혀도 결과는 같다 — 진짜 의존이 아니다)
- **상태**: **완료** (2026-09-02 · 반복 238)

### 스텝 3 — 화면 순서 == JSON 순서를 붙든다 (의존: 없음)

- **완료 기준**:
  - 같은 질의·같은 `page` 로 `/`(HTML)와 `/search`(JSON)를 둘 다 부르고, HTML 에서
    뽑은 결과 URL 목록이 JSON `results[].url` 과 **순서까지 같다**.
  - 결과가 2건 이상이고 순서가 실제로 구별되는 질의를 쓴다 — 1건이면 순서 단언이
    무의미하다 (`digest.md ## 판단 필요` 의 *"부정 단언 하나가 다른 이유로 통과할 수
    있다"* 와 같은 함정).
  - `_do_html` 이나 `do_GET` 한쪽의 `_page_hits` 호출을 다른 `limit`/`offset` 으로
    바꾸는 변이가 **이 단언에 잡힌다.**
  - 제품 `src/` **0줄**.
- **건드릴 파일**: `tests/test_serve.py`
- **의존**: 없음
- **상태**: **완료** (2026-09-02 · 반복 239)

## 4. 하지 않을 것

범위 고정 (카파시 3번 — 직교 편집 금지).

- **근거 문단 API (사양 기능 7·8)** — 계획 47 이다. 사양의 `## 사람이 정할 것` 2번이
  쪼개기로 이미 정했다. 새 엔드포인트·문단 자르기·근거 정확도 90% 측정 전부 여기 없다.
- **속도 제한 (사양 `## 사람이 정할 것` 1번, 가정 «IP 당 분당 60회»)** — 사양 스스로
  "사람이 정할 것" 이라 적었고 초안 숫자다. 별도 계획.
- **`has_next` 를 `truncated` 로 쪼개는 것** — `digest.md ## 판단 필요` 의 그 항목이
  **"사용자 확인 후보"** 로 못박아 뒀다. 이 계획이 버전을 넣어 **그것을 여는 길을
  만들지만, 열지는 않는다.**
- **JSON 검색 p95 300ms 측정 (사양 성능 4)** — 이 계획은 질의 경로를 안 건드린다
  (`_page_hits` 무수정). 오늘의 p95 8.86ms 기준선이 그대로다. 재측정은 e2e 가 한다.
- **`indexer` CLI 의 종료 코드** — 계획 40 `exit-code-contract` 가 닫은 계약이다.
  이 계획은 HTTP 상태만 본다.
- **버전 협상(`Accept` 헤더 · 여러 버전 동시 서빙)** — 소비자가 0명이고 버전이 1개다.
  두 번째 버전이 실제로 필요할 때가 열 때다 (ponytail 1번).
- **넓은 `except Exception` 자체의 재조사** — 2-5 참조. 이미 쟀고 무죄였다.
- **`data/crawl.db`** — 무변경. 읽지도 않는다.

## 5. 설계 트리거 — 걸린다 (건너뛰지 않는다)

`rules/design.md` 1절의 트리거 셋에 걸린다:

| 트리거 | 무엇이 걸리나 |
|---|---|
| **공개 인터페이스 추가·변경** | `/search` 의 상태 코드 계약이 바뀐다 (500 → 503). 오늘 그 값을 단언하는 테스트가 있다 |
| **데이터 구조 변경 (필드 추가)** | 응답 스키마에 버전이 붙는다 |
| **대안이 2개 이상 갈림** | 아래 넷 |

→ 다음 반복은 **설계**다. `docs/design_json-contract.md` 를 쓴다.
`rules/design.md` 3-1절대로 대안은 **서로 다른 출발점**(최소 · 정공법 · 되돌리기 우선)
에서 하나씩 낸다.

### 갈림길 A — 버전을 어디에 두나

① 본문 필드 `"version": 1` (최소) · ② URL 경로 `/v1/search` (정공법) ·
③ 미디어 타입 `application/vnd.websearch.v1+json` · ④ 응답 헤더.
**판정 축**: 사양 기능 9(*"필드를 지우거나 뜻을 바꾸는 변경은 새 버전에서만"*)를
실제로 집행할 수 있나 · 사양 경량 4(*"실행할 명령이 늘지 않는다"*) · 오늘 `/search`
를 부르는 저장소 안 호출자(`e2e/*.py` 여럿, `serve.main` 이 찍는 안내 줄)를 깨나.

### 갈림길 B — 503 을 어디서 가르나

① `do_GET` 에 `except (FileNotFoundError, StaleIndexError)` 한 갈래 (최소) ·
② `indexer` 에 공통 상위 예외를 세우고 `serve` 는 그 하나만 잡는다 (정공법 —
`indexer.main` 도 이미 이 셋을 rc 로 번역하고 있어 두 진입점이 한 자리로 모인다) ·
③ 요청마다 `os.path.exists` 선검사 (거절 예상 — `search()` 가 이미 하는 일의 사본).
**판정 축**: 화면 경로(`_do_html`)에도 같은 갈래가 필요하다면 ①은 두 벌이 된다
(ponytail의 *"한 곳에 가드 하나가 호출자마다 가드보다 작은 diff"*).

### 갈림길 C — 화면(`/`)도 503 을 내나

사양 디자인 5 는 **API 만** 말한다. 그러나 원인이 같은데 상태가 다르면 운영자가 같은
사고를 두 값으로 본다. 오늘 `TestHtmlPathFailsSafely` 의 500 단언 셋이 이 결정에 걸린다.

### 갈림길 D — "아직 색인 전"(오늘 200)도 «색인이 없다» 인가

2-4 참조. 이 저장소가 네 번 닫은 *"실패가 성공으로 위장된다"* 계보에 속하지만,
서버가 멀쩡하고 색인만 안 돈 상태를 503(서비스 불가)이라 부르는 것이 맞는지는 별개다.
**설계가 실측으로 정한다** — `crawl` 만 돌린 DB 를 만들어 오늘의 200 이 실제로 무엇을
가리는지 본다.

## 7. 보안 · 데이터 판정

- **신뢰 경계**: `/search` 는 이미 공개 경계다. 이 계획은 **입력 검증을 하나도 안
  건드린다** — `_parse()` 의 질의 길이·페이지 상한 검증 그대로다.
- **유출**: 새 상태 코드가 새 정보를 흘리나? 503 은 "색인이 없다"를 알린다. 오늘의
  500 도 같은 상황에서만 나므로 **관측 가능한 정보량이 같다**(이름이 정확해질 뿐이다).
  본문에 경로·트레이스백이 안 실린다는 오늘의 단언 둘을 503 으로 그대로 옮긴다.
- **데이터**: `data/crawl.db` 무변경. 스키마·마이그레이션 없음. 읽기도 안 한다.
- **의존성**: 0 (stdlib 만). 사양 경량 5 그대로.
- **하네스 정지 조건 해당 없음** — 스키마·마이그레이션·배포·삭제·비밀정보·과금·
  의존성 어디에도 안 걸린다.

## 8. 이 계획이 틀렸다면 어디서 드러나나

- **설계 갈림길 A 에서 ②(`/v1/search`)가 이기면** 스텝 2 는 필드 추가가 아니라 경로
  추가이고, `e2e/*.py` 중 `/search` 를 직접 부르는 것들이 전부 걸린다. 그때는 스텝 2
  가 커져 계획을 다시 쪼개야 한다. **설계가 그것을 먼저 세는 것이 설계의 일이다.**
- **갈림길 D 가 "미색인 DB 도 503" 으로 정해지면** `TestUnindexedDb` 의 오늘 값이
  뒤집히고, `e2e/tokenizer_e2e.py` 처럼 옛 색인 상태를 재는 e2e 가 함께 걸릴 수 있다.
  걸리면 스텝 1 이 예상보다 크다는 신호다.
- **스텝 3 의 변이가 안 죽으면** — 즉 `_page_hits` 호출 한쪽을 갈라도 단언이 살아
  있으면 — 그 테스트는 순서가 아니라 다른 것을 재고 있는 것이다. `digest.md
  ## 판단 필요` 의 *"부정 단언 하나가 다른 이유로 통과할 수 있다"* 가 바로 그 함정이다.
- **사양의 판정을 이 계획이 못 채우면** — 기능 6·9·디자인 5 중 하나라도 DONE 에서
  거짓이면 계획이 잘못 쪼개진 것이다. 남은 것을 계획 47 앞에 다시 연다.

## e2e 시나리오

계획 전체가 끝난 뒤 1회 실행한다. 사용자(= 이 API 를 부르는 **남의 시스템**) 관점.

1. **색인이 있는 서버에 붙는다** — `serve` 를 실제 프로세스로 띄우고 `GET /search?q=…`
   를 부른다. 200 · JSON · **버전 필드** · 결과 N건.
2. **같은 질의를 화면으로도 본다** — `GET /?q=…` 의 HTML 에서 결과 URL 을 순서대로
   뽑아 1번의 `results[].url` 과 **완전히 일치**하는지 본다 (사양 기능 6 판정).
3. **색인을 치운다** — DB 파일을 옮기고 같은 질의를 다시 부른다. **503 · JSON** ·
   본문에 경로도 트레이스백도 없다 · stderr 에 원인 한 줄 (사양 디자인 5).
4. **질의를 틀린다** — `q` 없이 부른다. **400 · JSON** (오늘 계약 그대로 유지된다).
5. **대조군** — 위 셋 중 상태 코드를 하나라도 500 으로 되돌리면 시나리오가 RED 가
   되는지 확인한다. 안 되면 시나리오가 아무것도 안 재고 있는 것이다.

**새 `e2e/*.py` 가 필요한지는 e2e phase 가 정한다** — 계획 41·42·45 는 프로세스로 잴
것이 없어 0개로 뒀지만, 이 계획은 제품이 HTTP 응답을 바꾸므로 잴 것이 있다.
