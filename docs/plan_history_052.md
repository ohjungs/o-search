# 계획 66 — `readme-shape-cover`

`README.md` 「잘하고 있나 재는 자」 표를 **밴드 아홉이 아니라 표 자신의 모양**으로 붙든다.
계획 65 가 닫은 것은 「문서에 적힌 아홉 수치가 `e2e/*.py` 상수와 같은가」 한 축이고,
**표를 넓히는 편집과 셋째 칸을 개명하는 편집은 오늘도 조용히 산다.**

**근거**: `digest [7]` 의 ①·④ 두 항목(2026-09-06 계획 65 테스트 phase·e2e phase 실측).
둘 다 **여는 조건이 이미 왔다** — ①이 스스로 적어 둔 여는 조건은 「README 표에 행을 더하는
날」이고, ④는 「측정기 파일을 개명·이동하는 날」이다. 이 계획이 표를 넓히는 자리를 여는 것이
아니라, **다음에 누군가 넓힐 때 울게** 한다. digest 자신이 「①과 같은 「표 구조」 축이라
**한 계획으로 묶는 편이 싸다**」로 적어 둔 대로 둘을 한 스텝에 넣는다.

`digest [7]②`(`Decimal` 대 float)는 리뷰 380 이 이미 닫았고, `[7]③`(`docs/specs/concept.md`
세 번째 사본)은 **열지 않는다** — 5절.

## 1. 문제 · 목표 · 기대 결과

**문제.** `tests/test_readme.py` 의 `QualityBandTest` 는 `QUALITY_BAND` 리터럴 아홉 줄을
들고 「README 에서 이 수치를 정확히 하나 뽑아 상수와 대조」한다. 방향이 **밴드 → 표** 한
쪽뿐이라 표 쪽에서 오는 두 편집이 안 걸린다.

- **① 행이 늘어도 조용하다.** 표에 여덟 번째 행을 끼우면 그 행의 합격선은 **대조 없이**
  들어온다. `QUALITY_BAND` 는 리터럴이라 자기가 모르는 행을 셀 방법이 없다.
- **④ 셋째 칸이 실재하는지 아무도 안 잰다.** 표의 셋째 칸(「무엇으로 재나」)은
  `` `e2e/quality_eval.py` `` 처럼 측정기 파일을 가리키는데, 그 파일이 실재하는지 보는
  단언이 0개다. `QUALITY_BAND` 가 임포트하는 것은 튜플 **자신의 셋째 원소**(`"quality_eval"`
  리터럴)이지 README 의 셋째 칸이 아니고, `E2E_COUNT` 대조는 파일 **개수**만 센다.
  **이 파일이 존재하는 이유(『README 가 없는 모듈 `websearch.cli` 를 안내한 채 푸시됐다』,
  `tests/test_readme.py:3-6`)와 정확히 같은 모양의 구멍**이다.

**목표.** 표의 **각 행**이 ① 대조받는 밴드에 물려 있고 ② 실재하는 측정기 파일을 가리키는지
본다. 그래서 «표를 넓히는 편집»과 «측정기를 개명하는 편집»이 대조를 빠져나가지 못한다.

**기대 결과.** 오늘 일곱 행은 전부 통과(오탐 0)하고, 아래 두 편집은 각각 **1건 이상 RED** 다.

- 행 추가: `| 새 축 | 뭔가 7배 이상 | \`e2e/design_check.py\` |`
- 셋째 칸 오타: `` `e2e/quality_eval.py` `` → `` `e2e/quality_evals.py` ``

## 2. 착수 탐침 — 두 구멍이 오늘도 살아 있다 (2026-09-06 · 반복 382)

`digest [7]`(「기록된 답을 실행 전에 다시 재라」)를 적용해 처방이 아니라 **진단부터** 다시
쟀다. 저장소 밖 사본(`src`·`tests`·`e2e`·`docs`·`README.md` · `.git`·`data/` 제외)에서
편집을 실물 파일로 심고, 매 판 `PYTHONDONTWRITEBYTECODE=1 PYTHONPYCACHEPREFIX=$(mktemp -d)`
를 줬다(`digest [7]` 바이트코드 캐시 항목). 워킹트리는 무변경이고 러너에 리다이렉션은 0회다.

| 판 | 무엇을 심었나 | 결과 |
|---|---|---|
| **기준선** | 저장소 원본 · 전수 | `Ran 623 tests in 15.724s` · `OK` · rc 0 |
| **M0** | 사본 무변이 · `test_readme.py` | `Ran 6` · `OK` · rc 0 (오탐 0) |
| **U1** | README 표에 행 하나 추가 | `Ran 6` · `OK` · rc 0 — **생존** |
| **U2** | 셋째 칸 `quality_eval` → `quality_evals` | `Ran 6` · `OK` · rc 0 — **생존** |

**전수는 기준선 한 판만 돌렸다.** U1·U2 는 `-p test_readme.py` 로 6건만 돌렸다 —
두 편집이 건드리는 것은 README 텍스트뿐이고 그것을 읽는 단언은 이 파일에만 있다
(계획 65 e2e 도 같은 이유로 `Ran 6` 으로 쟀다).

**digest 의 처방 한 줄을 정정한다.** `[7]①` 은 처방을 「표 행 수를 `len(QUALITY_BAND)` 와
대조하는 단언 한 줄」로 적어 뒀는데 **그대로는 성립하지 않는다** — 표는 **일곱 행**이고
`QUALITY_BAND` 는 **아홉 줄**이다(첫 행과 마지막 행이 각각 수치 둘을 담는다). 상수 `7` 을
적으면 그것이야말로 거울이라 3절이 방향을 바꿔 적었다. **진단은 옳았고 처방이 그때의
추정이었다** — `digest [7]`(cooldown-burn)이 말한 그 모양이 세 번째다.

**기점은 `origin/main` 으로 다시 쟀다.** 사람이 `bff2580` 로 병합해 `QualityBandTest` 는
이미 `main` 에 있다(`git show origin/main:tests/test_readme.py | grep -c QUALITY_BAND` → 2 ·
`git diff --stat origin/main HEAD -- tests/test_readme.py README.md` **빈손**). 고칠 자리가
`main` 안에 있으므로 계획 58 이 「기점은 아카이브 커밋」으로 판단했던 근거는 오늘 안 쓴다.

**1~5순위도 그대로 쟀다**(2026-09-06 · 반복 382). 전수 맨몸 `Ran 623` `OK` rc 0 ·
린터/타입체커 설정 파일 0개 · `TODO`/`FIXME`/`HACK` 이 `src/`·`tests/`·`e2e/` 에 1건인데
`tests/test_indexer.py:759` 의 **파서 입력 문자열 안**(계획 65 와 같은 건) ·
`docs/candidates.md` 부재 · `docs/patches/` 부재 · `digest ## 보류 (승인 대기)` 0건(본문이
통째로 HTML 주석) · 활성 계획 0 · `git status --porcelain` 빈손.
**`gh` 는 한 번도 안 불렀다** — 이번 반복의 하드 제약이라 이슈 목록은 안 쟀다.

## 3. 스텝 — 1개

**스텝 1/1 — `tests/test_readme.py` 에 표 «모양» 축 단언 둘을 넣는다.**

- **어디서 시작하나**: `tests/test_readme.py:50` 의 `QUALITY_BAND` 아래. 새 클래스
  `BandTableShapeTest` 를 `QualityBandTest`(124행) 다음에 붙인다 —
  `if __name__ == "__main__"` 가드(156행)보다 **위**여야 한다(`digest [7]`: 가드 뒤에 붙인
  클래스는 직접 실행에서 존재조차 안 한다).
- **무엇이 이미 참인가**: `QUALITY_BAND` 아홉 줄이 이미 있고 각 줄의 둘째 원소가 README
  에서 수치를 뽑는 정규식이다. `README` 상수(24행)는 저장소 최상위 `README.md` 를 가리키고,
  `README.parent` 는 저장소 루트다(`test_verification_counts_match_reality:117` 이 이미
  `README.parent.glob("e2e/*.py")` 로 쓰는 관용구다).
- **무엇을 넣나**: 셋.
  1. 모듈 수준 정규식 하나 — 「잘하고 있나 재는 자」 표의 **데이터 행만** 잘라낸다.
     README 에는 표가 셋(일꾼 · 종료 코드 · 합격선)이라 **제목으로 잘라야** 엉뚱한 표를
     안 잰다. 제목 줄 + 빈 줄 + 머리 줄 + 구분 줄을 건너뛰고 그 뒤 `|` 줄을 묶는 모양이다.
  2. **행 커버 단언** — 각 행이 `QUALITY_BAND` 의 정규식 **하나 이상**에 걸리는가.
     걸리는 것이 없으면 그 행의 합격선은 대조 밖이다. 행 목록이 비면(정규식이 죽으면)
     빈손 위에서 조용히 통과하므로 **행이 하나 이상**인 것을 먼저 단언한다
     (`test_every_module_readme_names_is_importable:76` 이 이미 쓰는 관용구다).
  3. **측정기 실재 단언** — 각 행의 셋째 칸에서 백틱 안 경로를 뽑아
     `(README.parent / 경로).is_file()`. `〃`(윗 행과 같음)는 **건너뛰지 말고 윗 행의
     경로를 이어받는다** — 건너뛰면 `〃` 로 적힌 행이 영영 안 재지는 눈먼 자리가 생긴다.
     오늘 `〃` 는 마지막 행 하나이고 이어받는 값은 `e2e/design_check.py` 다.
- **`README.md` 는 `## 검증` 의 건수 한 줄만 고친다**(104행 `# 단위 623건`). 새 단언 둘이
  들어가면 전수가 625 가 되고, 같은 커밋에서 안 고치면
  `test_verification_counts_match_reality` 가 즉시 빨개진다 — **그것이 설계대로다.**
- **무엇으로 확인하나**: 4절 완료 기준 1~8.

**한 스텝인 이유**: 산출물이 파일 하나의 클래스 하나이고, 둘로 쪼개면 「행을 잘라낸다」와
「단언을 건다」가 되는데 앞엣것은 따로 검증할 수 없다(카파시 4번). ①과 ④는 **같은 행 목록**
위에서 돌기 때문에 나누면 잘라내는 코드가 두 벌이 된다.

## 5. 하지 않을 것

- **`docs/specs/concept.md` 축(`digest [7]③`)은 안 연다.** 세 번째 사본이 거기 있고 계획 65
  가 오늘 셋 일치를 확인했지만, 그 파일은 **사람이 고치는 읽기 전용 문서**다(이번 반복의
  하드 제약이기도 하다). 묶을지 말지는 사람이 정한다.
- **표의 둘째 칸 «문구» 는 안 잰다.** 잡는 것은 수치와 경로뿐이다. 문구를 통째로 단언에
  적으면 문구를 다듬는 날 단언도 같이 고쳐져 거울이 된다(계획 65 7절이 세운 원칙 그대로).
- **README 의 다른 두 표(일꾼 · 종료 코드)는 안 넓힌다.** 같은 「표 구조」 축이지만 그 둘은
  합격선이 아니라 설명이고, 오늘 그 표들이 낡았다는 실측이 0건이다(YAGNI).
- **`e2e/*.py` 상수는 한 자도 안 건드린다.** 이 계획은 문서 쪽 축만 넓힌다.
- **`digest` 의 `test_readme.py` 항목 `[5]`(`RUNNER_LINE`·`BUFFERED` 의 거짓 RED 방향 둘)은
  안 연다.** 오늘 무해하고 그 항목이 스스로 적은 여는 조건이 안 왔다 — 직교 편집이다
  (카파시 3번).
- **새 e2e 파일은 만들지 않는다.** 프로세스 밖 동작이 0 이라 `rules/e2e.md` 3절 면제가
  예상되지만, **e2e phase 가 근거 셋으로 다시 잰다**(계획 65 가 그렇게 했다).

## 7. 위험

- **새 행이 우연히 기존 밴드 정규식에 걸리는 경우**(예: 「1초에 9장 이상」). 커버 단언은
  통과하지만 기존 `QualityBandTest` 의 「정확히 하나」 단언이 둘을 잡아 RED 다 — 두 자리가
