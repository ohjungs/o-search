## 반복 75 — 2026-08-27 · 리뷰 반영 (search-ui)

- 한 일: 백지 리뷰의 지적 9건 중 **high 1·medium 3·low 5** 를 분류해 8건 반영. 235/235, e2e 9종 전부 종료 0
- **리뷰가 확인해 준 것과 뒤집은 것이 갈린다.** 이스케이프 자체는 안 뚫렸다 — 적대적 URL 8종 실사격에서 `href="javascript:` 0건, `<script` 0건. 뚫린 건 **검증 장치**였고 넷 다 같은 유형이다: **없어진 것을 못 보는 검사**
- **[high] 다크 블록이 없으면 라이트 맵이 다크 행세를 했다.** `dark = dict(light, **{})` 라 "다크 7쌍 전부 OK" 를 찍고 **종료 0**. 다크 CSS 를 통째로 지워도 통과했다 — 파일 첫머리 독스트링이 금지한 바로 그것이다. 변이 확인: 다크 블록 제거 → 종료 2
- **다크 미디어쿼리가 2개면 `"".join()` 결과가 원문에 없어 `replace` 가 무동작**이 되고 **라이트 맵이 다크 값으로 오염**됐다(리뷰 실측 `--bg-page` = `#000000`). 인덱스 슬라이싱 + 중괄호 세기로 고쳤다. non-greedy `.*?\}\s*\}` 는 중첩 깊이를 모른다. `and (min-width:…)` 가 붙은 형태도 이제 찾는다
- **[medium] 고정폭 검사가 `px` 만 봤는데 제품 CSS 는 전부 `rem`** 이다(`max-width:36rem`, `44rem`). **검사기의 눈먼 자리가 정확히 제품이 사는 곳이었다.** rem/em/vw/% 환산으로 고치고, 모르는 단위는 종료 2. 변이 `width:40rem` → `(= 640) > 360` 으로 종료 1
- **[medium] `PAIRS` 커버리지 강제가 라이트 맵만 봐서 다크 전용 `--fg-` 토큰이 빠져나갔다** → 두 맵 합집합. 변이 `--fg-visited` 를 다크에만 추가 → 종료 2
- **테스트에도 같은 것이 있었다.** 이 파일 XSS 단언이 전부 `assertNotIn` 이라 **`_safe_href` 가 무조건 `None` 을 돌려줘도 전부 통과**했다 — 링크가 통째로 사라지는 변이를 아무도 못 잡는다. 긍정 짝(`assertIn('href="http://ok.test/')`)을 붙이고 fixture 에 멀쩡한 URL 을 하나 넣었다. 변이 확인: 항상 `None` → 4건 실패
- **[low] `_safe_href("http")` 가 통과했다** — `"http".split(":")[0]` 은 `"http"` 다. `//evil.test/x` 같은 스킴 없는 상대 경로도 뚫렸다. 신뢰 경계라 짧아도 닫았다(`partition` 으로 콜론 유무 확인)
- **[low] 오류 페이지가 `SEARCHBOX % ("", " autofocus")`** 였다 — 친 질의어를 버려 다시 치게 만들고, autofocus 가 스크린리더 사용자를 **오류 문구를 지나쳐** 입력창으로 끌고 간다. `serve.py:104` 주석이 결과 페이지에 대해 직접 금지한 것과 같은 상황이다
- **[low] `h1` 이 어디에도 없었다** — 제목 계층이 `h2` 부터 시작했다. 홈 브랜드와 결과 안내문을 `h1` 으로 올리고 크기는 CSS 가 그대로 유지한다(**계층은 의미용, 크기는 시안용**). `assert_page_basics` 에 단언 추가
