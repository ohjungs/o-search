## 이번 계획에서 가장 값진 것은 코드가 아니라 리뷰다

백지 리뷰가 **이스케이프 자체는 안 뚫렸다**고 실사격으로 확인했다(적대적 URL 8종).
대신 **검증 장치가 비어 있는 자리 넷**을 찾았고, 넷 다 같은 실패 유형이었다 —
**없어진 것을 못 보는 검사**. 초록불이 근거 없이 켜져 있었다.

1. 다크 블록이 없으면 라이트 맵이 다크 행세를 하며 "7쌍 OK"를 찍고 **종료 0**
2. 다크 미디어쿼리가 2개면 `replace` 가 무동작이 되어 **라이트 맵이 다크 값으로 오염**
3. `PAIRS` 커버리지 강제가 라이트 맵만 봐서 **다크 전용 `--fg-` 토큰이 빠져나감**
4. 고정폭 검사가 `px` 만 보는데 **제품 CSS 는 전부 `rem`** — 눈먼 자리가 제품이 사는 곳

그리고 테스트 쪽에도 같은 것이 있었다: XSS 단언이 전부 `assertNotIn` 이라
`_safe_href` 가 **무조건 `None` 을 돌려줘도 전부 통과**했다.

넷 다 고치고 **변이로 다시 확인**했다. 여기서 나온 규칙 하나:
**부정 단언에는 반드시 긍정 짝을 붙인다.** ("나쁜 것이 없다"는 "아무것도 없다"로도 참이다)

이번 밤에 이 실패 유형을 **내가 세 번 겪었다** — 구현 전 RED 에서 이스케이프
테스트 3개가 공허하게 통과한 것, 자체 점검을 회색으로만 짜서 채널 가중치 변이를
놓친 것, 그리고 위 넷. `digest.md` 로 올릴 1순위 후보다.
