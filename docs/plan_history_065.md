# 계획 79 `rate-limit` — 공개 API 에 IP 당 분당 60회 제한을 건다

## 1. 왜 지금인가

`docs/specs/concept.md` 「사람이 정할 것」 1번이다. **사양은 숫자도 방식도 이미 줬다** —
로그인이 없으니 IP 가 유일한 손잡이고, 남용 대응은 인증이 아니라 속도 제한이며,
1단계 가정은 **IP 당 분당 60회**다. 비어 있던 것은 **착수 시점**뿐이고, 사용자가
자율 판단을 위임했으므로 지금 연다.

**지금인 이유**는 계획 77·78 이 규모 축을 열었기 때문이다. 10만 문서를 담을 수 있게
된 검색엔진이 **제한 0** 으로 공개 API 두 개(`/search`·`/passages`)를 열어 두고 있다.
`/passages` 는 p95 138ms 로 `/search`(16ms)의 8배라, 남용 비용이 경로마다 다르다.

## 2. 먼저 의심할 것 — 여기는 공유 상태다

`serve` 는 **`ThreadingHTTPServer`** 다(`serve.py:364`). 속도 제한 카운터는 요청
스레드가 동시에 읽고 쓰는 **공유 상태**라, `rules/dev.md` 6-1절·`severity.md` 의
「공유 상태를 건드리면 승인 쪽으로 기운다」에 걸린다. 이 종류의 결함은 **테스트가
초록이고 리뷰도 통과한 뒤 부하에서만 드러난다.**

그래서 이 계획은 **락과 그 계약을 테스트로 먼저 고정**하고 구현한다.
「두 스레드가 동시에 61번째를 쏘면 정확히 하나만 통과한다」가 그 계약이다.

## 3. 설계 — 슬라이딩 창, stdlib 만

- **IP → 최근 요청 시각 `deque`**. 요청마다 60초 밖을 앞에서 버리고 길이를 본다.
- **고정 창(분 단위 카운터)을 안 쓰는 이유**: 창 경계에서 2배 버스트가 통과한다
  (59초에 60회 + 61초에 60회). 슬라이딩은 그 구멍이 없고 값은 `deque` 하나다.
- **메모리는 스스로 준다** — 창이 빈 IP 는 키째 지운다. 상주하는 것은 «최근 1분 안에
  요청한 IP» 뿐이라 따로 청소기를 두지 않는다.
- **의존성 0** (`collections.deque` · `threading.Lock` · `time.monotonic`).
- **`time.monotonic` 을 쓰는 이유**: 벽시계는 NTP 보정으로 뒤로 갈 수 있고, 그러면
  창이 늘어나 제한이 조용히 풀린다.

응답은 **429** 에 `Retry-After` 헤더. 본문은 기존 `_send` 관용구를 그대로 쓴다.

## 4. 스텝

| # | 산출물 | 완료 기준 |
|---|---|---|
| 1 | 리미터 (TDD · 동시 실행 계약 포함) | 실패 테스트 먼저 · 경계 60/61 · 창 만료 · 스레드 |
| 2 | `serve` 에 배선 + 429 | 두 JSON 경로에 적용 · 전수 초록 |
| 3 | e2e | 실제 HTTP 로 61번째가 429 · `Retry-After` |

## 4-a. 결과

전수 **685 OK rc 0** · HTTP e2e 5종 rc 0 · 측정 하네스 4종 rc 0.
배선을 **실제 서버로** 확인했다(429 + `Retry-After` · 두 경로 공동 예산 · 404 는 예산
안 먹음 · 화면 제한 밖 · `None` = 무제한). 동시 실행 계약은 스레드 8개 × 200회에
통과 정확히 50.

**제한이 측정 하네스를 죽였고 그것을 실측이 잡았다.** `passage_eval` 이 429 를 받아
「잴 수 없다」로 죽었다 — 질의 40개 × 5회 = 200회라 당연히 넘는다. **제한이 재는 대상을
검색 지연에서 리미터로 바꿔 버린 것**이라, `rate_limit=None` 갈래를 열고 셋이 쓴다.

**오늘 막는 것은 없다** — 서버가 `127.0.0.1` 에만 바인드해 외부에서 닿지 못한다.
그럼에도 넣는 이유는 노출되는 날 제일 먼저 필요한 것이 이것이고, 노출과 제한을 같은
날 하면 그날 급해서 대충 하기 때문이다. 전문: `docs/e2e/rate-limit/result.md`.

## 5. 하지 않을 것

- **화면(`/`)은 제한하지 않는다.** 사람이 브라우저로 쓰는 경로라 한 번의 검색이 여러
  요청을 부르지 않고(정적 자산이 없다), 남용 축은 API 다. 넣으려면 숫자가 따로 필요하다.
- **IP 별 다른 한도·경로별 다른 한도를 두지 않는다.** `/passages` 가 8배 비싼 것은
  사실이지만 사양이 준 숫자는 하나뿐이다. 쪼개려면 근거를 재고 사양을 고친 뒤에 한다.
- **프록시 헤더(`X-Forwarded-For`)를 믿지 않는다.** 위조 가능하고, 지금 앞단에 프록시가
  없다. 믿을 앞단이 생기는 날 그 신뢰 경계를 따로 판단한다 — `rules/security.md` 축이다.
- **저장하지 않는다.** 재시작하면 창이 비는 것이 맞다. 영속화는 다중 인스턴스 이야기고,
  컨셉 2단계까지 단일 머신이다.
