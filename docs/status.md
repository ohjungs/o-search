## 설계가 닫은 갈림길 둘 (`docs/design_search-ui.md`)

**1. HTML 을 어디로 내나 → `/` 는 HTML, `/search` 는 JSON 그대로.**

```
GET /          → 검색 홈      GET /?q=김치 → 결과 페이지
GET /search?q= → JSON (무변경)  그 외 → 404 (무변경)
```

`Accept` 협상(가)을 버린 이유: 같은 URL 이 헤더에 따라 다른 것을 내면
`e2e/perf_search.py` 의 p95 가 **어느 코드의 p95 인지 헤더에 달리게** 된다.
성능 축은 `concept.md` 우선순위에서 디자인보다 위라 거래가 거꾸로다.
정적 HTML + `fetch()`(다)를 버린 이유: 첫 화면에 왕복이 하나 더 붙어
**이 계획이 스스로 재겠다고 세운 LCP 기준을 첫 결정으로 나쁘게 만든다.**

`serve.py:24` 의 `_parse()` 를 **재사용한다**(같은 파일 `:27` 주석이 진입점 방어를
한곳에 모으라고 직접 말한다). `q` 가 비면 `_parse()` 를 부르기 **전에** 홈을 낸다 —
`_parse()` 를 고치면 JSON 의 400 계약이 바뀐다.

**2. 대비를 무엇에 대고 재나 → 이름은 검사기가, 값은 CSS 가 갖는다.**
CSS 는 색을 `--fg-*`/`--bg-*` 토큰으로만 선언하고, 검사기는 **쌍의 이름만** 들고
값은 매번 응답의 `<style>` 에서 읽는다 → 드리프트가 구조적으로 불가능하다.
`--fg-` 토큰 중 쌍 목록에 빠진 것이 있으면 **종료 2**(측정 불능) — 커버리지 구멍을
규약이 막는다. 다크(`prefers-color-scheme`)는 오버라이드를 덮은 두 번째 맵으로 한 번 더.

## 스텝 1 이 지킬 것 (설계에서 확정)

- 이스케이프 **4자리**: 질의어(`value=`·`<title>`) · 제목 · URL · 스니펫.
  속성 자리는 `quote=True`(기본값)가 필요하다.
- **`href` 는 이스케이프만으로 부족하다** — `javascript:` 는 `&`·`<`·`"` 를 하나도
  안 써서 `html.escape()` 를 그대로 통과한다. 렌더 시점에 **스킴을 확인**한다.
- 접근성: `<form role="search">` · 입력에 접근 가능한 이름 · `<html lang="ko">` ·
  결과 제목 `<h2><a>`. **키보드는 폼 GET 이라 기본으로 된다**(JS 0KB → 포커스 트랩 없음).
- 시안 `demo_ui.py` 는 **형태만** 가져온다 — 자체 `build_db`, 하드코딩 예시 링크,
  `real.db` 탐색은 저장소가 쓰지 않는 것이다.

**LCP 는 브라우저 없이 직접 못 잰다**(야간 의존성 추가는 정지 조건). 대리 지표로 간다:
외부 서브리소스 0 · 문서 gzip 크기 · 서버 왕복 p95. **못 잡는 것은 브라우저 레이아웃·
페인트 시간**이고, 업그레이드 경로는 사람이 헤드리스를 붙일 때 Lighthouse 교체다.
360px 은 viewport meta · 360px 초과 고정폭 없음 · **`overflow-wrap`**(공백 없는 긴
크롤 URL 이 이 제품의 진짜 넘침 원인이다) 셋으로 잰다.
