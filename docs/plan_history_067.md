# 계획 81 `ethics-floor` — 크롤 윤리 상수를 규율이 아니라 기계가 지킨다

## 1. 왜 지금인가 — 오늘 실제로 뚫렸다

2026-09-09 무인 사이클이 메모리 부족으로 강제 종료되며 작업 트리에 이것을 남겼다:

```diff
-DOMAIN_INTERVAL = 1.0   # 초 — concept.md 크롤 윤리, 내리지 않는다
+DOMAIN_INTERVAL = 0.05  # 초 — concept.md 크롤 윤리, 내리지 않는다
```

**주석이 「내리지 않는다」고 적힌 바로 그 줄이고, 전수 706건이 그 상태로 전부 초록이었다.**
잡은 것은 검사가 아니라 **사람이 diff 를 눈으로 본 것**이다. 그것은 기제가 아니다.

## 2. 왜 기존 단언이 못 잡나 — 전부 상수를 «참조»한다

`tests/test_frontier.py` 의 넷과 `test_crawl.py` 가 `DOMAIN_INTERVAL` 을 **임포트해서**
비교한다(`assertEqual(f.interval("a.test"), DOMAIN_INTERVAL)`). 값을 바꾸면 **단언도
같이 따라가서** 언제나 참이다. 「간격을 지키나」는 재지만 「그 간격이 윤리 하한 위인가」는
아무도 안 잰다.

**이것이 이 저장소가 여러 번 배운 모양이다** — 자가 자기 축을 안 재면 조용히 초록이다
(`digest` 의 「하한 못의 값 변이는 아무도 안 문다」·「축 이름을 통째로 단언한다」와 같은 칸).

## 3. 무엇이 윤리 하한인가

`docs/specs/concept.md` 기능 3: *"robots.txt 준수, 도메인당 요청 간격 1초 이상은 기능이
아니라 **전제 조건** — 어기는 코드는 리뷰에서 RED 다."* 그리고 갈림길 우선순위 1위가
크롤 윤리다. **사양이 준 숫자가 1초**라 하한은 리터럴 `1.0` 이다.

**하한을 상수로 안 빼고 테스트에 리터럴로 박는 이유**가 여기 핵심이다 — 상수로 빼면
그 상수를 같이 내려서 다시 뚫린다. 재는 쪽과 재이는 쪽이 같은 값을 공유하면 자가 아니다.

## 4. 스텝

| # | 산출물 | 완료 기준 |
|---|---|---|
| 1 | 윤리 하한 못 (TDD) | 실패 테스트 먼저(오늘 0.05 를 재현) · 전수 초록 |

**한 스텝이다.** 20줄 안쪽·파일 1~2개지만 **짧은 경로로 가지 않는다** — 보안·윤리 축이라
`SKILL.md` 4-1절의 「보안·데이터와 무관」 조건에 안 걸리고, 근거가 실제 사고라 기록이 값이다.

## 4-a. 결과 — 변이 3판이 전부 물었다

| 변이 | 결과 |
|---|---|
| `DOMAIN_INTERVAL = 0.05` (실제 사고값) | **FAILED 2** |
| `DOMAIN_INTERVAL = 0.9` (경계) | **FAILED 2** |
| `set_delay` 의 `max()` 제거 | **FAILED 1** |

전수 **708 OK rc 0**. 변이는 **사본**에서 쟀다 — 원본을 낮춰 재면 중단이 곧 위반으로
남는다. **이 계획 도중에 내가 한 번 그 실수를 했고** 바로 되돌린 뒤 사본으로 옮겼다.
규율은 이렇게 새고, 그래서 못이 필요하다. 전문: `docs/e2e/ethics-floor/result.md`.

## 5. 하지 않을 것

- **`DOMAIN_INTERVAL` 값을 안 바꾼다.** 1.0 이 맞고, 이 계획은 그것을 **붙드는** 일이다.
- **`MAX_DELAY`(30초)는 하한 축이 아니다** — 그건 「너무 긴 간격을 요구하는 도메인을
  버린다」는 상한이라 방향이 반대다. 같이 묶으면 못이 무엇을 지키는지 흐려진다.
- **처리량은 이 계획에서 안 건드린다.** 오늘 실측으로 처리량은 **도메인 수에 정비례**
  (1→1.03 · 2→2.08 · 4→4.40 · 8→9.86 문서/초)이고 코드 문제가 아니다. 컨셉 성능 2
  (5문서/초)는 **도메인 5개 이상이면 자동 충족**이라 고칠 코드가 없다 — 시드 이야기다.
