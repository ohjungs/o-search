# 결과 — 계획 83 `userinfo-leak`

## 1. 무엇을 재기로 했나 — 축 하나가 사라졌다

`e2e/domain_key_e2e.py` 는 017(도메인 열쇠)의 실물 회귀 탐지기였다. 018 이 대소문자·
기본 포트를 `normalize` 로 접으면서 그 축이 죽었고, 남은 것이 **userinfo** 하나였다.
계획 83 이 자격증명 URL 을 입구에서 거절하면 그 하나도 프런티어에 못 온다 —
**018 때와 같은 모양**으로, 재려던 상황 자체가 안 만들어진다.

그 파일의 종료 2 가드(「잴 대상이 사라지면 측정 불능」)가 조용한 통과 대신 크게 실패해
이것을 놓칠 수 없게 했다. 실측:

```
측정 불능 — 같은 서버 페이지 도착 표본이 2개다(필요 4) · 종료 2
```

**017 의 e2e 급 회귀 탐지기는 여기서 끝난다.** 남는 것은 단위
`tests/test_urls.py` 의 `TestDomainKey` 다. 하네스(같은 서버·Host 로그·간격 측정)는
그대로 쓰고 **재는 것만** 「세 표기가 한 도메인으로 묶인다」에서
**「자격증명 표기는 수신 0건 · 남은 표기는 여전히 한 칸」**으로 갈아 끼웠다.

## 2. 결과

```
OK 5.2s — 같은 서버 3회 도착(표기 a.test · 자격증명 u:pw@a.test 는 0건)
간격 ['2.14', '2.14'] · robots 1회 · 대조군(a.test:443) 간격 ['1.15', '1.03']
--control → 측정 불능(2)
```

전수 **717 OK**.

## 3. 실물 한 번이 **거짓 초록**을 잡았다

처음 쓴 단언은 **Host 헤더에 `@` 가 오는가**였다. 단위는 초록, e2e 도 초록.
변이(=`normalize` 의 거절을 지운 사본)에서 돌리자 이렇게 나왔다:

```
OK 7.2s — 같은 서버 4회 도착(표기 a.test · 자격증명 u:pw@a.test 는 0건) …
                    ↑ 3회여야 하는데 4회다. 그런데 단언은 통과했다
```

**`urllib` 은 Host 헤더에 userinfo 를 안 싣는다.** 자격증명 요청이 실제로 나갔는데도
Host 는 `a.test` 로만 찍혀, 단언이 **누출 위에서 초록**이었다 — 이 e2e 가 겨냥한
바로 그 실패 모양(「잴 대상이 사라졌는데 참이 되는 단언」)을 내가 새로 만든 자에서
반복한 것이다.

증거를 **경로**로 바꿨다. `/p1` 은 자격증명 href 로만 존재하므로 **도착 = 우리가 그
URL 로 요청을 보냈다**는 뜻이고, 여기에 `Authorization` 헤더 검사를 더했다.
같은 변이에서:

```
AssertionError: 자격증명 URL 이 남의 서버에 도착했다: [('a.test', '/p1')]
 — 우리 요청이 남의 비밀번호를 실어 날랐다 · 종료 1
```

## 4. 단위가 못 보는 자리

단위는 `links.extract` 가 `None` 을 버리는 것까지만 본다. 여기서 재는 것은
**남의 서버가 그 요청을 받았는가**이고, 그것은 소켓 반대편에서만 보인다.
크롤 윤리 축(`concept.md` 갈림길 1순위)의 단언은 늘 이쪽에 하나 있어야 한다.
