# O-Search

인터넷에 있는 글을 모아 두었다가, 물어보면 찾아 주는 프로그램이다.

## 어떻게 일하나 — 일꾼 셋

| 일꾼 | 하는 일 | 비유 |
|---|---|---|
| `crawl` | 웹사이트를 돌아다니며 글을 주워 온다 | 책을 주워 오는 아이 |
| `indexer` | 주워 온 글을 낱말별로 정리한다 | 책 뒤에 붙는 «찾아보기» 를 만드는 아이 |
| `serve` | 물어보면 찾아서 보여 준다 | 도서관 안내 데스크 |

순서대로 해야 한다. 글을 안 주워 오면 정리할 게 없고, 정리를 안 하면 찾아 줄 수가 없다.
주워 온 글은 `data/crawl.db` 라는 상자 하나에 다 들어간다.

## 무엇으로 만들었나

파이썬에 **원래 들어 있는 것만** 썼다. 밖에서 가져다 쓴 것이 하나도 없다.
그래서 따로 설치할 게 없다.

한글은 두 글자씩 잘라서 찾는다(«김치찌개» → «김치 / 치찌 / 찌개»). 그래야 띄어쓰기가
달라도 찾아진다.

## 해 보기

명령이 셋이다. 하나씩 차례로 친다.

```bash
PYTHONPATH=src python3 -m websearch.crawl https://example.com --max 100  # 1. 주워 온다 → data/crawl.db
PYTHONPATH=src python3 -m websearch.indexer data/crawl.db                # 2. 정리한다
PYTHONPATH=src python3 -m websearch.serve data/crawl.db                  # 3. 보여준다 → http://localhost:8000
```

앞에 붙은 `PYTHONPATH=src` 는 «프로그램이 어디 있는지» 알려 주는 말이다. 설치를 안 했으니
매번 알려 줘야 한다.

화면 없이 답만 보고 싶으면 이렇게 물어봐도 된다:

```bash
PYTHONPATH=src python3 -m websearch.indexer data/crawl.db --query 검색어
```

무엇을 하라는 말 없이 그냥 부르면, 「이렇게 쓰세요」 하고 사용법을 알려 준다.

## 끝나고 남기는 숫자

프로그램은 일을 마치면 숫자를 하나 남긴다. 잘 됐는지 아닌지를 그 숫자로 말한다.

| 숫자 | 무슨 뜻인가 | 그럼 뭘 해야 하나 |
|---|---|---|
| **0** | 잘 됐다 (찾은 게 0건이어도 잘 된 것이다) | 다음 걸 하면 된다 |
| **1** | **준비가 안 됐다** — 상자가 없거나, 정리가 낡았거나, 상자가 깨졌거나, 문(포트)이 막혔다 | 준비물을 챙겨 준다 |
| **2** | **명령을 잘못 썼다** | 사람이 명령을 고쳐 친다 |
| **130** | 사람이 Ctrl-C 로 멈췄다 | 다시 하거나 그만둔다 |

## 보여주는 아이는 잘 안 죽는다

상자가 없거나 깨져 있어도 `serve` 는 일단 뜬다. 대신 물어보면 이렇게 답한다.

- **503 — 「아직 준비가 안 됐어요」**: 상자가 없거나, 정리가 낡았거나, 주워 온 글이 없다.
  **다시 주워 오고 다시 정리하면 낫는다.**
- **500 — 「제가 고장났어요」**: 상자 모양이 어그러진 경우다(예: 글 내용을 담는 칸이 통째로
  없다). 이건 다시 돌려도 안 낫는다 — 주워 오는 것도 정리하는 것도 그 상자에서는 죽는다.

**무엇을 물어봤는지에 따라 답이 달라지지 않는다.** 같은 상자라면, 찾는 게 있든 없든 같은
숫자가 나온다. (예전에는 「김치찌개」를 물으면 500, 「없는말」을 물으면 200 이 나와서
상자가 멀쩡한 줄 알았다. 그게 고쳐야 했던 고장이다.)

`serve` 가 1 을 남기는 경우는 **문을 못 열었을 때뿐**이다. 서버는 계속 켜져 있는
프로그램이라, 끝나면서 숫자로 알려 줄 상대가 없다.

## 착하게 주워 오기

빨리 하는 것보다 착하게 하는 것이 먼저다.

- 같은 사이트에는 **1초에 한 번보다 자주 안 간다**
- 문 앞에 붙은 쪽지(`robots.txt`)를 읽고 **하지 말라는 건 안 한다**
- 그 쪽지가 너무 길면 512KB 까지만 읽고, 잘린 마지막 줄은 **버린다**
  (반쯤 읽은 규칙은 원래보다 헐거워서, 하지 말라는 걸 해도 되는 줄 알게 된다)

이 약속은 우리 프로그램 말이 아니라 **상대 서버가 실제로 받은 기록**으로 확인한다.
스스로 「잘 지켰다」고 하는 건 증거가 아니기 때문이다.

## 잘하고 있나 재는 자

| 무엇을 | 얼마나 잘해야 | 무엇으로 재나 |
|---|---|---|
| 잘 찾나 | 10개 중에 맞는 게 80% 이상 | `e2e/quality_eval.py` |
| 근거가 맞나 | 보여 준 문단의 90% 이상이 물어본 말을 담고 있어야 | `e2e/passage_eval.py` |
| 빠른가 | 100번 중 95번은 0.3초 안에 | `e2e/perf_search.py` |
| 문단도 빠른가 | 100번 중 95번은 0.5초 안에 | `e2e/passage_eval.py` |
| 잘 주워 오나 | 1초에 5장 이상 | `e2e/perf_crawl.py` |
| 화면이 가벼운가 | JS 50KB 이하 | `e2e/design_check.py` |
| 글씨가 잘 보이나 | 배경과 4.5배 이상 차이 나게 (글씨 아닌 것 — 포커스 링 같은 표시 — 은 3배) | 〃 |

**눈에 안 보이는 글은 근거로 안 쓴다.** 웹페이지에는 숨겨 놓은 글이 있다(`<template>`,
`hidden`, `aria-hidden="true"`, `display:none`, 글자 크기 0). 사람 눈에 안 보이는 걸
「여기 이렇게 써 있어요」 하고 내밀면 거짓말이 되니까 빼 놓는다. 다만 HTML 한 장만 보므로,
바깥 파일(CSS)로 숨긴 것까지는 못 본다.

## 확인하기

```bash
PYTHONPATH=src python3 -m unittest discover -b -s tests   # 단위 609건
ls e2e/*.py                                               # e2e 시나리오 21종
```

e2e 는 하나씩 따로 돌린다 — `PYTHONPATH=src python3 e2e/<이름>.py`.

## 어떻게 만들어 가나

무엇을 하고 있는지는 전부 `docs/` 에 적혀 있다. `docs/status.md` 가 지금 신호등,
`docs/index.md` 가 지금까지 한 일 목록, `docs/digest.md` 가 **같은 실수를 또 한 기록**이다.
일 하나에 가지 하나를 쓴다(`loop/<이름>`).

테스트는 **일부러 고장 내 본다.** 코드를 슬쩍 망가뜨렸는데도 테스트가 「괜찮아요」 하면,
그 테스트는 아무것도 안 지키고 있는 것이다. 그래서 망가뜨려 보고, 테스트가 울어야만
통과로 친다. 이 저장소에서 「다 통과했어요」가 거짓말이었던 적이 여러 번 있었고, 전부
이 절차에서 들켰다.
