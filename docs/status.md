## 이 계획이 여는 것

**`--deadline` 의 계약이 워커 안에서 깨진다.** 예산이 만료돼도 워커의 재시도는 나간다.
착수 탐침: `--deadline 2` · 안 답하는 서버 · `Crawl-delay: 30` →
**종료 70.08초**(예산의 35배)이고 서버가 받은 페이지 요청이 **3건**(`t=0.05 / 30.05 / 60.06`)이다.
**t=2 에 예산이 만료된 뒤 두 건이 더 나갔다** — "꼬리가 붙는다"가 아니라 계약 위반이다.
근거: `digest.md ## 다음 계획 후보` `[5]`.

**그 항목의 처방("`stop.set()` 몇 줄이 전부")은 절반만 맞았다** — 사본에서 갈라 재니
`stop.set()` 만은 **70.08초**(메인 루프가 `futures.wait(timeout=None)` 에 갇혀 예산
만료를 못 본다), `futures.wait` 자르기만도 **70.07초**(워커의 재시도 잠이 그대로),
**둘 다일 때만 10.05초 · 요청 1건**이다. 계획 34 가 신호 축에서 배운
"깨우기와 접기는 하나다" 가 예산 축에서 되풀이됐다.

**오늘의 447건과 e2e 18종은 이 변화를 하나도 안 잰다** — 사본에서 전부 초록이었다.
그래서 스텝 1·2 의 본체는 코드가 아니라 **그것을 재는 단언**이다.
