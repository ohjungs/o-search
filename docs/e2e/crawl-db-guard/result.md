## 판정 재확인 — 새 e2e 를 왜 안 만들었나

설계 7절이 "재는 것이 `main(argv)` 의 반환값과 stderr 이라 프로세스 경계가 필요 없다" 로
새 e2e 0개를 확정했고, 계획 7절이 **반증 신호**를 적어 뒀다: *단위에서 세운 상황이 2-2 의
실측과 다른 예외를 내면 자원을 진짜로 못 세운 것이므로 e2e 로 올린다.*

**그 반증 신호를 이 스텝에서 직접 쟀다.** 단위는 이 계약을 목(`mock.patch`)으로 재고,
사람이 보는 것은 셸의 rc 와 stderr 다 — 그 둘이 같은지는 **진짜 프로세스**로만 확인된다.
그래서 저장소에 파일을 만드는 대신 **1회 탐침**을 돌렸다(임시 디렉터리, `cwd` 도 거기,
`python3 -m websearch.crawl http://127.0.0.1:9/ --max 1`):

| 상황 | rc | stderr | 화면 |
|---|---|---|---|
| **0. 대조군** — 정상 디렉터리 (잣대) | **0** | 0줄 | stdout `수집 0 페이지` |
| 1. 비 DB 파일 | **1** | **1줄** | `DB 를 열 수 없다: data/crawl.db — file is not a database` |
| 2. 부모가 일반 파일 | **1** | **1줄** | `DB 를 열 수 없다: data/crawl.db — [Errno 17] File exists: 'data'` |
| 3. 경로가 디렉터리 | **1** | **1줄** | `DB 를 열 수 없다: data/crawl.db — unable to open database file` |

바뀐 자리가 여기다. **다른 예외는 나오지 않았다** → 반증 신호 없음, 판정 유지.
대조군이 rc 0 이라 "전부 1 이 나오는 세계" 가 아니라는 것도 같이 재진다.

탐침 스크립트는 스크래치패드에서만 살고 저장소에 안 들어온다. 저장소에 남길 값이 없다 —
같은 네 상황을 `tests/test_crawl.py` 의 단위 셋이 이미 붙들고 있고(변이 M1·M2·M3 로
확인됨), 프로세스 배선(`sys.exit(main(...))` 세 곳)은 계획 40 테스트가 전수로 확인했다.
**e2e 를 하나 더 만들면 같은 계약을 두 번 재고 19종이 20종이 될 뿐이다**(ponytail 1번).
