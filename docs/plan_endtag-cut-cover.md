# 계획 59 — `endtag-cut-cover`

닫는 태그가 자손을 잘라내는 자리(`src/websearch/extract.py` `_BlockParser.handle_endtag`
의 `del self._els[i:]`)를 붙드는 단언이 **subTest 한 칸**뿐이다. 그 한 칸이 다른 이유로
바뀌면 자르기가 조용히 살아난다.

- **근거**: `docs/digest.md` `## 다음 계획 후보 (테스트 phase 갭, 8점 미만)` 의 `[5]`
  「닫는 태그가 자손을 잘라내는 자리를 붙드는 단언이 하나뿐이다」(2026-09-03 계획 51
  테스트 2 등재). 그 항목이 스스로 **「다음 테스트 phase 의 첫 후보로 둔다」**로 닫혀
  있어, 오늘 열려 있는 후보 중 **여는 조건이 따로 없는 유일한 항목**이다.
- **기점**: `loop/passage-cost-band` 의 계획 58 마감 커밋. `src/websearch/extract.py` 와
  `tests/test_extract.py` 는 `origin/main`(`d1fe3e9`)과 **바이트 동일**이라

  병합이 끝나면 언제든 `main` 에서 다시 딸 수 있다. 지금 갈라 두면 이 계획서가 그쪽
  브랜치에 없어 하네스가 매 반복 읽을 파일을 잃으므로 **쌓아 둔 채로 간다**(57 → 58 과 같은 모양).

## 1. 문제 · 목표 · 기대 결과

**문제.** `handle_endtag` 는 `_els`(열려 있는 모든 비-void 요소 스택)에서 닫히는 태그를
뒤에서 찾아 **거기서부터 끝까지** 자른다(`del self._els[i:]`). 이 «자손까지 함께 자른다»가
없으면 안 닫힌 자손이 숨김 플래그를 문서 끝까지 붙들어, **보이는 본문 문단이 조용히
사라진다** — 계획 51 이 겨눈 오탐 방향 그대로다. 그런데 오늘 그 자르기를 실제로 붙드는
것은 단언 **한 칸**이다.

**목표.** `del self._els[i:]` 를 `del self._els[i:i+1]` 로 바꾸는 변이가 **둘 이상**의
독립된 모양에서 죽게 한다. 새로 붙는 모양은 **암묵적으로는 못 닫히는 자손**(`_IMPLIED_END`
에 없는 태그)이어야 한다 — 오늘의 유일한 칸(`안 닫힌 li`)은 `li` 가 `_IMPLIED_END` 의
키라서, 그 표를 손대면 함께 흔들린다.

**기대 결과.** 제품 `src/` **0줄** · 고치는 파일 **`tests/test_extract.py` 하나** ·
단위 건수 **605 무변**(subTest 는 메서드 수를 안 늘린다 → `README.md` 무접촉).

## 2. 착수 탐침 — 오늘 다시 쟀다 (2026-09-05 · 반복 345)

`digest [7]`「기록된 답을 실행 전에 다시 재라」의 **열 번째 적용**. 파일을 안 고치고
원본 소스를 문자열로 비틀어 `sys.modules` 에 심는 **메모리 변이**로 쟀다.

| 변이 | 오늘 실측 | 판정 |
|---|---|---|
| **M-a `del self._els[i:i+1]`** | `Ran 605 · failures=1` — `test_an_unclosed_child_does_not_pin_a_hidden_region_open (shape='안 닫힌 li')` | **얇다. 이 계획의 표적** |
| M-b `del self._els[i+1:]` | `failures=16` (`test_extract` 15 · `test_indexer` 1) | 여유 충분 |
| M-c 루프를 앞에서부터 | `failures=6` | 여유 충분 |
| M-d `break` 삭제 | `failures=6` | 여유 충분 |
| M-e `_open` 을 꼭대기 `pop` 으로 | `failures=2` | 여유 충분 |

무변이 대조군은 같은 하네스에서 `Ran 605 · failures=0`. **얇은 방향은 하나뿐이다** —
digest 항목이 적은 «단언이 하나뿐» 은 오늘도 참이고, 형제 넷까지 넓히는 것은 값이 0 이다.

**안 재지는 모양도 실측으로 확정했다.** 원본과 변이에 같은 입력을 먹여 답을 비교했다:

| 입력 | 원본 | 변이 M-a | 갈리나 |
|---|---|---|---|
| `<div hidden><span>속</div><p>보이는</p>` | `[('p','보이는')]` | **`[]`** | **갈린다** |
| `<div hidden><span><em>속</div><p>보이는</p>` | `[('p','보이는')]` | **`[]`** | **갈린다** |
| `<div hidden><p>속</div><p>보이는</p>` | `[('p','보이는')]` | 같음 | 안 갈린다 |
| `<div hidden><span>속</span></div><p>보이는</p>` | `[('p','보이는')]` | 같음 | 안 갈린다 |
| `<section><span>가</section><p>나</p>` | `[('section','가'),('p','나')]` | 같음 | 안 갈린다(오탐 자) |

가르는 것은 **`<span>`·`<em>` 처럼 `_IMPLIED_END` 에 없는 자손이 안 닫힌 채로 있을 때**다.
`<p>` 자손이 안 갈리는 이유는 다음 `<p>` 시작 태그가 `_implied_end` 로 이미 걷어내기
때문이고, 자손을 제대로 닫으면(`</span>`) `_els` 꼭대기가 `div` 라 변이도 같은 답을 낸다.
오늘 이 모양을 밟는 테스트는 **0건**이다(그래서 M-a 가 한 칸에 걸려 있다).

## 3. 스텝 — 1개

`TestExtractBlocks.test_an_unclosed_child_does_not_pin_a_hidden_region_open` 의
`for name, html in [...]` 목록에 **암묵적으로 못 닫는 자손** 모양을 더한다(2절 표에서
