# 설계: 마지막 ⚪ 보고서가 핀보다 나중이면 빨강 (계획 122 `pin-rot-nail`)

## 결정

**축 ㉢ 을 쓴다** — `docs/reports/` 에서 **신호가 ⚪ 인 마지막 보고서의 날짜**가
`status.md` 핀 줄의 **날짜보다 나중이면** 빨강이다. **새 상태 파일 0개 · 새 줄 0개 ·
제품 코드 0줄.** 핀 줄은 지금 꼴을 **그대로** 정규식으로 읽는다:

```python
PIN = re.compile(r"^## 빈손 대조 핀 — 기준 트리 `([0-9a-f]{7,40})` \((\d{4}-\d{2}-\d{2})", re.M)
# 실측: ('26f1393', '2026-10-22')  ← `status.md` 현재 핀 줄에서 그대로 나온다
```

**못 찾으면 빨강이다.** 「재지 못했다」로 조용해지는 길을 두지 않는다 — 그 길이 계획 120
의 교훈(「재는 자가 죽었는데 초록이다」)이 난 자리다. 핀 줄 꼴이 드리프트하면 **그
드리프트가 곧 실패**고, 처방은 꼴을 되돌리거나 정규식을 같이 고치는 것이다.

## 대안 비교

출발점 셋에서 하나씩 냈다(`design.md` 3-1절).

| | ㉠ 변경 파일 수 임계 (정공법) | ㉡ 핀 날짜 K일 묵음 (최소) | **㉢ 마지막 ⚪ > 핀 날짜** (되돌리기 우선) |
|---|---|---|---|
| 되돌릴 수 있나 | 테스트 하나 revert | 같다 | 같다 — **셋 다 커밋 하나** |
| 더 적게 쓰나 | 임계 상수 하나 추가 | 상수 하나 | **상수 0개** — 비교 대상이 둘 다 트리에 있다 |
| 기존 것과 맞나 | `read_budget_gap` 꼴 | 같다 | 같다 |
| 다음이 편한가 | **아니다** | **아니다** | **그렇다** |

**㉠·㉡ 을 버린 이유가 같다 — 둘 다 「공허한 손」을 유도한다.** 핀의 값은 「**지난 빈손 밤**
이후 트리가 안 변했다」는 것이다. 핀을 아무 날에나 `HEAD` 로 갈아끼우면 가드는 초록이
되지만 핀은 「마지막으로 손댄 때 이후 무변경」만 말하게 되어 **용도를 잃는다.** ㉠ 은
계획 3개쯤에서, ㉡ 은 K일마다 정확히 그 손을 부른다. ㉢ 은 **빈손 밤에만** 옮기라고 하고
그것이 핀의 정의다. 그리고 임계·K 가 감이던 자리가 사라진다.

**되돌리기 수단: ③ 커밋 하나로 revert.** 테스트 추가뿐이라 제품 경로가 없다.

## 가정 — **깼다** (`design.md` 3-2절 · 측정 3회 · 커밋 0 · 저장소 무변경)

계획서의 가정은 「보고서 40개가 신호를 **일정한 꼴**로 들고 있다」였다. **틀렸다.**

- `| **신호** | <이모지>` 줄이 **40개 중 32개**에만 있다 — 🟡 26 · 🟢 4 · **⚪ 2**.
  없는 8개: `09-10_verdict-head` `09-12_pin-coverage` `09-14_order-probe` `09-29`
  `10-02` `10-03` `10-06` `10-08`.
- **그중 하나는 실제로 빈손 밤이다** — `night_2026-09-12_pin-coverage.md` 는 ⚪ 빈손인데
  표 줄도 `## ⚪ 종합` 머리도 없다. 즉 **느슨하게 세면 덜 세고, 문서 전체에서 `⚪` 를
  찾으면 범례 줄(`night_2026-10-08.md` 의 「🔴 실패 · 🟡 판단 · 🟢 완료 · ⚪ 빈손」)이
  거짓 양성이다.** 양쪽으로 다 틀리는 입력이다.
- **그 꼴을 지키는 테스트는 0개다** — `grep -rn 'reports' tests/ scripts/ e2e/` 에
  `docs/reports/` 를 읽는 자가 없다. 계획서 설계 질문 3 의 답: **아무도 안 지킨다.**

**그런데 결손이 전부 과거에 몰려 있다** — 8개가 모두 **2026-10-08 이하**고,
**2026-10-09 이후는 32개 전부 줄을 갖는다.** 이것이 설계를 가른다.

## 결론 — 꼴 가드는 **가장 최신 보고서 하나**만 본다

과거 8개를 고치는 것은 직교 편집이고(카파시 3번) 날짜 상수를 박는 것은 또 하나의 감이다.
**셋째 길**: 꼴 가드가 **사전순 마지막 `night_*.md` 한 개**에만 「신호 줄이 하나 있다」를
요구한다. 각 보고서는 **쓰인 날 최신이므로** 앞으로 쓰는 모든 보고서가 지켜지고, 과거는
한 줄도 안 건드린다.

**그래서 판정이 구조적으로 안전하다.** 못 세는 ⚪ (과거 8개 중 09-12)는 **전부 핀 날짜
2026-10-22 보다 과거**라 `마지막 ⚪ > 핀` 을 성립시킬 수 없다 — 과소 계수가 거짓 초록을
만들지 못한다. 앞으로의 ⚪ 는 꼴 가드가 지켜 반드시 잡힌다. **과거는 영향 0 · 미래는 가드됨**
이 이 설계의 요점이고, 날짜 상수 없이 그렇게 된다.

날짜는 **파일명에서** 읽는다(`night_YYYY-MM-DD…` → `name[6:16]`) — 같은 날 두 벌이 있는
날이 넷이라(`09-09` 2 · `09-10` 2 · `09-12` 3 · `09-14` 2) 접미사를 허용해야 한다.

## 계약 — 개발이 지킬 것

1. **판정은 텍스트·이름 목록에서 갈린다** — `pin_rot_gap(status_text, reports)` 꼴로
   순수 함수를 두고 살아 있는 트리는 그 입력을 만드는 자가 읽는다
   (`read_budget_gap`/`read_budget_sizes` 선례 그대로)
2. **경계는 초과가 아니다** — 마지막 ⚪ 날짜 **== 핀 날짜**인 날은 조용하다(`cap_gap` 과
   같은 판단). 오늘이 바로 그 경우다(둘 다 2026-10-22)
3. **⚪ 가 0건이면 조용** — 아직 빈손 밤이 없던 저장소에서 거짓 RED 를 내지 않는다
4. **핀 줄을 못 찾으면 빨강** · **신호 줄 없는 최신 보고서도 빨강**
5. 꼴 가드와 핀 가드는 **테스트 둘**이다 — 하나가 빨개도 다른 하나의 사유가 가려지지 않는다
6. 외부 네트워크 0 · 새 의존성 0 · `git` 호출 0 (**날짜만 쓰므로 `subprocess` 가 필요없다** —
   계획서가 `test_merge_script.py` 선례를 들었지만 ㉢ 은 그 선례조차 안 쓴다)

## 되돌리기

커밋 하나 revert. 테스트 둘과 `README.md` 장부 줄만 들어간다.

## 범위 밖 (→ `digest` 후보로 등재한다)

- **과거 보고서 8개의 신호 줄 결손** — 고치면 직교 편집이고, 판정에 영향이 0 이라 급하지 않다.
  다만 「보고서를 **집계**하는 자가 생기는 날」(예: 밤 성적의 추이) 그 8개가 구멍이 된다
- **핀을 옮기는 손의 자동화** — 「빈손 밤이 보고서를 쓰기 전에 핀을 옮긴다」는 순서 계약이
  없어 지금은 못 짠다. 이 계획이 세우는 가드가 그 계약의 **첫 조각**이다
