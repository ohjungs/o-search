# 결과 — 계획 82 `throughput-shape`

## 1. 근거 — 오늘 내가 그 숫자에 속았다

실물 크롤이 찍은 것은 `수집 400 페이지` 한 줄뿐이었다. 따로 잰 **3.67문서/초**를 보고
**크롤러가 느린 줄 알았다.** 다시 재니 처리량은 도메인 수에 정비례였고
(1·2·4·8 → 1.03·2.08·4.40·9.86) 시드가 4도메인이라 **지속 상한 4.00 의 92%** 에 이미
붙어 있었다 — **고칠 코드가 없는데 반나절을 봤다.**

**그 오인의 값이 크다**: 처리량이 안 나올 때 손이 가는 곳은 `DOMAIN_INTERVAL` 이고,
그것은 크롤 윤리 상수다(계획 81 이 못을 박은 바로 그 자리). 오늘 아침 죽은 무인 실행이
실제로 그 값을 0.05 로 내려 놓았던 것도 같은 압력이다. **요약이 천장을 같이 말해 주면
그 손이 안 간다.**

`perf_crawl.py` 는 이미 도메인 수를 옆에 찍는다 — 빠져 있던 것은 **사용자가 실제로 보는
CLI** 쪽이다. digest 의 *"숫자 옆에 그 숫자를 낸 입력의 모양을 적는다"* 가 벤치마크에는
적용됐고 제품 출력에는 안 됐다.

## 2. 결과

```
수집 9 페이지 · 3 도메인 · 2.0초 = 4.45 문서/초 (지속 상한 3.00)
```

전수 **709 OK rc 0**.

## 3. 실물 한 번이 라벨 오류를 잡았다

처음 쓴 라벨은 **「이론 상한」**이었고 단위 테스트는 초록이었다. 로컬 3도메인에 실제
CLI 를 돌리니 이렇게 나왔다:

```
수집 9 페이지 · 3 도메인 · 2.0초 = 4.45 문서/초 (이론 상한 3.00)
                                    ↑ 상한을 넘었다
```

**도메인별 첫 요청은 기다리지 않는다.** 3도메인이면 t=0·1·2 에 각 3발씩 9발이 2.0초에
나가 4.45/초가 된다. 지속 상태(t→∞)에서만 3.00 으로 수렴한다.

그냥 「상한」이라 적으면 **그 줄이 자기 모순**이고, 읽는 사람이 요약 전체를 못 믿게
된다 — **그건 안 적는 것보다 나쁘다.** 「지속 상한」으로 고쳤다.

**단위 테스트는 이걸 못 잡는다** — 모의 크롤이라 간격이 안 흐르고 시간이 0에 가깝다.
잡은 것은 실물 한 번이다. 이 저장소가 여러 번 배운 「측정 하네스가 재지 않는 세계가
곧 버그가 숨는 곳」의 또 한 칸이고, 이번엔 **내가 방금 만든 자**에서 났다.

## 4. 테스트가 시계에 안 기대게 둔 자리

단위 단언은 **처리량 값을 못박지 않는다** — 모의 크롤은 0초에 가까워 그 숫자를 고정하면
기계 속도에 기댄 단언이 된다(계획 78 이 시계 해상도에서 배운 것과 같은 자리).
재는 것은 **「천장을 옆에 적었나」**지 「얼마나 빨랐나」가 아니다.
