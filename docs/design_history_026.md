# 설계: 환경 오류는 **rc 1**, 명령줄 오류는 **rc 2** — 세 CLI 가 같은 값을 쓴다

**계획**: `plan_exit-code-contract.md` · **트리거**: 공개 인터페이스 변경(세 CLI 의 종료
코드) · 대안 3갈래 · 되돌리기 어려움 · **작성**: 2026-09-01

## 결정

**대안 A.** `indexer.main` 의 환경 오류 네 갈래를 `rc 2` → **`rc 1`** 로 내린다.
제품 diff 는 `src/websearch/indexer.py` **한 파일 4줄**(`:242`·`:248`·`:253`·`:262`)이고
`serve.py`·`crawl.py` 는 **0줄**이다.

가른 것은 **잡히지 않은 예외가 이미 rc 1** 이라는 사실이다. 파이썬은 처리되지 않은
예외를 1 로 끝낸다 — `serve.py:329-333` 이 그것을 근거로 적어 뒀고(*"안 잡을 때도 1
이었다 … 바뀌는 것은 트레이스백뿐"*), `test_indexer.py:230` 의 주석은 색인 쪽의 **고치기 전
동작이 `트레이스백 + rc=1`** 이었다고 남겼다. 즉 rc 1 은 이 저장소가 고른 값이 아니라
**런타임이 이미 내고 있는 값**이고, 손으로 처리한 갈래만 2 로 갈라져 나온 것이다.

→ B(`serve` 를 2 로 올린다)를 고르면 **처리한 환경 오류는 2, 처리 못 한 환경 오류는 1**
이라는 불일치가 영구히 남는다. 새 `except` 를 안 단 갈래가 생길 때마다 계약이 갈린다.
A 는 그 틈이 없다: 안 잡힌 예외가 저절로 옳은 값으로 떨어진다.

**버린 축**: 변경 크기. A 는 단언 7곳을 옮기고 B 는 제품 1줄이다. 작은 쪽을 안 골랐다.

## 계획의 근거 정정 — 재확인 결과 하나가 틀렸다

계획 6절이 설계에 물은 것 셋 중 **② 가 사실과 다르다.**

- **계획 2-1 ② "`serve` 의 rc 1 을 고정하는 단언이 0건" 은 거짓이다.**
  `tests/test_serve.py:890-899` `test_bind_failure_is_reported_instead_of_crashing` 이
  `assertEqual(rc, 1)` 로 값을 붙들고 **docstring 에 규칙까지 적어 뒀다**. 계획의
  `grep "serve.main"` 이 못 본 이유는 그 단언이 헬퍼 `call()`(`:792`)을 거쳐 부르기
  때문이다. → **B 의 비용은 "0곳" 이 아니라 1곳 + 기록된 근거의 삭제**다.
  일반화: **호출을 grep 해 커버리지를 세면 헬퍼 뒤의 단언이 통째로 안 보인다.**
- **계획 2-1 ① "`crawl` 은 이미 계약을 지킨다" 는 참이다.** `crawl.main` 의 반환값은
  `{0, 2, 130}` 뿐이다. `crawl.py:318` 의 `return 1` 은 `main` 이 아니라 페이지를 세는
  헬퍼 `_store_result`(`:274`)의 "이 페이지를 주웠나" 값이라 종료 코드가 아니다. `NoUsableSeedsError`(`:380`)는
  `crawl.py:25-32` 가 **사용자 입력 오류**라고 이유까지 적어 뒀다 → rc 2 유지.

## 재시도 축은 **가르지 않는다** (계획 6절 물음 2)

락은 재시도하면 풀리고 손상 DB 는 안 풀린다. 그래도 값을 넷째로 늘리지 않는다 —
**이 저장소에 종료 코드를 보고 재시도하는 호출자가 0곳**이기 때문이다(`README` 의
`crawl && indexer`, e2e 의 `returncode` 단언뿐, 재시도 루프 없음). 지금 값을 고르면
`75 EX_TEMPFAIL` 인지 `3` 인지의 갈림길을 **쓰는 사람 없이** 정하게 된다.

- **오늘의 구분자**: stderr 문구다. 락만 *"DB 가 잠겨 있다 — 크롤이 끝난 뒤 다시 돌린다"*
  를 내고 나머지는 원문을 그대로 보인다(`indexer.py:258-261`, 계획 39 가 세운 갈래).
- **여는 조건**: **재시도하는 호출자가 실제로 하나 생길 때.** 그때 값을 그 호출자와 함께
  정한다. 그전에 정하면 `digest [7]` 이 세 번 관찰한 *"보류 항목의 처방은 그때의 추정"*
  을 네 번째로 밟는다.

## 스텝 — 계획의 2스텝을 **1스텝으로 합친다**

계획 스텝 1("값을 바꾸기 전에 오늘의 값을 못박는다, `src` 0줄")의 **전제가 무너졌다**:
위에서 확인한 대로 오늘의 rc 는 이미 전부 단언이 붙어 있다(`serve` 환경 1 · `serve`
인자 2 · `indexer` 환경 6 · `indexer` 인자 2 · `indexer` 130 · `crawl` 7 + e2e). 못박을
빈자리가 없으므로 별도 스텝은 **0줄짜리 반복**이 된다.

→ **개발 1스텝**: 위 표의 7단언을 먼저 뒤집어 RED(462건 중 7건 실패)를 본 뒤
`indexer.py` 4줄과 `README` 표를 넣어 GREEN. 변이 M1(`:242` 만 2 로 되돌리기)이
**단언 하나만** 죽여야 한다.
