## 리뷰 phase 가 찾은 것 (반복 87) — 지적 6건 중 4건 반영

패스 A(백지)를 **별도 세션**에 diff 만 주고 돌렸다. 배경을 안 준 것이 값을 냈다 —
6건 중 4건이 통과선을 넘었고, 그중 둘은 작성자가 배경을 알기에 안 보이던 것이다.

1. **"간격 시계를 거는 유일한 자리다" 가 과한 주장이었다.** `mark_sent` 기준으로는
   맞지만(grep 실측: 호출처 2곳, 둘 다 `_store_result`) **"요청이 나가는 유일한 자리"**
   로 읽힌다. 실제로 계약 밖으로 나가는 요청이 둘 있다 → docstring 에 무엇이 밖인지 적었다
2. **`scenario_blocked` 의 robots 준수 단언이 netloc 을 안 봤다.** 앞 시나리오의 늦은
   핸들러가 `clear()` 뒤에 한 줄 흘리면 **남의 세계 요청으로 빨개진다** → `n in NETLOCS`
3. `perf_crawl` docstring 이 "판정 3개" 로 멈춰 세 세계를 도는 지금 구조와 어긋났다.
   `workers<8` 이면 [차단]·[예외] 가 **안 도는데 "통과" 만 찍던 것**도 출력에 적었다
4. 차단 경로 주석 산술 오류(`홈 + p6~p11` → `홈 + /p7~/p11`)

**버린 것 2건** (`severity.md` 80점 미만 — 다시 찾지 않도록 남긴다):
`BASELINE_BLOCKED` 9.0→7.0 완화는 **75점**. 여유가 12% 로 얇은 것은 사실이나 4회 실측
(10.24·10.26·10.29·10.31)에서 흔들린 적이 없어 **추정에 머문다.** 실제로 한 번이라도
흔들리면 그때 낮춘다 — 흔들린 적 없는 검사를 미리 무디게 하지 않는다. stderr 단언
강화는 50점.

**새 갭 1건은 고치지 않고 digest 로.** `fetcher` 재시도가 연결 실패 시 **3회를
0.4ms 안에** 보낸다(탐침 실측 — 받자마자 끊는 서버에 요청 1건 → TCP 연결 3회).

안 지난다. **이 계획이 연 것이 아니다** — `fetcher.py` 는 이 diff 에 없다(`--name-only`
실측). 고치려면 워커 스레드를 붙드는 sleep 이냐 재시도를 크롤 루프로 올리느냐의
**설계 결정**이고 동시화 계약 3·4와 얽힌다 → 야간 자동 적용 대상 아님

**패스 B(대조)에서 걸린 것은 없다.** 설계 계약 6개를 코드로 하나씩 대조했다 —
