# e2e 결과 — pagination-ui (015)

2026-08-27 · 브랜치 `loop/pagination-ui` (기점 `716d245`) · 자동(야간) · 반복 101

## 무엇을 사용자 관점으로 봤나

계획이 연 문제는 한 문장이었다 — **"주소창을 편집할 줄 아는 사람만 11번째 결과를 본다."**
서버는 진작부터 2페이지를 줄 수 있었고 `?q=X&page=2` 를 손으로 치면 나왔다. 없던 것은
**화면에 그려진 길**이다.

그래서 검증도 주소창을 안 건드린다. `page=2` 를 조립해 넣는 순간 재는 것이 서버가 되고,
정작 이 계획이 만든 것(링크)은 안 재게 된다. **화면이 준 `href` 를 그대로 따라간다.**

수단은 새 `e2e/pagination_ui_e2e.py` — 로컬 서버를 crawl 로 수집·색인하고 사용자가 하는
그대로 `python3 -m websearch.serve <db> --port 0` 로 띄운다. 바깥 네트워크는 안 탄다.

문서는 **11개**로 잡았다. 20개(정확히 2페이지)는 마지막이 꽉 찬 **특수 케이스**다.
11개면 2페이지에 1건만 남아 `len(hits) > PAGE_SIZE` 의 부등호가 틀리면 사용자가
다음을 눌러 **빈 화면**을 본다. 시드 페이지에는 `김치` 를 안 넣었다 — 넣으면 히트가
12건이 돼 재려던 경계가 사라진다.

## e2e 자신을 변이로 검증했다

**무변이 기준선(`0`)을 먼저 잡고** 기능을 세 방향으로 되돌렸다. 셋 다 잡힌다.

| 변이 (기능 되돌리기) | 결과 |
|---|---|
| `_pager` 가 늘 `""` — 이동 블록을 통째로 안 그린다 | **잡힘 · 종료 1** — "갈 곳이 있는데 화면에 다음 링크가 없다" |
| `_page_hits` 의 `+ 1` 삭제 — 다음의 유무를 알 수 없게 된다 | **잡힘 · 종료 1** — 같은 자리 |
| `has_next` 를 무시하고 늘 `다음` 을 낸다 | **잡힘 · 종료 1** — "마지막 페이지가 다음을 내줬다" |

## 측정 불능(2)과 빨강(1)을 가르는 데 한 번 고쳤다

첫 판은 `다음` 링크의 개수를 `measured()` 에 넣었다. 그러면 **기능을 통째로 지운 것과
문서가 모자란 것이 같은 종료 코드 2로 나온다** — 회귀가 "못 쟀다" 로 보고되는 것이다.

갈랐다. **갈 곳이 있는지는 화면이 아니라 API 로 먼저 묻는다**(`/search?…&page=2` 의
결과 수). 여기서 0이면 **2**(잴 대상이 없다), 여기는 있는데 화면에 링크가 없으면
**1**(빨강). M-a 가 실제로 2가 아닌 **1**로 죽는 것을 확인했다.

계측기를 JSON API 로 쓴 것은 의도적이다 — 재려는 대상은 HTML 쪽 링크이고, API 는
이번 계획이 안 건드린 **독립된 기준선**이다.

## 리뷰가 잡은 것 — 테스트 15건이 실행되지 않고 있었다

백지 세션이 `if __name__ == "__main__"` **뒤에** 붙은 새 클래스 3개를 잡았다.
`python3 tests/test_serve.py` 로 직접 돌리면 `unittest.main()` 이 그 자리에서
`SystemExit` 을 내 아래 클래스가 정의조차 안 된다 — **55건 OK**, `discover` 로는
70건 OK. **양쪽 다 초록**이라 사라졌다는 신호가 어디에도 없었다.

같이 잡힌 것: 이스케이프 테스트가 이동 링크를 안 재고 있었다(특수문자 질의는 히트가
0건이라 `_pager` 가 조기 반환한다 — 통과시킨 것은 검색창의 이스케이프였다).
자세한 것은 `docs/history_current.md` 반복 100.
