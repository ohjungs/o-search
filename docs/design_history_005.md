# 설계: robots Crawl-delay 를 도메인 간격에 반영

## 결정

`RobotsCache.delay(url)` 가 초를 돌려주고, **크롤 루프가 그 값을 `Frontier.set_delay(domain, seconds)`
로 밀어넣는다.** 프런티어는 도메인별 간격을 `max(1초, 요청값)` 으로 들고 있다가
`next()` · `seconds_until_ready()` 에서 쓴다. **30초를 넘는 요청은 지키지 못하니
그 도메인을 크롤 대상에서 버린다** — 간격을 깎아 계속 때리지 않는다.

## 대안 비교

| | A. 밀어넣기 (루프 → 프런티어) | B. 당기기 (프런티어 → robots 콜백) | C. 프런티어 불변, 루프가 sleep |
|---|---|---|---|
| 되돌리기 | 커밋 하나 revert | 커밋 하나 revert | 쉬움 |
| 코드량 | 적음 (프런티어 +6줄) | 보통 — 주입 배선·테스트 더블 | 적음 |
| 기존과 일치 | ○ 간격 판정이 프런티어에 남는다 | △ 프런티어가 네트워크를 부른다 | ✗ 간격 책임이 두 곳으로 갈린다 |
| 다음이 편한가 | 보통 | 좋음(순서 제약 사라짐) | 나쁨 — 한 도메인 대기가 전 도메인을 멈춘다 |

**선택: A** — 간격 판정을 **프런티어 한 곳**에 유지하는 유일한 안이면서 가장 적게 쓴다.
`Frontier(now=...)` 시계 주입이 이미 있어 새 테스트도 실제로 잠들지 않는다.

**버린 이유: B** — `next()` 안에서 robots.txt 를 받으러 네트워크를 타게 된다. 큐에서
URL 을 꺼내는 함수가 수 초 블로킹되고, 지금 6건인 프런티어 테스트에 전부 robots 더블이 붙는다.
**C** — 크롤 루프는 단일 스레드다. 여기서 자면 라운드로빈이 있는 이유(다른 도메인은 계속 돈다)가
사라진다. 컨셉 성능 축을 이유 없이 깎는다.

## 갈림길 2개 — 컨셉 우선순위(크롤 윤리 1순위)로 갈랐다

- **stdlib 이 소수를 버린다**(`Crawl-delay: 3.5` → `None`, 3.9.6 실측). 그대로 두면 **1초로
  떨어져 요청보다 3.5배 빠르게 때린다.** → `crawl_delay()` 가 `None` 일 때만 **robots 본문에서
  `crawl-delay:` 줄의 실수 값을 긁어 가장 큰 값**을 쓴다. 느린 쪽으로만 틀리는 폴백이다.
- **상한이 없다**(`86400` → `86400`). 지키면 무인 크롤이 하루를 잔다. 깎으면 윤리 위반이다.
  → **30초 초과는 도메인을 버린다.** "못 지키겠으면 안 간다" 가 두 축을 다 지키는 유일한 답이다.

## 가정 — 탐침으로 확인했다 (2026-08-25, 커밋 없음)

**"robots 는 그 도메인의 첫 URL 을 팝한 뒤 적재되지만, 간격은 두 번째 팝부터 필요하므로 늦지 않다."**
→ 참. `Frontier` 를 상속한 스크립트로 첫 팝 직후 `set_delay(5.0)` 을 불러 확인했다.
다른 도메인은 영향 없고, 과대 간격 도메인은 큐에서 사라지며 이후 `add()` 로도 다시 안 들어온다.
**같은 탐침이 하나 더 알려줬다**: `next()` · `seconds_until_ready()` 가 모듈 상수
`DOMAIN_INTERVAL` 을 직접 읽으므로 **메서드만 추가해서는 안 먹는다** — 두 곳을 도메인별 조회로
바꿔야 한다(스텝 2 가 건드릴 정확한 지점).

## 계약 — 개발이 지킬 것

- `RobotsCache.delay(url) -> float | None` — `None` 은 "지시 없음"(호출부가 1초를 쓴다).
  robots 적재는 `allowed()` 와 **같은 캐시 1회**를 쓴다(`tests/test_robots.py:31` 계약).
- `Frontier.set_delay(domain, seconds)` — `seconds` 는 `float | None`.
  내부 간격은 `max(DOMAIN_INTERVAL, seconds or 0)`. **1초 아래로는 절대 내려가지 않는다.**
  `seconds > MAX_DELAY(30.0)` 이면 그 도메인 큐를 비우고 이후 `add()` 도 그 도메인을 받지 않는다.
- `frontier.py` 에 `MAX_DELAY = 30.0` 을 `DOMAIN_INTERVAL` 옆에 둔다(간격 정책은 한 파일).
- `crawl.crawl()` 은 `robots.allowed(url)` 로 robots 가 적재된 **직후** `set_delay` 를 부른다.
  기존 루프 순서·`store.has` 스킵 경로는 그대로 둔다.

## 되돌리기

커밋 하나 revert. 스텝 1·2 는 순수 추가라 스텝 3(배선)만 되돌려도 동작은 오늘과 같아진다.

## 범위 밖 (→ `digest.md` 후보)

- robots UA 그룹 매칭: `USER_AGENT = "websearchbot/0.1"` 의 슬래시 때문에
  `User-agent: websearchbot/0.1` 그룹은 매치되지 않는다(`can_fetch` 도 이미 그렇다)
- 소수 폴백은 **UA 그룹을 구분하지 않는다** — 남의 그룹 값을 집어 더 느려질 수 있다.
  느린 쪽 오류라 허용한다(`ponytail:` 주석으로 천장을 남긴다)
- `Retry-After`·429 백오프, `Request-rate`, robots 캐시 TTL
