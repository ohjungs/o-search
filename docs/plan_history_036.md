## 1. 문제 · 목표 · 기대 결과

### 문제

`docs/project.md ## 명령` 은 **맨몸으로 돌려라**(파이프·`grep`·`head`·`tail`·
리다이렉션 금지)를 명령을 읽는 바로 그 자리에 적어 두었다. 그런데도 같은 위반이
**누적 30회** 재발했다(`docs/status.md ## 러너 규율`, `docs/digest.md ## 반복 실패`).
`digest` 가 세어 둔 마지막 다섯 건의 형태는 전부 다르지만 방아쇠는 하나다:

| # | 반복 | 형태 | 그때의 「이유」 |
|---|---|---|---|
| ⑬⑭ | 241·242 | `wc -l && 러너 2>&1 \| tail -4` | 다른 명령에 러너를 얹었다 |
| ⑮ | 242 | `2>/dev/null` | 잡음을 줄이려고 stderr 를 버렸다 — `Ran/OK` 가 그 stderr 다 |
| ⑯⑰ | 267·269 | `\| tail -5` · `2>&1 \| tail -40` | 출력이 길다 |
| ⑱ | 271 | `\| tail -5` + `2>/dev/null` | 변이 배터리 중간이라 길다 |

**여덟 번째 자리에서도 방아쇠는 «출력이 길다» 였고, `digest` 가 처방 후보를
등재해 둔 뒤에도 그랬다 — 등재는 방아쇠를 없애지 못한다.**

그리고 오늘 실측에서 **여태 아무도 안 적은 것이 하나 더 보였다**: 맨몸으로 돌려도
`Ran 578 tests / OK` 가 **화면의 마지막이 아니다**. `unittest` 의 판정은 stderr(무버퍼)
로 나가고 테스트의 `print()` 는 stdout(블록 버퍼)으로 나가서, 남은 stdout 버퍼가
**`OK` 뒤에 늦게 플러시된다**(오늘 실측: `OK` 아래로 `수집 0 페이지`·`1 문서 색인`
등이 이어졌다). 즉 «판정이 잘렸다» 를 눈으로 확인하려는 사람은 맨몸으로 돌려도
화면 끝이 아니라 **가운데**를 뒤져야 한다. 이것이 「출력이 길다」를 계속 만드는
물리적 원인이다.

### 목표

**«가릴 이유» 를 없앤다.** 저장소가 안내하는 단위 테스트 명령에 `-b` 를 넣어,
통과한 테스트의 출력은 화면에 안 나오고 **실패한 테스트의 출력만** 실패 보고서
안에 붙게 한다. 그리고 그 `-b` 가 다음에 조용히 사라지지 않도록 검사 하나가 붙든다.

### 기대 결과

같은 578건이 같은 시간에 돌고, 화면은 **약 90줄에서 5줄로** 줄고, 마지막 줄이 `OK`
가 된다. 실패했을 때 보이던 것은 **하나도 안 줄어든다**.

### 무엇이 이미 참인가 (이 저장소를 처음 여는 사람을 위한 전제)

- 단위 스위트는 **578건**이고 맨몸 13.4~13.6초에 OK 다(2026-09-03 실측 2회).
- 저장소가 단위 러너를 적어 둔 자리는 **두 곳**이고 형태가 서로 다르다:
  - `README.md:69` — `PYTHONPATH=src python3 -m unittest discover -s tests   # 단위 578건`
  - `docs/project.md:14` — `PYTHONPATH=src python3 -m unittest discover tests`
    (`-s` 없이 위치 인자)
- `tests/test_readme.py` 의 `ReadmeCommandsTest` 가 `README.md` 를 **입력으로 읽어**
  세 가지를 이미 본다: `-m websearch.<모듈>` 이 임포트 가능한가 · 인터프리터가
  `python3` 인가 · `단위 N건`/`e2e 시나리오 N종` 이 실제와 같은가. 이 파일이 있는
  이유는 «깨진 것이 코드가 아니라 코드와 문서 **사이**» 라서다 — `-b` 도 정확히
  그 사이에 있는 값이다.
- `docs/project.md ## 명령` 의 머리말(8~12줄)은 맨몸 규율을 이미 적고 있다.
  **이 계획은 그 문장을 지우지 않는다** — `-b` 는 잡음을 없앨 뿐 파이프를
  허용하지 않는다.

## 3. 계획 phase 가 오늘 직접 잰 것 (맨몸·단독 4회)

① **`-b` 없이** `PYTHONPATH=src python3 -m unittest discover -s tests`
→ `Ran 578 tests in 13.416s` · `OK` · 화면 약 90줄 ·
**`OK` 뒤로 `수집 0 페이지`·`1 문서 색인` 등이 더 나왔다**(늦은 stdout 플러시).

② **`-b` 붙여** 같은 명령 `-b`
→ `Ran 578 tests in 13.547s` · `OK` · 화면 **5줄** · `OK` 가 **마지막 줄** ·
거른 테스트 **0건**(578 그대로) · 시간 차 없음.

③ **후보가 남긴 「확인할 것 하나」**(`-b` 는 `sys.stdout` 을 바꾸므로 별도 프로세스나
스레드로 나가는 로그에는 안 먹을 수 있다) → **셋 다 샌 것이 0줄이다**:
- 서브프로세스는 원래 안 샌다 — `tests/test_indexer.py:1098` 은 `stdout=subprocess.PIPE`,
  `tests/test_quality_eval.py:77`·`tests/test_passage_eval.py:45` 는 `capture_output=True`.
- 스레드로 나가는 `http.server` 의 `127.0.0.1 - - [...]` 로그는 `sys.stderr` 를
  **호출 시점에** 찾으므로 `-b` 의 교체분을 그대로 탄다 — ② 에서 0줄이 그 답이다.
- 테스트들이 자기 안에서 `mock.patch("sys.stderr", ...)` 를 쓰는 자리(`test_crawl.py`
  에만 20여 곳)는 `-b` 교체분 **위에** 겹쳐 쌓였다가 원복되므로 충돌하지 않는다.
  ② 에서 578건이 전부 초록인 것이 그 답이다.

④ **`-b` 가 실패를 삼키지 않는가** — 통과 1건·실패 1건짜리 임시 스위트로 확인:
`PASS_STDOUT_MARK`/`PASS_STDERR_MARK` 는 **안 나오고**, 실패한 테스트의
`FAIL_STDOUT_MARK`/`FAIL_STDERR_MARK` 는 트레이스백 아래 `Stdout:`/`Stderr:` 블록으로
**둘 다 나온다**. rc 1.

**여기서 천장 하나가 보였고 계획서에 적는다** — ④ 에서 `FAILED (failures=1)` 뒤에도
늦은 stdout 플러시 한 줄이 붙었다. 즉 `-b` 는 **초록 실행에서만** 판정을 마지막
줄로 만든다. 빨간 실행에서는 판정 뒤에 실패 본문 일부가 더 나온다 —
**그건 봐야 할 것이지 가릴 것이 아니라서 이 계획의 목표에 어긋나지 않는다.**

## 4. 스텝

### 스텝 1/1 — 안내하는 러너 명령에 `-b` 를 넣고, 검사가 그것을 붙든다

**TDD 순서로 간다** (`tests/test_readme.py` 가 이 저장소에서 문서를 입력으로 읽는
자리다):

1. `tests/test_readme.py` 의 기존 `ReadmeCommandsTest` 에 단언 하나를 더한다 —
   `README.md ## 검증` 의 `unittest discover` 줄이 `-b` 를 갖는가. **이 시점에서
   RED 여야 한다**(아직 안 넣었으므로). RED 를 눈으로 확인한 뒤에 2로 간다.
2. `README.md:69` 와 `docs/project.md:14` 에 `-b` 를 넣는다.
   `docs/project.md:14` 는 실행 확인 날짜 주석도 오늘 실측으로 갱신한다.
3. 맨몸·단독으로 러너를 돌려 **579건 OK** 를 눈으로 읽는다(단언 +1).
4. `README.md` 의 `단위 578건` 을 **579** 로 고친다 — `test_readme.py` 자신이
   그 숫자를 실제 스위트로 대조하므로 3 과 4 는 같은 커밋이어야 한다.

**건드리는 파일 3개** · **제품 `src/` 0줄** · **새 파일 0개** · **새 의존성 0**.

### 왜 스텝이 1개인가

노드가 하나다. 검사와 문서 두 줄은 **서로의 산출물을 읽는다** — 검사는 `README.md`
텍스트를 입력으로 받고, 문서 숫자(`단위 579건`)는 검사가 만든 건수를 받는다.
가르면 어느 쪽으로 갈라도 중간 커밋이 RED 다.

## 5. 완료 기준 (대칭으로 잰다)

계획 49 가 짧았던 이유가 **완료 기준이 처음부터 대칭**이었기 때문이고, 계획 48 이
길어진 이유가 **재는 자가 한쪽만 재고 있었기** 때문이다. 그래서 여기서는 «사라져야
할 것» 과 «그대로여야 할 것» 을 **같은 수의 줄로** 적는다.

**A. 사라져야 할 것 (거짓 쪽)**

1. 초록 실행의 화면이 **약 90줄 → 5줄**. 마지막 줄이 `OK` 다.
2. `OK` **뒤에 붙던 늦은 stdout 플러시 줄이 0줄**(오늘 ① 에서는 붙었다).
3. 통과한 테스트가 찍던 로그(`수집 0 페이지`·`1 문서 색인`·`127.0.0.1 - - [...]`·
   `--max 는 1 이상의 …`)가 **화면에 0건**.

**B. 그대로여야 할 것 (참 쪽)**

1. `Ran 579 tests` · `OK` · rc **0**. 거른 테스트 **0건** — `-b` 앞뒤 건수가
   578 → 579 이고 그 +1 은 이 계획이 **의도해서 더한 단언 하나**다.
2. 실행 시간이 **±0.5초 안**(오늘 13.416 / 13.547).
3. 실패했을 때 그 테스트의 stdout·stderr 가 **둘 다** 실패 보고서에 나온다 —
   테스트 phase 가 **변이 1건으로 실측**한다(제품 코드 한 줄을 깨서 빨갛게 만들고,
   그 테스트가 찍은 로그가 `Stdout:`/`Stderr:` 로 보이는 것을 눈으로 읽는다).
4. `-b` 를 지우면 새 단언이 **죽는다** — 변이 1건으로 실측한다(가드가 진짜
   붙드는지). `README.md` 쪽과 `docs/project.md` 쪽을 **각각** 지워 본다.

**C. 저장소 불변**

- `docs/specs/` 무변경 · `data/crawl.db` sha256 무변경 · 제품 `src/` **0줄** ·
  새 e2e 파일 **0개** · 새 의존성 **0**.
- e2e 는 **한 종도 안 건드린다**. e2e phase 는 전수 20종 rc 0 만 확인한다.

## 6. 설계를 생략한 사유

**트리거 하나에 걸린다 — 「3개 이상 파일에 걸침」**(3개다). 나머지 다섯은 전부
안 걸린다: 새 파일 0 · 공개 인터페이스 무변경 · 데이터 구조 무변경 · 되돌리기는
`-b` 두 글자를 지우는 것 · **대안이 갈리지 않는다**.

그런데도 설계 phase 로 안 넘긴다. 사유는 **그 트리거가 막으려는 것이 이미
닫혀 있기 때문**이다 — 트리거의 목적은 「구조적 결정이 개발 중에 즉흥적으로
내려지는 것」을 막는 것이고(`design.md` 4줄), 이 계획의 유일한 갈림길
«`-b` 냐 판정 줄을 다시 찍는 얇은 래퍼냐» 는 **2026-09-02 계획 48 리뷰 6 이
실측으로 이미 닫았고 그 판정이 `digest [9]` 에 숫자째로 남아 있다**(래퍼 = 새 파일
+ 새 코드 + 사다리 7칸 / `-b` = 새 파일 0 + 새 코드 0 + 사다리 3칸). 이 계획이
설계 문서를 쓰면 **이미 내려진 결정을 다시 쓰는 것**이고, 그것은 `design.md 2절`
이 경계하는 「없는 결정을 지어내는」 자리다.

**3개 중 2개는 한 줄 문자열 편집**(`README.md`·`docs/project.md`)이고 세 번째는
**기존 클래스에 단언 하나**(`tests/test_readme.py`)다. 새 구조가 0이다.

## 7. 하지 않을 것 (범위 고정)

- **제품 코드를 안 고친다.** 테스트가 찍는 로그는 제품(`crawl`·`indexer`·`serve`)이
  정상 동작 중에 내는 것이고, 그것을 지우는 것은 **제품의 관측성을 테스트 화면을
  위해 깎는 것**이다. `-b` 는 화면만 조용하게 하고 제품은 안 건드린다.
- **`docs/project.md` 의 맨몸 규율 문장을 안 지운다.** `-b` 는 파이프의 대체재가
  아니다. 잡음이 줄어도 `2>&1 | tail` 은 여전히 판정을 자른다.
- **e2e 20종의 실행 방법을 안 바꾼다.** `-b` 는 `unittest` 플래그이고 e2e 는
  `python3 e2e/<이름>.py` 로 직접 도는 스크립트라 해당 없다.
- **`~/.claude/skills/loop-harness/rules/` 를 안 건드린다** — 저장소 밖이다
  (`digest [9]` 가 이 경계를 이미 적어 두었다). 이 계획이 고치는 것은 **이 저장소가
  자기 명령을 적어 둔 두 줄**뿐이다.
- **늦은 stdout 플러시 자체를 안 고친다**(`PYTHONUNBUFFERED=1` 같은 것을 안 붙인다).
  `-b` 가 초록 실행에서 그 줄을 0으로 만들면 목표는 달성된다. 빨간 실행에 남는
  것은 5절 C 아래의 **적어 둔 천장**이다.
- **`README.md` 의 다른 명령·표를 안 건드린다**(직교 편집 금지).
