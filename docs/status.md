## 이번 반복이 한 것 (테스트 4)

**① 대조 — 리뷰 3 의 승인 필요 2건은 실제로 닫혔다.** 변이 X1(되감기 삭제) · X2(옛 조건
복귀) · X3(`>` → `>=`)를 다시 심어 RED 2·2·1 로 그대로 물었다. 원복할 것은 없었다.

**② 갭 — 개발 6 의 예고 하나가 틀렸다.** «태그명 도중 · 엔티티 도중 · 주석 `<!--` 도중은
같은 변이에서 죽는다» 중 **주석은 아니었다**. 되감기 조건 `html.rfind("<") > html.rfind(">")`
는 안 닫힌 구성물이 **자기 안에 `>` 를 담을 때** 비교가 뒤집혀 **아예 안 걸린다** —
주석 · 선언 · 인용된 속성값이 전부 그 모양이다. `html.parser` 가 EOF 에서 미완성
구성물을 데이터로 흘려 소비자가 다시 마크업 조각을 받는다. 실측 RED 2건:

```
AssertionError: '<' unexpectedly found in '김치찌개 <!-- TODO: <a href=x> 옛 링크'
AssertionError: '<' unexpectedly found in '김치찌개 <a title="a > b" href="xxx…'
```

주석 쪽은 **화면에 안 보이는 내용이 근거 문단이 된다** — 사양 기능 8 은 문단이 원문에서
읽히는 텍스트라고 정한다. **원인은 「입력이 하나뿐인 단언」의 여섯 번째 사례다**:
개발 6 의 새 단언 3건이 쓰는 입력이 전부 «안 닫힌 `<` 뒤에 `>` 가 없는» 모양 하나뿐이라
어떤 조건을 써도 다 걸렸다.

**③ 죽는 변이가 없는 단언은 안 넣었다 — 후보 수리 다섯을 얹어 재고 둘만 남겼다**
(`.mutation-lock` 아래 · 프로세스 밖 프로브 · `git diff -- src/` **0줄**):

| 입력 | C0 현행 | C1 `<!--` 만 아는 문자열 수리 | C2 조건만 넓히기 | C4 되감기 반복 | C5 파서에 묻기 |
|---|---|---|---|---|---|

새는» 모양과 `<![CDATA[` 도중은 다섯 후보에서 판정이 **한 칸도 안 갈려** 안 세웠다.
