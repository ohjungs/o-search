## 1. 문제 · 목표 · 기대 결과

### 문제

**계획 40 이 세 CLI 의 종료 코드를 맞췄지만, `crawl` 은 값만 맞고 화면은 안 맞다.**

`python3 -m websearch.crawl <시드>` 를 DB 를 열 수 없는 환경에서 돌리면
**rc 1 + stderr 14~16줄 트레이스백**이 나온다(2-2 실측). 값은 계약대로다 —
잡히지 않은 예외를 파이썬이 rc 1 로 끝내고, `README.md` 의 계약표가 rc 1 을
"환경 오류" 로 정의한다. **틀린 것은 값이 아니라 복구 정보다.**

같은 상황에서 `indexer.main` 은 한 줄 안내를 낸다(`indexer.py:240-265`):

```
DB 파일이 없다: data/crawl.db
크롤 데이터가 없다(pages 테이블 없음): … / 먼저 크롤한다: python3 -m websearch.crawl <시드 URL>
DB 가 잠겨 있다 — 크롤이 끝난 뒤 다시 돌린다: …
DB 를 열 수 없다: … — file is not a database
```

`crawl` 은 같은 부류에서 `sqlite3.DatabaseError: file is not a database` 로 끝나는
스택 트레이스를 낸다. 호출자에게 "무엇을 하면 되는지" 가 없다.

### 목표

**`crawl` 의 환경 오류를 `indexer` 와 같은 모양으로 만든다** — 값(rc 1)은 그대로 두고
트레이스백을 **한 줄 안내**로 바꾼다.

### 기대 결과

- 2-2 표의 환경 오류 네 상황이 전부 **rc 1 · stderr 안내 한 줄 · 트레이스백 0줄**.
- `crawl` 의 정상·인자·중단 경로의 rc(0 · 2 · 130)는 **한 값도 안 바뀐다**.
- `README.md` 종료 코드 계약표는 **안 바뀐다**. rc 1 행의 "어디서" 칸이 이미
  *"`crawl`: DB 손상·쓸 수 없는 경로"* 라고 적고 있어 값도 범위도 오늘 참이다
  (계획 40 이 넣었다) — **이 계획이 바꾸는 것은 문서가 아니라 화면이다.**
- `data/crawl.db` 실물·스키마 무변경 · 단위 **462건 + 새 단언**이 전부 OK.

### 2-1. 착수 탐침이 근거 항목의 진술 하나를 넓혔다

`[6]` 은 처방을 *"`crawl.main` 에 `except sqlite3.Error` 갈래를 하나 더는 일이고,
`Store.__init__` 이 유일한 진입점이라 자리는 한 곳"* 이라고 적었다.
**열거가 덜 됐다** — 네 상황 중 하나(`data` 가 일반 파일)는 `sqlite3` 예외가 아니라
`os.makedirs` 의 **`FileExistsError`(= `OSError`)** 다(2-2 ④). `sqlite3.Error` 만 잡는
처방은 그 하나를 그대로 흘린다.

계획 40 이 배운 것과 **같은 모양**이다 — 설계서가 "옮기는 자리 전수 7곳" 이라 적었는데
여덟째(`e2e/indexer_interrupt_e2e.py:281`)가 다른 문법형이라 안 세어졌다.
이번에는 **예외 종류**가 그 자리다. 그래서 아래 2-2 는 값이 아니라 **예외 타입까지**
실측으로 적는다.

### 2-2. 실측한 오늘의 동작 (2026-09-01 · 스크래치패드 임시 디렉터리 · `cwd` 도 거기)

`PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=<저장소>/src python3 -m websearch.crawl http://127.0.0.1:9/ --max 1`

| # | 상황 | 새어 나온 예외 | 던진 곳 | rc | stderr |
|---|---|---|---|---|---|
| ① | `data/crawl.db` 가 비 DB 파일 | `sqlite3.DatabaseError: file is not a database` | `store.py:23` (`PRAGMA journal_mode=WAL`) | **1** | **14줄** 트레이스백 |
| ② | `data/` 가 쓰기 불가(`chmod 500`) | `sqlite3.OperationalError: unable to open database file` | `store.py:22` (`sqlite3.connect`) | **1** | **14줄** 트레이스백 |

### 2-3. 오늘 이 자리를 붙들고 있는 단언 — **0건**

- `grep -n "traceback" tests/test_crawl.py` → 3건이고 **전부 인자 오류**다

  `test_deadline_flag_errors_return_usage_not_traceback:1268`).
- `crawl` 의 **환경** 오류를 재는 단언은 `tests/`·`e2e/` 에 **하나도 없다.**
  계획 39·40 이 두 번 잡은 모양("관례로 인용된 값을 아무도 안 붙들고 있다")이 여기도 참이다.

### 2-4. 넓은 그물이 덮어 버리는 것 (설계가 답할 자리)

`crawl.py:315` 의 `store.upsert(...)` 는 `_store_result` 안에 있고, `_store_result` 는
**워커가 아니라 메인 루프**가 부른다(`crawl.py:214`·`:257`). `future.result()` 를 감싼
`try` 밖이라 **크롤 도중의 쓰기 실패(디스크 참 등)도 `crawl()` 밖으로 그대로 나온다.**

→ `main()` 에서 `crawl(...)` 호출 전체를 `except sqlite3.DatabaseError` 로 감싸면
**"DB 를 열 수 없다" 가 "쓰다가 실패했다" 까지 덮는다.** 오진이고, 그때는 이미 주운
페이지 수(`수집 N 페이지`)도 잃는다. 그물의 폭이 진짜 갈림길이다.

## 3. 대안 (설계로 넘긴다 — 여기서 고르지 않는다)

| | 무엇을 하나 | 제품 diff | 걸리는 것 |
|---|---|---|---|
| **A** | `main()` 에서 `crawl(...)` 을 `except (sqlite3.DatabaseError, OSError)` 로 감싸고 안내를 찍는다 | `crawl.py` ~8줄 (+ `import sqlite3`) | 가장 짧다. 대신 **2-4 의 넓은 그물** 그대로다 — 열기 실패와 쓰기 실패가 같은 안내가 되고, `OSError` 는 크롤 전 구간의 파일·소켓 오류까지 삼킬 수 있다 |
| **B** | `Store.__init__` 이 자기 실패를 도메인 예외(`StoreOpenError`)로 바꿔 던지고 `main()` 이 그것만 잡는다 | `store.py` ~6줄 + `crawl.py` ~5줄 | 그물이 **정확히 열기 순간**이다. `crawl.py` 가 `sqlite3` 를 몰라도 된다(오늘 import 조차 없다). 대신 파일 둘이고 새 예외 이름 하나가 는다 |
| **C** | `crawl()` 안에서 `Store(db_path)` 한 줄만 감싸고 `NoUsableSeedsError` 처럼 도메인 예외로 올린다 | `crawl.py` ~7줄 | 파일 하나이고 그물도 좁다. 대신 `crawl()` 이 `sqlite3` 를 알게 되고, **저장 계층의 실패 처리가 크롤 로직 안에 산다** |

**직교하는 두 번째 물음**: 안내가 **DB 경로를 이름으로 부를 것인가**. `main()` 은
경로를 모른다 — `db_path="data/crawl.db"` 는 `crawl()` 의 **기본 인자**(`crawl.py:119`)다.
부르려면 모듈 상수로 올리거나(`indexer` 처럼 `main` 이 경로를 쥔다) 예외가 경로를
싣고 올라와야 한다. `indexer` 의 안내 넷은 전부 경로를 찍는다.

**세 번째 물음**: 락(`database is locked`)을 따로 안내할 것인가. `indexer.py:262` 는
가른다(*"크롤이 끝난 뒤 다시 돌린다"*). `crawl` 은 자기가 쓰는 쪽이라 상대가 다르다.

## 6. 설계 판단 — **필요하다**

`rules/plan.md` 6-1 · `design.md` 1절의 **"대안이 2개 이상 갈린다"** 에 걸린다.
3절의 A·B·C 는 셋 다 동작하지만 결과가 다르다:

- **그물의 폭이 다르다** — A 는 크롤 도중의 쓰기 실패까지 같은 안내로 덮고(2-4),
  B·C 는 열기 순간만 덮는다. 사용자가 보는 문장이 상황마다 맞느냐가 여기서 갈린다.
- **계층 경계가 다르다** — `crawl.py` 가 `sqlite3` 를 알게 되느냐(A·C),
  `store.py` 가 도메인 예외를 내느냐(B). 오늘 `crawl.py` 는 `sqlite3` import 가 없다.
- **`Store` 는 `crawl` 만의 것이 아니다** — B 를 고르면 `Store` 의 공개 계약이 바뀌고,
  그건 되돌리기가 A·C 보다 비싸다(`design.md` "공개 인터페이스 변경").

→ `phase: 설계`. 설계 문서는 `docs/design_crawl-db-guard.md`.
**설계가 답해야 할 것은 넷이다:**

1. **어느 대안인가** — A/B/C 중 하나. 고른 이유와 **버린 축**을 적는다.
2. **그물의 폭** — 크롤 도중의 `store.upsert` 실패(2-4)는 어떻게 끝나야 하나.
   같은 안내인가, 다른 안내인가, 오늘처럼 트레이스백인가. **답을 안 적으면 미결이다.**
3. **잡을 예외의 전수** — 2-2 의 네 상황을 예외 타입으로 다시 확인한다.
   `sqlite3.DatabaseError` 만으로는 ③이 샌다(2-1). 다섯째 자리가 없는지 본다.
4. **안내가 경로를 부르는가 · 락을 따로 부르는가** — 3절의 직교 물음 둘.
   `indexer` 의 관용구를 그대로 따를지, 여기선 상대가 달라 다르게 갈지.

## 7. e2e 판단 — **잠정 "새 e2e 0개" · 설계가 되받아 적는다**

`rules/plan.md` 는 계획 시점에 e2e 를 정하라고 한다. 계획 40 의 리뷰가
*"계획서가 스스로 '여기에 되받아 적어라' 고 적어 둔 7절이 세 반복째 비어 있었다"*
를 잡았으므로, **이번에는 미정으로 두지 않고 잠정 판정을 먼저 적는다.**

**판정 기준(계획 39·40 과 같은 것)**: 바뀐 것을 재는 데 **프로세스 경계나 진짜 OS 자원**
(포트 점유, 파일 락, argv)이 필요하면 e2e 를 붙인다. 목으로 같은 예외를 세워
재지는 것이면 단위로 끝낸다.

**잠정 판정 — 새 e2e 0개.** 근거 둘:
- 재는 것은 `main(argv)` 의 **반환값과 stderr** 다. 트레이스백은 예외가 `main` 밖으로
  샐 때만 생기므로, "잡혔다" 는 `main` 이 정상 반환하는 것으로 재진다 —
  프로세스 경계가 필요 없다. 계획 40 테스트가 *"프로세스 rc 를 정하는 곳은
  `sys.exit(main(...))` 세 곳뿐"* 이라고 전수로 확인했다.
- 진짜 OS 자원(쓰기 불가 디렉터리·비 DB 파일)은 `tempfile` + `chmod` 로 **단위 안에서**
  만들 수 있다. `e2e/crawl_e2e.py` 가 더하는 것은 argv·서브프로세스뿐이다.

**반증 신호**: 단위에서 만든 상황이 2-2 의 실측과 **다른 예외**를 내면(예: `chmod` 가
루트 권한에서 무력) 그때는 자원을 진짜로 못 세운 것이므로 e2e 로 올린다.
**설계가 이 판정을 확인하거나 정정해서 이 절에 되받아 적는다.**
