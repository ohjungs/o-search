② stderr 재지향 ③ 파이프가 먹는 `rc`. **`-b` 는 ①의 초록 절반만 덮는다**(실패한 테스트의

`>log` 후 `cat` 판이 **판정 축에서 동률**이고 갈린 것은 실행 중 화면뿐이라 **흐르는 쪽**을
골랐다. `pipestatus` 가 틀렸을 때의 증상(`rc` 가 `tee` 의 0)이 **정확히 이 계획이 막는

### 반복 627 — 개발 스텝 1 · **재는 자가 섰고 빨갛다** (`tests/test_verdict_wrapper.py`)

6건 중 **5건 실패**(전수 818건 `FAILED (failures=5)` `rc=1`). 실패 메시지가 「없는 파일」이
아니라 **「마지막 줄이 판정을 안 실었다」**를 가리킨다 — 완료 기준 그대로다. 소스를 읽는
가드가 아니라 **실제로 돌리는** 자다: 계약 ③(`rc`)은 낱말을 세서는 영영 못 잰다. 여섯째는
**대조군**이라 지금 초록이어야 맞다 — 래퍼 없이 같은 파이프를 태우면 판정이 실제로 사라지는지
먼저 확인한다(안 사라지면 나머지 다섯은 「고쳐서 통과」가 아니라 **깨진 적 없는 것을 잰 것**).
**그리고 이 반복이 서른일곱 번째 표본을 냈다** — 전수를 친다면서 `discover -b`(시작 디렉터리
**누락**)를 쳐 **`Ran 0 tests / OK / rc=0`** 을 받았다. **파이프를 안 붙였는데도 0 을 세며
초록**이었다 — 조항이 못 덮는 **새 얼굴**이고, 잡아낸 것은 눈이 아니라 `project.md` 에 적힌
명령과 대 본 것이다(후보 등재). README 단위 수 가드가 812→818 로 물어 함께 맞췄다.

**같은 반복 끝에 하나 더 — 조항을 어겼는데 손실이 0 이다.** 기록을 갱신하고 전수를 다시
칠 때 `2>/tmp/vl_run.txt` 뒤에 `echo "rc=$?"` 와 `grep -E '^(Ran |OK|FAILED|FAIL: )'` 를
붙였다. **가려진 것은 없다** — 리다이렉션은 파이프와 달리 `$?` 를 안 먹고, 판정도 `rc` 도
화면에 있었다. **계수에 넣지 않는다**(항목이 세는 것은 «가려진 횟수»다). 값은 다른 데 있다:
손이 저절로 간 모양이 **계획 106 의 래퍼와 같은 모양**이었다 — 전량을 파일로 남기고 판정만
다시 찍기. **조항이 막으려던 충동은 「판정만 보고 싶다」이고, 그 충동은 옳다.** 막아야 할
것은 충동이 아니라 충동이 손으로 갈 때 생기는 손실이고, 그래서 처방이 문장이 아니라 기제다.

**환경 변수는 래퍼 «앞»에 둔다** — `"$@"` 로 넘어온 `VAR=val` 은 배정이 아니라 명령

### 반복 634 — 설계 phase · **둘 중 하나로는 안 된다** (`design_zero-population.md`)

**C(둘 다)** 를 골랐고 고른 이유가 비교표의 마지막 두 줄이다. **A(래퍼만)는 오늘 난
사고를 못 막는다** — 그날 친 명령엔 파이프도 래퍼도 없었다. **B(`tests/__init__.py` 만)는
덫 하나를 치울 뿐** 「0건인데 초록」이라는 판정은 그대로다(오타 난 `-k`, 빈 `-s` 대상).
둘은 겹치지 않고 **서로의 구멍이 상대의 값**이다. **digest 의 처방을 탐침이 뒤집었다** —
그 항목은 「밖에서 세는 자리는 래퍼뿐」이라 적었는데 더 싼 자리가 있었다: 세는 대신
**덫을 치운다**. 래퍼 쪽 값은 `rc=2` 로 잡았다 — 이 저장소에서 **2 는 판정이 아니라
「재지 못했다」** 이고 0건이 정확히 그것이다. 3-2절 가정 셋을 실측으로 깼다: 빈
`__init__.py` 로 문서화된 **세 꼴 전부 826 OK** · `-m unittest tests.test_deps` **9건 OK**
(사본·원본) · `Ran 0 tests in 0.000s` 표기 확인. 계약에 **「판정 칸이 빈 것과 0건은 다르다」**
를 못박았다 — e2e 스크립트의 `── rc=0` 은 그대로 0 이어야 한다.
