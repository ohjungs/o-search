## 1. 문제 · 목표 · 기대 결과

### 문제

**호출하는 쪽이 종료 코드만 보고는 무엇을 해야 할지 알 수 없다.** 두 갈래다.

**(가) 같은 종류의 실패가 명령마다 다른 값이다.**
`indexer.main` 은 환경 오류 네 갈래를 전부 `rc 2` 로 내고, `serve.main` 은
환경 오류 한 갈래를 `rc 1` 로 낸다. `serve.py:329-333` 은 그 이유를 주석으로
적어 뒀다 — *"사용자 입력이 아니라 환경이라 usage(2)가 아니고 … rc 1"*.
`README.md:28` 도 같은 편이다 — *"인자 없이 부르면 각 명령이 자기 usage 를 낸다(rc 2)"*.
그런데 `indexer` 는 없는 DB·크롤 데이터 없음·옛 색인·락·손상 DB 를 **전부 rc 2** 로 낸다.

**(나) 재시도하면 풀리는 오류와 안 풀리는 오류가 같은 값이다.**
계획 39 가 더한 `sqlite3.DatabaseError` 갈래(`indexer.py:254-262`)는 **락**(30초를
기다리고도 안 풀린 것 — 답은 "나중에 다시")과 **손상 DB·비 DB 파일**(답은 "다른 파일을
줘라")을 **같은 rc 2** 로 낸다. 지금 이 둘을 가르는 것은 stderr 문구뿐이라,
`crawl && indexer` 나 cron 재시도 래퍼는 문구를 파싱해야 한다.

### 목표

세 CLI(`crawl`·`indexer`·`serve`)가 **하나의 종료 코드 계약**을 따르고, 그 계약이
문서(`README.md`)와 코드 주석과 단언에서 **같은 것을 말한다.**

### 기대 결과

- 종료 코드의 의미가 `README.md` 에 **표 한 벌**로 적혀 있고, 세 명령이 그것을 지킨다.
- 각 값을 고정하는 단언이 존재한다 — 특히 지금 **0건**인 `serve` 의 환경 오류 값.
- 재시도 가능/불가능이 종료 코드로 갈린다(방법은 설계가 정한다 — 3절 대안 C 참조).

### 가정 (틀리면 계획을 다시 쓴다)

- 이 저장소의 CLI 를 부르는 외부 스크립트는 없다(`README.md`·`e2e/`·`tests/` 가 전부다).
  → 4절 스텝 0 에서 `grep` 으로 확인한다. 있으면 호환 부담이 생겨 대안 선택이 달라진다.
- `data/crawl.db` 는 안 건드린다(8절).

### 2-1. 착수 탐침이 근거 항목의 진술 **둘**을 정정했다

digest `[7]` 은 계획 39 리뷰가 백지 패스에서 쓴 것이라 전수 조사가 아니었다.
읽고 실행해서 확인한 결과 **두 군데가 틀렸다.** (digest `[7]` 관찰의 재현이다 —
*"항목의 진단은 옳아도 세부는 그때의 추정이다"*.)

**① "세 모듈짜리 계획" 이 아니라 둘이다.**
`crawl.main` 에는 환경 오류 갈래가 **0개**다. `rc 2` 를 내는 자리 일곱 곳
(`crawl.py:326`·`333`·`337`·`347`·`356`·`380`)은 전부 인자 오류이고,
digest 가 환경으로 센 `crawl.py:380 NoUsableSeedsError` 는 `crawl.py:25-32` 의
docstring 이 **사용자 입력 오류(rc 2)** 라고 이유까지 적어 뒀다:

> "0페이지 수집" 과 다르다. 저쪽은 크롤이 돌았고 결과가 없는 것이라 rc 0 이고
> (robots 가 정당하게 막은 사이트가 그 자리다), 이쪽은 요청이 한 건도 나갈 수
> 없는 것이라 사용자 입력 오류(rc 2)다.

→ **갈린 것은 `indexer` 와 `serve` 둘뿐이다.** `crawl` 은 이미 계약을 지키고 있고
이 계획에서 `crawl.py` 의 rc 값은 **안 바뀐다**(5절).

**② `serve` 의 rc 1 을 고정하는 단언이 0건이다.**
`grep "serve.main" tests/*.py e2e/*.py` 에 rc 1 을 재는 자리가 **하나도 없다**.
"저장소 관례" 로 인용된 값을 아무도 안 붙들고 있다 — 계획 39 리뷰가
`_doc_count`·`search` 의 `timeout=30` 에서 잡은 것과 **같은 모양**이다.

## 3. 대안 (설계로 넘긴다 — 여기서 고르지 않는다)

세 개가 떠올랐고 서로 다른 것을 희생한다. **대안이 둘 이상이면 이미 설계가 필요하다**
(`rules/plan.md` 6-1). 설계가 `docs/specs/concept.md ## 갈림길에서의 우선순위` 와
아래 비용으로 고른다.

| | 무엇을 하나 | 옮기는 단언 | 걸리는 것 |
|---|---|---|---|
| **A** | 환경 오류를 **rc 1** 로 모은다 (`serve` 를 따라간다) | 7곳 | `README.md:28`(rc 2 = usage)과 맞다. 대신 21·24·26·27·29 가 세운 "트레이스백 대신 rc 2" 서술을 **말만** 고쳐야 한다(동작 의도는 안 바뀐다) |
| **B** | `serve` 를 **rc 2** 로 내린다 | 0곳 (+ 새 단언 1) | 제품 diff **1줄**. 대신 `README.md:28` 의 "rc 2 = usage" 가 거짓이 되고, `serve.py:329-333` 이 적어 둔 근거를 지운다 |
| **C** | 재시도 가능(락)만 **별도 코드**로 가른다 | 1곳 (락 단언) | 문제 (나)를 정면으로 푼다. 대신 계약이 세 값에서 네 값으로 늘고, 어느 값인지(`75 EX_TEMPFAIL`? `3`?)가 또 갈림길이다 |

**A 와 C 는 배타적이지 않다.** 설계가 둘 다 택할 수도 있고, 그러면 스텝이 는다.
`crawl` 의 rc 값은 **어느 대안에서도 안 바뀐다** — 이미 계약을 지킨다(2-1).

## 4. 스텝 분할과 완료 기준 (잠정 — 설계가 확정한다)

설계 전이라 **스텝 수는 2 로 잠정**이다. 설계가 대안 A+C 를 함께 고르면 3 이 된다.
각 스텝은 그것만 읽고 시작할 수 있어야 한다.

### 스텝 0 (설계 안에서 처리 · 별도 커밋 아님)

- 시작점: `grep -rn "websearch.crawl\|websearch.indexer\|websearch.serve" --include=* .`
- 확인할 것: 이 저장소 밖으로 종료 코드를 노출하는 호출처가 있나(1절 가정).
- 확인법: 히트가 `README.md`·`docs/`·`e2e/`·`tests/` 뿐이면 가정이 참이다.

### 스텝 1 — 계약을 한 곳에 적고, 지금 값을 전부 못박는다 (`src/` 0줄)

- **시작점**: `README.md:28` 의 한 줄(`인자 없이 부르면 각 명령이 자기 usage 를 낸다(rc 2)`).
- **무엇이 이미 참인가**: `tests/test_indexer.py` 에 rc 2 단언 8건,
  `tests/test_crawl.py` 에 7건, `e2e/tokenizer_e2e.py:153` 에 1건이 있다.
  `serve` 의 환경 오류 rc 를 재는 단언은 **0건**이다(2-1 ②).
- **할 것**: ① `README.md` 에 종료 코드 표를 만든다(`0`·`2`·`130`·`serve` 의 `1`,
  **오늘의 값 그대로**) ② `tests/test_serve.py` 에 환경 오류(bind 실패) rc 단언을
  **한 건** 추가해 지금의 rc 1 을 못박는다.
- **완료 기준**: 단위 462 → **463건 OK** · `src/` diff **0줄** ·
  변이 M1(`serve.py:333` 의 `return 1` → `return 2`)이 **새 단언 하나만** 죽인다.
- **예상 파일**: `README.md` · `tests/test_serve.py`
- **왜 먼저인가**: 값을 바꾸기 전에 **지금 값이 무엇인지 재는 자리**를 만든다.
  이 스텝이 없으면 스텝 2 의 변경이 "고친 것"인지 "몰래 바뀐 것"인지 구별되지 않는다.
  계획 39 리뷰가 M6 로 배운 것이다(`plan_history_025.md` 9절).

### 스텝 2 — 설계가 고른 대안을 적용한다

- **시작점**: 설계 문서(`docs/design_exit-code-contract.md`)의 결정 절.
- **무엇이 이미 참인가**: 스텝 1 이 끝나 오늘의 모든 rc 값에 단언이 붙어 있다.
- **완료 기준**: ① 설계가 고른 값으로 세 명령이 끝난다(실측 rc 표를 2-2 형식으로 다시 잰다)
  ② `README.md` 표와 코드가 일치 ③ 단위 **463건 이상** OK, 줄면 RED
  ④ 변이 검사 — 바꾼 갈래마다 값을 되돌리는 변이가 **각각 다른 단언**을 죽인다.
- **예상 파일**: 대안 A → `src/websearch/indexer.py` · `tests/test_indexer.py` ·
  `e2e/tokenizer_e2e.py` · `README.md` / 대안 B → `src/websearch/serve.py` ·
  `tests/test_serve.py` · `README.md`.
  **여기 없는 파일을 고쳐야 하면 YELLOW** — 특히 `src/websearch/crawl.py`(5절).

두 스텝은 **직렬**이다 — 스텝 2 가 스텝 1 이 만든 단언을 읽고 고친다(진짜 의존).

## 6. 설계 판단 — **필요하다**

`rules/plan.md` 6-1 의 기준에 걸린다: **대안이 셋 떠올랐고**(3절) 서로 다른 것을
희생하며, 하나는 `README.md` 를 거짓으로 만들고 하나는 e2e 를 포함한 7곳의 단언을
옮긴다. 값이 세 CLI 의 **공개 계약**이라 되돌리기도 싸지 않다.

→ `phase: 설계`. 설계 문서는 `docs/design_exit-code-contract.md`.
설계가 답해야 할 것은 셋이다:

1. **어느 대안인가** — A/B/C 중 하나 또는 A+C. 고른 이유와 **버린 축**을 적는다.
2. **재시도 가능/불가능을 종료 코드로 가르나** — 가른다면 어느 값인가.
   가르지 않는다면 호출자가 무엇으로 판단하는지를 적는다.
3. **`crawl` 은 정말 안 건드려도 되나** — 2-1 ①의 판정을 설계가 한 번 더 확인한다.
   (계획 39 의 근거가 백지 패스라서 틀렸다. 이 계획의 근거도 한 번은 대조되어야 한다.)

## 7. e2e 판단 — **새 e2e 0개** (설계가 대안 A 를 고른 결과 · 리뷰 1/1 이 되받아 적었다)

**되받아 적은 결과(2026-09-01, 리뷰).** 아래 기준을 대안 A 에 적용하면 **새 파일 0개**다.
바뀐 값을 재는 데 프로세스 경계가 필요한 자리는 이미 둘 다 e2e 에 있다 —
`e2e/tokenizer_e2e.py:153`(옛 색인 질의)와 **설계가 빠뜨렸던 여덟째 자리**
`e2e/indexer_interrupt_e2e.py:281`(중단 뒤 질의)이 진짜 서브프로세스의 rc 를 재고,
둘 다 `Traceback` 부재 단언을 함께 들고 있다(rc 1 은 안 잡힌 예외와 값이 같아
**값만으로는 못 가른다** — 이 계약의 유일한 구조적 대가고, 그 대가를 갚는 것이 그 단언이다).
`serve` 의 bind 실패(포트 둘이 필요한 OS 자원)는 이 계획이 **안 건드리는 값**이라 해당 없다.
대안 B 였다면 붙였어야 했다.

## 7-1. 원래 적었던 것 — **미정 · 설계가 정한다**

지금 아는 것: `e2e/tokenizer_e2e.py:153` 이 이미 옛 색인의 rc 2 를 **진짜 서브프로세스로**
재고 있어, 대안 A 를 고르면 그 줄이 자동으로 새 계약의 e2e 가 된다(새 파일 0개).
대안 B 를 고르면 `serve` 의 bind 실패를 재는 자리가 필요한데, 그것은 **포트를 점유한
프로세스 둘**이 있어야 하는 단위 밖 상황이다.

**계획 시점에 확정하지 못하는 이유를 적는다** — 무엇을 e2e 로 잴지가 대안 선택에
달려 있고, 대안은 설계가 고른다. `rules/plan.md` 7절이 요구하는 "구현에 맞춰
시나리오를 낮추지 않는다" 는 **판정 기준을 미리 못박아** 지킨다:

> **e2e 를 붙이는 조건**: 바뀐 값을 재는 데 **프로세스 경계나 진짜 OS 자원**(포트 점유,
> 파일 락, argv)이 필요하면 붙인다. 목으로 같은 예외를 세워 재지는 것이면 단위로 끝낸다.

이 기준은 계획 39 가 쓴 것과 같다(락은 WAL 물리 때문에 계층을 올려도 못 재서 e2e 를
안 붙였다). 설계가 이 기준을 적용한 결과를 계획서 7절에 **되받아 적는다.**
