### 반복 678 — 짧은 경로 · **루프가 이틀 연속 죽었는데 겉보기로는 정상이었다**

로그에 `루프 종료 rc=1` 이 10/04·10/05 두 줄 있었다. 출력을 `>/dev/null 2>&1` 로 버려
**왜인지 알 길이 없었고**, 스크립트는 그대로 진행해 `exit 0` 으로 끝나 `launchctl` 에도
`last exit code = 0` 으로 남았다. **이틀간 개발 0줄인데 「밀 것 없음」만 찍혔다** — 9월에만
세 번 겪은 그 모양이다(재는 자가, 지키는 자가 조용히 죽어 있었다).

셋을 고쳤다: 실패 출력을 로그에 남긴다 · 연속 실패를 센다 · **`exit 1` 로 끝낸다**(종료
코드가 사실을 말해야 `launchctl` 로 알 수 있다). 네 경로를 실측했다 — 1회차 `rc=1`+출력 ·
2회차 「연속 2회」 · 성공 시 카운터 삭제+`rc=0`. **첫 측정은 버렸다**: REPO 를 없는 경로로
두어 `cd` 가 먼저 실패했고 그 `rc=1` 을 처방의 것으로 읽을 뻔했다.

원인은 사람 몫이다(결정 ⑪) — 인증이 끊기면 밤이 스스로 복구할 수 없다. 스크립트는
저장소 밖(`~/.local/bin`)이라 커밋되는 것은 이 기록뿐이다.
